## 2. 背景与现网基线（2026-11-17 实测）

## 4. 需求明细

### 4.1 P0·死代码清理（D2/D3/D4）

1. 删除 `LabAutoGradingService.java` 全文件、`ScoringDecisionMode.java` 全文件。
2. `ExamScoringService` 保留类与 `isObjective()`，删除 `scoreObjectiveQuestion()`；`ExamServiceTests` 中凡直接调用该方法的断言一律改写为经 `ScoringEngine` 路由的等价用例。**语义覆盖基线（即该测试类现网直调用例的实际覆盖，改写前后不得减少）**：单选全对 / 全错、多选精确匹配与顺序无关、判断别名归一、SHORT/主观类型不参与自动判分（`isObjective=false`）、null 与空字符串答案判 0 分。填空的逐空累加语义不在 `ExamServiceTests` 基线内（现网该类无直调填空用例），由共享策略既有测试承担，不在本次改写范围。
3. 删除后全仓 grep 不得残留对已删符号的引用。

### 4.2 P1·三域状态机收敛（D8，单独立项）

需求：三域「逐题求和 → allScored 判 GRADED → score_record upsert/remove」收敛为 grading 层唯一公共组件，三域调用；保持各域现有状态语义（考试 `autoScore+manualScore` 两段、作业整卷覆盖入口、实验逐步评分）不变。约束：须先出独立技术方案并通过自查收敛；若涉及 Flyway 迁移，先过备份门禁。

### 4.3 P2·胶水与透传收敛（D5/D7）

1. `LabAssessmentAdapter` 删除，`LabScoringSupport` 直接注入 `ScoringEngine`。
2. scoringConfig 解析与答案归一化工具收敛为 grading 层唯一公共工具类；`GradingAdapter` 与 `LabScoringSupport` 改为调用该工具，判分行为逐用例不变（以 `./mvnw test` 全绿为门槛）。

### 4.4 P3·前端优化（D10/D11/D12/D13）

1. 删除 `api/labs.ts` 的 `releaseTeacherLabScores`。
2. 新增 scoreSource 共享文案映射，覆盖 `AUTO` / `SUGGESTED`（lab 现网值）/ `RECOMMENDED`（exam、homework 现网值）/ `AUTO_ACCEPTED` / `TEACHER`，三域批改页统一接入；作业页不再裸显英文原值。
3. 实验两个批改页重复函数抽共享。
4. 「评分汇总」卡与完成度维持前端实时计算，不改（D13）。

## 5. 非目标与否决项（评估结论，防止回潮）

| 项 | 结论 | 理由 |
|---|---|---|
| 简化/拆掉策略引擎 | **否决** | 5 题型 × 3 域真实共享，拆掉即回到三份判分实现 |
| 主观题建议分升级为语义/AI 匹配 | **否决（不立项）** | 现关键词规则透明、可解释（judgeDetail 可审计）、教师可改分兜底；升级属独立产品需求，当前无需求输入 |
| 「人工评分完成度」改后端字段 | **否决** | 批改中间态需即时反馈，纯前端 computed 零成本且无一致性风险（N8） |
| 考试总分展示改读后端 totalScore | **维持现状** | 批改中 totalScore 未定稿，前端实时重算 + GRADED 后 detail 刷新已对齐 |
| 消除三层分数镜像 / 三张逐题表合表 | **否决（本期）** | 涉及表结构与 analysis 口径，收益不抵风险；D9 已决策保留 |
| 客观题放开教师改分 | **否决** | 现网口径「客观题由系统自动评分，不支持手工改分」（`ExamReportService.java` L317）语义正确；快照缺失按主观题处理已是合理逃生口 |
| 删除 `ScoreRecordWriter` / `ScoreReleaseSupport` | **否决** | 三域真实公共能力（D6） |
| 实验成绩发布入口链路核实 | **移入非目标** | 后端端点 `/teacher/labs/{id}/release-scores` 保留（D10/D17）；前端无调用方的实验成绩发布替代链路核实另行立项，不属本 PRD 范围 |
