### 1.1 已定决策清单

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| D1 | 统一边界 | 只统一**基础规格 + 页面骨架 + 通用状态表达 + 通用交互规格**；三种角色的页面节奏与专业工作区不套模板。统一的是词汇表，不是文章结构 |
| D2 | 分层架构 | 固定四层：`L0 tokens`（`assets/tokens.css`）→ `L1 primitives`（`assets/layout.css`）→ `L2 ui components`（`components/ui/`）→ `L3 pages`（`views/**` 只写页面专属编排）。不新增 `src/` 顶层目录 |
| D3 | 单一事实来源 | 颜色、字号、间距、圆角、阴影、层级、动效只在 `tokens.css` 定义；页面与组件不得出现新的颜色字面量。既有 `workbench/workbench.css` 保留，但其变量必须改为引用全局 token |
| D4 | 不推翻三套壳层 | 继承 `AGENTS.md`：`/teacher`、`/student`、`/admin` 三套壳层与导航语义不合并；平台超管继续复用 `/admin` 壳层。统一发生在壳层内部的基础件，不改变路由与角色边界 |
| D5 | 不统一的对象 | 实验三栏批改台、考试答题页、实验分步作答、代码编辑区、学生任务卡流、教师高密度表格、登录页左右分栏，保持现有信息密度与编排；不得为“同形”牺牲操作效率或可读性。登录页仍纳入 token 与按钮规格，仅布局不动 |
| D6 | 颜色 token | 语义化命名，不按色值命名。收敛为：背景 2 档、文字 5 档（含反白）、描边 3 档、表面 2 档、品牌 3 组（教师 teal / 校管 violet / 学生 blue）、反馈 4 组、状态 4 组。具体映射见 §4.1 FR-1 |
| D7 | 字号与间距 | 目标阶梯：字号 `11/12/13/14/16/18/22/28/36/44/58`，间距 `4/8/12/16/20/24/32`，圆角 `999/16/12/8/6`，阴影 3 档。P0 只做**等值替换**；不在目标阶梯内的值（10/15/17/20/24/26/30/32/34 px 与 3/4/9/10/14/18/22/24/28/32 px 圆角，42px 归入 44px）**统一在 P3 归一**，按「最近档位、距离相同取较大档」处理并逐页截图确认 |
| D8 | 断点口径 | 固定五档：`640 / 768 / 900 / 1024 / 1280`。CSS 变量无法用于 `@media` 条件，因此断点以**文档常量 + 源码断言**约束，不引入 `postcss-custom-media` 等新依赖。P0 只登记，P1 起新代码必须取五档之一 |
| D9 | 全局样式文件 | 新增 `frontend/src/assets/tokens.css` 与 `frontend/src/assets/layout.css`，`main.ts` 引入顺序固定为 `element-plus/theme-chalk → tokens.css → global.css → layout.css`。本 PRD 显式修订 11-19 技术方案 TD20「禁止新增全局样式文件」与 11-19 PRD D18「不修改 global.css」——这两条仅约束其自身交付范围，本期正是全局样式治理 |
| D10 | 骨架类不改名 | P1 把 `page` / `page-header` / `toolbar-card` / `table-card` / `state-card` / `identity-cell` / `summary-grid` 等**沿用原名**提升为全局类，删除页面内 scoped 副本。这样 P1 不需要改任何模板，风险最低 |
| D11 | 骨架类唯一版本 | 同名类只保留一份定义，且以现网出现次数最多的版本为准：卡片 `radius 12px`、`padding 12px 14px`、`border #e2e8f0`、`shadow 0 6px 18px rgba(15,23,42,.04)`；`page-header` 以 `flex / space-between / align-items flex-start / gap 16px` 为唯一版本。页面若有刻意的视觉变体，必须改用独立类名，不得再复制同名类 |
| D12 | 组件抽取门槛 | 只抽取现网存在 **≥4 处重复实现** 的结构，最终 6 个：`AppPageHeader` / `AppToolbarCard` / `AppTableCard` / `AppStatusTag` / `AppEmptyState` / `AppMetaChip`。`kpi-card` 现网仅 1 处使用，**不抽组件**，保留为全局类。不建按钮、输入框等 Element Plus 已有原子的包装层 |
| D13 | 状态与元信息表达 | 状态类统一 `AppStatusTag`（内部基于 `el-tag`，对外只暴露语义 `tone`：`neutral / success / info / warning / danger` 与 `label`）；统计 / 元信息类统一 `AppMetaChip`。现网 6 种自研 chip 按语义拆分：`status-chip` / `exam-chip` 归 `AppStatusTag`；`workbench-chip` / `header-stat-chip` 归 `AppMetaChip`；`status-pill`（三栏批改台）与 `result-status-badge`（考试答题页，含 Material 图标）属 FR-15 不迁移项，仅做 token 化。`el-tag` 不强制一次性全量替换，但同一业务状态的画法必须唯一 |
| D14 | 空状态表达 | 统一 `AppEmptyState`，内部用 `el-empty`，支持 `description` 与可选操作按钮；`empty-text` 表格内联空文案保留在 `el-table` 内（表格内不嵌卡片），`el-result` 仅用于整页加载失败 |
| D15 | 按钮规格 | 以 Element Plus 为唯一按钮实现：`primary / default / danger / warning / info` + `text` / `link` 形态，尺寸 `default(32px) / small(28px)`。禁止新增自定义按钮类；现网 `.action-button` 仅作为 `workbench` 内部实现保留并改为引用 token，不再扩散到其它目录。登录页既有 `.ghost-button` / `.text-link` 在 P3 迁移为 `el-button`（`default` / `text`）。原生 `<button>` 仅允许用于整块可点击卡片（需带 `type="button"` 与可访问名称），样式由全局 `.app-click-card` 提供 |
| D16 | 对话框与表单规格 | 对话框宽度固定四档：`480 / 640 / 860 / 1040px`，映射规则写死：轻量新增 / 编辑表单用 `480`，带多字段与说明的表单用 `640`，含题目配置 / 批量操作 / 预览用 `860`，含三栏或大面积表格用 `1040`，不出现其它宽度。新增 / 编辑表单统一 `label-position="top"`；表格操作列统一右对齐、`fixed="right"`、`link` 按钮，超过 3 个动作收进「更多」下拉 |
| D17 | 图标规格 | Material Symbols Outlined 为唯一图标体系（现网 28 个文件使用，`el-icon` 仅 3 个文件）。图标尺寸固定 `18px`（按钮与正文内联）/ `24px`（导航与独立图标）。禁止新增 `el-icon` 与 `@element-plus/icons-vue` 引用；存量 3 个文件在 P3 迁移 |
| D18 | 内联样式治理 | 现网 63 处内联 `style` 中，图标尺寸 / 间距类改为全局工具类（`.app-icon--sm` 等）；真正的动态值（如按分数计算的宽度、颜色）保留内联并加注释。禁止用内联样式表达静态颜色、圆角、字号 |
| D19 | 渐变与角色主题 | 角色主色继续通过壳层 `.theme-teacher / .theme-admin / .theme-student` 注入，但变量定义改到 `tokens.css`，页面不得再自建 `--labs-*` / `--detail-*` / `--blank-*` / `--materials-*` / `--steps-*` / `--batch-*` 这类页面私有主题前缀（共 6 套），需改为引用全局语义 token |
| D20 | 不动契约 | 后端、Flyway、HTTP 路径、请求体、`frontend/src/types/`、`frontend/src/api/` 全部零改动；本期只改样式与展示层组件，不改任何业务逻辑、权限判断与数据流 |
| D21 | 防回潮门禁 | 不新增 lint 依赖；用仓库既有的 vitest 源码断言方式新增 `assets/__tests__/designTokens.spec.ts`，以**基线棘轮**方式校验：颜色字面量数量、`!important` 数量、非标准断点数、`el-icon` 引用数、同名骨架类定义数均不得高于基线，且 `tokens.css` / `layout.css` 必须被 `main.ts` 正确引入 |
| D22 | 实施分期 | P0 token 层（不改模板）→ P1 骨架去重（不改模板）→ P2 六组件抽取与逐页迁移 → P3 交互与视觉规格统一 → P4 门禁与规范回写。每期独立可验收、可回滚；未完成前不得声称全站统一完成 |
| D23 | 视觉回归方式 | 每期完成后，教师端取 `Dashboard` / `Labs` / `exams/Results`，学生端取 `Dashboard` / `Labs` / `exams/Detail`，校管端取 `Dashboard` / `Teachers` / `Students`，再加登录页，共 10 页做前后截图对比；除 PRD 明确列出的变化外，不允许出现布局位移 |

## 3. 目标与非目标

### 3.1 目标

1. 全站基础视觉规格只有一份定义：改一次颜色 / 圆角 / 字号 / 阴影，所有引用处同步生效。
2. 等价页面骨架只有一份实现：新增管理页不再复制 `.toolbar-card` / `.table-card` / `.identity-cell`。
3. 同一业务状态、同一空状态、同一操作按钮在全站只有一种表达方式。
4. 三种角色的信息节奏与专业工作区**保持差异**，但差异来自编排，不来自各写一套基础件。
5. 建立不新增依赖的防回潮门禁，使上述收敛不会随新页面回退。
6. 全程无后端、数据库、权限、接口契约变更；真实服务与真实账号下逐期验收通过。

### 3.2 非目标（明确否决）

| 非目标 | 结论与理由 |
|---|---|
| 把全站页面改成同一套布局模板 | 否决：违反 D1 / D4 / D5 与 `AGENTS.md` 三角色节奏约束；教师高密度管理台、学生任务流、校管治理视角必须保留差异 |
| 一次性重写 16305 行 scoped CSS | 否决：风险与回归成本不可控；改为 P0 等值替换 + P1 去重 + P2 逐页迁移的渐进路径 |
| 统一所有字号为单一值、所有间距为单一值 | 否决：统一的是**阶梯**，不是单值；教师表格与学生正文应取不同档位 |
| 引入 Tailwind / CSS-in-JS / Storybook / 新 UI 组件库 / stylelint | 否决：与 `frontend-code-style.mdc` 既有约束冲突，且本期用现有 vitest 源码断言即可满足门禁 |
| 全量替换 `el-tag` 为自研状态组件 | 否决：21 个文件的机械替换收益低、回归面大；改为「同一状态画法唯一 + 新代码走 `AppStatusTag`」 |
| 抽按钮 / 输入框 / 表格等 Element Plus 原子组件的包装层 | 否决：D12 门槛不满足，属于过度封装 |
| 改后端、Flyway、HTTP 契约、`api/`、`types/`、权限判断 | 否决：本期为展示层治理，任何契约改动都超出需求 |

## 6. 已否决方案

| 方案 | 否决理由 |
|---|---|
| 只新增一份设计规范文档，不改代码 | 现状问题是样式重复实现，文档无法约束既有 16305 行 scoped CSS，也无法阻止新页面继续复制 |
| 一次性把所有 scoped 样式搬进全局文件 | 选择器优先级与作用域会整体改变，回归面覆盖全站，收益与风险不成比例 |
| 用 CSS 变量统一媒体查询断点 | CSS 变量不能用于 `@media` 条件；`@custom-media` 需要新增 PostCSS 依赖，违背 D21 |
| 引入 Tailwind 以「原子类统一」 | 与 `frontend-code-style.mdc`「不引入 Tailwind」直接冲突，且需要重写全部模板 |
| 把三种角色页面合并成一套模板 | 违反 `AGENTS.md` 三角色节奏约束，会降低教师管理效率与学生任务清晰度 |
| 全量替换 `el-tag` / `el-button` 为自研组件 | 21 / 41 个文件的机械替换回归面过大，且包装层不满足 D12 抽取门槛 |
| 删除 `workbench.css`，全部并入 `global.css` | 11-19 已交付且验证的样式边界应保留；本期只做 token 对齐，不做目录搬迁 |
| 用截图快照测试做视觉回归 | 需引入浏览器测试依赖与基线图片仓库，超出本期工具链约束；改为人工 10 页截图 |
