## 2. 背景与目标

### 2.1 背景

| # | 问题 |
|---|---|
| P1 | 编码全表唯一与「题目按教师私有」的资源模型错位；列表、编辑、删除均按 `(school_id, created_by)` 隔离，跨教师、跨校却不能同码 |
| P2 | 外部导入（教材 / 平台题库短码如 `S-001`）在多教师、多校场景必然大面积撞码，服务端 40900 静默跳过，教师漏题而不自知 |
| P3 | 预检口径（本教师题库）与服务端口径（全表）不一致，出现「预览通过、提交跳过」的误导；「再次导入」是唯一合法情形 |
| P4 | 平台没有编码规则，编码被误当作内容去重工具；实际编码只管身份与导入幂等 |
| P5 | `uk_question_bank_source_ref` 是全局唯一索引，服务层却按 `schoolId` 查询，唯一索引与读路径粒度不一致（总纲 V7.0 D10 定 `school_id` 为唯一租户隔离列）；幂等键须与查询同粒度 |
| P6 | 全局唯一 `code` 与不含 `school_id` 的唯一索引使编码语义与按校隔离的资源模型不一致；本期只收敛到归属维度，不预设任何未来分片方案（§3） |

### 2.2 目标

1. 把编码唯一性收敛到归属维度，消除跨教师 / 跨校导入撞码与预检口径错位。
2. 发布平台编码规则，明确编码「由谁编、怎么编、校验边界在哪」，替代隐含的全局号语义。
3. 立住发号契约与索引形状，使总纲 V7.0 阶段 2 的三层归属（D10）可在不改编码语义、零回填的前提下加列换键；不预设分表方案（分表属总纲未定义能力，见 §3）。
4. 同步既有文档口径，避免「全局唯一」旧表述继续被实现者当作依据。

### 2.3 成功标准（可测）

- 同校两名教师各导入含 `S-001` 的同一批 JSON 均成功；该教师重复导入时全部记为「跳过（编码已被占用）」。
- 服务端判重不再出现跨教师、跨校 40900；预检结果与提交结果一致。
- 编码规则的全部违规形态都有明确拒绝文案，导入预览逐行标 ERROR 且阻断提交。
- `V29` 在 UT H2 mem、本机 MySQL、路径 B H2 文件库三形态通过（口径与 §7.5 一致）；`./mvnw test`、`npm run build` 通过。

## 4. 发号策略

### 4.1 三类号

| 号 | 谁发 | 唯一范围 | 可变 | 职责 | 索引形状 |
|---|---|---|---|---|---|
| `id` | DB 自增 | 全平台（逻辑） | 不可变 | 快照、组卷、审计等机器引用，须与 `school_id` 同用 | 本期不改生成方式（D23 / §3） |
| `code` | 系统自动码（教师端 `Q-...`、复制链路 `HW/LAB`）/ 外部导入原码 / 用户手填复制码，按平台规则 | 本教师题库命名空间 | 可改（教师端新增题编码只读锁定） | 人读、口述、导入幂等、本教师题库内定位 | 唯一键含 `school_id` |
| `source_ref` | 系统（V22 已有） | 本期改为 `(school_id, source_ref)` | 不可变 | 复制来源追溯，格式预留 `COPIED:{questionId}` | 索引含 `school_id` |

### 4.2 平台编码规则

**硬规则（系统强制）**

| # | 规则 |
|---|---|
| H1 | 非空、去首尾空格、统一大写存储 |
| H2 | 字符集 `A-Z 0-9 - _`（规范化后校验） |
| H3 | 长度 ≤ 64 |
| H4 | 保留自动码形状 `^HW\d+$`、`^LAB\d+S\d+$`；在 D9 规范化之后匹配，用户提交码命中则拒绝 |
| H5 | 归属维度唯一（D2）；由 `V29` 唯一索引与 FR-2 判重共同保证，不另写格式校验代码 |

**软规则（仅对导入文件升级为 H6 硬规则；其余入口仍为提示文案，不校验）**：`<来源前缀>-<批次/章节>-<序号>`，如 `Q-FOUND-001`、`T-2026-001`；序号定长便于排序。导入文件的 H6 正则与作用域见 `2026-11-10-题库批量导入JSON文件与编码规范PRD.md` §3.4。

### 4.3 校验边界

- H1–H4 只作用于用户提交的 `code`（经 API 的新增 / 编辑、导入、手填复制码）；现网系统自动生成的三类码不经过该校验：教师端 `Q-{题型}-{时间戳}{随机位}`、复制链路 `HW{id}` / `LAB{id}S{no}`。
- H1 沿用现网 `SaveQuestionRequest` 的 `@NotBlank` 与 `normalizeCode`；**H3 后端现无长度校验**（`SaveQuestionRequest` 只有 `@NotBlank`，仅 `CopyQuestionToBankRequest` 有 `@Size(max = 64)`），由 FR-4 在后端补齐；导入预览现已有长度校验，沿用。
- `update` 提交码与原值一致时，豁免 H2、H4；H1、H3 仍生效（存量不合规码不追溯、不被迫改名）。
- 违规一律拒绝并给出明确文案，不做静默转写（转写会让外部原码对不上），错误码沿用 `40000` 参数错误段位。
- 导入预览阶段按同一规则逐行判为阻断性 ERROR，存在 ERROR 时禁止提交；与导入 JSON 字段白名单校验并列生效。
- **口径同步（2026-11-10）**：导入文件的 `code` 在 H1–H5 之外另受 H6 三段式前缀 / 序号规则约束；H6 只作用于导入文件，教师端自动码、复制链路自动码、存量数据与 `POST /api/v1/questions` 单题新增 / 编辑仍按 H1–H5。详见 `2026-11-10-题库批量导入JSON文件与编码规范PRD.md` §3.4。

### 4.4 各场景发号

| 场景 | 编码 |
|---|---|
| 教师端新增 / 编辑（现网） | `QuestionEditorDialog.vue` 调用 `buildQuestionCode` 生成 `Q-{题型前3位}-{yyMMddHHmmss}{4位大写base36}`，编码只读锁定；编辑沿用原码；本期不改该交互、不加输入框、不提供生成建议编码按钮 |
| 外部导入 | 保留原码；`code` 必填，缺码整行标 ERROR，不补码、不转写、不加后缀；不合规原码由教师改码后重试 |
| 作业 / 实验复制 | 沿用 `HW{homeworkQuestionId}` / `LAB{labId}S{stepNo}`，`resolveCode` 做 `trim + 大写 + 截断 64`（现网 D24） |
| 手填复制码 | 用户显式传 `code` 时按 H1–H4 校验，命中 40900 由教师改码后重试；系统不自动改写编码 |
| 撞码处理 | 服务端 40900，由教师改码后重试；系统不自动改写编码（现网 D24 / 导入 TD16） |

未来校内公开与机构资产的发号规则属总纲 V7.0 D15 阶段 2–4 独立方案范围，本 PRD 不定义、不登记候选（§3）。
