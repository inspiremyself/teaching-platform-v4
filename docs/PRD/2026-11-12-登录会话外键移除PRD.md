### 1.1 已定决策清单（需求侧）

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| P1 | 做什么 | 移除 `user_login_session.user_id -> sys_user.id` 的 **DB 层外键** `fk_user_login_session_user`，使登录事务不再因外键校验对 `sys_user` 父行取 S 锁；随后把 `AuthService#login` 的 `saveAndFlush` 回退为 `save`，删除围绕外键锁顺序的 3 行注释与 `InOrder` 回归用例。不新增业务能力 |
| P2 | 迁移 | 新增唯一脚本 `V32__drop_user_login_session_fk.sql`（`db/migration/` 实测 `V1`–`V31` 连续、最大 `V31`）；`V1`–`V31` 一字不改、不 `flyway repair`。迁移只做「删外键 + 建显式索引」，不建表、不加列、不回填、不删数据 |
| P3 | 外键口径 | 全库对齐 `V31` 的现网裸列范式：**DB 层不建外键**，参照完整性由应用层保证。本 PRD 只移除点名的这 1 条；`V10` 的 `fk_lab_step_answer_log_answer` 与 `V20` 的 `fk_lab_sub_metrics_submission` 保留、不在本 PRD 范围内 |
| P4 | 实体映射 | `UserLoginSession` 的 `@ManyToOne` + `@JoinColumn` **保留不改**：JPA 关联映射不是 DB 外键，`ddl-auto=validate` / `none` 都不生成或校验 FK；改成 `Long userId` 裸列会牵动派生查询、JPQL、`@EntityGraph` 与 `JwtAuthenticationFilter`，收益仅为范式文字一致 |
| P5 | 索引 | 双侧统一新增一条显式索引承接 `findFirstByUser_IdAndStatusOrderByCreatedAtDesc` 查询；MySQL 侧 `V11` 建 FK 时自动生成的 `user_id` 单列索引**保留不删**（索引名动态定位成本高，删除收益仅为去冗余），不新增唯一约束、不加 `uk(user_id,status)` |

| P7 | 会话语义 | 不改会话状态机、不改 `handleExistingActiveSession`、不修复「REPEATABLE READ 下并发产生多条 `ACTIVE` 会话」；验收不以「仅 1 条 `ACTIVE`」判定，与 `12aa15e` 方案的 D6 一致 |

- `docs/技术方案/2026-11-12-并发登录死锁修复技术方案.md` V1.6 是**历史决策记录**：其 D3「父行 X 锁先于带 FK 子行 INSERT」、D7「保留 `fk_user_login_session_user`」、§8 第 4 条、§10「删除 FK」否决行，描述的是 `12aa15e` 交付时的现网事实。本 PRD 重新决策后，按 P9 只追加引用、不改写这些行。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 会话外键 | `V11__single_session_login.sql` 具名创建的 `fk_user_login_session_user`，`user_login_session.user_id -> sys_user.id` |
| S→X 锁升级环 | 多个同账号登录事务各自经外键校验持有 `sys_user` 父行 S 锁，commit flush 的 `update sys_user` 又申请 X 锁，互持互等形成 MySQL 1213 |
| 裸列范式 | `V31` 与 `1B` 收口方案确立的现网做法：关联只存 `BIGINT` 裸列 + 索引，取值由应用层校验，不建 DB 外键、不加 DB CHECK |
| 同轮联动自查 | 本 PRD 与配套技术方案一起按 `self-review-and-fix` 方案模式迭代，收敛结论记入配套技术方案 §10 修订记录 |

## 3. 业务形态与不变边界

本需求是**数据库约束与并发锁链路的技术债清理**，不新增任何页面、路由、菜单、角色、权限项或 API：

| 角色 | 本需求前后 |
|---|---|
| `TEACHER` / `STUDENT` / `SCHOOL_ADMIN` / `PLATFORM_ADMIN` | 登录入口、登录请求体、成功 / 失败响应、会话踢出行为、可见范围全部不变 |
| 运维 / DBA | `user_login_session` 不再有 DB 层参照完整性；直接手工删 `sys_user` 行不再被 DB 拒绝（现网无此入口），由 P3 的应用层口径承接 |

**端到端链路（本需求范围内）**：登录 → 插入会话行不再触发父行外键校验 → `update sys_user` 回到 commit flush → 同账号并发退化为父行 X 锁上的普通串行等待 → 无 1213、无 500。

## 6. 非目标（本需求明确不做）

1. 不移除 `V10` / `V20` 的另外 2 条外键，不清理其它表的 DB 约束。
2. 不给 `audit_log` / `http_access_log` / 任何登录事务内 INSERT 的表新增指向 `sys_user` 的 FK（会重新制造 S→X 环）。
3. 不改 `UserLoginSession` 为裸列、不改派生查询 / JPQL / `@EntityGraph`、不改 `ddl-auto` 矩阵与 4 个 Flyway 占位符。
4. 不加 `uk(user_id,status)`、不改会话唯一性、不加 `FOR UPDATE`、不加 `@Version` / `@DynamicUpdate`、不加限流 / 重试 / 缓存 / 连接池参数。
5. 不改登录 API、响应体、错误码、前端三套壳层、`request.ts` 两名单、`GlobalExceptionHandler`。
6. 不新增全局死锁异常分支、不把 1213 映射成 409 / 503；不新增依赖本机 MySQL 的 JUnit 并发用例。
7. 不清 `data/h2/`、不动 `data/files/` / `data/backups/`，不裸删 `data/` 整树。
8. 不 commit / push / PR；本轮不写迁移、不改代码与测试。
