## 2. 背景与目标

### 2.1 背景

1. 现网批量导入是 textarea 粘贴纯数组，唯一「规范」是灰色占位示例（单条 `S-001` 单选题）与一句「编码会自动去空格并转大写后判重」；字段表、三题型示例、`code` 硬规则、批次阻断规则只写在 PRD 与代码里，教师看不到。
2. 现网占位示例只有一条 `S-001` 单选题（`answer` 为数组 `["A"]`），缺 MULTI / JUDGE、缺省字段与编码规则说明；调研截图里的示例更把 `answer` 写成字符串 `"A"`，与现网「`answer` 必须为数组」冲突，按现网校验会整行报错并触发整批阻断。两者的短码 `S-001` 都不具备来源与批次语义，无法支撑按章节管理题库。
3. 弹窗文案「校验错误的行不导入」暗示其余行可导入，实际实现是「任一 ERROR 则全部 READY 收口为 ERROR」（TD21），语义冲突会误导教师。
4. 平台已有 H1–H5 编码硬规则与归属维度唯一键，但业务命名规范只是软规则提示，外部导入码形态不可控。

### 2.2 目标

1. 让教师拿到一份**可直接上传**的规范示例文件，文件自包含字段要求、编码要求、机器可读 JSON Schema 与三题型示例。
2. 用 JSON Schema 把规范变成可执行契约，页面提示、下载文件、前端校验共享同一份定义。
3. 让导入 `code` 具备可读的前缀与序号结构，便于检索、排序与按批次对账；不改变平台发号契约。
4. 让弹窗文案与实际批次行为一致。

## 3. 导入文件规范

### 3.1 文件与编码

| 项 | 唯一结论 |
|---|---|
| 文件名 | `题目批量导入模板.json` |
| 后缀 | `.json`，其它后缀报 `仅支持 .json 文件` |
| 编码 | UTF-8；允许带 BOM，读取时剥离 `\uFEFF` 后解析 |
| 大小 | ≤ 2 MB，超出报 `导入文件不能超过 2 MB` |
| 题量 | `questions` 长度 1–500，空数组报 `至少需要一道题目`，超过报 `单次导入不能超过 500 道题` |
| 数量 | 单文件；重新选择文件覆盖旧文件并重新解析，不合并多文件 |
| 读取 | `file.text()`；`stripBom()` 与 `validateImportFileMeta(fileName, size)` 为纯函数，供单测覆盖 |

### 3.2 wrapper 结构

模板文件顶层固定 4 个键；上传时 `formatVersion` 与 `questions` 必填，`spec` 与 `schema` 允许省略且不校验其内容；出现第 5 个顶层键报 `导入文件包含不支持的顶层字段：<name>`。`formatVersion` 必须等于常量 `1.0`，否则报 `导入文件版本不支持，请重新下载模板`。根节点为数组时报 `导入文件必须是包含 formatVersion 与 questions 的 JSON 对象，请下载规范示例`。

§3.2 展示的是序列化后的文件内容；`spec.codeRequirements.pattern` 与 `schema.items.properties.code.pattern` 两处字面量在代码中均由 `QUESTION_CODE_PATTERN.source` 生成，`schema` 字段整体由 `QUESTION_IMPORT_SCHEMA` 对象引用，不存在第二份正则或第二份 schema。`spec.codeRequirements.hardRules` 为展示顺序，实际校验顺序按 §3.4 表与 §3.6 第 1 条执行。

### 3.3 字段要求

| 字段 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| `code` | string | 是 | 无 | H1–H6，见 §3.4 |
| `type` | string | 是 | 无 | `SINGLE` / `MULTI` / `JUDGE`，大小写不敏感 |
| `stem` | string | 是 | 无 | 去首尾空格后非空 |
| `difficulty` | string | 否 | `EASY` | `EASY` / `MEDIUM` / `HARD`，大小写不敏感 |
| `options` | array | 选择题必填 | 判断题补 `T/F` | ≥ 2 项，元素 `{ key, content }`，`key` 不重复、`content` 非空；判断题 `key` 集合恰为 `{T, F}` |
| `answer` | array | 是 | 无 | 非空 key 数组；每个 key 必须属于 `options`；单选恰好 1 个、多选至少 1 个、判断仅 `T/F` |
| `analysis` | string | 否 | `''` | 出现时必须为字符串 |

7 个字段之外一律拒绝，含废止的 `score`。`spec.fieldRequirements`、AJV `items.properties`、页面字段表、`validateRow` 白名单由同一份常量生成。

### 3.4 `code` 编码要求

| # | 规则 | 校验内容 | 错误文案 |
|---|---|---|---|
| H1 | 归一化 | 去首尾空格、统一大写；判重、提交、展示均用归一值 | `code 不能为空` |
| H3 | 长度 | 归一后 ≤ 64 字符 | `code 长度不能超过 64 个字符` |
| H2 | 字符集 | `^[A-Z0-9_-]+$` | `code 只能包含 A-Z、0-9、- 和 _` |
| H4 | 保留形状 | 拒绝 `^HW\d+$`、`^LAB\d+S\d+$` | `code 不能使用系统自动编码格式（HW{数字} / LAB{数字}S{数字}）` |
| H6 | 前缀与序号 | `^[A-Z][A-Z0-9]{0,7}-[A-Z0-9]{1,15}-\d{3,6}$`，即来源前缀 1–8 位、批次/章节 1–15 位、数字序号 3–6 位 | `code 必须符合 <来源前缀>-<批次/章节>-<序号>（如 LINUX-OS-001）` |

**判重规则（H5，非阻断、不产生 ERROR）**：唯一作用域为 `UNIQUE (school_id, created_by, code)`；文件内重复编码记 `跳过：JSON 内重复编码`，题库已存在编码记 `跳过：题库已存在该编码`，提交时 `40900` 记 `编码已被占用`。判定顺序见 §3.6。

H6 只在导入文件的 `code` 上生效（D10）；不新增来源前缀黑名单，三段式正则本身排除 `Q-{题型}-{时间戳}{随机位}` 等系统自动码形状。合规样例 `LINUX-OS-001`、`T-2026-001`、`Q-FOUND-001`；不合规样例 `S-001`（缺批次段）、`LINUX-OS-1`（序号不足 3 位）、`LINUX-OS-ABC`（序号非数字）、`LINUX_OS_001`（分隔符错误）、`HW12` / `LAB3S1`（H4）、中文码（H2）。小写输入经 H1 归一后按大写校验，例如 `linux-os-001` 归一为 `LINUX-OS-001` 并通过。H2 / H3 / H4 对 H6 合规码恒真，仍按上表顺序保留，以复用现网 `validateRow` 的校验顺序与错误文案。

### 3.5 JSON Schema 与校验分层

- 前端内置 `QUESTION_IMPORT_SCHEMA`，根为数组 schema（即模板 `schema` 字段的值），`minItems: 1`、`maxItems: 500`、`items.additionalProperties: false`、`items.properties.code.pattern` 取 `QUESTION_CODE_PATTERN.source`。
- 使用 `import Ajv2020 from 'ajv/dist/2020'`，以 `new Ajv2020({ allErrors: true, strict: false })` 编译 `QUESTION_IMPORT_SCHEMA.items`；不得使用 AJV 默认 draft-07 实例。
- 对归一后的每题逐项调用编译结果，命中错误映射为行级 `ERROR`；文案按错误类型写死：`additionalProperties` → `不支持的字段：<params.additionalProperty>（题库只接受内容字段）`（沿用现网 `questionImport.ts:64-66` 文案，保证含字段名）、`required` → `缺少必填字段：<params.missingProperty>`、其它结构错误 → `第 N 行：字段 <instancePath> 不符合导入规范`。手写 `code` 硬规则在此步之前先行（§3.6），`code` 违规只给 §3.4 专用文案，AJV 的 `code.pattern` 作为冗余防线，不作为第二条文案来源。
- 顶层 wrapper 结构（`formatVersion` const、顶层键白名单、`questions` 为数组、数量上限）由 `parseImportDocument` 手写校验，命中为 `fatalError`，不渲染预览表。
- 业务语义（`options.key` 重复、`answer` key 归属、题型答案个数、判断题 `T/F`、判重、批次阻断、H4）由手写校验承担，AJV 不重复实现。
- 上传文件里的 `schema` 字段不参与校验执行；用户改动该文件内 schema 不改变前端内置规则。
- 归一预处理输出同时作为 AJV 输入、手写校验输入与 `toPayload` 输入，唯一数据真相。

### 3.6 导入规则

1. 判定优先级：顶层结构 → 逐题归一 → 手写 `code` 硬规则（H1 → H3 → H2 → H4 → H6）→ AJV 结构校验 → 手写业务语义（选项-答案关系、题型答案个数、判断题 `T/F`）→ JSON 内更早的重复 → 题库已存在编码 → `READY`；同一行只归一类，`code` 违规只产生 §3.4 的唯一文案。
2. 任一 `ERROR` 行出现时，所有 `READY` 行改为 `ERROR`（D12 文案）并删除 `draft`，`SKIP` 行保持，`readyCount` 归零，「开始导入」禁用。
3. 提交按预览行顺序串行调用 `POST /api/v1/questions`，逐条携带 `{ silent: true }`；`40900` 记「编码已被占用」跳过，其它错误记「失败」并保留 `draft`。
4. 导入进行中禁关闭、禁遮罩与 ESC、禁二次提交；本轮结束后恢复「再次导入」。
5. 结果区保留「复制失败项」，输出形态按 D16。

| 否决项 | 原因 |
|---|---|
| 保留粘贴框作为回退 | 与 D3 冲突：两套输入形态会让规范文件与粘贴文本的校验口径分叉，且用户已明确不保留 |

| 把字段要求写进 JSON 注释或题目对象里的 `_remark` 键 | JSON 不支持注释；7 字段白名单会拒绝未知键并触发整批阻断 |
| 执行上传文件内的 `schema` 做校验 | 用户可篡改 schema 绕过校验；规范必须以前端内置常量为唯一真相 |
| 只把三段式作为提示文案而不强制 | 用户已明确「code 规范要强制前缀/序号」；软规则无法保证批量码形态一致 |
| 平台发号或导入时自动补前缀 / 补号 / 加后缀 | 与 `2026-11-10` PRD D10 / D12 / D17 冲突；外部原码必须对得上账 |
| 改成「错误行跳过、其余行导入」 | 与 `2026-11-10` 技术方案 TD21 及其测试冲突；部分落库会让教师在不知情下得到不完整题库。本期改文案、不改行为 |
| 后端新增 H6 校验 | 编辑器自动码 `Q-{题型}-{时间戳}{随机位}` 经同一单题接口提交，会被三段式正则拒绝；H6 只约束导入文件 |
| 新增服务端模板下载接口或静态模板资源 | 现网学生模板已是前端运行时生成；无需后端改动 |
| 用 AJV 一次校验整个 wrapper 文档 | 顶层含 `spec` / `schema` 元数据，且需要逐题定位行号；改为内置数组 schema 的 `items` 逐项校验 + 顶层手写校验 |
