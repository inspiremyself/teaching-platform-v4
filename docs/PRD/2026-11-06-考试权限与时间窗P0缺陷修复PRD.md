## 2. 背景与问题定位

### 2.1 背景

全项目自查（后端 `./mvnw test` 与前端 `npm run build` 均通过）发现三个测试无法覆盖的高危缺陷，集中在考试详情读取、考试时间窗控制与组卷取题归属。三者都属于“接口可用、逻辑错误”的类型，一旦上线即造成越权与考试公平性问题。

### 2.2 根因

| 编号 | 现象 | 根因 |
|---|---|---|
| P1 | 任意教师可读取他人考试详情与标准答案 | `ExamController.detail` 仅声明 `@GetMapping("/exams/{id}")`，无 `@PreAuthorize`；`ExamService.getExamDetail` 只对 `STUDENT` 做状态与班级成员校验，`TEACHER` 分支不做归属校验；且对 `TEACHER` 无条件返回 `answerJson` 与 `analysisText` |
| P2 | 学生可提前开考、考试结束后无限期补交 | `ExamService.startExam` 只校验 `PUBLISHED` 与班级成员，从不读取 `exam.startAt` / `exam.endAt`；`deadlineAt` 直接用 `now + durationMinutes`，未与 `endAt` 取更早值 |
| P3 | 超时提交仍被接收并评分 | `ExamService.submitExam` 在 `now > submission.deadlineAt` 时仅把状态改为 `AUTO_SUBMITTED`，随后继续删除旧答案、写入本次答案并逐题评分，没有拒绝分支 |
| P4 | 学生端展示“当前处于允许参加的考试窗口”与实际可开始状态不一致 | `ExamService.listExams` 中 `canStart = submissionOpt.isEmpty()`，完全未考虑 `startAt` / `endAt`；`canResume` 只判断 `IN_PROGRESS`，未判断截止时间 |
| P5 | 教师可将他人题库题目组进自己的作业/考试 | `HomeworkService.addQuestionFromBank` 与 `ExamService.buildExamQuestion` 均使用 `questionBankRepository.findById`，未校验 `createdBy`；题库列表本身按 `findByCreatedBy` 隔离，组卷路径绕过了这层隔离 |

### 2.3 影响面

- P1：跨教师读取题干与标准答案，可直接用于泄题；属于越权访问，无法通过前端隐藏规避。
- P2/P3：考试公平性失效，成绩数据失真，且现有 `AFTER_DEADLINE` 可见性规则依赖 `endAt`，与可无限补交叠加后成绩发布逻辑失去意义。
- P5：间接获取他人题库内容（含答案快照），等价于题库数据越权导出。

## 3. 目标与成功标准

### 3.1 目标

1. 考试详情只对命题教师本人与符合条件的班级学生开放；标准答案与解析对命题教师始终可见，学生仅在已提交且成绩可见后按现状返回。
2. 考试开始与交卷严格受 `startAt` / `endAt` / `durationMinutes` 约束，超时请求被拒绝而不是静默接收。
3. 学生端“可开始 / 可继续”标记与后端时间窗判定一致。
4. 作业与考试组卷只能使用当前教师自己的题库题目。

### 3.2 成功标准

- 教师 A 请求教师 B 的考试详情返回 HTTP 403，响应不含任何题目或答案字段。
- 命题教师请求自己的考试详情，`answerJson` 与 `analysisText` 正常返回。
- 学生无进行中提交且当前时间早于 `startAt` 时调用开始接口返回 HTTP 400「考试尚未开始」。
- 学生无进行中提交且当前时间不早于 `endAt` 时调用开始接口返回 HTTP 400「考试已结束」。
- 学生已有进行中提交时，即使 `endAt` 已过，开始接口仍返回原提交与剩余时间 0，由前端触发自动交卷。
- 学生在 `deadlineAt + 120s` 之后调用交卷接口返回 HTTP 400「考试已结束，无法提交」，数据库不新增或覆盖任何答案。
- `endAt` 早于 `now + durationMinutes` 时，`deadlineAt` 等于 `endAt`。
- 教师 A 使用教师 B 的题库题目组卷返回 HTTP 404「题库题目不存在」，不产生任何作业题目或考试题目记录。
- 学生端考试列表的 `canStart` / `canResume` 与上述时间窗判定一致。

| 术语 | 定义 |
|---|---|
| 命题教师 | 考试记录 `created_by` 对应的教师用户 |

## 6. 核心流程

### 6.1 教师查看考试详情

1. 请求进入 `GET /api/v1/exams/{id}`，前置角色限制只允许 `TEACHER` 与 `STUDENT`。
2. 教师分支校验 `exam.createdBy == currentUser.id()`。
3. 校验通过后返回考试基本信息、题目列表，并附带 `answerJson`、`analysisText`。
4. 校验失败返回 `40300`「无权限查看该考试」，不返回任何题目字段。

### 6.2 学生开始考试

1. 请求进入 `POST /api/v1/exams/{id}/start`，角色必须为 `STUDENT`。
2. 校验考试存在且状态为 `PUBLISHED`。
3. 校验当前学生属于考试班级；非本班学生返回 403，不进入后续判定。
4. 保留现有内联题拦截：试卷含 `questionId` 为空的历史内联题时返回 400「试卷包含不支持的题目，请联系教师」，该拦截位置保持在班级成员校验之后、提交查询之前。
5. 已存在 `IN_PROGRESS` 提交时直接返回该提交与剩余时间，不校验 `startAt` / `endAt`。
6. 无进行中提交时校验时间窗：`startAt` 非空且 `now < startAt` 返回 `40000`「考试尚未开始」；`endAt` 非空且 `now >= endAt` 返回 `40000`「考试已结束」。
7. 时间窗通过后创建新提交，`deadlineAt = min(now + durationMinutes, endAt)`。
8. 剩余秒数按 `max(0, deadlineAt - now)` 计算。

### 6.3 学生交卷

1. 请求进入 `POST /api/v1/exams/{id}/submit`，角色必须为 `STUDENT`。
2. 查找当前学生该考试的提交记录，不存在返回 404；状态非 `IN_PROGRESS` 返回「考试已提交，不能重复提交」。
3. 若 `now > deadlineAt + 120s`，返回 `40000`「考试已结束，无法提交」，不写入任何答案。
4. 若 `now > deadlineAt` 且在宽限期内，状态置 `AUTO_SUBMITTED`；否则置 `SUBMITTED`。
5. 按现有逻辑删除旧答案、写入本次答案、逐题评分、汇总分数。
6. 后续状态结案与成绩记录写入逻辑不变。

### 6.4 组卷取题

1. 作业新增题库题目或考试创建/更新提交题目项时，按题目 ID 与当前教师 ID 查询题库。
2. 查询不到（不存在或不属于当前教师）返回 `40400`「题库题目不存在」。
3. 校验通过后按现有逻辑生成题目快照并落库。

## 7. 功能需求

### FR-1 考试详情访问控制

#### 7.1.1 角色限制

- `GET /api/v1/exams/{id}` 仅允许 `TEACHER`、`STUDENT`；实现写死为 controller 方法上的 `@PreAuthorize("hasAnyRole('TEACHER','STUDENT')")`。
- `SCHOOL_ADMIN` 与其他角色返回 HTTP 403，错误码 `40300`、错误信息「Access Denied」（由 `GlobalExceptionHandler` 的 `AccessDeniedException` 分支产生）；本期不复用该接口作为校管巡查入口。
- Service 层只对教师归属与班级成员抛 `40300`「无权限查看该考试」，两类 403 的 HTTP 状态相同、文案不同，测试断言按此区分。

#### 7.1.2 教师分支

- 必须校验 `exam.createdBy == currentUser.id()`。
- 校验失败返回 `40300`「无权限查看该考试」。
- 校验通过后保持现有返回结构，`answerJson` 与 `analysisText` 正常返回。

#### 7.1.3 学生分支

- 保持现有规则：考试状态必须为 `PUBLISHED` 或 `CLOSED`，且当前学生属于考试班级。
- 沿用现有可见性规则：未提交或 `canStudentSeeScore=false` 时不返回 `answerJson`、`analysisText`；已提交且成绩可见时按现有逻辑返回 `answerJson`、`analysisText`，现有测试 `studentDetailIncludesAnalysisTextWhenScoreVisible` 必须继续通过。
- 不在本期新增“学生仅可查看已开始考试详情”的限制，避免影响现有结果页恢复逻辑。

#### 7.1.4 验收标准

- 教师 A 访问教师 B 的考试详情返回 403，响应体不含 `questions`。
- 命题教师访问自己的考试详情返回 200，题目项包含 `answerJson`。
- 非班级学生访问返回 403。
- 班级学生访问 `PUBLISHED` / `CLOSED` 考试返回 200；未提交或成绩不可见时题目项不含 `answerJson`、`analysisText`；已提交且成绩可见时按现状返回这两个字段。
- 校管访问返回 403。
- 不存在的考试 ID 对所有角色返回 404。

### FR-2 考试时间窗与交卷截止

#### 7.2.1 开始校验

- 状态校验保持 `PUBLISHED`。
- 班级成员校验保持现状，位于时间窗校验之前，避免非本班学生通过错误文案探测考试时间状态。
- 已存在 `IN_PROGRESS` 提交时直接返回该提交及剩余时间，不校验 `startAt` / `endAt`；剩余时间按 `max(0, deadlineAt - now)` 计算。该路径保证考试结束瞬间刷新页面仍能触发交卷。
- 无进行中提交时校验时间窗：`startAt` 非空且当前时间早于 `startAt` 返回 `40000`「考试尚未开始」；`endAt` 非空且当前时间不早于 `endAt` 返回 `40000`「考试已结束」。

#### 7.2.2 截止时间

- 新建提交时 `deadlineAt = min(now + durationMinutes, endAt)`。
- `endAt` 为空时取 `now + durationMinutes`。
- `durationMinutes` 保持现有 `@NotNull` 约束，不新增下限校验。
- 已存在 `IN_PROGRESS` 提交时沿用其原 `deadlineAt`，不因重新进入而延长。

#### 7.2.3 交卷拒绝

- `now > deadlineAt + 120 秒`：返回 `40000`「考试已结束，无法提交」。
- 拒绝发生在删除旧答案与写入新答案之前，确保数据库无副作用。
- 拒绝后提交状态保持 `IN_PROGRESS`，不自动改为 `AUTO_SUBMITTED`；教师关闭考试不会改变该提交状态，本期不做收口，收口规则列入后续迭代（见 §14.2）。
- 交卷不校验 `exam.status`：教师关闭考试后，进行中的提交仍按原 `deadlineAt` 与宽限期判定，不因 `CLOSED` 额外拒绝。

#### 7.2.4 宽限期

- `deadlineAt < now <= deadlineAt + 120 秒`：接受交卷，状态置 `AUTO_SUBMITTED`。
- 宽限期内接受的答案按正常链路评分，成绩口径与普通交卷一致。

#### 7.2.5 验收标准

- `startAt` 为未来时间时开始接口返回 400，且不创建提交记录。
- `endAt` 已过时开始接口返回 400，且不创建提交记录。
- `endAt` 早于 `now + durationMinutes` 时，新建提交的 `deadlineAt` 等于 `endAt`。
- 学生在截止前交卷状态为 `SUBMITTED`。
- 学生在宽限期内交卷状态为 `AUTO_SUBMITTED`，答案与分数正常落库。
- 学生在宽限期外交卷返回 400，答案表与提交表均无变化。
- 同一学生重复进入考试，`deadlineAt` 不发生延长。

### FR-3 学生考试列表可操作标记

#### 7.3.1 判定规则

- `canStart = 无提交记录 && (startAt 为空 || now >= startAt) && (endAt 为空 || now < endAt)`。
- `canResume = 提交状态为 IN_PROGRESS && (deadlineAt 为空 || now <= deadlineAt + 120 秒)`；`endAt` 已计入 `deadlineAt`，不重复判断。
- `canViewResult` 沿用现有 `canStudentSeeScore` 逻辑，不在本期调整。

#### 7.3.2 接口与前端

- 字段名与返回结构不变，仅取值逻辑调整。
- 学生端 `frontend/src/views/student/exams/List.vue` 与 `Detail.vue` 不新增字段、不改请求。
- 列表提示文案“当前处于允许参加的考试窗口”在后端 `canStart` 收紧后自动与真实状态一致，不单独改文案。

#### 7.3.3 验收标准

- `startAt` 未到时列表 `canStart=false`，前端不展示可开始入口。
- `endAt` 已过且无进行中提交时 `canStart=false`。
- 进行中提交超过 `deadlineAt + 120 秒`时 `canResume=false`；仍在该宽限期内时 `canResume=true`。
- 正常窗口内首次进入 `canStart=true`。

### FR-4 组卷题库题目归属

#### 7.4.1 覆盖入口

| 入口 | 方法 | 现状 |
|---|---|---|
| 作业新增题库题目 | `HomeworkService.addQuestionFromBank` | `findById`，未校验归属 |
| 考试组卷（创建） | `ExamService.buildExamQuestion`（由 `createExam` 调用） | `findById`，未校验归属 |
| 考试组卷（更新） | `ExamService.buildExamQuestion`（由 `updateExam` 调用） | 同上 |

#### 7.4.2 规则

- 统一改为按 `id + currentUser.id()` 查询题库。
- 查询不到时返回 `40400`「题库题目不存在」，与现有“题目不存在”文案一致。
- 不新增“题库题目是否可复用”的状态判断，沿用现有 `reusableFromBank` 语义。
- 只读展示路径（考试详情读取解析文本、提交详情读取解析文本）不做重复归属校验，由 FR-1 与既有考试归属校验兜底。

#### 7.4.3 验收标准

- 教师使用自己的题库题目组卷成功。
- 教师使用他人题库题目组卷返回 HTTP 404，且作业题目表、考试题目表无新增记录。
- 考试更新时混入他人题目，整单失败且原题目列表保持不变（事务回滚）。
- 原有使用教师本人题目的创建与更新流程回归通过。

## 8. 业务规则汇总

| 编号 | 规则 |
|---|---|
| BR-1 | 考试详情只对命题教师本人与考试班级学生开放 |
| BR-2 | 标准答案与解析对命题教师始终返回；学生仅在已提交且 `canStudentSeeScore` 为真时返回；校管与其他角色不返回 |
| BR-3 | 考试开始受 `startAt` / `endAt` 双向约束，未开始与已结束分别返回明确业务提示 |

| BR-5 | 交卷仅在 `deadlineAt + 120s` 内被接受，超时请求不产生任何写入 |
| BR-6 | 宽限期内交卷统一标记 `AUTO_SUBMITTED` |
| BR-7 | 学生列表 `canStart` / `canResume` 必须与后端时间窗判定一致 |
| BR-8 | 组卷只能使用当前教师自己的题库题目，越权按“题目不存在”处理 |
| BR-9 | 本期不新增数据库迁移、不改表结构、不做历史数据修复 |

## 10. 非功能需求

### 10.1 性能

- 考试详情、开始、交卷不新增额外查询批次；归属校验复用已加载的 `Exam` 实体字段。
- 组卷归属校验由主键查询改为“主键 + 教师 ID”查询，不增加查询次数。

### 10.2 权限与安全

- 权限判定在后端完成，前端隐藏不作为安全边界。
- 越权响应不包含题目、答案、解析、学生作答等敏感字段。
- 考试详情角色限制与归属校验必须同时存在，缺一不可。

### 10.3 兼容性

- 历史考试若 `startAt` / `endAt` 为空，行为与现状一致（不限时）。
- 历史 `IN_PROGRESS` 提交保留原 `deadlineAt`，不回溯重算。
- 现有依赖 `canStart=true` 的学生端用例需同步调整为符合时间窗语义。

### 10.4 数据一致性

- 交卷拒绝必须发生在任何写操作之前，避免“状态未变但答案已删”的中间态。
- 组卷归属校验失败时整单回滚，不产生部分题目记录。
- 状态、答案、分数、成绩记录仍在同一事务内完成。

## 11. 异常与边界场景

| 场景 | 预期行为 |
|---|---|
| 教师访问他人考试详情 | 403，响应不含 `questions` |
| 教师访问不存在的考试 | 404「考试不存在」 |
| 学生打开尚未开始的考试详情 | 详情接口返回 200（FR-1.3 不变），点击开始时返回 400「考试尚未开始」 |
| 校管访问考试详情 | 403 |
| 学生在 `startAt` 前开始 | 400「考试尚未开始」，无提交记录 |
| 学生在 `endAt` 后开始（无进行中提交） | 400「考试已结束」，无提交记录 |
| 学生在 `endAt` 后开始（已有进行中提交） | 返回原提交与 `deadlineAt`，`remainingSeconds=0`，由前端触发交卷 |
| `startAt` / `endAt` 均为空 | 允许开始，`deadlineAt = now + durationMinutes` |
| `durationMinutes` 大于窗口剩余时间 | `deadlineAt` 等于 `endAt` |
| 截止前 1 秒交卷 | 状态 `SUBMITTED` |
| 截止后 60 秒交卷 | 状态 `AUTO_SUBMITTED`，答案正常落库 |
| 截止后 121 秒交卷 | 400「考试已结束，无法提交」，无写入 |
| 重复进入考试 | 返回原提交，`deadlineAt` 不延长 |
| 已提交后再次交卷 | 400「考试已提交，不能重复提交」 |
| 使用他人题库题目组卷 | 404「题库题目不存在」，无题目记录 |
| 考试更新时混入他人题目 | 整单失败，原题目保持不变 |
| 考试已 `CLOSED` 但学生仍在原 `deadlineAt` 前交卷 | 按 D8 接受，状态按 D7 判定 |
| 考试已 `CLOSED` 且学生在宽限期内交卷 | 按 D8 接受，状态 `AUTO_SUBMITTED` |

## 14. 风险与后续迭代

### 14.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 前端本地时钟与服务器不一致 | 学生端倒计时归零前后可能多提交一次 | 服务端宽限 120 秒兜底，超时请求返回明确提示 |
| 自动交卷请求网络延迟 | 正常答卷被判定超时 | 宽限期覆盖常见抖动；文案提示学生及时手动交卷 |
| 收紧 `canStart` 影响既有用例 | 现有测试可能依赖“发布即可开始” | 测试计划明确同步调整，夹具补 `startAt` / `endAt` |
| 校管被拒绝访问考试详情 | 若后续校管需要巡查将无法复用 | 后续单独设计校管只读接口，不复用考试详情 |
| 历史越权数据 | 已发生的跨教师读取无法追溯 | 本期不做追溯，后续结合访问日志排查 |

### 14.2 后续迭代

- 作业重复提交覆盖已批改状态与截止时间校验（P1）。
- `MANUAL_RELEASE` 下考试成绩记录补写（P1）。
- 超时被拒后长期停留在 `IN_PROGRESS` 的提交收口规则（自动置 `AUTO_SUBMITTED` 还是教师手动终止）。
- 校管端考试巡查只读接口。
- 考试防作弊与异常行为采集。
- 题库复制服务的归属与性能优化。
