### 1.1 已定决策清单（需求侧）

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| P1 | 术语 | 本平台**不引入**独立「课程(course)」实体与「课程编码」；本需求中的「课程编码」统一指**学科编码**（subject code）。`course_material` 是课程资料表、教材是内容目录对象，二者都不是课程。开课实例、排课、课表、外部教务同步属非目标（§6） |
| P2 | 学科真相源 | **平台级学科标识**唯一真相源为总纲 D11 / D25 的 `subject` 表，不另建学科表；`school_subject` 是**本校启用与本地别名层**（不是第二个全局真相源），保留校管自治与现有表结构。平台字典只承载需跨校对齐的学科，本校独有学科由本校字典承载且不进入平台字典 |
| P3 | 跨层关联键 | 平台学科与学校学科之间的关联**一律用 `id`**（`school_subject.global_subject_id` → `subject.id`）；禁止用名称、`code` 字符串匹配、`平台code+学校code` 拼接键做跨层关联 |
| P4 | 平台学科编码 | 沿用现网学科编码规则：`^[A-Z0-9-]{1,64}$`、trim 后转大写、`code` **全平台唯一且不可变**；不含下划线（与题库编码 H2 的字符集各自独立，互不借用）；题库批量导入文件专用的 H6 三段式前缀 / 序号规则**不适用于学科编码**（§1.2 / §4.2） |
| P5 | 平台学科字段与生命周期 | `subject` 业务字段写死为四列：`id` / `code` / `name` / `status`（`ACTIVE` / `DISABLED`），审计列沿用 `BaseEntity` 的 `created_at` / `updated_at`；**不硬删除**、不改已发布 `code`、改名只改展示名、不新增其它业务列；初始种子条目由阶段 2 技术方案按总纲 D25 写死（§3.1） |
| P6 | 学校侧编码 | `school_subject` 的 `UNIQUE(school_id, code)` **保持不变**；「从平台启用」生成的映射行预填平台 `code`，该行 `code` 锁定不可修改；`name` 允许本校别名（1～128），`status` 沿用 `ACTIVE` / `DISABLED` |
| P7 | 映射列与基数 | `school_subject` 增可空 `global_subject_id BIGINT NULL`；`NULL` = 本校自建 / 未启用；新增 `UNIQUE(school_id, global_subject_id)`（NULL 不参与唯一约束），**一校一平台学科最多一条映射行**；不新建映射表、不建 DB 外键，沿用现网裸列 + 应用层校验 |
| P8 | 同名科目 | 平台「数学」与学校「数学」是**一条平台学科 + 每校一条启用行**，不是两条平行学科。启用时本校已存在同 `code` 且未映射的行 → **升级该行为映射行**（保留原 `id`，避免 `class_teacher.subject_id` 悬空）；该行已映射到其它平台学科 → 拒绝并沿用 `40000`，文案「该编码已映射到其它平台学科」。校管不得再新建与已启用平台学科同 `code` 的平行行 |
| P9 | 停用与解绑 | 学校侧停用沿用现网 `DISABLED` 语义（禁止新指派、已有 `class_teacher.subject_id` 保留）；不删除映射行、不清空 `global_subject_id`；平台学科 `DISABLED` 后已有映射行保持不变，新建启用行一律拒绝，错误码沿用现网 `40026`、文案写死为「平台学科已停用，不能启用」（与现网 `40026`「学科已停用，不能指派」同码段、不同触发点，不新增错误码） |
| P10 | 学校自建 | **允许**，且 `global_subject_id = NULL`。自建学科服务本校组织层（班级学科教师指派、现网学科字典管理）**与本校 `SCHOOL` 归属内容**（`school_subject_id`，总纲 V7.1 / D25）；**不承载** `PLATFORM` 内容与教材目录，二者需平台 `subject.id`。教学任务侧 `subject_id` 按 D11（V7.1）**写死指向 `school_subject.id`**，校验本校 `ACTIVE` 学科、含自建行；本文不另立取值域 |
| P11 | 存量回填 | `V14` 产生的 `SE-ARCH` / `DB-PRINCIPLE` / `UNSPECIFIED` / `LEGACY-*` 全部保持 `global_subject_id = NULL`；**不按名称或编码自动匹配**、不改写 `code` / `name` / `status`、不硬删除、不改 `class_teacher.subject_id` |
| P12 | 编码通则 | 引用 `2026-11-10-题库编码作用域收敛与发号规则PRD.md` D10 / D11：`id` 为机器引用、`code` 为人读与导入幂等、否决统一发号器与 UUID。该通则适用于平台学科与学校学科；跨层关联只用 `id`，`code` 不承担跨层身份 |

## 2. 背景与目标

### 2.1 要解决的问题

| # | 问题 |
|---|---|
| P1 | 现网只有学校一级学科字典 `school_subject`，平台侧没有学科字典，不存在「平台→学校」两级映射；平台学科与学校同名学科无法判定是否同一对象 |
| P2 | 新开通学校不预置任何学科，校管手工自建且 `code` 校内自定，跨校编码互不对齐；`V14` 回填的 `LEGACY-*` 与 `UNSPECIFIED` 无语义，不能作为跨校匹配依据 |
| P3 | 平台若上线教材 / 课件 / 共享内容，内容层学科归属需要稳定、跨校一致的标识；用学校本地 `code` 或名称无法承载 |
| P4 | 未来「一个科目多个教材」要求学科与教材是 1:N，若把教材绑在学校本地学科上，教材无法跨校共享，且同学科多教材会被迫退化成「一条记录 + 版本字段」 |
| P5 | 全仓不存在「课程(course)」实体与课程编码规则；若不先统一术语，学科编码、教材编码、开课实例编码会混成一套码 |

### 2.2 目标

1. 建立「平台学科字典 → 学校启用映射」的单层引用模型，平台与学校同名学科落到同一权威标识。
2. 保留学校自建学科能力，同时划清「本校组织层可用 / 不承载跨校共享内容」的边界。
3. 把编码职责固定为「`id` 机器引用、`code` 人读与导入幂等」，杜绝跨层按名称或编码拼接关联。
4. 为总纲 D25 的「一科多教材」提供不与两级映射冲突的学科侧契约。

### 2.3 成功标准（可测）

- 平台学科 `MATH` 被 A、B 两校各自启用后，两校各有一条 `global_subject_id` 指向同一 `subject.id` 的映射行，两校 `school_subject.id` 不同。
- 同一学校第二次启用同一平台学科被唯一约束拒绝；同校把两个本地学科映射到同一平台学科被拒绝。
- 学校自建学科的 `global_subject_id` 恒为 `NULL`，可用于班级学科教师指派、教学任务 `subject_id` 与本校 `SCHOOL` 内容的 `school_subject_id`；**不出现在** `PLATFORM` 内容与平台教材目录的学科归属中（P18 / P20）。
- 迁移后 `V14` 存量学科的 `code` / `name` / `status` / `class_teacher.subject_id` 全部不变。

## 4. 模型与编码契约

### 4.1 两层学科与内容分域（最终结论）

**学科不是「永远平台级」**：平台与学校各有一个学科实体，作用域不同；内容记录的学科标签再按 `owner_scope` 分域。

| 层 | 对象 | 标识（写死） | 编码作用域 | 写权限 |
|---|---|---|---|---|
| 平台 | `subject`（数学 / `MATH`） | `id` 全平台唯一 | `code` 全平台唯一、不可变 | `PLATFORM_ADMIN` |
| 学校 | `school_subject`（启用行 / 自建行） | `id` + `school_id` | `UNIQUE(school_id, code)` 保持 | 本校 `SCHOOL_ADMIN` |
| 映射 | `school_subject.global_subject_id` | 指向 `subject.id` | `UNIQUE(school_id, global_subject_id)`，NULL = 自建 / 未启用 | 本校 `SCHOOL_ADMIN` |
| 教学任务 | 作业 / 实验 / 考试 / 题库 / 资料 `subject_id` | **`school_subject.id`**（含自建行，P19 / D11） | 本校 `ACTIVE` 学科；历史 NULL | 按 D11 / D21 |
| 内容·平台 | 教材 `textbook` 与 `PLATFORM` 课件 / 题目 `global_subject_id` | **`subject.id` 非空单值**（P18 / D25） | 跨校对齐；学校逐条启用教材 | `PLATFORM_ADMIN` |
| 内容·学校 | `SCHOOL` 课件 / 题目 `school_subject_id` | **本校 `school_subject.id` 非空单值**（含自建学科，P18 / D25） | 仅本校可见（D21）；`global_subject_id` 可空 | 本校 `SCHOOL_ADMIN` |

两列学科归属**互斥、不得互相赋值**；学科筛选按该记录的分域归属列精确匹配，结果集一律先经 D21 过滤（D24 ⑤），故 `SCHOOL` 内容用本校学科不污染跨校对齐。

### 4.2 编码通则

- `id` 承担快照、映射、审计等全部机器引用；跨层关联只认 `id`。
- `code` 承担人读、口述、导入幂等与本校定位；平台 `code` 全平台唯一，学校 `code` 校内唯一，二者互不拼接、互不推断。
- 平台学科与学校学科都沿用现网 `^[A-Z0-9-]{1,64}$` + trim + 大写；不引入统一发号器、UUID、无含义全局码（引用题库编码 PRD D10 / D11）。题库批量导入规范 PRD 的 H6 三段式 `^[A-Z][A-Z0-9]{0,7}-[A-Z0-9]{1,15}-\d{3,6}$` 只作用于导入 JSON 的 `code`，**不作用于学科编码**：`MATH` / `SE-ARCH` 等学科码不按三段式校验、不补前缀、不加序号。
- 禁止按名称做跨层匹配：`V14` 的 `LEGACY-*` 与 `UNSPECIFIED` 无稳定语义，名称重复在现网合法（P11）。

### 4.3 启用与映射规则

1. 校管从平台学科字典选择一条 `ACTIVE` 学科发起启用；平台学科 `DISABLED` 时拒绝新建启用行（`40026`）。
2. 本校已有同 `code` 且 `global_subject_id` 为空的行 → 升级该行（P8），保留 `id` / `name` / `status` / `assignmentCount` 语义；已有行映射到其它平台学科 → `40000` 拒绝。
3. 本校无同 `code` 行 → 新建映射行，预填平台 `code` 与 `name`，`status = ACTIVE`，`global_subject_id` 指向 `subject.id`。
4. 映射行的 `code` 锁定不可修改；`name` 允许改为本校别名；停用沿用现网 `DISABLED` 语义（P9）。`update` 契约写死：现网 `UpdateSubjectRequest` 的 `name` + `code` 两个 `@NotBlank` 字段一字不改，校管编辑别名时仍提交原 `code`；后端对映射行要求规范化后的提交 `code` 与库中原值一致，不一致返回 `40000`「映射学科编码不可修改」，对自建行沿用现网可改码与 `40902` 判重。
5. 一校一平台学科最多一条映射行，由 `UNIQUE(school_id, global_subject_id)` 保证；违反返回 `40000`，不新增错误码。
6. 启用、停用、编辑别名三处均写 `AuditLogService`，动作沿用现网 `SUBJECT_CREATE` / `SUBJECT_UPDATE` / `SUBJECT_STATUS`。

### 4.4 学校自建学科边界

- 自建行 `global_subject_id = NULL`，`code` 按现网规则校内唯一，与平台字典无关联。
- 自建学科服务**本校组织层**：班级学科教师指派、学科字典启停、现网 `/admin/subjects` 查询；也服务**教学任务侧 `subject_id`**（P19）。
- 自建学科可作为本校 `SCHOOL` 归属内容的 `school_subject_id`（P18 / 总纲 V7.1 / D25），因此**不再是内容层死数据**；`SCHOOL` 内容按 D21 仅本校可见，用本校学科不产生跨校歧义。
- 自建学科**不承载** `PLATFORM` 内容与教材目录：两者必须填平台 `subject.id`（P20）；平台字典只承载需跨校对齐的学科。
- 学校需要平台尚不存在的**跨校共享学科**时，由平台超管在平台字典维护；**不引入**学校申请 / 平台审核流（总纲 §6 已否决审核流），本校独有学科直接建在本校字典、不进入平台字典。

### 4.5 与「一科目多教材」的兼容约束

- 教材目录平台级：教材与 `PLATFORM` 课件 / 题目的学科归属指向平台 `subject.id`（非空单值）；`SCHOOL` 课件 / 题目的学科归属指向本校 `school_subject.id`（非空单值，含自建学科）。两列互斥、不得互相赋值（P18 / D25）。
- 同一平台学科下允许多条独立教材记录，学校逐条启用；同学科新增教材不自动启用、不继承其它教材的挂载行（总纲 V7.1 / D25）。学校不自建教材（P20）。
- 学科筛选按该记录的**分域归属列**精确匹配（`PLATFORM` 按 `global_subject_id`、`SCHOOL` 按 `school_subject_id`），结果集先经 D21 过滤，不按 `content_mount` 挂载目标反推；按某教材筛选不展开同学科其它教材（总纲 V7.1 / D24 ⑤）。
- 两级映射（启用 / 停用 / 别名）只决定本校可见的平台学科与教材，**不参与内容记录的归属列计算**；`school_subject.global_subject_id` 与内容表 `global_subject_id` 同取值域但用途不同。
- `UNIQUE(school_id, global_subject_id)` 只约束学校映射表；不得给内容表 `global_subject_id` / `school_subject_id` 加唯一约束（总纲 V7.1 / D25 / §7 已否决「一科一本教材」）。

## 附录 A 已否决方案

| 否决项 | 原因 |
|---|---|
| 平台与学校各建一套独立学科码表，按名称 / `code` 自动对齐 | 同名 ≠ 同学科；现网 `name` 可重复、`LEGACY-*` 与 `UNSPECIFIED` 无语义，自动匹配必然产生错误映射 |
| 用「平台 code + 学校 code」拼接复合键做跨层关联 | 与 `id` 机器引用通则冲突，且学校 `code` 可被校管改动，关联键不稳定 |
| 把平台学科复制成每校平行记录、不保留映射列 | 教材 / 课件归属失去跨校一致的 `subject.id`，D25 的 1:N 归属无法落地 |
| 允许一校多个本地学科映射到同一平台学科 | 任务侧按本地学科筛选、内容侧按平台学科筛选，统计与筛选出现两套口径 |
| 启用平台学科时无条件新建 `school_subject` 行 | 与已有同 `code` 行冲突（`UNIQUE(school_id, code)`），并会使既有 `class_teacher.subject_id` 悬空 |
| 映射行允许校管修改 `code` | 破坏与平台 `code` 的对齐与校内唯一键，导入 / 对账口径失效 |
| 学校自建学科挂 `PLATFORM` 内容 / 教材目录、参与跨校共享内容筛选 | `PLATFORM` 内容与教材必须填平台 `subject.id`；自建学科只有本校标识，按 D21 不进入跨校可见范围（P18 / P20 / 总纲 V7.1 / D25） |
| `SCHOOL` 内容也强制填平台 `global_subject_id`（V6.0–V7.0 旧口径） | `SCHOOL` 内容按 D21 仅本校可见、不产生跨校数据，强制平台学科会把校本学科挡在内容层外、迫使平台超管线下补字典；V7.1 改为按 `owner_scope` 分域（P18 / D25） |
| 学校自建教材 / 学校自建平台级学科字典 | 教材目录为平台级，学校只逐条启用（P20 / 总纲 V7.1 / §6） |
| 引入独立「课程编码」体系或把教材编码当课程编码 | 全仓无课程实体；会形成第三套码并混淆学科 / 教材 / 开课实例 |
| 学校申请新增平台学科的审核流 | 总纲 §6 已否决审核流 |
| 按名称回填存量 `global_subject_id`、迁移时改写 `LEGACY-*` 编码 | 存量编码为历史资产且无稳定语义，零改写是唯一可验收方案 |
| 一科一本教材 / `UNIQUE(global_subject_id)` / 一条教材记录 + 版本字段 / 学科-教材关联表 | 总纲 D25 / §7 已否决，直接否定「同一学科多个教材」需求 |
