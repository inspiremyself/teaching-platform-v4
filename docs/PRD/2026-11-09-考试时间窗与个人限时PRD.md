| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| D1 | 作答页右上角时钟的含义 | 显示"本次作答剩余时间"，倒计时终点为 `deadlineAt`；它不是独立的"考试窗口结束时刻"，但两者取更早者，因此等价于"你这次实际能答到的最后时刻" |

| D6 | 时长取值范围与截断 | `durationMinutes` 为整数 1–600；允许大于窗口长度，实际可用时间以 `endAt` 截断，教师端给出提示，不做拒绝 |

| D8 | 宽限期 | 服务端在 `deadlineAt` 后 120 秒内仍接受交卷与存草稿；交卷状态按结算规则：含主观题置 `AUTO_SUBMITTED`，全客观题直接结算为 `GRADED`。超过 120 秒一律拒绝。前端到期即锁定作答，并短路草稿保存，仅保留自动交卷与失败后的「重新交卷」入口 |

| D10 | 教师关闭考试 | 不改变进行中提交的 `deadlineAt`；学生仍可通过详情接口答到个人截止时间并交卷（现状保持）。`start` 仍要求 `PUBLISHED`；`CLOSED` 下继续作答走详情接口，不调用 `start` |
| D11 | 教师修改 `endAt` | 当前 `updateExam` 仅允许 `DRAFT`，已发布后无修改 `endAt` 的入口；已开始提交的 `deadlineAt` 为快照，任何后续数据变更都不回溯（本期保持） |
| D12 | 时钟展示内容 | 保留 `MM:SS` 倒计时（分钟位可 ≥ 60，保持两位补零）；必须同时展示绝对截止时刻（浏览器本地时区，格式与学生端现有 `M/D HH:mm` 一致）与本次实际限时分钟数；剩余 ≤ 5 分钟时使用危险色高亮。本次实际限时取 `Math.max(0, round((deadlineAt - startedAt) / 60000))`（时间戳按毫秒；等价于秒差 `/ 60`），任一缺失时回退 `durationMinutes`；四舍五入后 N 为 0 时（距截止不足约 30 秒），仍展示“本次限时 0 分钟”并追加“（窗口提前结束）”；当 `deadlineAt` 等于 `endAt`（误差 ≤ 1 秒）且实际分钟数小于 `durationMinutes` 时，追加"（窗口提前结束）" |
| D13 | 列表与详情文案 | 列表不可参加时区分「考试将于 X 开始」「已错过考试时间」「本次作答已超时」三种情况；详情页作答须知写明"窗口先结束则按窗口收卷"；历史无 `endAt` 的已发布考试追加"本场未设置统一截止时间"提示 |
| D14 | 历史数据兼容 | 历史 `PUBLISHED` 且 `endAt` 为空的考试按 `开始 + durationMinutes` 收卷，不回填数据；因发布后无编辑入口，教师如需统一截止时间必须新建考试。历史 `IN_PROGRESS` 且 `deadline_at` 为空的提交进入后按剩余 0 处理并立即交卷，状态含主观题记 `SUBMITTED`、全客观题记 `GRADED` |

## 2. 背景与现状调研

### 2.1 问题来源

学生作答页右上角存在一个时钟，用户无法判断它是"试卷统一截止时间"还是"个人剩余时间"；同时希望明确两条规则：

1. 考试存在最终截止时间限制；
2. 学生从进入作答开始，最长只能答固定分钟数。

典型场景：考试窗口为 12:00–13:00，单次限时 30 分钟。

### 2.2 调研结论

- 该时钟是**本次作答的剩余时间**，来自服务端下发的 `remainingSeconds`，终点为 `exam_submission.deadline_at`。
- `deadline_at` 在**首次开始作答时一次性写入**，取 `min(开始时刻 + durationMinutes, endAt)`，之后不因刷新、重进而延长，也不因教师修改考试配置而变化。
- 因此用户提出的两条规则**现网已经同时支持**：窗口提供最终截止，个人时长提供单次限时，二者冲突时窗口优先。
- 现网缺口集中在"配置能否保证窗口存在"与"学生能否看懂时钟"，不在计时算法本身。

### 2.4 现状差距

| 编号 | 差距 | 影响 |
|---|---|---|
| G1 | 考试可在没有 `endAt` 的情况下发布 | 需求①的"最终截止"失效，只剩个人倒计时 |
| G2 | 无时间顺序与时长后端校验 | 可配置出 `startAt >= endAt`、负时长等不可用窗口；异常窗口下学生可能立即被判定截止 |
| G3 | 时钟只显示剩余时间 | 学生不知道具体几点截止，也无法判断是否被窗口截断 |
| G4 | 列表与详情未解释"窗口优先" | 学生误以为"限时 30 分钟就一定给满 30 分钟" |
| G5 | `visibilitychange` 可见时仅重拉详情 | 离线或重拉失败时没有本地优先校准兜底；后台定时器被节流时到期交卷可能不触发 |
| G6 | 到期瞬间仍可能有未执行的草稿防抖 | 归零后仍可能发出一次草稿保存请求，与"到期锁定"语义不一致 |

## 3. 目标与成功标准

### 3.1 目标

1. 固化"窗口截止优先"的考试计时语义，教师、学生、测试三方理解一致。
2. 通过发布门禁与配置校验，保证新发布考试一定存在最终截止时间。
3. 让学生在自己的作答页看懂三件事：还剩多久、具体几点截止、本次限时多少分钟。
4. 到期收卷链路的客户端与服务端行为均有明确、可测的兜底。

### 3.2 成功标准

- 12:00–13:00、30 分钟的考试：12:10 进入，截止 12:40；12:45 进入，截止 13:00，时钟分别从 30:00 与 15:00 开始递减。
- 13:00 后无进行中提交的学生不能开始考试，返回 HTTP 400「考试已结束」。
- 未设置 `endAt` 的草稿无法发布，返回 HTTP 400「请先设置考试结束时间」。
- `startAt` 与 `endAt` 均非空且 `startAt >= endAt`，或 `durationMinutes` 超出 1–600 时，保存/发布被拒绝，返回 HTTP 400 与本文写死的文案。
- 倒计时归零时，作答控件与"交卷"按钮不可用，并立即发起自动交卷。
- 截止后 120 秒内交卷成功且状态为 `AUTO_SUBMITTED`（含主观题）或 `GRADED`（全客观题）；超过 120 秒交卷返回 HTTP 400 且答案表无写入。
- 服务端调度能在 `deadlineAt + 120s + 60s` 内将遗漏的进行中提交结算为 `AUTO_SUBMITTED`（含主观题）或 `GRADED`（全客观题）。
- 刷新、重进、切后台恢复均不会延长剩余时间。

## 4. 范围

### 4.1 本期范围

- 考试计时语义固化与文档化（窗口优先）。
- 教师端考试时间配置校验：发布入口的 `endAt` 必填、`endAt > 当前时间`、时间顺序，时长 1–600；`DRAFT` 更新允许 `endAt` 为空。已发布/已关闭考试无编辑入口（`updateExam` 仅 `DRAFT`），历史已发布且 `endAt` 为空的考试按 D14 兼容，不回溯拦截。
- 学生端作答页倒计时展示：绝对截止时刻、本次限时、最后 5 分钟高亮；补齐页面重新可见时的本地优先校准（现有仅重拉详情）。
- 学生端考试列表与详情页文案：开始时间、已错过、窗口优先说明、历史无统一截止提示。
- 相关后端测试补充、前端构建验证与手工验收。

### 4.2 不在本期范围

- "个人时长优先"（进入后固定给满 `durationMinutes`，允许跨过 `endAt`）。
- 按题目/题型设置独立截止时间。
- 开放已发布考试的时间编辑；教师关闭考试后对进行中作答立即收卷。
- 严格到秒截止（取消 120 秒宽限期）。
- 考试防作弊、切屏检测、断线重连、离线答卷缓存。
- 历史考试数据回填、历史提交截止时间重算。
- 作业、实验模块的时间窗调整。

## 5. 术语

| 术语 | 定义 |
|---|---|
| 考试窗口 | `[startAt, endAt)`；`startAt` 为空表示不限制开始，`endAt` 为空表示不限制结束 |
| 开始作答时刻 | 首次创建 `exam_submission` 时的服务端时间 `startedAt` |
| 本次作答截止时间 | `exam_submission.deadline_at`，`min(startedAt + durationMinutes, endAt)` |
| 个人限时 | 考试配置的 `durationMinutes`，即单次作答最多可用的分钟数 |
| 宽限期 | `deadlineAt` 之后 120 秒，用于容纳自动交卷、网络抖动与重试 |
| 窗口优先 | `endAt` 早于个人限时终点时，以 `endAt` 为最终截止，不补时 |
| 进行中提交 | `exam_submission.status = IN_PROGRESS` |

## 6. 核心流程

### 6.1 教师配置与发布

1. 教师在考试弹窗填写标题、班级、开始时间、结束时间、时长（1–600 分钟）。
2. 保存草稿：允许 `startAt` / `endAt` 为空；若两者同时存在必须 `startAt < endAt`，否则返回 40000「开始时间必须早于结束时间」。
3. 发布：在前述校验之外，要求 `endAt` 非空且晚于当前时间；`startAt` 非空时还必须早于 `endAt`。不满足分别返回 40000「请先设置考试结束时间」「结束时间必须晚于当前时间」「开始时间必须早于结束时间」。
4. 已发布考试不可再次编辑：`PUT /api/v1/exams/{id}` 仅允许 `DRAFT`，否则返回 40000「只有草稿状态的考试可以修改」（现状保持）。发布后如需调整时间，只能新建考试。
5. 时长允许大于窗口长度；教师端提示"晚于窗口结束前 N 分钟进入时，将按窗口结束时间提前收卷"。

### 6.2 学生开始作答

1. 学生点击「开始考试」，请求 `POST /api/v1/exams/{id}/start`。
2. 服务端校验 `PUBLISHED`、班级成员、无历史内联题、`now ∈ [startAt, endAt)`。
3. 考试仍为 `PUBLISHED` 且已存在 `IN_PROGRESS` 提交时，直接返回该提交的 `deadlineAt` 与剩余时间，不校验窗口、不重算截止；`CLOSED` 下 `start` 返回 40000「考试未发布，不能开始」，已开始学生通过详情接口继续。
4. 无进行中提交时创建提交，写入 `startedAt = now`、`deadlineAt = min(now + durationMinutes, endAt)`。
5. 响应返回 `submissionId`、`deadlineAt`、`remainingSeconds`；前端以此为基线启动倒计时。

### 6.3 作答与到期

1. 作答页显示剩余时间、绝对截止时刻、本次限时分钟数。
2. 前端每秒按本地单调差值更新剩余时间；作答内容按 1.5 秒防抖保存草稿（现网 `DRAFT_DEBOUNCE_MS = 1500`）。
3. 剩余时间归零：停止计时、禁用全部作答控件与"交卷"按钮、立即自动交卷。
4. 自动交卷成功：进入结果态。
5. 自动交卷失败：展示常驻错误条「考试已结束，自动交卷失败，请立即重试或联系教师」；网络/5xx 每 10 秒重试，最多 6 次；用户可随时点击「重新交卷」。

### 6.4 刷新、重进与切后台

1. 刷新或重新进入：详情接口在 `IN_PROGRESS` 时返回 `deadlineAt` 与 `remainingSeconds`，前端以新基线继续倒计时，不重置为完整时长。
2. 页面从后台恢复可见：先按本地基线立即重算剩余时间；若已归零且未触发过自动交卷，立即 `autoSubmit()`；随后重拉详情校正，重拉失败不影响已触发的交卷。
3. 已超过 `deadlineAt + 120s` 的进行中提交：列表 `canResume=false`，由服务端调度结算。
4. 已提交后再进入：按结果态展示，不恢复作答。

### 6.5 服务端兜底

1. 调度任务每 60 秒扫描 `IN_PROGRESS` 且 `deadlineAt <= now - 120s` 的提交，单批最多 100 条。
2. 每条提交在独立事务中结算：含主观题状态置 `AUTO_SUBMITTED`，全客观题直接结算为 `GRADED`；答案以已持久化草稿回退。
3. 单条失败只记 WARN，不影响同批其它提交。

## 7. 功能需求

### FR-1 窗口截止优先

#### 7.1.1 规则

- `deadlineAt = min(startedAt + durationMinutes, endAt)`。
- `endAt` 非空且早于个人限时终点时，最终截止取 `endAt`，不补足个人时长。
- `endAt` 为空时，最终截止取 `startedAt + durationMinutes`。
- 剩余时间按 `max(0, deadlineAt - now)` 计算，不允许负值。

#### 7.1.2 示例

考试窗口 12:00–13:00，`durationMinutes = 30`：

| 进入时刻 | `deadlineAt` | 实际可用 |
|---|---|---|
| 12:00 | 12:30 | 30 分钟 |
| 12:10 | 12:40 | 30 分钟 |
| 12:30 | 13:00 | 30 分钟 |
| 12:45 | 13:00 | 15 分钟 |
| 12:59:59 | 13:00 | 1 秒 |
| 13:00 及以后 | 不允许开始 | — |

#### 7.1.3 验收标准

- 12:45 进入时 `remainingSeconds` 约为 900，误差不超过 5 秒。
- `deadlineAt` 不晚于 `endAt`。
- 重复进入不重算、不延长 `deadlineAt`。

---

### FR-2 开始门禁与重复进入

#### 7.2.1 规则

- 新建作答必须满足：考试 `PUBLISHED`、当前学生属于考试班级、无历史内联题、`startAt` 为空或 `now >= startAt`、`endAt` 为空或 `now < endAt`。
- 考试仍为 `PUBLISHED` 且已有 `IN_PROGRESS` 提交：直接返回原提交，不校验窗口；即使 `endAt` 已过也返回 `remainingSeconds = 0`，由前端触发自动交卷。
- 已 `SUBMITTED` / `AUTO_SUBMITTED` / `GRADED`：返回 40000「考试已提交，不能重新开始」。
- 教师关闭考试（`CLOSED`）不阻止已开始学生继续作答与交卷；但 `start` 仍要求 `PUBLISHED`，`CLOSED` 下刷新/重进走详情接口，不调用 `start`。

#### 7.2.2 验收标准

- `startAt` 未到开始返回 400「考试尚未开始」，且不创建提交。
- `endAt` 已过且无提交开始返回 400「考试已结束」，且不创建提交。
- `endAt` 已过但有进行中提交返回原提交，`remainingSeconds=0`。
- `CLOSED` 且进行中提交在 `deadlineAt + 120s` 内仍可交卷。

---

### FR-3 倒计时展示与到期行为

#### 7.3.1 展示内容

作答页右上角必须同时包含：

1. 剩余时间：`MM:SS`，分钟位可大于 99，保持两位补零。
2. 绝对截止时刻：`截止 M/D HH:mm`，按浏览器本地时区渲染，数据源为服务端 `deadlineAt`；格式复用学生端现有 `formatDateTime`，不新造格式。
3. 本次限时：`本次限时 N 分钟`，`N = Math.max(0, round((deadlineAt - startedAt) / 60000))`（时间戳按毫秒；等价于秒差 `/ 60`）；`startedAt` 或 `deadlineAt` 缺失时回退 `detail.durationMinutes`。四舍五入后 `N = 0`（距截止不足约 30 秒）时仍展示“本次限时 0 分钟”。当 `deadlineAt` 等于 `endAt`（误差 ≤ 1 秒）且 `N < detail.durationMinutes` 时追加"（窗口提前结束）"。
4. 保留提示文案「到点自动交卷」。

剩余时间 ≤ 5:00 时，数字使用危险色（与现有 danger 语义一致）高亮。

倒计时必须单调不增：以 `performance.now()` 计算本地流逝时间，并对显示值取 `min(上次值, 新值)`；本机时间回拨不得让剩余时间增加。

#### 7.3.2 到期行为

- 归零时停止定时器，禁用全部作答控件与"交卷"按钮。
- 立即调用自动交卷；成功后进入结果态。
- 失败时展示常驻错误条与「重新交卷」按钮；网络/5xx 每 10 秒自动重试，最多 6 次；40000「考试已提交，不能重复提交」直接回到结果态，不重试。
- `deadlineReached = true` 时，`scheduleDraftSave()` 与 `flushDraft()` 直接短路，不再发起草稿保存请求；`doSubmit()` 到期后不执行提交前 flush，直接使用内存答案交卷。
- 清空归零前已排队的草稿防抖定时器，避免到期后补发。

#### 7.3.3 页面恢复

- 现状：`hidden` 时 `flushDraft()`；`visible` 且 `state === 'B'` 时调用 `loadExam()`，由服务端 `remainingSeconds` 重置基线，`startTimer(0)` 会触发自动交卷。
- 本期要求：可见时先按本地基线立即重算剩余时间；若已归零且未触发过自动交卷，置位 `autoSubmitTriggered` 后先 `autoSubmit()`，再 `loadExam()` 校正，避免 `startTimer(0)` 重复触发。
- 重拉失败（离线）不得吞掉已归零的自动交卷；恢复网络后沿用既有自动重试。

#### 7.3.4 验收标准

- 12:45 进入 12:00–13:00、30 分钟的考试，页面显示 `15:00`、`截止 11/9 13:00`、`本次限时 15 分钟（窗口提前结束）`。
- 12:10 进入同一考试，页面显示 `30:00`、`截止 11/9 12:40`、`本次限时 30 分钟`。
- 剩余 5:00 时数字变为危险色。
- 归零后输入框、选项、代码框、交卷按钮全部不可用。
- 归零后等待 10 秒，网络面板无新的草稿保存请求。
- 归零后自动交卷成功，状态为 `SUBMITTED` / `AUTO_SUBMITTED`（含主观题，按提交时刻区分）或 `GRADED`（全客观题）。
- 断网恢复后若已归零，自动交卷立即触发并重试。
- 断网状态下切后台再回来，若已归零仍会触发自动交卷，不依赖详情重拉成功。
- 页面切后台 10 分钟后回到前台，剩余时间与真实截止一致，不出现"多给时间"。

### FR-4 教师端时间配置与发布校验

#### 7.4.1 `createExam` / `updateExam`（仅 `DRAFT`）校验

| 校验项 | 规则 | 失败文案（code 40000 / HTTP 400） |
|---|---|---|
| 时长范围 | `durationMinutes` 为整数且 1 ≤ 值 ≤ 600 | `@Min`：考试时长必须大于 0 分钟；`@Max`：考试时长不能超过 600 分钟 |
| 时长非空 | `durationMinutes` 非空 | `@NotNull`：不能为空（前端本地阻止空值提交） |
| 时间顺序 | `startAt` 与 `endAt` 同时非空时必须 `startAt < endAt` | 开始时间必须早于结束时间 |
| 时长与窗口 | 允许 `durationMinutes > 窗口分钟数`，不拒绝 | 不产生错误，由前端提示按窗口截断 |

实现层归属：时长范围使用 DTO Bean Validation（`@Min(1)` / `@Max(600)`），由 Controller 触发；时间顺序与发布态校验依赖 `Exam` 当前状态，在 Service 层显式校验。`updateExam` 仅允许 `DRAFT`，非 `DRAFT` 返回 40000「只有草稿状态的考试可以修改」，不进入本节校验。

#### 7.4.2 发布态与更新状态校验

| 入口 | 额外规则 | 失败文案 |
|---|---|---|
| `changeStatus` `DRAFT → PUBLISHED` | `endAt` 非空且 `endAt > now`；`startAt` 非空时必须 `startAt < endAt` | `endAt` 为空：请先设置考试结束时间；`endAt <= now`：结束时间必须晚于当前时间；顺序错误：开始时间必须早于结束时间 |
| `createExam` 直接以 `PUBLISHED` 保存 | `endAt` 非空且 `endAt > now`；`startAt` 非空时必须 `startAt < endAt` | 同上 |
| `updateExam` 非 `DRAFT` | 仅 `DRAFT` 可修改（现状保持），不进入时间配置校验 | 只有草稿状态的考试可以修改 |

#### 7.4.3 校验顺序

- `changeStatus` `DRAFT → PUBLISHED`：先执行现有历史内联题拦截（「请先将题目保存到题库后再组卷」），再执行时间配置校验，保持现有测试语义。
- `createExam` / `updateExam`（`DRAFT`）：先执行现有班级权限、题库归属、题目重复校验，再执行时间配置校验。
- 任一校验失败均不落库。

#### 7.4.4 教师端交互

- 保存草稿：开始/结束时间仍可留空；前端本地校验时长 1–600、时间同时存在时 `startAt < endAt`，不通过直接提示并阻止请求；后端仍做同样校验作为最终防线。
- 发布按钮：前端本地校验 `endAt` 非空、`startAt` 非空时 `startAt < endAt`，不通过直接提示「请先设置考试结束时间」或「开始时间必须早于结束时间」且不发起请求；`endAt > 当前时间` 交由后端判定，前端只透传错误文案。
- `updateExam` 仅对 `DRAFT` 开放；教师端「编辑」按钮仅 `DRAFT` 可见（现状保持），不做已发布编辑的本地校验。
- `durationMinutes` 大于窗口分钟数时，弹窗内展示提示：「考试时长为 N 分钟，晚于窗口结束前 N 分钟进入时，将按窗口结束时间提前收卷」。

#### 7.4.5 验收标准

- 未设置结束时间的草稿发布失败，提示「请先设置考试结束时间」。
- `startAt = 13:00`、`endAt = 12:00` 保存失败，提示「开始时间必须早于结束时间」。
- `durationMinutes = 0` 或 `601` 保存失败，提示对应文案。
- 结束时间为过去时间的草稿发布失败，提示「结束时间必须晚于当前时间」。
- 非 `DRAFT` 考试调用 `PUT /api/v1/exams/{id}` 返回 400「只有草稿状态的考试可以修改」（现状回归）。
- 窗口 12:00–13:00、时长 30 分钟保存成功，并展示窗口截断提示。

### FR-5 列表与详情文案

#### 7.5.1 学生考试列表

- 保留「考试窗口」「时长」两个信息块。
- 不可参加时的提示按下列优先级取值：
  1. `submissionStatus = IN_PROGRESS` 且 `canResume = false`：「本次作答已超时，等待系统结算」。
  2. `startAt` 非空且 `now < startAt`：「考试将于 M/D HH:mm 开始」。
  3. `endAt` 非空且 `now >= endAt` 且无提交记录：「已错过考试时间」。
  4. 其它情况沿用现有文案。
- 文案只作提示，不参与权限与可开始判定；判定仍以服务端 `canStart` / `canResume` 为准。

#### 7.5.2 学生考试详情

- 作答须知第一条改为：「开始后连续计时 N 分钟；若考试窗口先结束，则按窗口结束时间收卷。」
- 历史 `PUBLISHED` 且 `endAt` 为空的考试：`startAt` 非空时窗口块按现有 `formatWindow` 显示「开始时刻 - 未设置」，`startAt` 也为空时显示「时间待定」；追加提示「本场未设置统一截止时间，按个人限时收卷；如教师需要统一截止时间，需新建考试。」
- 其余须知保持不变。

#### 7.5.3 验收标准

- 未开始考试列表显示「考试将于 M/D HH:mm 开始」。
- 已过窗口且无提交的考试显示「已错过考试时间」。
- 进行中提交已超宽限期时显示「本次作答已超时，等待系统结算」。
- 详情页文案随 `durationMinutes` 变化。
- 历史无 `endAt` 考试出现"未设置统一截止时间"提示。

| BR-1 | 作答页时钟是本次作答剩余时间，终点为 `deadlineAt` |

## 10. 非功能需求

### 10.1 性能

- 时间配置校验只读取请求体与当前 `Exam`，不新增查询。
- 学生作答页新增展示不新增请求，复用详情接口已有字段。
- 自动交卷调度沿用现有单批 100 条与独立事务，不扩大扫描范围。

### 10.2 安全与公平性

- 截止判定以服务端 `deadlineAt` 与服务器时间为唯一真相，前端倒计时不作为安全边界。
- 本机修改系统时间不得延长可交卷时间；超宽限期请求一律拒绝。
- 倒计时显示单调不增；本机时间回拨不得增加剩余时间（交卷仍以服务端时间为准）。
- 当前学生只能读写自己的 `exam_submission` 与草稿。

### 10.3 兼容性

- 历史已发布且 `endAt` 为空的考试按个人时长收卷，不阻断作答；因 `updateExam` 仅 `DRAFT`，教师无法直接补 `endAt`，需新建考试。
- 历史 `deadline_at` 为空的进行中提交按剩余 0 处理。
- 历史 `CLOSED` 考试不受发布新校验影响；`updateExam` 对非 `DRAFT` 仍返回 400「只有草稿状态的考试可以修改」。

### 10.4 可测性

- 所有时间相关用例使用相对当前时间的夹具，禁止固定日期。
- 宽限期边界使用 `deadlineAt - 1s`、`deadlineAt + 60s`、`deadlineAt + 121s` 三档断言。
- 窗口优先使用 12:00–13:00、30 分钟的等价相对时间构造。

## 11. 异常与边界场景

| 场景 | 预期行为 |
|---|---|
| 12:45 进入 12:00–13:00、30 分钟考试 | `deadlineAt=13:00`，剩余约 900 秒 |
| 12:10 进入同一考试 | `deadlineAt=12:40`，剩余约 1800 秒 |
| 13:00 整开始，无进行中提交 | 400「考试已结束」，不创建提交 |
| `endAt` 已过但有进行中提交 | 返回原提交，`remainingSeconds=0`，前端自动交卷 |
| 截止前 1 秒交卷 | 含主观题状态 `SUBMITTED`；全客观题 `GRADED`，答案与分数正常落库 |
| 截止后 60 秒交卷 | 含主观题状态 `AUTO_SUBMITTED`；全客观题 `GRADED`，答案与分数正常落库 |
| 截止后 121 秒交卷 | 400「考试已结束，无法提交」，答案表与提交表无变化 |
| 截止后 60 秒存草稿 | 服务端接受（宽限期语义不变）；前端到期已短路，不会主动发送新草稿 |
| 截止后 121 秒存草稿 | 400「考试已结束，无法保存草稿」 |
| 到期瞬间存在排队的草稿防抖 | 清除定时器，不发送请求；自动交卷使用内存答案与已落库草稿 |
| 到期前已发出的草稿请求 | 允许完成，服务端在宽限期内正常接收；不追回、不回滚 |
| 刷新页面 | 剩余时间按服务端重新计算，不恢复满时长 |
| 重复点击开始 | 返回同一提交，`deadlineAt` 不变 |
| 教师关闭考试，学生仍在作答 | 可继续到个人截止时间并交卷；刷新走详情接口，`start` 返回 400「考试未发布，不能开始」 |
| 教师尝试修改已发布考试的时间 | 400「只有草稿状态的考试可以修改」；已开始学生不受影响 |
| 通过数据修复直接改 `endAt` | 已开始学生的 `deadlineAt` 仍为快照，不提前、不延后 |
| 草稿未设置 `endAt` 就发布 | 400「请先设置考试结束时间」 |
| `startAt >= endAt` | 400「开始时间必须早于结束时间」 |
| `durationMinutes = 0` / `601` | 400 对应时长文案 |
| 非 `DRAFT` 调用更新接口 | 400「只有草稿状态的考试可以修改」 |
| `durationMinutes > 窗口分钟数` | 保存成功，实际按 `endAt` 截断 |
| 历史 `PUBLISHED` 且 `endAt` 为空 | 按个人时长收卷，详情页出现"未设置统一截止时间"提示 |
| 历史 `IN_PROGRESS` 且 `deadline_at` 为空 | 进入后立即交卷，状态含主观题记 `SUBMITTED`、全客观题记 `GRADED` |
| 页面切后台期间归零 | 回到前台立即重算并触发自动交卷 |
| 自动交卷遇网络异常 | 每 10 秒重试，最多 6 次，期间展示错误条与「重新交卷」 |
| 自动交卷遇「考试已提交，不能重复提交」 | 直接同步结果态，不再重试 |

## 14. 风险与后续迭代

### 14.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 前端本地时钟被修改 | 倒计时显示异常 | 倒计时以服务端 `remainingSeconds` 为基线并保证单调不增；交卷以服务端时间为准 |
| 网络延迟导致开始响应偏晚 | 学生实际可用时间少 1–2 秒 | 服务端以创建时刻计算；误差在可接受范围 |
| 调度任务单批 100 条 | 超大考场结算延迟到后续批次 | 按分钟分批，最迟延迟可估算；必要时后续扩容 |
| 发布门禁影响既有测试夹具 | 现有创建/发布用例失败 | 测试计划列出需补 `endAt` 的用例，同批修改 |
| 列表"已错过"依赖浏览器时间 | 本机时间错误时提示不准 | 仅提示，不参与 `canStart` / `canResume` 判定 |
| 教师无法提前收卷 | 泄题等突发场景无法立即终止 | 列入后续迭代，本期明示为非目标 |
| 已发布后无法补 `endAt` | 历史无统一截止的考试只能新建 | `updateExam` 仅 `DRAFT` 为现状，本期不开放已发布编辑；详情页明示 |

### 14.2 后续迭代

- 教师提前收卷立即生效：提交/存草稿与调度同时取 `min(submission.deadlineAt, exam.endAt)`。
- 严格到秒截止：宽限期可配置为 0。
- 按题目/题型独立限时。
- 防作弊、切屏检测、断线重连、离线答卷缓存。
- 历史考试与历史提交的数据修复工具。
