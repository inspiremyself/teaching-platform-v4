## 2. 背景与问题定位

### 2.1 背景

2026-11-06 全项目自查中，前端 `npm run build` 与后端 `./mvnw test` 均通过，但测试未覆盖以下六类缺陷。它们分别造成跨校数据泄露、账号被盗后旧会话持续有效、实验报告永久不可批改、考试未发布成绩泄露、并发提交产生重复数据、教师评分被学生覆盖，统一列为 P0。

上一轮已完成的 JWT 身份以数据库为准、实验重复提交状态机、学生成绩发布可见性，不在本期范围。

### 2.2 根因

| 编号 | 现象 | 根因 |
|---|---|---|
| P1 | 任意登录用户可按 id 读取任意查重任务详情 | `PlagiarismController.detail` 缺少角色注解；`PlagiarismService` 只拦学生与教师，校管直穿；`teacherOwnsTask` 对非教师默认返回 `true` |
| P2 | 改密或校管重置密码后，旧设备仍可继续访问 | 改密只更新 `password_hash`，不处理登录会话；校管重置只踢最近一条 `ACTIVE` 会话 |
| P3 | 教师修改或删除已作答实验的题项后，报告永久无法批改且总分失真 | 题项增删改只校验实验归属，不校验实验状态与是否已有提交；`gradeReport` 要求覆盖全部已答项，删除题项后答案成为孤儿行 |
| P4 | 考试未发布或未到可见时机，学生仍能推断客观题对错与小分 | 学生端详情与交卷响应无条件返回 `autoScore`、`manualScore` 与逐题 `isCorrect`，只有 `totalScore` / `earnedScore` 受 `scoreVisible` 控制 |
| P5 | 双击或并发交卷产生重复答案；重复批改产生重复成绩，统计被放大 | `submitExam` 为 find-then-check，无锁；`exam_answer`、`score_record` 均无唯一约束；成绩写入为无锁 find-then-save |
| P6 | 作业已批改后学生再次提交，教师评分被覆盖 | `submitHomework` 只拒绝 `CLOSED`，不校验提交状态；重复提交会把状态打回 `SUBMITTED` 并覆盖总分 |

### 2.4 影响面

- P1：校管账号可遍历 id 读取任意学校学生的姓名、相似度与原始比对结果，属于跨租户越权读。
- P2：账号被盗后修改密码无效，攻击者 token 在有效期内持续可用；校管重置学生密码后，学生其他设备仍在登录态。
- P3：一次教师改题即可让已完成实验报告永久无法批改，且总分累加孤儿答案，直接破坏成绩数据。
- P4：`MANUAL_RELEASE`、`AFTER_DEADLINE`、`AFTER_TEACHER_CONFIRM` 三种发布策略被绕过，学生通过详情或交卷响应均可提前获知客观题判定。
- P5：并发交卷产生重复答案后，详情与批改接口因查询返回多行而 500；重复成绩使平均分、完成率等统计失真。
- P6：学生一次直接 API 调用即可抹掉教师已录入的评分，且旧成绩记录残留。

## 3. 目标与成功标准

### 3.1 目标

1. 查重详情只对任务归属人开放，校管不再具备跨校读取能力。
2. 密码变更与校管重置后，除当前会话外的旧会话立即失效。
3. 实验题项结构只在草稿且无提交时可改，已发布实验只能通过复制调整。
4. 学生端考试详情与交卷响应严格遵守成绩可见性，未发布不泄露任何判分信息。
5. 考试提交与成绩写入具备数据库级幂等保障，并发不产生重复数据。
6. 作业提交具备明确状态机，已提交/已批改只能由教师打回后修改。

### 3.2 成功标准

- 学生、教师、校管分别用非本人任务的 id 调用查重详情，均返回 403。
- 同一账号两端登录，A 端改密后 B 端下一次请求返回 401，A 端仍可正常访问。
- 校管重置学生密码后，该学生所有在线设备下一次请求返回 401。
- 已发布实验修改或删除题项返回 400，已有报告批改、总分、成绩记录不受影响。
- 已有作答的实验回退草稿返回 400。
- `MANUAL_RELEASE` 考试在未发布前，学生详情与交卷响应中均不出现任何分数或对错字段。
- 并发两次交卷只有一次成功，`exam_answer` 每个题目只有一行，详情接口不出现 500。
- 同一 `(business_type, business_id, student_id)` 在 `score_record` 最多一行。
- 作业已提交/已批改后再次提交返回 400；教师打回后学生可重新编辑并提交。
- 前后端构建与全量测试通过。

## 7. 核心流程

### 7.1 查重详情鉴权

1. 过滤器完成身份解析后，控制器按角色白名单拦截：仅 `TEACHER`、`STUDENT`。
2. 服务层读取任务，任务不存在返回 404。
3. 学生校验 `task.studentId == currentUser.id()`，不匹配返回 403。
4. 教师校验任务所属活动由本人创建，不匹配返回 403。
5. 其他角色在服务层同样返回 403，作为控制器注解之外的兜底。
6. 通过后返回现有详情结构，字段不变。

### 7.2 密码变更会话失效

1. 校验旧密码；失败时仅记录审计，不处理任何会话。
2. 更新密码哈希。
3. 查询该用户全部 `ACTIVE` 会话。
4. 保留当前请求的 `sessionKey` 对应会话，其余置 `KICKED` 并写入 `invalidated_at`；被踢会话下一次请求返回 HTTP 401，业务码 `40102`，文案沿用现有「账号已在其他设备登录」。
5. 当前请求无有效 `sessionKey` 时，全部置 `KICKED`。
6. 返回成功；当前设备无需重新登录。
7. 校管重置学生密码走同一批量失效逻辑，但不存在“保留当前会话”，全部 `ACTIVE` 置 `KICKED`。

### 7.3 实验题项变更

1. 校验教师身份与实验归属。
2. 读取实验状态；非 `DRAFT` 直接拒绝。
3. 统计该实验提交数；大于 0 直接拒绝。
4. 通过后执行新增、修改或删除。
5. 状态回退同样先校验提交数为 0，再允许 `PUBLISHED` / `CLOSED` → `DRAFT`；`changeLabStatus` 与 `updateLab` 两个入口执行同一校验。
6. `updateLab` 在存在提交时禁止修改 `classId`。
7. 需要调整已发布实验时，使用现有复制实验能力生成副本。

### 7.4 考试提交与成绩写入

1. `startExam` 先按 `(examId, studentId)` 查询提交；已存在则按现有状态返回。
2. 新建提交遇到唯一键冲突时，在事务外捕获 `DataIntegrityViolationException`，再于新事务中按 `(examId, studentId)` 重读已存在提交并返回，不抛 500。
3. `submitExam` 以悲观写锁读取提交行，锁内校验状态为 `IN_PROGRESS`。
4. 锁内完成旧答案删除、逐题评分、答案写入、提交状态推进。
5. 成绩记录写入在提交行锁内先查后写；唯一约束兜底，仍冲突时返回 `40900`，不产生重复行。
6. 整个过程不产生重复答案或重复成绩。
7. 交卷响应按成绩可见性输出；不可见时分数为 `null`，`resultAvailable = false`。

### 7.5 作业提交与打回

1. 学生提交时读取作业与现有提交。
2. 作业 `CLOSED` 返回 400。
3. 已有提交状态为 `SUBMITTED` 或 `GRADED` 时返回 400，不产生任何写入。
4. 无提交或 `SAVED` 时允许提交，状态置 `SUBMITTED`。
5. 教师打回时校验作业归属与状态，作业 `CLOSED` 拒绝。
6. 打回将提交置 `SAVED`，清空评分时间、总分、教师评语与逐题评分痕迹，保留作答内容。
7. 打回后删除对应 `(HOMEWORK, homeworkId, studentId)` 成绩记录（若存在），与打回前状态无关。
8. 学生打回后可重新编辑并提交。

## 8. 功能需求

### FR-1 查重详情鉴权

#### 8.1.1 接口与权限

- 接口：`GET /api/v1/plagiarism/tasks/{id}`，路径与响应结构不变。
- 控制器增加 `@PreAuthorize("hasAnyRole('TEACHER','STUDENT')")`。
- 服务层按 D2 执行归属校验；校管在该接口直接返回 403。
- 错误码沿用 `40300`，文案统一为「无权限访问该查重记录」。

#### 8.1.2 关联校验修正

- `teacherOwnsTask` 改为：非 `TEACHER` 返回 `false`，由调用方显式处理学生与校管分支。
- 学生分支保持“仅本人任务”。
- 教师分支保持“仅本人创建活动下的任务”。

#### 8.1.3 验收标准

- 学生 A 读取学生 B 的任务返回 403。
- 教师 A 读取教师 B 的任务返回 403。
- 校管读取任意任务返回 403。
- 学生读取本人任务、教师读取本人任务返回 200。
- 查重列表接口行为不变，仍仅教师可访问。

### FR-2 密码变更会话失效

#### 8.2.1 改密

- 旧密码错误时不踢任何会话，行为与现状一致。
- 改密成功后，按 D3 / D4 批量失效。
- 被踢会话返回 HTTP 401 与业务码 `40102`，文案沿用现状；本期不新增会话状态值，也不改 `JwtAuthenticationFilter`。
- 当前会话继续可用，用户不需要重新登录。
- 审计日志不记录密码明文，事件与字段保持现状。

#### 8.2.2 校管重置密码

- 复用同一批量失效能力，按 D5 踢掉该学生全部 `ACTIVE` 会话。
- 重置成功响应与审计字段不变。

#### 8.2.3 会话仓储

- 新增 `int kickActiveSessionsByUserId(Long userId, OffsetDateTime invalidatedAt)` 与 `int kickActiveSessionsByUserIdExceptSessionKey(Long userId, String sessionKey, OffsetDateTime invalidatedAt)` 两个 `@Modifying` 批量更新方法。
- 现有 `findFirstByUser_IdAndStatusOrderByCreatedAtDesc` 保留不动，登录单会话与 `forceLogin` 逻辑不变，避免破坏 `AuthServiceTests` 现有 mock。
- 会话状态只使用现有枚举值 `ACTIVE` / `LOGGED_OUT` / `KICKED` / `EXPIRED`，不新增枚举。
- 不新增数据库迁移。

#### 8.2.4 验收标准

- 同一账号在 A、B 两端登录，A 端改密后 B 端下一次请求返回 401，A 端正常。
- 改密请求无会话标识时，该用户全部旧会话失效。
- 旧密码错误时，A、B 两端均不受影响。
- 校管重置学生密码后，该学生所有会话失效。
- 其他用户会话不受影响。

### FR-3 实验题项与状态约束

#### 8.3.1 题项结构变更

| 操作 | 允许条件 | 拒绝文案 |
|---|---|---|
| 新增题项 | 实验 `DRAFT` 且提交数为 0 | 实验已发布或已有学生作答，不能修改题项 |
| 修改题项 | 实验 `DRAFT` 且提交数为 0 | 同上 |
| 删除题项 | 实验 `DRAFT` 且提交数为 0 | 同上 |

- 提交数通过新增的 `LabSubmissionRepository.countByLabId(Long labId)` 获取，不新增迁移。
- 校验必须发生在任何写入之前。
- 拒绝时题项表、答案表、提交表、成绩表均无变化。

#### 8.3.2 状态回退

- `PUBLISHED` / `CLOSED` → `DRAFT`：提交数为 0 时允许，否则返回 400「已有学生作答，不能退回草稿」。
- 该规则同时适用于 `changeLabStatus` 与 `updateLab` 的状态字段，不得通过 `updateLab` 绕过。
- 存在提交时，`updateLab` 修改 `classId` 返回 400「已有学生作答，不能变更所属班级」。
- `DRAFT` → `PUBLISHED` 仍执行现有“必须配置题项”校验。
- 其余状态变更沿用现有逻辑。

#### 8.3.3 已发布实验的调整

- 不提供原地解锁。
- 教师通过现有复制实验生成副本，在副本上修改题项后重新发布。
- 复制功能行为不变。

#### 8.3.4 验收标准

- 草稿且无提交时，题项增删改正常。
- 已发布实验题项增删改返回 400，答案与报告不变。
- 已有提交的实验回退草稿返回 400。
- 无提交的实验回退草稿成功。
- 已有报告的批改、总分、成绩记录不受影响。

### FR-4 考试判分遮蔽

#### 8.4.1 字段规则

| 字段 | `scoreVisible = true` | `scoreVisible = false` |
|---|---|---|
| `autoScore` | 实际值 | `null` |
| `manualScore` | 实际值 | `null` |
| `totalScore` | 实际值 | `null` |
| `isCorrect` | 实际值 | `null` |
| `earnedScore` | 实际值 | `null` |
| `teacherComment` | 实际值 | `null` |
| `studentAnswer` | 实际值 | 实际值 |
| `resultAvailable` | `true` | `false` |

- `scoreVisible` 继续使用现有 `canStudentSeeScore` 判定，不新增模式。
- 0 分在可见时正常返回 0，不使用真假值判断。
- 正确答案 `answerJson` 与解析 `analysisText` 维持现有可见性控制。
- `submitExam` 响应同样按上表输出：不可见时 `autoScore`、`totalScore` 返回 `null`，并返回 `resultAvailable = false`；可见时保留现有数值并返回 `resultAvailable = true`。

#### 8.4.2 前端展示

- 学生考试详情在 `resultAvailable = false` 时，成绩卡显示“成绩待教师发布”，不显示数字。
- 逐题区域在判分字段均为 `null` 时不渲染对错标签与得分，只展示学生自己的作答。
- 后端返回 `null` 时不得通过默认值渲染为 0。
- 前端状态切换以 `resultAvailable` 为准，不得仅凭 `submissionStatus = GRADED` 进入成绩视图。

#### 8.4.3 验收标准

- `MANUAL_RELEASE` 未发布：详情中不出现任何分数与对错。
- `MANUAL_RELEASE` 发布后：详情立即出现分数与对错，无需改数据。
- `AFTER_DEADLINE` 截止前不可见，截止后可见。
- `AFTER_TEACHER_CONFIRM` 下 `SUBMITTED` 不可见，`GRADED` 可见。
- `IMMEDIATE` 行为与改造前一致。
- 0 分正常显示。
- 学生自己的答案始终可见。
- 交卷响应在不可见时不返回 `autoScore` / `totalScore`，且 `resultAvailable = false`。
- 交卷响应在可见时保持现有数值，并新增 `resultAvailable = true`。

### FR-5 提交并发与成绩唯一

#### 8.5.1 考试提交锁

- `ExamSubmissionRepository` 新增 `findByExamIdAndStudentIdForUpdate(Long examId, Long studentId)`，加 `@Lock(LockModeType.PESSIMISTIC_WRITE)`，命名对齐 `LabSubmissionRepository.findByLabIdAndStudentIdForUpdate`。
- `submitExam` 使用该方法读取提交行；状态校验、答案删除、答案写入、状态推进、成绩写入全部在锁内完成。
- 后到的事务阻塞后读到最新状态，按“已提交”拒绝。
- `startExam` 外层方法不加 `@Transactional`；创建提交调用独立的 `@Transactional` 方法，在事务外捕获 `DataIntegrityViolationException`（唯一键 `uk_exam_submission`），再于新事务中按 `(examId, studentId)` 重读并返回既有提交；不得在同一事务内捕获后继续查询。
- 作业 `gradeSubmission` 与 `gradeAnswer` 先按 id 读出 `(homeworkId, studentId)` 用于定位，再用 `HomeworkSubmissionRepository.findByHomeworkIdAndStudentIdForUpdate` 重新加锁读取，后续状态校验与成绩写入一律使用锁内读到的对象。

#### 8.5.2 数据库唯一约束

新增迁移 `V23__unique_answer_and_score_record.sql`，顺序固定为“先去重、后建约束”：

- `exam_answer`：按 `(exam_submission_id, question_id)` 分组，保留 `id` 最大的一条。
- `score_record`：按 `(business_type, business_id, student_id)` 分组，保留 `id` 最大的一条。
- 新增 `uk_exam_answer_submission_question`。
- 新增 `uk_score_record_business_student`。
- 去重 SQL 必须同时兼容 MySQL 8 与 H2 2.x，使用派生表包裹同表子查询。
- 实体类同步声明唯一约束，保持 JPA 元数据与库表一致。

#### 8.5.3 成绩写入幂等

- 复用现有 `grading/service/ScoreRecordWriter.write(businessType, businessId, studentId, classId, score, gradedAt)`，不新建组件，不改方法签名。
- 将 `ExamService.upsertScoreRecord`、`LabService.upsertScoreRecord`、`HomeworkService.gradeSubmission`、`HomeworkService.refreshSubmissionGradeState` 四处直接写入全部改为调用该组件。
- 并发控制由 D29 的提交行悲观写锁承担：同一 `(businessType, businessId, studentId)` 的写入在锁内串行，`ScoreRecordWriter` 内先查后写即可；不对不存在的成绩行加悲观锁（空行加锁无法阻止并发插入）。
- `V23` 唯一约束作为兜底；若仍触发唯一键冲突，抛 `BusinessException(40900, "成绩记录并发冲突，请重试")`，不返回 500，也不产生第二行。
- `ScoreRecordWriter.write` 声明 `@Transactional`，可被已开启事务的调用方直接复用。
- 不新增成绩表、不改响应结构。
- 实验打回删除 `score_record` 的现有行为保持不变。

#### 8.5.4 验收标准

- 并发两次交卷只有一次成功，失败方返回 400「考试已提交，不能重复提交」。
- `exam_answer` 每个 `(submission, question)` 只有一行。
- 考试详情、批改接口不再因多行查询返回 500。
- 并发批改同一提交，`score_record` 最终只有一行。
- 三域统计中的平均分、完成数不再被重复成绩放大。
- 迁移可在 H2 与 MySQL 上重复执行验证通过。

### FR-6 作业提交状态机与打回

#### 8.6.1 学生提交

| 当前状态 | 提交行为 |
|---|---|
| 无提交记录 | 允许提交 |
| `SAVED` | 允许提交（教师打回后） |
| `SUBMITTED` | `40000`「作业已提交，如需修改请联系教师打回」 |
| `GRADED` | `40000`「作业已批改，如需修改请联系教师打回」 |
| 作业 `CLOSED` | `40000`「作业已关闭，不能提交」 |

- 状态与作业关闭校验必须发生在答案写入、查重、成绩写入之前。
- 拒绝时提交表、答案表、查重任务表、成绩表均无变化。

#### 8.6.2 教师打回接口

- 路径：`POST /api/v1/teacher/homework-submissions/{id}/return`。
- 权限：`@PreAuthorize("hasRole('TEACHER')")`，并校验作业归属。
- 允许状态：`SUBMITTED`、`GRADED`。
- 作业 `CLOSED` 时拒绝：「作业已关闭，不能打回」。
- 其他状态返回「仅已提交或已批改的作业可打回」。
- 响应：`submissionId`、`status = SAVED`、`homeworkId`、`studentId`。
- 审计调用 `AuditLogService.log(actor, AuditAction.HOMEWORK_SUBMISSION_RETURN, AuditResourceType.HOMEWORK_SUBMISSION, submissionId, detail)`；`detail` 仅含 `homeworkId`、`studentId`、`fromStatus`，不记录学生作答内容；两个枚举常量按 D28 新增，`action` / `resource_type` 列均为 `VARCHAR(64)`，无迁移。

#### 8.6.3 打回数据语义

- 提交状态置 `SAVED`。
- 清空 `gradedAt`、`totalScore`、`teacherComment`；`HomeworkSubmission` 无 `submittedAt` 字段，不新增、不清空。
- 逐题清空 `score`、`autoScore`、`suggestedScore`、`judgeDetail`、`teacherComment`，`scoreSource` 重置为 `TEACHER`，`acceptedAutoScore` 置 `false`。
- 保留 `answerText`、`answerJson` 等作答内容。
- 打回时删除对应 `(HOMEWORK, homeworkId, studentId)` 成绩记录（若存在），与打回前是 `SUBMITTED` 还是 `GRADED` 无关。

#### 8.6.4 前端

- 教师作业提交页对 `SUBMITTED` / `GRADED` 显示“打回”，二次确认后刷新列表与统计。
- 学生作业详情沿用现有只读逻辑：`SUBMITTED` / `GRADED` 只读，`SAVED` 可编辑。
- `api/homeworks.ts` 增加打回方法，统一走 `request.ts`。

#### 8.6.5 验收标准

- 首次提交成功。
- `SUBMITTED` 再次提交返回 400，答案与状态不变。
- `GRADED` 再次提交返回 400，教师评分不变。
- 教师打回 `GRADED` 后，状态为 `SAVED`，逐题评分清空，成绩记录删除，学生可重新编辑提交。
- 教师打回 `SUBMITTED` 后，状态为 `SAVED`；若存在历史成绩记录同样删除。
- 打回写入 `HOMEWORK_SUBMISSION_RETURN` 审计，`detail` 不含作答内容。
- 打回后重新提交进入 `SUBMITTED`，教师可重新批改。
- 作业关闭后学生不能提交，教师不能打回。

| `V23` 去重误删数据 | 历史答案或成绩缺失 | 迁移前强制备份；去重规则固定为保留 `id` 最大；执行后核对计数 |
| 唯一约束与存量重复冲突 | 迁移失败，后端无法启动 | 先去重后建约束；迁移在 H2/MySQL 预演 |
| 改密踢会话范围过大 | 用户被意外登出 | 仅踢除当前会话；无会话标识时才全踢 |
| 实验题项锁定影响教师日常 | 已发布实验无法改题 | 引导使用复制实验；复制能力不改造 |
| 考试判分遮蔽影响既有页面 | 学生看不到原本可见的信息 | 仅非 `IMMEDIATE` 模式受影响；前端按 `resultAvailable` 分支 |
| 作业打回新增入口 | 教师误操作导致成绩清除 | 二次确认；打回仅限已提交/已批改；记录审计 |
| 悲观锁导致交卷等待 | 极端并发下响应变慢 | 锁粒度限定为单学生单考试提交行 |

回滚策略：

- 代码问题直接回滚至上一版本。
- `V23` 属破坏性去重，回滚代码不会恢复被删除行，必须使用迁移前备份恢复数据库。
- 作业打回属新增能力，回滚代码后已有 `SAVED` 记录按现有逻辑继续可提交，无需数据修复。
