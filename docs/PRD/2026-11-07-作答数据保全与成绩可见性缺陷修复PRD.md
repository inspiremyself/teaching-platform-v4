## 2. 背景与问题定位

### 2.1 背景

2026-11-07 全项目自查中，后端 `./mvnw test`（498 个用例）与前端 `npm run build`（含 `vue-tsc --noEmit`）均通过，但仍发现 5 个测试覆盖不到、会直接造成**学生作答数据丢失**或**成绩提前泄露/永久缺失**的缺陷。它们都发生在学生端作答与成绩读取主链路上，属于上线即会触发的真实问题。

### 2.2 缺陷清单与根因

| 编号 | 严重级别 | 现象 | 根因 |
|---|---|---|---|
| B1 | P0 | 实验题「只上传图片、不写文字」时保存必然失败，答案无法入库 | 后端 `SaveStepAnswerRequest.answerText` 标注 `@NotBlank`，但前端图片草稿的 `answerText` 恒为空串；实际 `LabService.saveAnswer` 本身已允许文字为空，仅 DTO 校验拦截 |
| B2 | P0 | 实验作答切题、提交、关闭/离开页面时，未保存的修改静默丢失 | 切题 `selectItem` 不保存上一题；1.2s 自动保存定时器回调读取的是「触发时的 currentItem」；`submitAll` 只保存当前题；`onBeforeUnmount` 只清定时器不 flush |
| B3 | P0 | 考试作答刷新页面后答案全部变空，倒计时归零时会用空白卷自动交卷 | 系统没有考试草稿保存接口；`getExamDetail` 仅在 `SUBMITTED/AUTO_SUBMITTED/GRADED` 时回填答案，`IN_PROGRESS` 不返回任何已答内容 |
| B4 | P1 | 考试到达截止时间但主观题未批完时，学生把客观题得分当成最终总分并看到「结果已出」 | `canStudentSeeScore` 对 `AFTER_DEADLINE` 只判断 `now >= endAt`，不判断提交是否 `GRADED`；`IMMEDIATE` 同样不判断，交卷时 `totalScore` 已被写成 `autoScore` |
| B5 | P1 | `MANUAL_RELEASE` 模式下的全客观题考试，成绩记录永远不写，学生在「我的成绩」中永久缺失该考试；且教师端当前没有可用的成绩发布入口 | `submitExam` 仅在 `canStudentSeeScore=true` 时写 `score_record`；`releaseScores` 只翻转 `score_released` 标记，不补写记录；读取端只认 `score_record`；`Results.vue` 中 `releaseScores` 仅定义未绑定任何按钮，属死代码 |

### 2.3 影响面

- B1：实验「文字 + 多图作答」能力对图片路径实际不可用，学生截图作答丢失，教师批改缺材料。
- B2：学生在题间切换或提前提交时静默丢答案，且无任何失败提示，属于不可恢复的数据丢失。
- B3：考试刷新/断网重连即丢全部作答；自动交卷会把空白卷提交并判 0 分，直接影响成绩公平性。
- B4：主观题未批完即公开不完整分数，学生误判成绩已定，引发申诉；`IMMEDIATE` 模式同样受影响。
- B5：成绩记录缺失导致成绩单、成绩分析、教师统计与该考试成绩不一致，且没有自愈路径。

## 3. 目标与成功标准

### 3.1 目标

1. 实验答案保存能力与题型能力对齐：文字、图片、文字 + 图片均可保存，清空答案也可保存。
2. 实验作答任何一次切题、提交、离开都不会静默丢失已输入内容。
3. 考试作答具备服务端草稿能力，刷新/断网重连可恢复；自动交卷使用最后草稿，不提交空白卷。
4. 考试成绩只在「最终成绩已产生」且「可见性模式允许」时对学生公开，未批完不泄露任何分数。
5. 成绩记录在提交结案时写入，发布动作幂等补写，保证成绩单与三域统计一致。

### 3.2 成功标准

- 实验题只上传图片即可保存成功，重新进入详情可回显图片。
- 实验题清空文字与图片后可保存成功，重新进入详情为空。
- 实验作答第 2 题后立即点第 3 题：第 2 题先保存成功再切换；保存失败时停留第 2 题并提示。
- 实验作答后直接点提交：所有 dirty 题项全部保存成功后才提交；任一失败不提交。
- 考试作答后刷新页面：已答题恢复；刷新后倒计时归零自动交卷，提交内容为草稿而非空白。
- 考试主观题未批完时：学生端不出现任何分数，显示「阅卷中」。
- `MANUAL_RELEASE` 全客观题考试：交卷后 `score_record` 立即存在但学生不可见；教师发布后「我的成绩」出现该考试。
- 发布接口重复调用不产生重复成绩记录。

## 5. 术语

| 术语 | 定义 |
|---|---|
| 草稿 | 学生在 `IN_PROGRESS` 状态下保存、尚未交卷的作答内容 |
| 最终成绩 | 提交状态为 `GRADED`，客观题自动评分与主观题人工评分均已完成的成绩 |
| 阅卷中 | 提交状态为 `SUBMITTED` 或 `AUTO_SUBMITTED`，尚未进入 `GRADED` |
| dirty 题项 | 当前草稿与最近一次成功保存内容不一致的实验题项 |
| 可见性模式 | 考试的 `scoreVisibilityMode`：`IMMEDIATE` / `AFTER_TEACHER_CONFIRM` / `AFTER_DEADLINE` / `MANUAL_RELEASE` |
| 幂等写入 | 同一业务键重复执行不产生重复数据，结果保持一致 |

## 6. 核心流程

### 6.1 实验保存答案（含仅图片）

1. 学生编辑某题文字或图片，触发 1.2s 防抖自动保存，或点击「保存」。
2. 前端构造 `answerText` 与 `answerPayloadJson`（图片在 payload 中）。
3. 后端校验实验可作答、步骤归属、提交可编辑。
4. 后端按题型解析 payload：允许图片的题型校验图片合法性；不允许图片的题型拒绝携带图片。
5. 文字与图片均为空时按「清空」处理，写入空 `answer_text` 与空 payload，返回 200。
6. 写入答案并追加答案快照日志，返回 `answerId` 与 `submissionStatus`。

### 6.2 实验切题 / 提交 / 离开

1. 切题：先对待切走的当前题执行保存；成功后再切换 `currentIndex` 与路由 query。
2. 自动保存定时器触发时，保存**定时器绑定的题项**，而不是当前题。
3. 提交：遍历全部 dirty 题项顺序保存；全部成功后再调用提交接口。
4. 路由离开：先保存当前全部 dirty 题项；失败时二次确认，用户确认后离开。
5. 关闭浏览器：`beforeunload` 检测到 dirty 时提示浏览器原生确认。

### 6.3 考试草稿保存与读取

1. 学生作答，前端 1500ms 防抖后调用 `PUT /api/v1/exams/{id}/draft`。
2. 后端校验角色、考试与班级成员、提交状态为 `IN_PROGRESS`、当前时间不晚于 `deadlineAt + 120s`。
3. 后端按 `(submissionId, questionId)` 逐题 upsert `exam_answer.answer_json`，不评分、不改状态、不写成绩。
4. 学生刷新页面，`getExamDetail` 返回 `submissionStatus=IN_PROGRESS` 与每题 `studentAnswer`。
5. 前端用 `studentAnswer` 恢复草稿，并按 `deadlineAt` 重启倒计时。

### 6.4 考试交卷

1. 前端组装本次交卷 payload（包含当前所有题目；未作答题目为空值）。
2. 后端对 payload 中缺失的 `questionId` 读取已持久化草稿作为有效答案。
3. 后端按现有逻辑逐题评分、汇总、结案。
4. 提交状态进入 `GRADED` 时立即写 `score_record`。
5. 响应按 D11/D13 返回 `resultAvailable`、`gradingInProgress` 与（可见时）分数。

### 6.5 成绩发布

1. 教师调用 `POST /api/v1/teacher/exams/{id}/release-scores`。
2. 后端校验收归属，置 `score_released=true`。
3. 同事务内遍历该考试全部 `GRADED` 提交，幂等 upsert `score_record`。
4. 接口重复调用返回成功，不产生重复记录。

## 7. 功能需求

### FR-1 实验答案保存支持仅图片与清空（B1）

#### 7.1.1 后端校验

- `SaveStepAnswerRequest.answerText` 改为普通 `String`，移除 `@NotBlank`。
- 服务端不再因 `answerText` 为空拒绝保存；是否允许图片仍由 `LabAnswerImageSupport.allowsImages(questionType)` 决定。
- 文字为空且图片为空时，按清空处理：保存空 `answerText` 与空 payload，返回 200。
- 非图片题型携带图片仍返回 `40000`「当前题型不支持图片作答」。
- 图片路径、数量、配额校验沿用现有 `validateImagesForSave`。

#### 7.1.2 前端

- `saveCurrent` 不再因「只有图片没有文字」阻断保存。
- 清空文字与图片后允许保存，用于撤销已保存内容。
- 保存失败提示沿用现有错误反馈。

#### 7.1.3 验收标准

- 仅上传 1 张图片、`answerText=''` 保存返回 200，重新进入详情可见图片。
- 文字 + 图片保存返回 200，文字与图片均回显。
- 删除全部图片与文字后保存返回 200，重新进入详情为空。
- 单选题携带图片保存返回 400「当前题型不支持图片作答」。

---

### FR-2 实验作答落盘策略（B2）

#### 7.2.1 自动保存

- 自动保存定时器在创建时绑定题项 id；回调保存该题项，不读取 `currentItem`。
- 保存队列保持串行，避免同一题项并发覆盖。
- 切换题项不清除其他题项的待保存状态。

#### 7.2.2 切题

- `selectItem` 先 `await persistCurrentItem()`：
  - 成功：切换题项并更新路由 query。
  - 失败：不切换，保持原题并提示「当前题保存失败，请重试」。
- 上一题与下一题按钮沿用同一规则。

#### 7.2.3 提交

- `submitAll` 在调用提交接口前，遍历所有 `isItemDirty(item)` 为真的题项顺序保存。
- 任一题项保存失败：中止提交，提示失败题项，不调用提交接口。
- 全部保存成功后才允许提交，提交前的「至少保存一题」与实验小结校验保持现状。

#### 7.2.4 离开页面

- `onBeforeRouteLeave` 中执行 flush；失败时 `ElMessageBox.confirm` 二次确认，用户确认后离开。
- `beforeunload` 在存在 dirty 题项时设置 `returnValue` 触发浏览器原生确认。
- `onBeforeUnmount` 不承担保存职责，只做采集收尾。

#### 7.2.5 验收标准

- 第 2 题输入后 1.2s 内点击第 3 题：第 2 题保存请求先发出，成功后切到第 3 题。
- 断网时点击第 3 题：不切换，停留第 2 题并提示保存失败。
- 第 2、3 题均为 dirty 时点击提交：两题都保存成功后提交。
- 第 3 题保存失败时点击提交：不提交，提示失败。
- 有 dirty 题项时关闭标签页出现浏览器离开确认。

### FR-3 考试草稿能力（B3）

#### 7.3.1 接口定义

- 新增 `PUT /api/v1/exams/{id}/draft`，仅 `STUDENT`。
- 请求体与交卷一致：`answers: [{ questionId, questionType, answerText, answerJson, selectedOptions }]`。
- 响应：`{ submissionId, savedAt, savedCount }`；`savedAt` 为服务端 `OffsetDateTime` 的 ISO-8601 字符串。

#### 7.3.2 后端校验与写入

- 校验考试存在、学生属于考试班级、提交存在且状态为 `IN_PROGRESS`。
- `deadlineAt` 非空且 `now > deadlineAt + 120s` 时返回 `40000`「考试已结束，无法保存草稿」；`deadlineAt` 为空时不做时间限制。
- `questionId` 必须属于该考试题目集合，否则返回 `40000`「题目不属于该考试」。
- 按 `questionId` 去重，同一请求重复题目以最后一条为准。
- 空答案同样写入：文字为空且图片为空时写入标准空 payload，用于覆盖旧草稿实现清空；`answerJson` 为空时写 `null`，不写空字符串。
- 草稿答案规范化复用 `submitExam` 的 `resolveAnswerJson`：`selectedOptions` 非空时写入选项 JSON，确保单选/多选恢复一致。
- `savedCount` 为按 `questionId` 去重后的写入题数。
- 仅写入 `answer_json`；不写 `submitted_at`，不改 `status`，不写评分字段与 `score_record`。
- 已存在的 `(submissionId, questionId)` 行执行更新，不存在则新增。

#### 7.3.3 读取

- `getExamDetail` 在 `IN_PROGRESS` 时，为每道题返回 `studentAnswer`（草稿 `answer_json`）。
- 该分支不返回 `isCorrect`、`earnedScore`、`answerJson`、`analysisText`。
- 已提交/已批改分支保持现状，不改变现有答案与解析返回规则。

#### 7.3.4 前端

- 答案变化后 1500ms 防抖保存；保存请求串行。
- 切题、交卷、`visibilitychange=hidden` 时立即 flush；`beforeunload` 不发起异步保存，仅依赖最近一次成功草稿。
- 保存失败只提示，不阻断作答，不清空本地草稿。
- 刷新恢复后沿用现有倒计时启动逻辑。

#### 7.3.5 交卷兜底

- `submitExam` 在**删除旧答案之前**读取该提交已有草稿，构建 `questionId -> answerJson` 映射。
- payload 中缺失的题目使用草稿答案；payload 中出现的题目（含空值）以 payload 为准。
- 删除旧答案后用合并结果按题写入，避免先删后读导致草稿丢失。
- 兜底仅影响作答内容，不改变评分、状态机与成绩可见性规则。

#### 7.3.6 验收标准

- 作答 3 题后刷新：3 题答案恢复。
- 断网时作答，刷新后恢复到最近一次成功草稿。
- 刷新后倒计时归零：自动交卷提交的内容与草稿一致，不为空白。
- 超过 `deadlineAt + 120s` 调用草稿接口返回 400。
- 已提交状态调用草稿接口返回 400。
- 非本班学生调用草稿接口返回 403。

### FR-4 考试成绩最终态与可见性（B4）

#### 7.4.1 最终态判定

- 新增统一判定：`final = submission.status == GRADED`。
- 仅 `final=true` 时才可能存在「可公开成绩」。

#### 7.4.2 可见性矩阵

| 模式 | 可公开条件 |
|---|---|
| `IMMEDIATE` | `final` |
| `AFTER_TEACHER_CONFIRM` | `final` |
| `AFTER_DEADLINE` | `final && exam.endAt != null && now >= exam.endAt`（`endAt` 为空时该模式不可见，沿用现状） |
| `MANUAL_RELEASE` | `final && exam.scoreReleased` |

#### 7.4.3 返回字段

- 不可公开且非 `final`：仅 `SUBMITTED` / `AUTO_SUBMITTED` 返回 `gradingInProgress=true`；`IN_PROGRESS` 返回 `gradingInProgress=false`，由作答页正常进入答题态。
- 不可公开但已 `final`（`MANUAL_RELEASE` 未发布、`AFTER_DEADLINE` 未到期）：`resultAvailable=false`、`gradingInProgress=false`、所有分数字段为 `null`。
- 不可公开时题目级 `isCorrect`、`earnedScore`、`teacherComment`、`answerJson`、`analysisText` 均为 `null`。
- 可公开时保持现有字段与语义。
- 学生考试列表：非 `final` 或不可公开时不返回 `totalScore`；已批改且可公开时按现状返回。
- `StudentScoreVisibilityResolver` 仅对 `BusinessType.EXAM` 追加 `submission_status = GRADED` 前置条件；`IMMEDIATE` 与 `AFTER_DEADLINE` 在非 `GRADED` 时一律不可见；`LAB` / `HOMEWORK` 读取规则不变。

#### 7.4.4 前端

- `resultAvailable=false && gradingInProgress=true` 时展示「阅卷中」，不展示分数与对错。
- `IN_PROGRESS` 时进入答题态，不展示「阅卷中」。
- `resultAvailable=false && gradingInProgress=false` 时展示「成绩待发布」，不展示分数与对错，不进入结果详情。
- `final` 且可公开时进入现有结果页逻辑。
- 结果页状态判定改为：`submissionStatus === 'IN_PROGRESS'` 进入答题态；`resultAvailable=true` 进入结果态；`gradingInProgress=true` 进入阅卷中态；其余进入待发布态；不得仅凭 `submissionStatus === 'GRADED'` 进入结果态。
- 不新增学生自行触发批改或查询的入口。

#### 7.4.5 验收标准

- `AFTER_DEADLINE` 到期但主观题未批：详情与交卷响应 `resultAvailable=false`，所有分数为 `null`。
- `AFTER_DEADLINE` 到期且已批完：分数正常返回。
- `IMMEDIATE` 主观题未批完：同样遮蔽，显示「阅卷中」。
- `AFTER_TEACHER_CONFIRM` 未批完：分数为 `null`。
- `MANUAL_RELEASE` 未发布：分数为 `null`、`gradingInProgress=false`，显示「成绩待发布」；发布且已批完：分数正常返回。
- `AFTER_DEADLINE` 且 `endAt` 为空：该模式不可见，显示「成绩待发布」。
- 学生列表在非最终态或不可公开时不出现分数。

### FR-5 成绩记录写入与发布补写（B5）

#### 7.5.1 写入时机

- 提交状态进入 `GRADED` 时写 `score_record`，与可见性无关。
- 客观题交卷即 `GRADED`：交卷事务内写入。
- 主观题最终确认后 `GRADED`：确认事务内写入。
- 业务键固定为 `(business_type=EXAM, business_id=examId, student_id)`，复用 `ScoreRecordWriter` 幂等写入。

#### 7.5.2 发布入口与补写

- 教师考试结果页 `exams/Results.vue` 页头新增「发布成绩」按钮，绑定现有 `releaseScores` 方法；点击前 `ElMessageBox.confirm` 二次确认，执行期间禁用按钮。
- 已发布（`scoreReleased=true`）后按钮文案改为「重新发布成绩」并保持可点击，用于幂等补写历史缺失记录。
- `releaseScores` 在置 `score_released=true` 后，遍历该考试全部 `GRADED` 提交，逐条补写。
- 补写采用「先按业务键查询，存在则更新分数，不存在则新增」，不依赖唯一冲突异常兜底。
- 接口允许重复调用；重复调用不新增重复记录。
- 补写仅针对 `GRADED`，不为阅卷中提交造记录。

#### 7.5.3 读取端

- `StudentScoreVisibilityResolver` 按 D21 执行：仅 `BusinessType.EXAM` 追加 `submission_status = GRADED` 前置条件，`LAB` / `HOMEWORK` 过滤矩阵保持不变。
- 成绩分析查询沿用现有规则，本期不扩大指标口径。
- 记录写入完整后，`MANUAL_RELEASE` 考试在发布后自然出现在「我的成绩」。

#### 7.5.4 验收标准

- 教师结果页可见「发布成绩」按钮，点击出现二次确认，确认后发布成功。
- 已发布后按钮显示「重新发布成绩」，再次点击成功且不产生重复记录。
- `MANUAL_RELEASE` 全客观题交卷后：`score_record` 存在，学生端不可见。
- 教师发布后：学生「我的成绩」出现该考试，分数正确。
- 发布接口连续调用两次：`score_record` 仍只有一行。
- 主观题批改完成后：`score_record` 存在且分数等于最终总分。
- 考试阅卷中：不存在该学生的 `score_record`。

## 8. 业务规则汇总

| 编号 | 规则 |
|---|---|
| R1 | 实验答案保存只要求「文字或图片至少一项」，两者都空表示清空，不报错 |
| R2 | 实验任何切题、提交、离开动作都必须先完成待保存题项的落盘 |
| R3 | 考试草稿只在 `IN_PROGRESS` 且未超过截止宽限期时允许写入 |
| R4 | 草稿只保存作答内容，不产生任何评分与状态副作用 |
| R5 | 交卷时 payload 缺失题目回退草稿，payload 出现题目以 payload 为准 |
| R6 | 只有 `GRADED` 才可能公开成绩；可见性模式只决定「何时公开」，不决定「是否已产生」 |
| R7 | `SUBMITTED` / `AUTO_SUBMITTED` 一律显示「阅卷中」且不返回分数；`IN_PROGRESS` 属于作答中，不显示「阅卷中」；`GRADED` 但不可公开显示「成绩待发布」 |
| R8 | `score_record` 在 `GRADED` 时写入，发布动作只做可见性开关与幂等补写 |
| R9 | 本期不改数据库结构，草稿复用 `exam_answer` 与既有唯一约束 |

## 10. 非功能需求

### 10.1 性能

- 草稿保存单次请求只做按题 upsert，不触发评分与快照查询。
- 前端防抖 1500ms + 串行队列，避免高频请求。
- 实验提交前 flush 按题顺序执行，不并发写库。

### 10.2 权限与安全

- 草稿接口只允许 `STUDENT`，且必须校验班级成员与提交归属。
- 草稿响应不回传标准答案、判分结果与解析。
- 成绩记录补写必须校验教师对考试的归属。

### 10.3 兼容性

- 未升级前端缓存旧页面时，后端新增字段保持向后兼容。
- `IN_PROGRESS` 详情新增 `studentAnswer` 不改变已提交/已批改分支。
- 旧数据无草稿时按「无答案」恢复，不报错。

### 10.4 数据一致性

- 草稿 upsert 依赖 `uk_exam_answer_submission_question`，并发保存同一题不产生多行。
- 交卷草稿兜底与 payload 合并后，同一题只评分一次。
- 成绩记录写入与发布补写均走 `ScoreRecordWriter`，重复执行结果一致。

## 11. 异常与边界场景

| 场景 | 期望行为 |
|---|---|
| 仅图片保存实验答案 | 200，图片入库 |
| 清空实验答案 | 200，答案为空 |
| 非图片题型传图片 | 400「当前题型不支持图片作答」 |
| 实验切题时保存失败 | 不切题，停留原题并提示 |
| 实验提交时某题保存失败 | 不提交，提示失败题项 |
| 考试刷新后无草稿 | 恢复为空，按现有逻辑继续作答 |
| 草稿接口在截止宽限期后调用 | 400「考试已结束，无法保存草稿」 |
| 草稿接口 `deadlineAt` 为空 | 不做时间限制，正常保存 |
| 草稿接口 `questionId` 不属于该考试 | 400「题目不属于该考试」 |
| 交卷 payload 缺少已保存草稿题 | 使用草稿答案评分 |
| 交卷 payload 某题明确为空 | 以空答案评分，不回退草稿 |
| 主观题未批完且已到截止时间 | `resultAvailable=false`、`gradingInProgress=true`、分数为 `null` |
| `IN_PROGRESS` 继续作答 | `gradingInProgress=false`、`resultAvailable=false`，正常答题 |
| 已 `GRADED` 但 `MANUAL_RELEASE` 未发布 | `resultAvailable=false`、`gradingInProgress=false`、分数为 `null` |
| `AFTER_DEADLINE` 且 `endAt` 为空 | 不可见，`gradingInProgress=false` |
| 发布接口重复调用 | 成功，成绩记录不重复 |
| 成绩记录补写重复执行 | 先查后写，已有记录更新分数，不新增重复行 |

## 14. 风险与后续迭代

### 14.1 风险

- 草稿写入复用 `exam_answer`，若历史数据已有重复行，upsert 可能触发唯一约束；上线前需确认 V23 已执行且无重复。
- 教学场景中草稿保存频率较高，需关注数据库写入量与连接池占用。
- 交卷草稿兜底按 `questionId` 是否出现在 payload 判定，空答案题目不会被误判为「缺失」。
- 成绩可见性收紧后，部分此前能看到部分分数的学生将暂时看不到分数，需要产品侧同步说明。
- `StudentScoreVisibilityResolver` 仅对 `EXAM` 追加 `GRADED` 条件，需回归 `LAB` / `HOMEWORK` 成绩列表不受影响。

### 14.2 后续迭代

- 服务端定时自动交卷（覆盖学生长期不打开页面的场景）。
- 考试草稿跨设备同步与冲突提示。
- 实验题项级草稿冲突与版本号。
- 成绩记录历史数据一次性修复脚本。
- 分数上下界校验与批改状态门禁统一。
