## 2. 背景与现网基线（2026-11-17 实测）

### 2.1 调研结论

教师端侧边栏当前有独立一级菜单「实验报告」（`navigation.ts` L26），指向全局批改队列页；但该菜单在**数据模型、设计意图、考试对照、移动端**四个维度都站不住脚：

| 维度 | 事实 | 证据 |
|---|---|---|
| 数据本质 | 后端无独立「实验报告」实体，报告由 `labId + studentId` 的最新 `experiment_submission` 运行时拼装 | `lab/entity/LabSubmission.java`（`experiment_submission`，含 `summary_text` / `total_score`）；设计文档 `docs/superpowers/specs/2026-04-22-teacher-lab-report-view-design.md` L40「报告不落库，不保存为独立文档」 |
| 设计意图 | 现有设计明确队列页语义是「批改工作台」，报告只是其中一个按钮动作，不是独立业务域；明确「不做额外实验报告列表或管理界面」 | 同上设计文档 L21、L28、L35 |
| 考试对照 | 考试只有「考试」一个一级菜单，结果页 `/teacher/exams/:id/results` 挂在考试下，不存在「考试结果」一级菜单 | `router/index.ts` L46–L47、`navigation.ts` L28 |
| 移动端 | 教师端移动端导航本就没有「实验报告」，只有总览 / 实验 / 作业 / 考试 / 我的 | `navigation.ts` L57–L63 |
| 需求依据 | PRD / 技术方案中无任何「实验报告设为一级菜单」的产品需求，提及均为缺陷修复 / 门禁 / 展示口径 | `docs/PRD/` 与 `docs/技术方案/` 全量扫描 |

**结论**：功能数据上报告属于实验任务，但信息架构上被提为一级菜单，与考试口径不一致。按方案 B 收进「实验」的实验结果页。

- **信息架构**：教师端侧边栏从 9 项减为 8 项；报告类页面从一级入口下沉为实验结果页的下级动作。

## 3. 目标与成功标准

1. 教师端侧边栏不再出现「实验报告」一级菜单，教师从「实验」进入结果页即可查看与批改报告。

3. 队列页删除后，打回能力迁移到评分台，批量重判 / 批量批改 / 纯报告能力不丢失。
4. 学生端、后端接口、表结构、角色权限、错误码零改动；既有评分 / 翻页 / 打回工作流行为不变。

**成功标准**：`t9001` 登录后侧边栏无「实验报告」；从「实验」台账点任一实验「查看结果」→ 结果页学生行「批改报告」→ 评分台可打分、可打回；`20260001` 的作答 / 提交 / 查看成绩链路完全不变；前后端构建与测试全绿。

## 6. 口径与核心流程

### 6.1 教师批改报告（新入口链路）

1. 教师登录 → 侧边栏「实验」（无「实验报告」项）。
2. 实验台账某行点「查看结果」→ `/teacher/labs/:labId/submission-overview`。
3. 结果页按学生 × 子题矩阵展示提交状态；有提交的学生行显示「批改报告」「实验报告」按钮。
4. 点「批改报告」→ `/teacher/lab-reports/:submissionId` 评分台；可逐题评分、确认分、必要时打回。
5. 评分台「上一个 / 下一个学生 / 班级」沿用全量队列翻页（D9）；「返回」回到来源页（`router.back()`）。
6. 点结果页「实验报告」→ 新标签打开纯报告只读页（D6）。

### 6.2 打回（能力迁移）

1. 教师在评分台打开一份 `SUBMITTED` 或 `GRADED` 报告。
2. 页头「打回」按钮可点（其他状态禁用）。
3. 确认后调用 `returnTeacherLabReport(reportId)`：提交状态回到 `SAVED`，答案与小结保留，成绩清除。
4. 成功后刷新详情与评分台队列，学生可重新编辑提交。

### 6.3 学生无感知

学生端路由、页面、接口与提交行为零改动；打回后学生按现网规则重新编辑提交，无需新 UI。

### 10.1 兼容性

- 删除队列页后，浏览器历史中指向 `/teacher/lab-reports` 的旧链接走 catch-all 重定向首页，不出现白屏或路由错误。

- 不新增前端可直达的越权入口：所有批改 / 打回 / 纯报告动作仍由后端 `@PreAuthorize("hasRole('TEACHER')")` 与 ownedLab 校验兜底。

### 10.3 一致性

- 结果页「批改报告」入口使用的 `submissionId` 与评分台 / 打回 / 批量批改使用的 ID 为同一提交主键，不引入第二套标识。

## 14. 风险与后续迭代

### 14.1 风险

- **打回入口可达性**：队列页删除后，若评分台打回按钮遗漏或状态判定错误，教师将无法要求学生重做；由 FR-4 与 §12.4 双重验收兜底。
- **历史链接失效**：教师收藏的 `/teacher/lab-reports` 链接重定向首页，需在交付说明中告知。
- **评分台刷新上下文**：打回 / 翻页后 `router.back()` 的来源可能变化，文案用中性「返回」规避措辞错误。
- **死代码残留**：删除队列页后需全仓 grep 确认 `LabReports.vue`、两个前端 API 函数与两个前端类型（`LabReportQuery` / `TeacherLabReportStats`）无残留引用，避免 lint / 构建告警；勿误删名称近似的后端 `LabRequests.TeacherLabReportQuery`。

### 14.2 后续迭代

- 后端冗余端点 `GET /teacher/lab-reports`（分页）、`/stats` 的清理（独立技术债，需评估其他调用方后另立 PRD）。
- 死函数 `releaseTeacherLabScores` 的接线或清理（独立技术债）。
- 若教师反馈需要跨实验待批改聚合视图，另立"待批改看板"需求（不复用旧队列形态）。

## 15. 已否决方案

| 否决项 | 原因 |
|---|---|
| 方案 A：保留实验报告一级菜单，仅在其内部按实验分组 | 未消除一级菜单，与用户诉求（不要单独一级菜单）和考试口径不一致 |
| 保留全局队列页、只把菜单项改成隐藏 / URL 直达 | 留下孤儿页面与隐藏入口，与"放弃全局批改队列"的产品意图不符，且打回仍分散在队列页 |
| 删除队列页的同时删除评分台翻页 API `/queue` | 评分台 / 批量批改页翻页依赖该端点（N8 / D9），删除会破坏批改工作流 |
| 把打回留在队列页、评分台不迁移 | 队列页删除后打回能力丢失，学生无法被要求重做（D4） |
| 改后端把报告建成独立实体 / 新增端点 | 超出信息架构调整范围，违反 D12 / D13，且现有设计明确报告不落库 |
| 结果页内嵌完整评分台（单页三栏） | 属大规模重构，超出本期信息架构调整范围；保留现有评分台路由更稳妥 |
