## 2. 背景与现网基线（2026-11-24 实测）

### 2.1 调研结论

两个入口的产品定位并不冲突，但用户视角会被"同一组数字 + 同一张趋势图出现两次"误导为重复页面；后端事实上已经复用，前端却各写一套展示与图表代码，接口还多带了分析页不消费的字段。治理方向是**保留双入口的职责分工，删除重复承载，并把现存口径差异显式说明**。

| 维度 | 总览 | 分析报表 |
|---|---|---|
| 路由 | `/teacher/dashboard`，`name: teacher-dashboard`，`meta.title = 教师工作台` | `/teacher/analysis`，无 `name` / `meta.title` |
| 页头 | 「教师控制台 / 工作台总览」「教师工作台」+ 动态副标题 | 「教师控制台 / 分析报表」「成绩分析与统计」+ 固定副标题 |
| 主数据块 | 关键指标 4 卡、近期评分趋势、待办与提醒、快捷入口、风险与建议 | 汇总 4 卡（页头重复一遍）、最近评分趋势、班级对比、参与面板、任务类型分布、洞察 |
| 接口 | `GET /analysis/dashboard` | `GET /analysis/teacher-overview` + `GET /analysis/teacher/participation/{type}/{id}` |
| 移动端 | 有 | 无 |

### 2.3 影响面

- **用户视角**：总览更聚焦"行动"，分析页去掉重复数字后更像下钻视图；两页之间新增一条明确的下钻链路。
- **技术面**：前端改动集中在 2 个 SFC + 1 个 composable + 1 个类型文件 + 1 个新增测试；后端仅 `getTeacherOverview` 组装逻辑与 1 个测试断言。
- **回归面**：指标字段与算法不变，权限与数据范围不变，学生端 / 校管端 / 实验 / 作业 / 考试域零改动；风险集中在总览摘要的文案清理是否误删依赖，以及分析接口字段删减是否有隐藏消费者。

## 3. 目标与成功标准

1. 两页定位一眼可辨：总览只给行动所需指标、待办、入口与趋势摘要；分析页独占完整趋势图与聚合、参与、洞察模块。
2. 同一组 4 张汇总卡不再在分析页出现两次；同一张趋势图不再有两份前端实现；分析响应不再携带前端不消费的 `recentTasks` / `quickLinks`。
3. 现存统计口径差异有明确 UI 说明，教师能判断每个数字的时间窗与状态范围；**任何指标的数值算法不变**。
4. 教师可从总览趋势摘要一步进入分析页；移动端、权限、后端统计 SQL、数据库零变化。

**成功标准**：`t9001` 登录 →「总览」只见摘要趋势并点「查看分析」进分析页 → 分析页 4 卡只出现一次、完整趋势图与班级对比 / 参与面板正常 → 两页同一指标显示相同数值；`20260001/123456` 的学生端链路完全不变；前后端构建与测试全绿。

## 6. 口径与核心流程

### 6.1 教师使用流程（改造后）

1. 教师登录 →「总览」看关键指标与待办，从趋势摘要判断近 7 日评分节奏。
2. 点趋势卡「查看分析」→ `/teacher/analysis`；也可从侧边栏直接进入。
3. 分析页看同一组 4 卡（仅一次）、完整趋势图、班级对比、参与 / 完成面板、类型分布与洞察；需要逐名学生时从参与面板「查看名单」下钻。
4. 教师回「总览」处理待办与快捷入口；分析页不承担批改动作。

### 6.2 字段流向（改造后）

```text
GET /analysis/dashboard ── buildDashboard() ──> summaryCards / trend / recentTasks / quickLinks
                                                   ↓ 总览渲染 4 卡 + 趋势摘要 + 待办 + 入口
GET /analysis/teacher-overview ─ buildDashboard()（只取 summaryCards / trend）
                                + 分析专属查询 ──> sectionComparison / businessBreakdown
                                                  / insights / participationOverview
                                                   ↓ 分析页渲染，不再收到 recentTasks / quickLinks
```

### 6.3 口径解释（D5 写死文案，不改数值）

| 指标 | 真实算法（保持） | 展示说明 |
|---|---|---|
| 教学活动总数 | 教师创建 + 本校，三域活动计数，不限制状态 | 我创建的全时段活动（含草稿） |
| 待批改任务 | 实验 / 作业 `SUBMITTED`，考试 `SUBMITTED/AUTO_SUBMITTED` | 已提交待批改，不含草稿 |
| 平均成绩 | 任教班级 `score_record` 全时段均值 | 任教班级全时段评分均值 |
| 未开始人次 | 已发布 / 关闭活动 × 班级成员减去已有提交行 | 已发布/关闭活动，尚无提交行 |
| 近期评分趋势 | 近 7 日 `graded_at` 的评分记录 | 近 7 日已评分记录（两页原文保留） |
| 班级对比 / 类型分布 | `score_record` 全时段聚合 | 分析页统一说明中标注「全时段」 |
| 参与 / 完成 | 已发布 / 关闭活动 × 班级成员 | 分析页统一说明中标注「已发布 / 关闭活动」 |

- 未新增任何前端可直达的越权入口；「查看分析」指向的分析页已受路由守卫与端点 `hasRole('TEACHER')` 双重约束。

### 10.3 一致性

- 两页指标来自同一 `buildDashboard()`；后端不再复制无关字段，但共享算法不变。
- 口径说明文案在 PRD / 技术方案 / 前端展示三处一致；出现改文案需求时先改 PRD 与技术方案。
