### 1.1 已定决策清单

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| D1 | 分数语义 | 自动分 = **客观题**得分（系统判定，教师不可改）；人工分 = **主观题**得分之和（教师录入）；总分 = 两者之和。评分汇总卡文案固定为「客观题自动得分」「主观题人工得分」；队列窄空间固定用简称「客观 x · 主观 y · 总分 z」（FR-5）。任何位置不得表述为“附加分”或“覆盖分” |
| D2 | 改动边界 | 仅改考试批改页 `Results.vue`（模板、脚本、样式），并在同目录新增 1 个纯函数模块 `examGradingState.ts` 与 1 个单测 `frontend/src/views/teacher/__tests__/examGradingState.spec.ts`（D15 的 4 个场景须可测；现网 vitest 未配 Vue 插件，SFC 内逻辑不可直接 import）。后端、Flyway/DB、HTTP 契约、权限、三域评分引擎、`vitest.config.ts` 一律不改 |
| D3 | 保存入口 | **保持单一按钮「保存评分」**，不新增第二个按钮、不新增接口（继承 11-06 PRD D5） |
| D4 | 全客观题答卷 | 交卷即 `GRADED` 的现网行为不变（继承 11-06 PRD D1）；历史卡单仍通过同一按钮提交空 `answers` 结案（继承 11-06 PRD D4/D5） |
| D5 | 完成度计算 | 继续由前端实时 `computed` 计算，不新增后端字段（继承 11-17 PRD D13）；待评分态的“已评分”判定改为基于**显式评分标记**，不能把初始化的默认 0 当作已评分；`GRADED` 态已落库的主观题分数一律视为已评分，进度显示 `y/y`；无主观题时不显示 100% 进度条，改显示“本卷无主观题”说明 |
| D6 | 0 分语义 | 0 分是合法评分，但必须由教师显式输入后才视为“已评分”；默认占位 0 不算已评分，也不得在教师未确认时被保存为最终分 |

| D8 | 已评分态 | `GRADED` 答卷的所有评分控件禁用；保存按钮禁用且必须有灰化样式；提示改为用户口吻；「切换到下一份」升为主操作 |
| D9 | 客观题卡片 | 只读弱化：显示本题得分、判定说明与「客观题由系统判分，不支持修改」；**不显示建议分行**。`scoreSource` 标签沿用现有共享映射（继承 11-17 PRD D11） |
| D10 | 主观题卡片 | 视觉突出：有参考分时显示「系统参考分（仅供参考）」；提供分数输入与评语；未评分时状态为“待评分”而非显示 0；`GRADED` 后整卡只读 |

| D12 | 未保存草稿 | “未提交改动”= 主观题出现显式评分标记，或评语文本与打开答卷时的初始值不同，二者任一命中即视为有草稿；此时汇总区提示“有未保存的评分”，切换答卷前弹确认；保存成功或确认放弃切换后清空草稿标记与初始值快照 |

## 2. 背景与现网问题（2026-11-18 实测）

### 2.1 评分模型事实

| 项 | 现网行为 | 证据 |
|---|---|---|
| 客观题 | 交卷时系统判分，写入 `autoScore`；教师改分请求遇到客观题直接 `continue` | `ExamAnswerService.java` L298–302；`ExamReportService.java` L250–251、L313–317 |
| 主观题 | 交卷时 `score=null`；教师打分写入 `answer.score`，汇总为 `manualScore` | `ExamAnswerService.java` L302–306；`ExamReportService.java` L260–275 |
| 总分 | `totalScore = autoScore + manualScore`，两者互斥不相加覆盖 | `ExamReportService.java` L274–275、L404–407 |
| 结案 | 全部题目有分后状态转 `GRADED`；任一主观题仍为 `null` 则保持 `SUBMITTED` | `ExamReportService.java` L382–408 |
| 纯客观卷 | 交卷即 `GRADED`，不进入教师待办 | `ExamAnswerService.java` L316–318 |
| 单题复核 | 后端 `confirmAnswer` 允许 `GRADED` 且未发布时改单题分，但前端无任何调用方 | `ExamReportService.java` L298–304；前端全仓 grep 0 命中 |

### 2.2 页面问题清单

| 编号 | 现象 | 根因 / 证据 |
|---|---|---|
| P1 | “自动分 / 人工分”标签语义不明，教师误读为“基础分 + 附加分”或“人工覆盖自动” | `Results.vue` L195–205；实际语义见 §2.1 |
| P2 | “人工评分完成度 100%”与“人工分 0”并存，像全打 0 分 | 无主观题时 `completionPercent` 直接返回 100（`Results.vue` L314–317），页面无解释 |

## 3. 目标与非目标

### 3.1 目标

1. 教师看到任一答卷，一眼分清“哪些分是系统判的、哪些分需要自己打”。
2. 未评分、部分评分、已结案三种状态的控件可用性与提示明确一致。
3. 0 分不被误判为已评分；未评分题不会被默认保存。
4. 全客观题历史卡单仍可用原按钮结案，且不再显示误导性的 100%。

### 3.2 非目标（明确否决，防止回潮）

| 项 | 结论 | 理由 |
|---|---|---|
| 新增「确认自动评分并结案」第二按钮 | 否决 | 继承 11-06 PRD D5：单一按钮；纯客观卷交卷即结案，历史卡单用原按钮即可 |
| 后端状态机 / 完成度字段 / API 契约变更 | 否决 | 继承 11-17 PRD D8（单独立项）与 D13（完成度前端计算）；本 PRD 是展示与交互层修复 |
| 保存后自动跳转下一份 | 否决 | 教师需先看到已结案的最终分；保留手动「切换到下一份」的确定性 |
| 前端开放 `confirm-answer` 单题复核改分入口 | 否决（本期） | 后端虽支持 `GRADED` 未发布时改单题分，但前端无调用方；开放后需处理成绩发布冻结、草稿冲突，另立需求 |
| 作业、实验批改页同款改造 | 否决（本期） | 本 PRD 仅覆盖考试批改页；三域文案统一属 11-17 PRD P3 已有范畴 |
| 批量批改、评分模板、AI 建议分升级 | 否决 | 无需求输入，且属独立产品需求 |

## 4. 需求明细

### FR-1 评分汇总卡（右侧顶部）

1. 标题保持「评分汇总」，副注「客观题 + 主观题」。
2. 三行依次为：`客观题自动得分`（读 `detail.autoScore`）、`主观题人工得分`（读当前草稿计算的实时和）、`总分`（前两者之和），总分行保持高亮。
3. 进度区按答卷题型分两种展示：
   - 有主观题：`主观题评分进度 x/y 题` + 进度条；下方提示「待评 n 题；保存后未评题不会按 0 分提交」（由 D7 门禁保证）。
   - 无主观题：不显示百分比与进度条，显示「本卷无主观题，系统已完成判分」。
4. 若存在未提交改动，显示「有未保存的评分」标记（D12）。

### FR-2 客观题卡片（只读）

1. 卡片头部标签：`系统判分` + 对错状态（`判对` / `判错`）。
2. 展示题干、学生答案、标准答案、本题得分 `x/满分`。
3. 展示 `scoreSource` 中文标签与 `judgeDetail` 判定说明；无说明时用中性文案「系统自动判定」。
4. 不展示建议分；底部固定说明「客观题由系统判分，不支持修改」。
5. 得分输入控件不存在，任何状态下客观题均不可编辑。

### FR-3 主观题卡片（可编辑）

1. 卡片头部标签：`人工评分` + 状态（`待评分` / `已评分`）；待评分态由显式评分标记决定，`GRADED` 态按已落库分数一律显示「已评分 · 只读」（D5）。
2. 展示题干、学生答案；有标准答案时同样展示。
3. `suggestedScore` 有值时显示「系统参考分 X（仅供参考，不直接计入）」；无值时整行隐藏。
4. 提供分数输入（0–本题满分）与评语输入；未评分时分数框为空并提示“待评分”，不默认显示 0。
5. “当前得分”在未评分时显示「待评分」，已评分后显示 `x/满分`。
6. `GRADED` 态：分数、评语输入禁用，状态显示「已评分 · 只读」。

### FR-4 操作面板（右侧底部）

按答卷状态切换，只有单一「保存评分」按钮（D3）：

| 状态 | 提示区 | 保存评分按钮 | 另一操作 |
|---|---|---|---|
| 进行中 | 「学生仍在作答，暂不可评分」；所有评分控件禁用 | 隐藏 | 「切换到下一份」 |
| 待评分 · 有未评主观题 | 「还有 n 题未评分，请逐题确认分数（可给 0 分）」 | **禁用**，带灰化样式 | 「切换到下一份」（切换前按 D12 确认） |
| 待评分 · 全部主观题已评 | 「评分保存后答卷即结案，不能再次修改」 | **可用**；点击先确认再提交 | 同上 |
| 待评分 · 无主观题（历史卡单） | 「本卷无主观题，点击保存评分可重新计算并结案」 | **可用**，提交空 `answers` | 同上 |
| 已评分 `GRADED` | 「该答卷已完成评分，结果已锁定为只读」 | **禁用**，灰化样式，文案保持「保存评分」 | 「切换到下一份」升为主按钮 |

表中所有「切换到下一份」的可用性统一按现有 `nextSubmission` 是否为空判定：有下一份则可点，无下一份则禁用；表中的「同上」仅继承“切换前按 D12 确认”，即**所有状态**下切换答卷都执行草稿保护确认。按钮的 `:disabled` 必须配套可见的灰化样式（背景降饱和/透明度、光标 `not-allowed`），禁止出现“亮色禁用按钮”。

### FR-5 队列与页头文案

1. 队列项分数行：`客观 x · 主观 y · 总分 z`。
2. 页头指标：`待人工处理` → `待人工评分`，数值口径不变（仍为未 `GRADED` 的提交数）。
3. 状态徽章（待评分 / 已评分 / 超时提交 / 进行中）与后端枚举映射保持不变。

### FR-6 交互细节

1. **评分标记**：教师首次改动某主观题分数（含显式输入 0）才算“已评分”；初始占位值不算。切换答卷时标记随草稿一起重置。`GRADED` 态不再依赖本次会话的标记：已落库的主观题分数视为已评分，进度显示 `y/y`（D5）。
2. **草稿保护**：存在 D12 定义的未提交改动时切换答卷，弹确认「当前评分尚未保存，确定切换吗？」；取消则留在当前答卷，确认则丢弃草稿并清空标记与初始值快照。
3. **保存确认**：点击「保存评分」先弹确认「保存后答卷即结案且不可修改，确认保存？」，确认后走现有 `gradeExamSubmission` 链路。
4. **保存结果**：toast「评分已保存，答卷已结案」→ 刷新队列与当前详情，停留在当前答卷（D13）；失败时保留草稿，不切换状态。
5. **只读态**：`GRADED` 与「进行中」答卷均禁止任何评分输入，仅提示不同；「刷新结果」等页头操作保持原行为。

## 5. 验收标准

使用演示账号教师 `t9001/123456`、班级 `SE2026-1`，路径 B 起服务后手工验收：

1. 打开一份含客观题 + 主观题的待评分答卷：客观题卡片无建议分行且有“不支持修改”说明；主观题卡片有“待评分”标签、分数框为空；汇总显示「客观题自动得分 / 主观题人工得分 / 总分」及 `0/y 题` 进度。
2. 此时「保存评分」禁用并提示还有 n 题未评分；逐题输入分数（其中一题显式输入 0）后按钮可用，进度显示 `y/y 题`。
3. 点击保存 → 确认弹窗 → 成功 toast；队列该项变为「已评分」，总分 = 客观 + 主观，客观分未变；页面停留在当前答卷，评分控件变为只读。
4. 有未保存改动时切换答卷弹确认；取消保留当前答卷，确认后草稿清空且不残留标记。
5. 再次打开该已评分答卷：主观题状态显示「已评分 · 只读」、进度 `y/y`；保存按钮灰化不可点，提示为只读口吻，无开发术语；「切换到下一份」可用。
6. 打开一份无主观题的正常答卷（交卷后自动 `GRADED`）：显示「本卷无主观题，系统已完成判分」而非 100% 进度条，评分控件只读。历史卡单提交空 `answers` 结案路径由 11-06 PRD 既有后端测试覆盖，本 PRD 不手工造数。
7. 无主观题的正常新答卷交卷后仍直接为「已评分」，不进入待办（回归 11-06 PRD D1）。
8. 前端 `npm run build && npm run lint && npm test` 全绿，且新增用例覆盖「默认 0 不算已评分、显式 0 算已评分、`GRADED` 进度 `y/y`、无主观题不显示 100%」；后端与本 PRD 无关，无需回归 `./mvnw test`（技术方案若触及其它文件另按流程验证）。
9. 全仓核对：无新增接口路径、无新增 Flyway 文件、无权限与枚举变更；页面源码不含「验证保存链路」「`gradeExamSubmission`」等开发术语。
10. 队列分数行显示「客观 x · 主观 y · 总分 z」，页头指标显示「待人工评分」，数值口径不变。

## 6. 否决方案记录

| 方案 | 否决理由 |
|---|---|
| 新增「确认自动评分并结案」按钮，与「保存评分」并列 | 与 11-06 PRD D5 冲突；正常纯客观卷已自动结案，仅为历史卡单新增常驻按钮得不偿失 |

| 把完成度改由后端下发 | 继承 11-17 PRD D13：批改中间态需即时反馈，前端 computed 零成本且无一致性风险 |
