## 4. 数据契约与隔离规则

### 4.1 六表 school_id 契约（唯一口径）

| 表 | 回填来源（`V26`） | 索引名 | 索引列（顺序写死） | 新增行写入值 |
|---|---|---|---|---|
| `t_experiment` | `class_id → class_room.school_id` | `idx_t_experiment_school_class` | `(school_id, class_id)` | `currentUser.schoolId()`（含 `LabConfigService.copyLab` 深拷贝） |
| `homework` | `class_id → class_room.school_id` | `idx_homework_school_class` | `(school_id, class_id)` | `currentUser.schoolId()` |
| `exam` | `class_id → class_room.school_id` | `idx_exam_school_class` | `(school_id, class_id)` | `currentUser.schoolId()` |
| `question_bank` | `created_by → sys_user.school_id`（子查询限定 `school_id IS NOT NULL`） | `idx_question_bank_school_created_by` | `(school_id, created_by)` | `currentUser.schoolId()`（`QuestionService.create` 与 `QuestionBankCopyService` 复制入库） |
| `score_record` | `class_id → class_room.school_id` | `idx_score_record_school_student` | `(school_id, student_id)` | 业务主表 `exam` / `homework` / `t_experiment` 的 `school_id` |
| `plagiarism_task` | `student_id → sys_user.school_id`（子查询限定 `school_id IS NOT NULL`） | `idx_plagiarism_task_school_student` | `(school_id, student_id)` | 业务主表 `homework` / `t_experiment` 的 `school_id`；`business_id` 是 `*_submission` 行的 id，不是业务主表 id（见下方口径闭环） |

- 六表列定义统一为 `school_id BIGINT NOT NULL`；不加外键、不加 DB CHECK、不建生成列、不改既有唯一键。
- 「孤儿行」唯一定义（满足任一即命中）：① 按上表来源 JOIN 不到归属记录；② 归属记录的 `school_id` 为 NULL 或不属于 `school` 表；③ 以 `class_id` 为来源的表其 `class_id` 为 NULL（`t_experiment.class_id` 自 `V9` 起可空）。`V26` 按 `V24` 范式先 `DELETE` 6 张主表的孤儿行，再执行加列、回填、收紧、建索引；关联表行不删除、不补列，按 §4.2 由主表 id 归属间接限定。
- `class_room.school_id` 自 `V13` 起 `NOT NULL`；`sys_user.school_id` 自 `V25` 起可空，回填子查询一律带 `school_id IS NOT NULL`。
- 派生表口径闭环：`score_record.business_id` 是 `exam` / `homework` / `t_experiment` 主表 id；`plagiarism_task.business_id` 是 `homework_submission` / `experiment_submission` / `exam_submission` 的 id（LAB 历史行落在遗留 `lab*` 口径），**不得直接按 `business_id` 查 6 表主表**。两表 `school_id` 唯一真相是业务主表 `school_id`；`V26` 回填后按「业务主表能否反查且存在」二分处理：① `score_record` 按 `business_id` 直查主表、`plagiarism_task` 经 submission 表反查主表，主表行存在的历史行逐行断言 `school_id` 等于业务主表 `school_id`，不一致按孤儿定义处理；② 无法反查到 6 表主表行的历史行（现网 `V2__seed_data.sql` 的 `plagiarism_task` id = -2、`score_record` id = -1 等 `business_id` 无对应 submission / 主表行的演示行；全仓迁移无 `INSERT INTO lab` / `lab_submission`），按 §4.1 回填来源（`class_id → class_room.school_id`、`student_id → sys_user.school_id`）的值保留，不删除、不做主表一致性断言，行数在迁移前统计时单独登记到 §7.2 验收记录；③ 运行时新增行一律按 FR-5 从业务主表传值。1B 技术方案写死逐表等价性 `UPDATE` / `DELETE` 语句与 ① 的反查路径，`BusinessSchoolScopeSchemaTests` 按 ① ② 两类分别断言（② 只断言行仍存在且回填值等于来源值）。
- 备份校验通过后、写 `V26` 文件前，按孤儿定义逐表 `SELECT COUNT(*)` 统计 6 张主表孤儿行数并写入 §7.2 验收记录；`V26` 只删这些统计命中的行，不删其它业务行。
