### 4.2 Phase 1 · FR-2 题目配置纯函数收敛（D3）

1. 新增 `frontend/src/utils/questionConfig.ts`（纯函数，不 import Vue、不持有 ref），固定导出四项：
   - `resequenceConfiguredQuestions(items)`：`items.map((item, index) => ({ ...item, sortOrder: index + 1 }))`；
   - `mergeConfiguredQuestions(current, incoming, { includeInline })`：`current` 为调用方现有配置数组、`incoming` 为新带入数组。`includeInline: true`（作业）先保留 `current` 中 `sourceType === 'INLINE'` 的行，再逐条追加 `incoming`（`questionBankId` 命中 `current` 则复用旧行）；`includeInline: false`（考试）只保留 `incoming` 中带 `questionBankId` 的行，并逐条复用 `current` 中的同 `questionBankId` 行；两种模式返回前都调用 `resequenceConfiguredQuestions`；
   - `planTotalScore(items, scoreOf)`：`items.reduce((sum, item) => sum + (Number(scoreOf(item)) || 0), 0)`；
   - `mapOptionsForList(optionsJson)`：沿用现网 `parseQuestionAnswerArray(optionsJson ?? null)`，对象分支取 `record.key ?? String.fromCharCode(65 + index)` 与 `record.content ?? record.label ?? record.text`，非对象分支取字母序号与原值。
2. `useHomeworks.ts`、`useExamList.ts` 删除本地同名实现改为 import；`mergeConfiguredQuestions` 调用改为传 `configuredQuestions.value` 与 `includeInline`（作业 `true`、考试 `false`），`configuredQuestions.value = ...` 的赋值留在 composable。
3. `useExamList` 三处内联选项映射统一调用 `mapOptionsForList`；`views/teacher/Questions.vue` 中被带入题目时的重排与 `removeConfiguredQuestion` 内的重排改为调用 `resequenceConfiguredQuestions`。
4. `planTotalScore` 五处**全部**接入同一函数：`useHomeworks.ts:666`（`item => item.score`）、`useExamList.ts:575`（`item => item.score`）、`useHomeworkDetail.ts:74`（`question => question.score`）、`useExamDetail.ts:119`（`question => question.questionScore ?? question.score`）、`useStudentLabSteps.ts:117`（`item => item.stepScore`）；调用方仍以 `computed(() => planTotalScore(...))` 暴露，展示值不变。

## 5. 非目标与否决项

| 项 | 结论 | 理由 |
|---|---|---|
| 后端 admin 抽泛型 `BaseCrudService<T,R>` | **否决** | 审计动作、唯一键、视图字段、导入/重置密码等差异大；三泛型 + 多钩子的抽象成本高于约 900 行同构代码，属「为统一而统一」 |
| lab/homework 提交行并发领取抽泛型基类 | **否决** | 两段合计约 50 行，返回类型不同（void / status），抽取只换来一层薄封装；并发语义已在注释中写清 |
| 三域状态机 / 发布关闭 / 时间窗校验合并 | **否决** | 考试限时与自动交卷、实验 `dueAt` 必填、作业无发布门禁均为真实语义差异，合并必生条件分支 |
| 两套提交状态枚举统一 | **否决** | 沿用 11-20 PRD D9：`IN_PROGRESS` / `AUTO_SUBMITTED` 有真实消费点，统一会丢信息并触发字符串迁移 |
| `AnalysisService.isCompleted` 改 `Map`、SQL Handler 化 | **否决** | 11-24 PRD D5 已冻结算法与 SQL；Handler 化会把 SQL 藏进匿名类，可读性更差 |
| lab 评分入口接 `GradingAdapter` | **不纳入** | 沿用 11-20 PRD D2：10 项行为差异、3 项直接改分数，须先补特征测试再独立立项 |
| 判分后汇总模板方法 | **不重复立项** | 已在 11-20 PRD D6 / Phase 2 立项，本文不改变其范围与排期 |
| 前端抽通用列表页 / `resourceApi` 工厂 / 通用分页 composable | **否决** | 三域动作语义不同；接口 URL 与 DTO 差异大；全仓仅一处真分页，抽象只服务单点 |
| `workbench` 组件、评分策略、展示映射、日期格式化 | **不改** | 已由 11-19 / 11-20 / 11-25 交付，本期只删除其遗留旧实现 |
| 表结构、Flyway、HTTP 契约、权限、错误码 | **不改** | 本期为零行为变化的结构收敛 |
