## 2. 背景与问题定位

### 2.1 背景

2026-11-07 全量自查覆盖后端鉴权/事务/时间窗/评分链路与前端请求层/路由守卫/登录态/契约一致性。最近七批缺陷修复已使权限越权、考试交卷恢复、实验批改门禁等主链路收敛；本次自查确认 **1 个 P0 与 7 个 P1** 仍可在现有代码上稳定复现，且均未被测试覆盖（后端编译通过、前端 build 通过）。

### 2.3 影响面

- N1：教师无法编辑任何未设置时间的考试，直接影响考试主流程；属于确定性故障，与网络无关。
- N2：作业成绩有效性与状态机被破坏。草稿被提前终结后学生无法再作答，且成绩记录已写入，需要人工回滚。
- N3：作业开放时间失效，学生可提前看到并提交，教师无法按教学节奏控制。
- N4：实验截止时间与「截止后可见」整体不可用，教师配置项成为死功能。
- N5：双击或网络重试即出现 500，学生无法判断提交是否成功，易产生重复操作与数据争议。
- N6：校管端学科管理出现“无响应”式失败，管理员无法感知失败原因。
- N7：普通网络抖动导致登录态被清除，体验与支持成本显著上升。
- N8：登录成功却展示失败，随后触发多设备冲突确认，形成误导性闭环。

## 3. 目标与成功标准

### 3.1 目标

1. 考试编辑不再因空时间失败，新增与编辑的请求构造口径一致。
2. 作业草稿不可被评分，评分入口的状态门禁与实验模块对齐。
3. 作业开放时间成为真实服务端门禁，前端同步只读。
4. 实验时间窗可配置、可校验、可驱动成绩可见性。
5. 作业与实验的并发首次写入幂等，不再向前端暴露唯一约束 500。
6. 学科重复错误码独立，管理员能收到明确提示。
7. 路由守卫与登录流程不再把瞬时故障误判为登录失效。

### 3.2 成功标准

- 编辑无起止时间的考试并保存成功，响应 `200`。
- 对 `SAVED` 作业调用逐题评分接口返回 `400`，提交状态保持 `SAVED`，`score_record` 无新增。
- 在 `startAt` 之前调用作业提交接口返回 `400`，不产生任何写表。
- 教师可在实验创建/编辑中设置起止时间；`dueAt` 之后保存/上传/提交均返回 `400`；`AFTER_DEADLINE` 在配置了 `dueAt` 后能正常放出成绩。
- 并发两次提交作业、并发两次首次保存实验答案，均返回成功且数据库只有一条提交/题项记录。
- 学科编码重复返回 `40902`，前端出现明确错误提示，弹窗保持可编辑。
- 后端超时/5xx 时刷新页面不清 token；登录成功后不再触发二次 `/auth/me`。

## 5. 术语

| 术语 | 定义 |
|---|---|
| 时间窗 | 活动的 `startAt` 与 `dueAt`（实验实体列为 `end_at`）；为空表示该侧不限制 |
| 开始门禁 | 当前时间早于 `startAt` 时拒绝写操作 |
| 截止门禁 | 当前时间到达或晚于 `dueAt` 时拒绝写操作 |
| 草稿 | 作业提交状态 `SAVED`：学生已保存答案但未提交 |
| 幂等成功 | 唯一约束冲突后重读既有记录并返回成功，不产生重复数据 |
| 登录态失效 | token 过期、被踢下线或账号停用，需要重新登录 |

## 6. 核心流程

### 6.1 考试编辑

1. 教师打开考试编辑弹窗，时间为空时表单值为 `null`。
2. 提交编辑时，前端把 `null` 转为 `undefined`，JSON 中省略该字段。
3. 后端反序列化为 `null`，更新考试时间为空。
4. 保存成功，刷新列表。

### 6.2 作业逐题批改

1. 教师打开某份作业提交，请求逐题评分接口。
2. 服务端取提交行锁后校验 `submitStatus`。
3. `SAVED` 直接返回 `400`，不写任何答案分数、总分、成绩记录。
4. `SUBMITTED` / `GRADED` 继续按现有逻辑写分并刷新汇总状态。

### 6.3 作业提交（含开始与截止）

1. 学生打开作业详情，前端按 `startAt` / `dueAt` 计算当前是否可作答，并每秒刷新只读态。
2. 未开始或已截止时，编辑区与提交按钮禁用。
3. 服务端 `submitHomework` 依次校验：非 `DRAFT`、班级成员、`status != CLOSED`、`startAt` 已到、`dueAt` 未过。
4. 全部通过后写入提交、执行查重、保存查重任务。
5. 任一失败返回 `40000`，不产生任何写操作。

### 6.4 实验时间窗

1. 教师在创建/编辑实验时设置开始与结束时间（均可为空）。
2. 服务端写入 `lab.start_at` / `lab.end_at`。
3. 学生进入实验详情时读取时间窗，未开始或已截止则只读。
4. 保存答案、上传图片、提交实验时，服务端按时间窗拒绝越界写操作。
5. 成绩可见模式为 `AFTER_DEADLINE` 时，只有 `dueAt != null` 且当前时间不早于 `dueAt` 才向学生展示成绩。

### 6.5 并发首次写入

1. 作业提交或实验首存在两个并发请求中同时未查到记录。
2. 两个事务都尝试插入，后到者在唯一约束上失败。
3. 失败事务捕获 `DataIntegrityViolationException`，按业务键重读既有记录。
4. 重读成功后按幂等成功返回，不抛 500，不重复写成绩记录。

### 6.6 登录

1. 用户提交账号、密码、角色。
2. 登录接口成功后返回 `token`、`user`、`permissions`。
3. 前端直接落地 token 与 user，不再发起二次 `/auth/me`。
4. 跳转角色主页。

#### 7.4.5 时间窗合法性

- 创建/更新实验时，若 `startAt` 与 `dueAt` 同时非空且 `!startAt.isBefore(dueAt)`，返回 `40000`「开始时间必须早于结束时间」；校验对象是请求中的新值，不得校验实体旧值。

- `copyLab` 允许直接复制为 `PUBLISHED`，但按 D9 在 `AFTER_DEADLINE` 时重置模式为 `AFTER_TEACHER_CONFIRM`，因此不构成破态，无需额外发布门禁。
- 触发条件统一为：`scoreVisibilityMode == AFTER_DEADLINE && dueAt == null` → `40000`「截止后可见模式必须设置结束时间」。
- 不强制 `dueAt` 晚于当前时间，允许发布已过期实验用于查看。

#### 7.4.6 验收标准

### FR-5 并发首次写入幂等（N5）

#### 7.5.1 作业提交

- 把提交行的「查找或创建」抽取为独立事务方法，事务传播级别固定 `PROPAGATION_REQUIRES_NEW`；不得在既有 `@Transactional submitHomework` 内直接捕获冲突，因为内层失败会把外层事务标记为 rollback-only。
- 捕获 `DataIntegrityViolationException` 后按 `(homeworkId, studentId)` 重读既有提交。
- 重读成功则把该提交带回外层事务，并立刻用 `findByHomeworkIdAndStudentIdForUpdate` 在锁内重新取一次提交行，再执行答案写入与查重：`homework_answer` 无唯一约束，不加锁无法阻止两个并发请求各自 `orElseGet` 出两条答案。
- 重读失败才抛业务异常。
- 并发重复提交返回成功，提交记录保持一条、题项答案按 `(homeworkSubmissionId, homeworkQuestionId)` 不产生重复行。
- 提交路径本身不写 `score_record`；`score_record` 只由 `gradeSubmission` 与 `refreshSubmissionGradeState` 写入，并发改造不得改变这一点。
- 作业答案与查重写入仍在外层事务内，保持现有原子性。

#### 7.5.2 实验首存与题项首存

- `ensureEditableSubmission` 的「查找或创建」抽取为独立事务方法，传播级别 `PROPAGATION_REQUIRES_NEW`；捕获唯一约束冲突后按 `(labId, studentId)` 重读，仍不存在才抛 500。
- `prepareStepAnswer` 的「查找或创建」同样使用 `PROPAGATION_REQUIRES_NEW`；捕获冲突后按 `(submissionId, labStepId)` 重读。
- 两个方法都不得把 `DataIntegrityViolationException` 直接冒泡为 500。
- 重读得到的实体必须重新挂到当前持久化上下文（`save` 或 `merge`），避免后续更新落到游离态对象。

#### 7.5.3 验收标准

- 两个线程并发提交同一作业：一个成功写入，另一个返回成功且数据库仅一条提交记录；含题目作答时，`homework_answer` 不出现同一题目重复行。
- 两个线程并发首次保存同一实验答案：仅一条提交、一条题项答案。
- 并发后 `score_record` 不重复。
- 单线程正常路径行为不变。

## 10. 非功能需求

### 10.1 性能

- 新增时间判断均为内存比较，不引入额外查询。
- 并发幂等只在冲突路径多一次重读，正常路径无额外开销。
- 前端时钟每秒刷新仅更新组件内状态，不发起请求。

### 10.2 权限与安全

- 所有新增门禁位于既有所有权/成员校验之后，不改变权限模型。
- 时间判断一律使用服务端时钟，不信任前端时间。
- 前端只读仅作体验层配合，不作为唯一防线。

### 10.3 兼容性

- 历史考试、作业、实验时间字段为空时行为与现状一致。
- 历史 `SAVED` 作业提交在批改页降级为只读，不丢数据。
- 登录响应结构不变，后端无需同步发版。

### 10.4 数据一致性

- 被拒绝的批改与超时提交不产生半写入数据。
- 并发冲突后重读返回既有记录，不产生重复提交、重复题项答案或重复成绩记录。
- 实验时间窗配置不影响既有运行数据。

## 11. 异常与边界场景

| 场景 | 期望行为 |
|---|---|
| 编辑无时间的考试 | 保存成功 |
| 编辑时清空时间 | 保存成功，时间为空 |
| `SAVED` 作业逐题评分 | `40000`「学生尚未提交作业，不能批改」，状态不变 |
| `SUBMITTED` 作业逐题评分 | 成功 |
| `GRADED` 作业重新评分 | 按现有逻辑允许 |
| 作业 `startAt` 未到 | 提交返回 `40000`「作业尚未开始」 |
| `now == startAt` | 允许提交 |
| 作业 `now == dueAt` | 允许提交（沿用现有截止口径） |
| 实验 `startAt` 未到 | 保存/上传/提交返回 `40000`「实验尚未开始」 |
| 实验 `now == dueAt` | 保存/上传/提交返回 `40000`「实验已截止」 |
| 实验时间窗为空 | 不限制 |
| 实验 `startAt >= dueAt` | 创建/更新返回 `40000`「开始时间必须早于结束时间」 |
| `AFTER_DEADLINE` 未配置 `dueAt` | 前端保存前拦截；发布接口返回 `40000` |
| 并发两次作业提交 | 均成功，库中一条提交；含题目时不产生重复答案行 |
| 并发两次实验首存 | 均成功，库中一条提交与一条题项答案 |
| 学科编码重复 | `40902`，页面提示，弹窗不关闭 |
| `/auth/me` 超时 | token 保留，仅拦截器弹出一次错误提示，不跳登录 |
| `/auth/me` 返回 `40100` | 清 token，跳登录 |
| `AFTER_DEADLINE` 未配置 `dueAt` 且 `updateLab` 改发布 | 返回 `40000`，不写入 PUBLISHED |
| 登录成功 | 只发一次登录请求，直接跳角色主页 |

## 14. 风险与后续迭代

### 14.1 风险

- 作业开始门禁生效后，此前提前作答的学生行为会变为失败，需产品侧提前告知。
- 实验新增时间窗后，教师需要重新配置截止时间；历史实验时间仍为空，不受影响。
- 并发幂等改造涉及事务边界，若独立事务范围过大会影响答案与查重链路，需按 §7.5 限定为“提交行写入”本身。
- 学科错误码变更会影响现有测试与前端提示，需同步更新 `AdminSubjectControllerTests`。
- `LabRequests` 为 record，新增两个组件会破坏 `LabServiceTests` 中 10 处位置构造；漏改会直接编译失败，属于必须同步的改造。
- `lab.score_visibility_mode` 为 `nullable=false`，复制时不得写 null；按 D9 重置为 `AFTER_TEACHER_CONFIRM`。
- `updateLab` 的发布校验若沿用 `assertLabPublishable(lab)` 的旧实体快照，会漏判本次请求新设的 `AFTER_DEADLINE` 与 `dueAt`；必须用请求值判定后再 `applyLab`。
- `homework_answer` 没有唯一约束，并发双写不会报错而是静默产生重复答案；必须按 D10 在提交行锁内写答案，并在并发测试中断言答案行唯一。
- `UpdateExamPayload` 改为可选字段后，需确认无其他调用点依赖必填类型；`mock` 数据如声明该类型也应允许缺省。

### 14.2 后续迭代

- 统一 `40102` 与并发 401 的处理。
- 考试客观题评分口径统一。
- 关闭活动后的学生入口与成绩回看策略。
- 查重候选的班级/课程隔离。
- 题目编码作用域调整为教师或学校维度。
- 非法状态值统一转为 `40000`。
- 全局异常消息脱敏。
- 教师列表 N+1 优化。
