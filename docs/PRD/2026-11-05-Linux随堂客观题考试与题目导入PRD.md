## 2. 背景与目标

### 2.1 背景

授课教师需要在课堂上组织一次随堂测验，覆盖 Linux 操作系统基础知识。当前平台已具备考试、题库、自动评分能力，但存在以下使用障碍：

- 题目录入只能逐题在页面手工填写，缺少快速导入手段；
- 教师希望先用脚本拼装题目 JSON 文件，再上传到 Web 页面完成批量导入；
- 学生看到的题目顺序完全相同，现场考核存在抄袭风险；
- 学生交卷后能看到参考答案，但看不到题目解析；
- 平台默认的成绩可见性不适合“交卷即出分”的随堂测验场景。

### 2.2 目标

1. 教师可通过 API 或教师端 Web 上传 JSON 文件的方式快速导入客观题题库。
2. 教师可创建“纯客观题”试卷，并在建卷时选择是否题目乱序（默认不乱序）。
3. 学生在现场作答、交卷后立即获得成绩、逐题对错、参考答案与题目解析。
4. 教师可现场查看全班成绩与逐题作答结果。
5. 不影响现有考试、题库、评分链路的既有行为。

### 2.3 成功标准

- 一次导入 50 道客观题，教师无需逐题手工录入。
- 成绩可见性为 `IMMEDIATE` 的纯客观题试卷交卷后，学生在结果页立即看到总分与解析。
- 开启乱序的考试中，不同学生的题目顺序按学生维度变化（不保证任意两人必然不同），同一学生刷新后顺序稳定。
- 未开启乱序的考试保持现有固定顺序。
- 导入数据错误可在提交前被发现，不产生脏题。

## 4. 范围

### 4.1 本期范围

- 题库 JSON 文件上传导入（单选、多选、判断）。
- 教师端建卷：选择班级、时长、题库题目、每题分值。
- 考试组卷仅允许题库题（`BANK`），内联题在考试侧阻断。
- 建卷时新增“题目乱序”开关，默认关闭。
- 纯客观题试卷的即时评分、即时成绩、即时解析。
- 题目乱序在学生端的展示与稳定性保证。
- 教师端全班成绩查看（复用现有能力）。
- 相关缺陷修复：无效的成绩可见性选项、学生端解析缺失、判断题导入与组卷格式规范。

### 4.2 不在本期范围

- 主观题（简答、代码、填空）的即时评分与即时成绩。
- 选项顺序乱序。
- Excel / CSV 文件导入题目。
- 多套试卷（A/B 卷）自动分发。
- 防作弊（切屏检测、摄像头、锁屏等）。
- 题库跨教师共享、题目审核流。
- 考试中途自动保存草稿。
- 学生端移动端专项适配。
- 非 `IMMEDIATE` 模式下的学生端可见内容改造（对错标记沿用现网行为）。
- 内联题的题目身份模型重构与作业模块内联题改造（考试侧阻断内联题，作业侧保持现状）。

## 5. 术语

| 术语 | 定义 |
|---|---|
| 客观题 | 单选、多选、判断。可完全由系统自动评分 |
| 题库题（BANK） | 存储在题库中、可被多场考试复用的题目 |
| 内联题（INLINE） | 不落题库、仅存在于单场考试或作业的题目；本期考试侧禁止使用，作业侧保持现状 |
| 确定性洗牌 | 以固定种子生成的伪随机排序，相同种子得到相同顺序 |
| 成绩可见性 | 控制学生何时能看到成绩与答案，取值包括立即可见、教师确认后、截止后、手动发布 |
| 纯客观题试卷 | 全部题目均为客观题、无需人工评分的试卷 |

## 6. 核心流程

### 6.1 教师端流程

1. 教师下载规范示例并按 wrapper 格式整理题目 JSON 文件（本地脚本或手工拼装）。
2. 进入教师端“题库管理台”，点击“批量导入”。
3. 上传 JSON 文件，系统解析并展示预览与校验结果。
4. 阻断性校验全部通过后提交导入（重复编码项跳过），系统逐题写入题库。
5. 进入“考试管理”，新建考试：
   - 选择班级；
   - 设置考试时长；
   - 从题库选择题目并设置每题分值；
   - 选择是否“题目乱序”（默认关闭）；
   - 成绩可见性选择“交卷后立即可见”；
   - 保存并发布。
6. 课堂现场组织学生进入考试。
7. 考试结束后在教师端查看全班成绩与逐题结果。

### 6.2 学生端流程

1. 学生登录，进入“考试列表”。
2. 打开目标考试，点击“开始考试”。
3. 系统按考试配置决定题目顺序：
   - 未开启乱序：按教师组卷顺序；
   - 开启乱序：按“学生 + 考试”生成的稳定随机顺序。
4. 逐题作答，可上一题 / 下一题，可通过题号导航跳转。
5. 手动交卷，或倒计时结束后系统自动交卷。
6. 交卷后进入结果页；当成绩可见性为 `IMMEDIATE` 时立即查看：
   - 总分；
   - 自动评分；
   - 每题得分与对错；
   - 本人答案；
   - 参考答案；
   - 题目解析。

## 7. 功能需求

### FR-1 题库 JSON 文件上传导入

#### 7.1.1 入口

- 唯一入口：教师端“题库管理台”头部操作区，在“新增题目”左侧新增“批量导入”按钮；不新增菜单、不在其他页面提供入口。
- 弹窗标题：批量导入题目。

#### 7.1.2 JSON 规范

根节点为 wrapper 对象，题目位于 `questions` 数组；完整结构与自包含规范见 `docs/PRD/2026-11-10-题库批量导入JSON文件与编码规范PRD.md` §3.2。下方示例省略可选的 `spec` / `schema` 两键：

```json
{
  "formatVersion": "1.0",
  "questions": [
  {
    "code": "LINUX-OS-001",
    "type": "SINGLE",
    "stem": "Linux 中用于显示当前工作目录的命令是？",
    "difficulty": "EASY",
    "options": [
      { "key": "A", "content": "pwd" },
      { "key": "B", "content": "cd" },
      { "key": "C", "content": "ls" },
      { "key": "D", "content": "cat" }
    ],
    "answer": ["A"],
    "analysis": "pwd 用于打印当前工作目录；cd 切换目录；ls 列出目录内容。"
  },
  {
    "code": "LINUX-OS-002",
    "type": "MULTI",
    "stem": "以下哪些属于 Linux 常见文件系统？（多选）",
    "difficulty": "MEDIUM",
    "options": [
      { "key": "A", "content": "ext4" },
      { "key": "B", "content": "xfs" },
      { "key": "C", "content": "NTFS" },
      { "key": "D", "content": "btrfs" }
    ],
    "answer": ["A", "B", "D"],
    "analysis": "ext4、xfs、btrfs 为 Linux 常用文件系统。"
  },
  {
    "code": "LINUX-OS-003",
    "type": "JUDGE",
    "stem": "ext4 是 Linux 常见的文件系统之一。",
    "difficulty": "EASY",
    "options": [
      { "key": "T", "content": "正确" },
      { "key": "F", "content": "错误" }
    ],
    "answer": ["T"],
    "analysis": "ext4 是 Linux 主流文件系统之一。"
  }
  ]
}
```

#### 7.1.3 字段定义

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| code | string | 是 | - | 题目编码，在本教师题库内唯一；去首尾空格并转大写后存储与展示；规范化后长度不超过 64 个字符；导入文件必须符合 H6 三段式 `<来源前缀>-<批次/章节>-<序号>`（见 `2026-11-10-题库批量导入JSON文件与编码规范PRD.md` §3.4） |
| type | string | 是 | - | `SINGLE` / `MULTI` / `JUDGE` |
| stem | string | 是 | - | 题干 |
| difficulty | string | 否 | `EASY` | `EASY` / `MEDIUM` / `HARD` |
| score | integer | 否 | - | **不支持字段**（2026-11-10 起）：导入按白名单严格校验，含该字段的行明确报错并提示字段名，见 `docs/技术方案/2026-11-10-分值兼容负债彻底清除技术方案.md` CD4 |
| options | array | 选择题必填 | - | 元素为 `{ "key": "A", "content": "选项内容" }`；判断题可省略，由系统补 `T` / `F` |
| answer | array | 是 | - | 正确答案的 key 数组 |
| analysis | string | 否 | 空 | 题目解析，学生结果页展示；缺解析在预览中标黄提示，但不阻断导入 |

#### 7.1.4 校验规则

阻断性校验（任一不通过则禁止导入）：

1. 根节点必须是含 `formatVersion` 与 `questions` 的 wrapper 对象，`questions` 为数组且至少包含一道题（纯数组文件报致命错误并提示下载规范示例）。
2. 单题对象字段类型必须正确。
3. `code`、`stem` 去除首尾空格后非空；`code` 再统一转大写（`Locale.ROOT`），规范化后长度不超过 64 个字符；判重、提交与展示均使用规范化后的 `code`。
4. `type` 必须是 `SINGLE` / `MULTI` / `JUDGE` 之一。
5. 缺省 `difficulty` 时按 `EASY` 处理；出现时必须是 `EASY` / `MEDIUM` / `HARD` 之一。
6. `score` 属于白名单外字段：出现时该行 `ERROR` 并提示字段名（见《分值兼容负债彻底清除技术方案》CD4）。
7. `options` 至少 2 个，且 `key` 不重复、`content` 非空。
8. `answer` 非空，且每个 key 必须存在于 `options` 中。
9. 单选题答案必须恰好 1 个。
10. 多选题答案至少 1 个。
11. 判断题若提供 `options`，key 必须为 `T` / `F`；未提供时先自动补 `[{"key":"T","content":"正确"},{"key":"F","content":"错误"}]`，再执行第 7～10 条校验。

非阻断项（跳过并报告）：

- 当前教师题库中已存在相同 `code`（按转大写后的值比较，仅大小写不同也视为重复）；
- 同一份 JSON 内出现重复 `code`，仅保留第一条；
- 提交时服务端返回 409（本教师题库内编码重复），记为“跳过（编码已被占用）”，继续导入后续题目。

判定顺序：先对每行执行阻断性校验，未通过记“错误”；通过校验的行再判定是否与教师题库或 JSON 内更早的通过项重复，重复记“跳过”；同一行只归入一个结果类别。

#### 7.1.5 预览与提交

预览表格列：

| 列 | 说明 |
|---|---|
| 行号 | JSON 中的序号 |
| 编码 | code |
| 题型 | 单选 / 多选 / 判断 |
| 题干摘要 | 截断展示 |
| 答案 | 正确 key 列表 |
| 解析 | 有 / 无 |
| 校验结果 | 通过 / 跳过（重复或编码已占用）/ 错误原因 |

汇总信息：

- 待导入数量；
- 将跳过数量（重复编码）；
- 错误数量。

提交规则：

- 存在任一阻断性错误或待导入数量为 0 时，“开始导入”按钮禁用；
- 仅重复项不算阻断，可继续导入其余题目；
- 导入进行中“开始导入”按钮保持禁用，弹窗关闭按钮同时禁用；本轮结束后恢复，禁止两轮导入并发；
- 提交后按行顺序逐条调用单题新增接口（请求体 `code` 使用转大写后的规范化值），并展示进度。

导入结果：

| 结果 | 含义 |
|---|---|
| 成功 | 已写入题库 |
| 跳过 | 编码已存在或被占用，未写入 |
| 失败 | 服务端返回错误，展示错误信息，可复制后重试 |

导入完成后刷新题库列表。

#### 7.1.6 验收标准

- 上传合法 wrapper JSON 文件后，预览正确展示题目数量与内容。
- 存在错误字段时，错误行明确标红并给出原因。
- 有错误时不能提交。
- 待导入数量为 0 时不能提交。
- 重复编码被跳过，并在结果中列出；仅大小写不同（如 `linux-001` 与 `LINUX-001`）同样被判为重复。
- 导入进行中再次点击“开始导入”或关闭弹窗均无效。
- 导入成功后题目出现在题库列表中，编码、题型、题干、答案、解析均正确。
- 判断题导入后，学生端选择“正确 / 错误”能够正确判分。

### FR-2 题库管理（复用现有能力）

- 保留现有题目新增、编辑、删除、筛选能力。
- 导入的题目归属当前登录教师，仅本人可见。
- 归属维度唯一 UNIQUE (school_id, created_by, code)；比较与存储均使用去首尾空格并转大写后的值；不同教师使用相同编码（含仅大小写不同）时，该项记为“跳过（编码已被占用）”并提示。
- 题目列表原有校验提示（缺解析、选项数、答案数）继续有效。

### FR-3 建卷与发布

#### 7.3.1 建卷字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 考试名称 | 是 | 如“Linux 基础随堂测验” |
| 说明 | 否 | 考试要求 |
| 班级 | 是 | 只能选择教师负责的班级 |
| 时长 | 是 | 正整数分钟，必须大于 0 |
| 题目 | 是 | 只能从题库选择（`sourceType=BANK`）；不按题型硬过滤，但禁止内联题 |
| 每题分值 | 是 | 1–100 整数，总分自动累加（口径见 2026-11-09 分值 PRD） |
| 题目乱序 | 否 | 开关，默认关闭 |
| 成绩可见性 | 是 | 新建时默认“交卷后立即可见”；可改为“教师确认后可见”并提示后果 |

从题库选择判断题时，前端校验该题 `options` 的 key 恰为 `T` / `F` 且 `answer` 为 `T` / `F`；不符合或 JSON 解析失败时禁止加入本次考试，并提示“该判断题格式不兼容，请重新导入该题”。

保存与发布前校验配置题目必须全部为 `BANK`；存在 `INLINE` 时阻止保存/发布，并提示“请先将题目保存到题库后再组卷”。前端移除考试建卷弹窗中的内联题入口；后端 `createExam` / `updateExam` 收到 `sourceType=INLINE` 或 `questionId` 为空时返回 40000（HTTP 400），避免绕过页面写入。

编辑历史草稿时若已存在内联题，前端以只读告警项展示题干并提示“该题不支持，请删除后从题库重新选择”，保存按钮保持禁用，直至该题被移除。

#### 7.3.2 题目乱序开关

- 控件：开关（Switch），标签“题目乱序”。
- 默认值：关闭。
- 辅助文案：“开启后，题目顺序按学生生成；同一学生刷新后顺序保持不变。”
- 仅草稿状态可修改；考试发布后不可修改。
- 编辑考试时回显当前配置。

#### 7.3.3 成绩可见性

- 新建考试时，“交卷后立即可见（`IMMEDIATE`）”为默认选中项。
- 教师端下拉本期只保留两项：`IMMEDIATE`（交卷后立即可见）、`AFTER_TEACHER_CONFIRM`（教师确认后可见）。
- 编辑既有考试时，若原值为 `AFTER_DEADLINE` 或 `MANUAL_RELEASE`，下拉回显原值并提示必须改选前两项之一后才能保存；保存请求不会静默改写未改选的旧值。
- 移除当前表单中无效的“提交后可见（AFTER_SUBMIT）”，同时清理 `frontend/src/types/exam.ts` 中后端不存在的 `AFTER_SUBMIT` / `HIDDEN` 取值；`frontend/src/types/homework.ts` 与 `frontend/src/types/lab.ts` 不在本期改动范围。
- 选择 `AFTER_TEACHER_CONFIRM` 时，表单提示“学生交卷后不会立即看到成绩”。
- 当试卷包含主观题且成绩可见性为 `IMMEDIATE` 时，保存前弹出警告“主观题需人工批改，交卷后不会立即出成绩”；警告不阻止保存。
- 后端请求未传 `scoreVisibilityMode` 时，仍按现有默认值 `AFTER_TEACHER_CONFIRM` 处理；通过 API 创建实时出分考试时必须显式传 `IMMEDIATE`。

#### 7.3.4 发布

- 草稿状态可编辑、可删除。
- 发布后学生可在考试列表中看到并开始考试。
- 发布后不可修改题目、分值、乱序开关。

#### 7.3.5 验收标准

- 不勾选乱序时，创建出的考试所有学生顺序一致。
- 勾选乱序时，20 道题、10 名学生的考试至少出现两种题目顺序（学生账号前置见 7.4.4）。
- 保存后再次编辑，开关状态正确回显。
- 发布后开关不可修改。
- 选择格式不兼容的历史判断题时被阻止加入，并显示重新导入提示。
- 不出现“提交后可见”导致的保存失败。
- 含内联题的试卷无法保存或发布，并提示“请先将题目保存到题库后再组卷”。

### FR-4 学生现场考试

#### 7.4.1 开始考试

- 学生从考试列表进入考试详情，点击“开始考试”。
- 开始考试前必须校验学生属于考试班级；非本班学生返回 403。
- 考试题目必须全部为题库题；历史考试存在内联题时拒绝开始，返回 40000“试卷包含不支持的题目，请联系教师”。
- 系统返回截止时间，学生端开始倒计时。
- 同一学生同一场考试仅生成一条提交记录；未提交前可续考，提交后不可重考或重复提交。
- 已提交的考试再次进入时直接展示结果页。

#### 7.4.2 题目顺序

| 考试配置 | 学生看到 |
|---|---|
| 乱序关闭 | 与教师组卷顺序一致 |
| 乱序开启 | 按“学生 ID + 考试 ID”生成的稳定随机顺序 |

稳定性要求：

- 同一学生刷新页面、断线重进、换设备登录，顺序保持一致。
- 不同学生之间顺序按各自种子生成；目标是降低同序概率，不保证任意两名学生顺序必然不同。
- 题目编号按学生实际看到的顺序从 1 开始。
- 答案提交与评分按题目 ID 关联，不依赖题目位置。

#### 7.4.3 作答交互

- 单选：点击选项选中，再次点击取消。
- 多选：点击勾选 / 取消勾选。
- 判断：选择“正确 / 错误”。
- 支持上一题、下一题、题号导航跳转。
- 展示已作答 / 未作答 / 当前题状态。
- 交卷前提示未作答题数。
- 页面保持打开且倒计时归零时，前端自动交卷；页面关闭期间不会自动提交。
- 交卷后答案锁定，不可修改。

#### 7.4.4 验收标准

- 前置：管理员临时创建 9 名学生并加入目标班级，与演示学生合计 10 个账号；20 道题、10 名学生进入同一场开启乱序的考试，至少出现两种题目顺序。
- 同一学生刷新页面后题目顺序不变。
- 未开启乱序时顺序一致。
- 作答内容在交卷时完整提交。
- 页面保持打开时，倒计时归零可自动交卷。
- 重复点击交卷不会产生重复提交。

### FR-5 即时评分与即时成绩

#### 7.5.1 适用范围

- 仅纯客观题试卷支持“交卷即出分”。
- 试卷中存在主观题时，不承诺即时成绩，需教师人工批改后可见。

#### 7.5.2 评分规则

| 题型 | 规则 |
|---|---|
| 单选 | 学生选项与标准答案一致得满分，否则 0 分 |
| 多选 | 默认全匹配得分：选项集合与标准答案完全一致得满分，否则 0 分 |
| 判断 | 学生选择与标准答案一致得满分，否则 0 分 |

#### 7.5.3 成绩可见性

- 仅当试卷为纯客观题且成绩可见性为 `IMMEDIATE` 时，学生端结果页在交卷后立即展示：
  - 总分；
  - 自动评分；
  - 每题得分；
  - 每题对错；
  - 本人答案；
  - 参考答案；
  - 题目解析。
- 非 `IMMEDIATE` 模式下，`submitExam` 接口响应仍按现网返回 `autoScore` / `totalScore`，但学生端页面不展示总分、参考答案与解析。
- 教师端成绩查看不受学生可见性影响。

#### 7.5.4 验收标准

- 在纯客观题且 `IMMEDIATE` 条件下：20 道单选、每题 2 分，全对得 40 分。
- 多选少选、错选均为 0 分。
- 判断题正确 / 错误均能正确判分。
- 交卷后结果页立即显示总分，无需教师操作。
- 教师成绩页显示全班成绩与逐题得分。

### FR-6 学生查看答案解析

#### 7.6.1 展示条件

- 展示条件：学生提交存在且 `canStudentSeeScore(exam, submission)` 为 `true`；`IMMEDIATE` 模式下即交卷后立即展示。
- 解析来源：题库题读取 `QuestionBank.analysisText`；解析为空字符串时显示“暂无解析”。
- 每题展示：
  - 本人答案；
  - 参考答案；
  - 题目解析；
  - 得分 / 满分；
  - 对错。

#### 7.6.2 解析缺失

- 题目未填写解析或解析为空字符串时，展示“暂无解析”，不阻塞考试与评分。

#### 7.6.3 验收标准

- 导入时填写解析的题目，学生结果页可见解析。
- 未填写解析的题目，学生端显示“暂无解析”。
- 教师端仍可查看解析。

### FR-7 教师查看成绩

- 教师可在考试详情中查看：
  - 参考人数、提交人数；
  - 每名学生总分、状态、提交时间；
  - 每名学生的逐题作答、得分、对错。
- 纯客观题试卷提交后即有成绩，无需人工确认。
- 教师端题目顺序仍按组卷顺序展示；学生端题号可能因乱序不同。

#### 验收标准

- 教师能看到所有已提交学生的成绩。
- 点击学生可查看逐题结果。
- 成绩与学生在结果页看到的一致（学生可见时）。

### FR-8 题目乱序

#### 7.8.1 配置

- 考试新增布尔字段“题目乱序”，默认 `false`。
- 建卷时可设置，编辑草稿时可修改，发布后锁定。
- 前端读取 `shuffleQuestions` 时按 `=== true` 判定；字段缺失视为关闭，兼容旧响应。

#### 7.8.2 生成规则

- 基准顺序：始终按 `sortOrder` 升序排列后再洗牌，不依赖接口返回顺序。
- 随机种子：字符串 `${studentId}:${examId}`，用 FNV-1a 生成 32 位整数种子。
- 伪随机数源：`mulberry32(seed)`，用 Fisher-Yates 生成排列。
- 仅重排题目顺序，不修改题目 ID、答案、分值。
- 不改变选项顺序。

#### 7.8.3 边界

- 单题考试：顺序无变化。
- 学生重复进入：顺序不变。
- 同一天多次进入：顺序不变。
- 不同考试：即使学生相同，种子也不同；不保证排列必然不同。
- 考试发布后：乱序配置锁定，学生端只读取该配置。

#### 验收标准

- 20 道题、10 名学生参加同一场开启乱序的考试，至少存在两种不同顺序（账号前置见 7.4.4）。
- 同一学生连续刷新 3 次，顺序完全一致。
- 关闭乱序的考试，10 名学生顺序完全一致。
- 乱序后评分结果与不开启乱序时一致。

## 10. 非功能需求

- 支持 Chrome、Edge 最新版本。
- 桌面端为主要验收环境。
- 学生端移动端布局可用性不作为本期验收项。

### 10.4 数据一致性

- 乱序只影响展示顺序，不影响答案存储、评分与统计。
- 导入过程中若部分题目失败，已成功题目保留，结果页明确列出失败项。
- 重复编码不产生覆盖或重复写入；仅大小写不同的编码同样不产生重复写入。

## 11. 异常与边界场景

| 场景 | 预期行为 |
|---|---|
| 导入文件为空 | 提示“导入文件为空” |
| JSON 语法错误 | 提示具体解析错误位置，禁止导入 |
| 根节点不是 wrapper 对象 | 提示“导入文件必须是包含 formatVersion 与 questions 的 JSON 对象，请下载规范示例” |
| 题目字段缺失 | 预览标红并给出缺失字段 |
| 答案 key 不在选项中 | 预览标红，禁止导入 |
| 单选题多个答案 | 预览标红，禁止导入 |
| 判断题使用 true / false | 校验失败，提示使用 T / F |
| 编码重复（题库已有） | 标记跳过，不计入错误 |
| 编码在 JSON 内重复 | 后续重复项标记跳过 |
| 编码仅大小写不同 | 转大写后比较，视为重复，标记跳过 |
| 导入进行中重复点击或关闭弹窗 | 按钮与关闭操作禁用，直到本轮导入结束 |
| 导入中网络中断 | 中断后展示已完成结果，可重试失败项 |
| 考试未发布 | 学生考试列表中不可开始 |
| 学生不在班级 | 无法开始考试 |
| 考试已提交 | 再次进入直接显示结果 |
| 页面打开且倒计时结束 | 前端自动交卷并进入结果页 |
| 页面关闭期间倒计时结束 | 不自动提交；下次进入时若已超时，前端倒计时归零会立即交卷（答案可能为空） |
| 未开启乱序 | 所有学生顺序一致 |
| 题目未填写解析 | 学生端显示“暂无解析” |
| 成绩可见性非“立即可见” | 学生端页面不展示总分、参考答案与解析，提示等待教师确认；对错标记沿用现网行为 |
| 试卷包含内联题 | 阻止保存/发布，提示“请先将题目保存到题库后再组卷”；后端返回 40000 |
| 历史考试含内联题 | 学生端开始考试返回 40000，提示“试卷包含不支持的题目，请联系教师”；教师端查看不受影响 |

## 13. 现状差距与改造点

| 差距 | 现状 | 改造方向 |
|---|---|---|
| 学生端无解析 | 后端仅向教师返回 `analysisText` | 学生详情在学生成绩可见时返回解析；结果页增加解析区块 |
| 无批量导入 | 后端仅支持单题新增 | 前端增加文件上传、解析、校验、预览、循环提交 |
| 无题目乱序 | 所有学生按 `sort_order` 展示 | 新增考试开关字段、迁移、建卷表单、学生端确定性洗牌 |
| 成绩可见性无效选项 | 教师端存在后端不支持的 `AFTER_SUBMIT`，前端类型还含 `HIDDEN` | 删除 `AFTER_SUBMIT` 选项；前端类型对齐后端四个枚举值 |
| 纯客观题默认不出分 | 默认“教师确认后可见”，客观题不进入已批改状态 | 建卷时默认“交卷后立即可见”，并提示 |
| 内联题无稳定身份 | 内联题 `questionId` 为空，多题答案互相覆盖，交卷写库必然失败 | 考试侧阻断：前端移除入口并阻断保存，后端 `createExam` / `updateExam` 拒绝 `INLINE`（40000）；历史含内联题的考试只读；作业模块另议 |
| 判断题格式不统一 | 历史数据存在 true / false 字符串选项（解析后 key 为 A / B），学生作答必然判错 | 导入规范固定 T / F；组卷时校验判断题格式，不兼容题目禁止加入并提示重新导入 |
| 编码大小写跨库不一致 | MySQL 默认排序规则大小写不敏感、H2 敏感；同一编码仅大小写不同时预览与入库结果可能不一致 | 后端 `create` / `update` 统一 `trim` + 转大写，前端预检使用同一规则 |

## 14. 风险与后续迭代

### 14.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 考试中刷新页面丢失未提交答案 | 学生需重新作答；若已超时，重进会立即自动交卷并可能提交空卷 | 本期不改，考试须知中提示勿刷新、保持页面打开；后续增加草稿保存 |
| 教师端与学生端题号不一致 | 讲评时对照不便 | 按题干对照；后续可记录学生题序 |
| 单条导入无事务 | 网络中断导致部分成功 | 结果页列出失败项并支持重试 |
| 无防作弊能力 | 现场仍需人工监考 | 本期依靠现场监考 |
| 内联题历史数据 | 历史草稿若含内联题无法保存修改；已发布含内联题的考试学生端无法开始 | 教师需改为题库题后重新保存/发布；历史成绩与详情仍可查看；本期不做数据迁移 |
| 乱序仅前端实现 | 接口中仍返回原始顺序 | 学生无法通过正常界面看到原始顺序，风险可接受 |
| 洗牌算法变更 | 历史场次重算后的题序与当时不一致，讲评与复核难以对号 | 种子公式与算法视为冻结契约；确需变更时新增 `shuffle_version` 字段，按版本分派算法 |

## 15. 附录：现场操作示例

### 15.1 教师登录获取 Token

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"t9001","password":"123456","role":"TEACHER"}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')
```

### 15.2 通过 API 单题导入

```bash
curl -s -X POST http://localhost:8080/api/v1/questions \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "code": "LINUX-OS-001",
    "type": "SINGLE",
    "stem": "Linux 中用于显示当前工作目录的命令是？",
    "difficulty": "EASY",
    "optionsJson": "[{\"key\":\"A\",\"content\":\"pwd\"},{\"key\":\"B\",\"content\":\"cd\"},{\"key\":\"C\",\"content\":\"ls\"},{\"key\":\"D\",\"content\":\"cat\"}]",
    "answerJson": "[\"A\"]",
    "analysisText": "pwd 用于打印当前工作目录。"
  }'
```

### 15.3 创建考试

```bash
curl -s -X POST http://localhost:8080/api/v1/exams \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Linux 操作系统基础随堂测验",
    "description": "闭卷，单选题 20 道，每题 2 分。",
    "classId": 1,
    "durationMinutes": 30,
    "status": "DRAFT",
    "scoreVisibilityMode": "IMMEDIATE",
    "shuffleQuestions": true,
    "questions": [
      {"questionId": 101, "sourceType": "BANK", "sortOrder": 1, "questionScore": 2},
      {"questionId": 102, "sourceType": "BANK", "sortOrder": 2, "questionScore": 2}
    ]
  }'
```

创建后通过发布接口将考试状态切换为已发布：

```bash
curl -s -X POST http://localhost:8080/api/v1/teacher/exams/1/status \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"status":"PUBLISHED"}'
```
