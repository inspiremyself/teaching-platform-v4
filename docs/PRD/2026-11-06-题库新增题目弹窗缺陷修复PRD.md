## 1. 文档信息

| 项 | 内容 |
|---|---|
| 文档版本 | V1.1（经 4 轮自查收敛） |
| 编写日期 | 2026-11-06 |
| 状态 | 已定稿（决策写死，可直接进入技术方案） |
| 关联系统 | teaching-platform（教师端题库页 / 共享题目编辑器 / 考试与作业题目配置） |
| 适用读者 | 产品、前端、后端、测试、授课教师 |

### 1.1 已定决策清单

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| D1 | 校验提示展示时机 | 弹窗首次打开、用户尚未交互时**不渲染**错误面板；用户修改过任一字段或点击过提交后，面板才展示并随输入实时更新。字段校验规则本身不变 |
| D2 | 保存失败时的草稿 | 保存失败（如编码冲突、后端 4xx/5xx）后，弹窗内已填的题干、选项、答案、解析**必须原样保留**，禁止被重新 hydrate 覆盖 |
| D3 | 题库是否支持“代码题” | 题库题型的唯一集合为 `SINGLE / MULTI / JUDGE / FILL / SHORT`，移除“代码题”。`CODE` 仅保留在实验步骤域 |
| D4 | 题型持久化口径 | 题型枚举与落库值一一对应，删除 `CODE → SHORT` 的静默映射；保存什么题型、列表与再次编辑就展示什么题型 |
| D5 | 切换题型时的草稿处理 | 切换题型不做静默截断：多选多个答案切到单选时清空答案并提示重选。其余跨题型族切换保留各自答案草稿（判断题答案、填空答案、主观题答案），切回可继续编辑；任何时刻只序列化当前题型的答案结构 |
| D6 | 自动编码生成时机 | 编码在弹窗打开（或题型变化）时生成并锁定，**展示什么就存什么**，提交时不再重算；格式追加 4 位随机位消除同秒冲突。编码冲突返回 40900 时提示教师重新提交，下次提交重新生成 |
| D7 | 填空题重排 | 填空位重排必须一次性重建题干，保证“答案跟着填空位走”；不得因字符串首匹配替换导致答案错位 |
| D8 | 死代码 | `useTypedEditor` 中未被任何调用方使用的 `resetStructuredState` 在本次改造中**删除**，清理逻辑内联进 `setKind`，不留悬挂导出 |
| D9 | 数据库变更 | 本期不新增 Flyway 迁移、不修改表结构、不写历史数据修复脚本 |
| D10 | 后端枚举校验 | 本期不给 `question_bank.type` 增加后端白名单校验，避免影响存量数据；题型收敛只在前端入口完成 |
| D11 | 改动边界 | 只改题库新增/编辑弹窗与其复用方；题库列表、筛选、批量导入、删除链路不改 |
| D12 | 弹窗文案 | 弹窗副标题不得写死“由 Questions.vue 组装”，改为与使用方解耦的中性描述，因该弹窗同时被考试页与作业页复用。展开见 FR-7 |
| D13 | 题型收敛的影响面 | `QUESTION_TYPED_EDITOR_KIND_OPTIONS` 为题库、考试、作业三处共享常量，移除“代码题”后在**三处同时生效**；作业内联题与考试内联题同步不再提供代码题，不接受“只改题库页”的局部实现 |
| D14 | 编码时区与编辑态 | 编码时间戳使用**本地时区**（现状为 UTC，比北京时间慢 8 小时，需纠正）；编辑已有题目时沿用原编码，不生成新编码 |

## 2. 背景与问题定位

### 2.1 背景

教师端题库页（`frontend/src/views/teacher/Questions.vue`）点击“新增题目”打开共享弹窗（`frontend/src/components/question-config/QuestionEditorDialog.vue`）。该弹窗复用 typed-editor 能力维护题干、结构化答案与资产字段。

现状存在四类问题：一打开就满屏报错；保存失败会清空已填内容；选“代码题”保存后变成“简答题”；自动编码与填空题重排存在边界缺陷。其中“保存失败清空内容”会造成教师重复劳动与数据丢失，优先级最高。

### 2.2 复核结论与根因

| 编号 | 现象 | 根因 |
|---|---|---|
| P1 | 弹窗刚打开、一个字都没填，就显示 4 条红色“保存前请补齐” | `useTypedEditor.validationMessages` 对空表单恒产出 4 条消息；`TypedEditorShell` 以 `v-if="messages.length"` 无条件渲染，没有“是否已交互/是否尝试提交”的门控 |
| P2 | 保存失败后，已填的选项文案、正确答案、判断题答案、参考答案被清空 | `QuestionEditorDialog` 的 `watch([visible, initialQuestion])` 把页面侧的 `initialQuestion` 计算对象也纳入监听；`Questions.vue` 在 `submit()` 中先回写 `form.stem/type/...`，触发 `currentEditorQuestion` 重算，弹窗随即重新 `hydrateEditor`，用页面状态覆盖用户草稿 |
| P3 | 题型下拉有“代码题”，保存后列表显示“简答题”，再次编辑也显示“简答题” | `questionAdapter.serializeQuestionType` 把 `CODE` 强制映射为 `SHORT`；题型选项集合 `QUESTION_TYPED_EDITOR_KIND_OPTIONS` 却包含 `CODE`，形成“可选但不可存”的契约矛盾 |
| P4 | 同一秒内连续保存两道题，第二次提示“题目编码已存在” | 自动编码 `Q-{类型前3位}-{yyMMddHHmmss}` 精度到秒且全局唯一，无随机位、无冲突兜底 |
| P5 | 手动调整填空位编号顺序后，答案与空位错配 | `syncFillBlanks` 用 `String.replace` 逐个替换 token，替换的是首个匹配项；当题干 token 顺序与编号顺序不一致时，会把刚改名的 token 再次命中，导致答案整体错位 |
| P6 | 多选已选 3 项后切到单选，只保留 1 项；再切回多选也无法恢复，且无任何提示 | `setKind` 用 `slice(0, 1)` 静默截断多选答案，教师无法感知答案已被丢弃 |
| P7 | `resetStructuredState` 无任何调用方 | 历史重构遗留，职责应落在 `setKind`，当前为死代码 |
| P8 | 编码中的时间戳比教师本地时间慢 8 小时 | `buildQuestionCode` 使用 `new Date().toISOString()`，取的是 UTC 时间，未做本地时区格式化 |

### 2.3 复核后剔除的误报

上一版口头评估中的两条结论经代码复核不成立，本期不作为缺陷：

- “单选可保存多个正确答案”：`setKind('JUDGE')` 会清空 `selectedObjectiveOptionIds`，`setKind('SINGLE')` 会截断为 1，`toggleObjectiveAnswer` 在单选下只保留 1 项，全链路不存在多答案写入单选的路径。
- “正确答案可挂在空白选项上”：校验包含 `filledOptions.length !== objectiveOptions.length` 时提示“请补全所有选项内容”，任一选项为空即阻止提交。

## 3. 目标与成功标准

### 3.1 目标

1. 弹窗打开即为干净、无噪声的空白表单，只有真正需要提示时才出现校验面板。
2. 任何保存失败都不丢用户已填内容。
3. 题型枚举、保存值、列表展示、再次编辑四者完全一致。
4. 自动编码不再出现无解的冲突死路。
5. 填空题答案与填空位严格一一对应。
6. 清理题型切换与死代码造成的隐性状态残留。

### 3.2 成功标准

- 打开“新增题目”：无红色提示；填写题干后若仍有缺失项，面板才出现且内容随输入减少。
- 用已存在的编码保存失败：弹窗保持打开，题干、选项、正确答案、解析与失败前完全一致。
- 题型下拉不存在“代码题”；任一已保存题目的题型在列表与再编辑时均与保存时一致。
- 连续创建两道题不出现“编码已存在”死路。
- 填空题调整 token 顺序后，每个空的答案仍对应原空位。
- 多选切单选有明确提示，不再静默丢答案。

## 5. 术语

| 术语 | 定义 |
|---|---|
| 草稿 | 弹窗内当前正在编辑、尚未成功保存的题目内容 |
| hydrate | 用外部题目对象初始化弹窗内部 `typedEditor.draft` 的过程 |
| 题型族 | 客观选择（单选/多选）、判断、填空、主观（简答）四类互斥答案结构 |

## 6. 核心流程

### 6.1 新增题目（成功）

1. 教师点击“新增题目”，弹窗打开，表单为空白默认态（单选、基础、5 分、4 个空选项）。
2. 教师填写题型、难度、分值、题干、解析与结构化答案。
3. 点击“创建题目”，若存在缺失项，校验面板展示并中止提交，已填内容不变。
4. 校验通过，提交时生成唯一编码并创建成功，弹窗关闭、列表刷新。

### 6.2 新增题目（保存失败）

1. 教师完成填写并点击“创建题目”。
2. 后端返回业务错误（如编码已存在、参数校验失败）。
3. 弹窗保持打开，错误以消息提示呈现，草稿内容原样保留。
4. 教师修正后再次提交，不需要重新录入。

### 6.3 编辑题目

1. 教师在列表点击编辑，弹窗按该题当前题型、选项、答案、解析完成初始化。
2. 教师修改后保存，列表展示与再次编辑均反映最新结果。

## 7. 功能需求

### FR-1 校验提示门控

#### 7.1.1 展示规则

- 弹窗打开后的初始状态：不渲染校验面板，即使 `validationMessages` 非空。
- 满足任一条件后允许展示面板：用户修改过题型、题干、选项、答案、解析中任一字段；或点击过提交按钮。
- 面板展示后随输入实时更新，缺失项全部补齐时面板自动消失。
- 移除一条校验项时不得整块闪烁重建。

#### 7.1.2 不变项

- 校验规则与文案沿用现状：题干非空、客观题至少 2 个有效选项、选项内容需补全、单选/多选需设置答案、判断题需设置答案、填空题至少一个填空位且每空有答案、主观题需填写参考答案。
- 提交时仍按现有方式对首条缺失项做消息提示。

#### 7.1.3 验收标准

- 全新打开新增弹窗：不出现“保存前请补齐以下内容”。
- 仅填写题干后：面板出现，且不再提示“请填写题干内容”。
- 补齐全部必填项后：面板消失，“创建题目”可成功保存。
- 编辑已有完整题目打开时：面板不出现。

---

### FR-2 保存失败保留草稿

#### 7.2.1 初始化时机

- 弹窗草稿只允许在以下时机被初始化/覆盖：
  1. `visible` 由 `false` 变为 `true`；
  2. 同一次打开过程中，编辑目标发生变化（编辑题目 id 变化）。
- 页面侧的资产字段（编码、难度、分值、解析）变化**不得**触发弹窗重新初始化。
- `Questions.vue` 提交前回写页面 `form.*` 的行为不得影响弹窗草稿。

#### 7.2.2 失败处理

- 保存请求失败时，弹窗保持打开，不关闭、不清空、不重置任何输入。
- 失败提示沿用统一请求层的错误消息，不新增二次弹窗。
- 失败后按钮恢复可点击，允许直接重试。

#### 7.2.3 验收标准

- 使用已存在编码创建题目：提示编码已存在，弹窗内题干、4 个选项文案、已选正确答案、解析与提交前一致。
- 上述失败后直接改用新编码可一次保存成功。
- 编辑题目时保存失败：弹窗内容保持本次编辑值，不回退为上次保存值。
- 成功保存后重新打开新增弹窗：表单为干净默认态。

### FR-3 题型集合收敛

#### 7.3.1 题型清单

| 题型值 | 展示名 | 是否在题库下拉 |
|---|---|---|
| `SINGLE` | 单选题 | 是 |
| `MULTI` | 多选题 | 是 |
| `JUDGE` | 判断题 | 是 |
| `FILL` | 填空题 | 是 |
| `SHORT` | 简答题 | 是 |
| `CODE` | 代码题 | **否** |

- 题库题型下拉、题目挑选弹窗的题型筛选、前端 `QuestionType` 类型联合，三者同步移除 `CODE`。
- 该下拉选项来自共享常量 `QUESTION_TYPED_EDITOR_KIND_OPTIONS`，被题库、考试内联题、作业内联题三处共同使用；本次收敛对三处同时生效（D13），不得只改题库页入口。
- `TYPED_EDITOR_LABELS` 保留 `CODE` 文案，因实验步骤域仍在用。
- 自动编码的类型前缀只服务上述五类题型。
- `Questions.vue` 的题型归一函数不得再把 `CODE` 透传为可持久化类型；移除后若存在不可达分支，一并删除。

#### 7.3.2 持久化

- 删除 `CODE → SHORT` 映射，题型按编辑器选中值原样提交。
- 前端不再存在“选了代码题、存成简答题”的分支。
- 后端 `question_bank.type` 仍按字符串存储，本期不加枚举白名单（D10）。

#### 7.3.3 验收标准

- 题型下拉共 5 项，不含“代码题”。
- 题目挑选弹窗的题型筛选不含“代码题”。
- 考试页、作业页通过共享弹窗新增内联题时，题型下拉同样不含“代码题”。
- 新建单选题保存后，列表题型、再次编辑题型均为“单选题”。
- 已存在的 `SHORT` 题目再次编辑仍为“简答题”，不受影响。

### FR-4 题型切换草稿清理

#### 7.4.1 保留规则

- 单选 ↔ 多选：保留 `objectiveOptions` 的选项文案与选项键。
- 任意题型切换：保留题干原文与教师解析，不自动删除题干中的填空占位符。

#### 7.4.2 清理规则

统一原则：**所有题型的答案草稿默认保留，仅一处例外需清空并提示。**

- 唯一清空场景：由 `MULTI` 切到 `SINGLE` 且原选中数大于 1 时，清空 `selectedObjectiveOptionIds`，并提示“已切换为单选题，请重新选择正确答案”。
- 切到 `MULTI` 时保留已有选中项（1 项合法）。
- 切到 `JUDGE` 时**不清空** `selectedObjectiveOptionIds`，保留 `judgeAnswer`；切回单选/多选时原选择仍可用。
- 切到 `FILL` 时按题干重新同步填空位；离开填空题型时保留填空答案，供切回时复用。
- 切到 `SHORT` 时保留 `subjectiveAnswer`。
- 任一时刻只序列化当前题型对应的答案结构，其余题型的草稿数据不得进入提交载荷（现状已满足，需回归确认）。

#### 7.4.3 死代码

- **删除** `resetStructuredState` 函数及其导出，清理逻辑直接写在 `setKind` 中，避免出现“名为清理、实为死代码”的实现。

#### 7.4.4 验收标准

- 多选勾选 3 项后切到单选：3 项全部取消，出现切换提示；再切回多选仍为未选中状态。
- 单选选中 1 项 → 切判断题 → 切回单选：原选项仍为选中状态。
- 判断题选“正确”→切简答题→切回判断题：判断答案仍为“正确”。
- 单选填好 4 个选项后切判断题：判断提交载荷中不包含选项 JSON 的业务含义（判断题固定 T/F 选项）。
- 全仓不存在对 `resetStructuredState` 的引用或导出。

---

### FR-5 自动编码唯一性

#### 7.5.1 生成规则

- 编码在弹窗打开时生成一次并锁定；题型变化时重新生成。锁定后再提交，编码不再变化。
- 编辑已有题目时**沿用原编码**，不重新生成，预览与保存值均为原编码。
- 格式：`Q-{题型前3位大写}-{yyMMddHHmmss}{4位随机base36}`，随机位用于消除同秒冲突。
- 时间戳必须使用教师本地时区（`yyMMddHHmmss` 为本地时间），现状 `toISOString()` 的 UTC 口径需纠正（D14）。
- 弹窗顶部预览值与提交落库值必须完全一致，不允许提交时静默改码。
- 教师不提供编码输入框，编码不可人工编辑（现状保持）。

#### 7.5.2 冲突处理

- 后端返回 40900（题目编码已存在）时，展示业务错误消息，保留草稿；教师再次点击提交时重新生成编码。
- 不实现“自动无限重试”，避免掩盖真实故障。

#### 7.5.3 验收标准

- 连续快速创建两道题目，均保存成功，编码不相同。
- 打开弹窗后停留数分钟再提交，落库编码与弹窗展示完全一致。
- 编码中的时间戳与教师本地时间一致，不出现 8 小时偏移。
- 编辑已有题目并保存，编码保持不变。
- 构造编码冲突时提示明确，草稿不丢失；再次提交可成功。

---

### FR-6 填空位重排正确性

#### 7.6.1 规则

- 题干中每个填空位以出现顺序形成 1..N 的展示编号。
- 答案始终绑定“该空位”，而不是绑定编号数字。
- 重排必须一次性生成新题干与新填空位列表，禁止在循环中做逐次字符串替换。
- 删除中间空位后，其后空位编号顺延，答案随之顺延，不丢失。
- 题干中存在重复编号或乱序编号时，按出现顺序重排且答案不错位。

#### 7.6.2 验收标准

- 三空题干删除第 2 空：剩余两空答案分别为原第 1、第 3 空答案。
- 手动把 `【填空2】` 放在 `【填空1】` 之前：重排后两空答案仍对应各自文本位置。
- 重复出现 `【填空1】` 两次：重排为两个空位，答案互不串位。

---

### FR-7 弹窗文案与复用一致性

#### 7.7.1 规则

- 弹窗默认副标题改为中性描述，例如“先选择题型并维护题干与结构化答案，保存时自动生成题目编码”；不得出现任何调用方文件名（如 `Questions.vue`）。
- 新增态标题为“新增题目资产”，编辑态标题为“编辑题目资产”，不随调用方变化。
- 调用方显式传入说明文案时以传入值为准，但文案中不得包含调用方文件名。
- 编码预览标签统一为“系统自动生成编码”，避免与“打开时生成并锁定”的语义冲突；不得继续使用“提交时自动生成编码”。

#### 7.7.2 验收标准

- 题库页、考试页、作业页三处打开弹窗，副标题均不含 `Questions.vue` 等文件名。
- 三处标题与新增/编辑状态对应正确。
- 编码预览标签在创建态与编辑态表现一致：创建态展示待保存编码，编辑态展示原编码，标签文案为“系统自动生成编码”。

## 8. 业务规则汇总

| 编号 | 规则 |
|---|---|
| BR-1 | 未交互的空白表单不展示校验面板，避免噪声 |
| BR-2 | 保存失败不丢弃草稿，任何失败路径都保持弹窗内容 |
| BR-3 | 题库题型仅五类，题型值与落库值一一对应 |
| BR-4 | 编码在打开时生成并锁定，使用教师本地时间，同秒创建不冲突；编辑态沿用原编码 |
| BR-5 | 题型切换不做静默截断：多选多答案切单选时清空并提示重选；其余题型答案草稿保留但不参与当前题型序列化 |
| BR-6 | 填空答案绑定空位而非编号 |
| BR-7 | 弹窗只序列化当前题型的答案结构 |
| BR-8 | 本期无数据库迁移、无后端校验规则变更 |

## 10. 非功能需求

### 10.1 性能

- 校验门控只增加本地布尔状态，不引入额外请求。
- 填空位重排为一次线性扫描，不改变输入响应性能。

### 10.2 权限与安全

- 仍只允许教师维护自己创建的题目，沿用 `CurrentUser` 与 `createdBy` 约束。
- 不改变任何角色边界。

### 10.3 兼容性

- 存量题型数据（含 `SHORT`）可正常展示与编辑。
- 考试页、作业页复用同一弹窗的保存链路不受题型收敛影响。
- 实验步骤域的 `CODE` 题型与代码编辑器不受影响。

### 10.4 可维护性

- 编码生成逻辑只保留一份实现，不在页面与弹窗中各写一套。
- 弹窗文案与调用方解耦，避免复用方出现错误描述。

## 13. 现状差距与改造点

| 差距 | 现状 | 改造方向 |
|---|---|---|

## 14. 风险与后续迭代

### 14.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 移除“代码题”入口 | 熟悉旧入口的教师找不到该选项 | 题库域本就不存在代码题落库能力，移除是消除误导；实验步骤域仍可配置代码题 |
| 存量 `CODE` 数据（理论不可通过 UI 产生） | 若存在脏数据，编辑时题型回退为单选 | 本期不做数据修复；如出现可在后续单独排查 |
| 题型切换清空规则 | 教师需重新选择答案 | 有明确提示，优于静默丢数据 |
| 编码随机位 | 人工识别编码时不再严格连续 | 随机位仅 4 位，保留可读前缀 |

### 14.2 后续迭代

- 题库编码改为可人工自定义（需后端唯一性校验与编辑入口）。
- 弹窗内字段级错误定位（滚动到首个缺失项）。
- 题库列表分页后，编辑弹窗选项改为按 id 单题拉取，降低对列表全量数据的依赖。
