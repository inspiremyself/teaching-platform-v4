## 6. 口径与核心流程

### 6.1 教师批改（新主链路）

1. 实验台账某行点「查看结果」→ `/teacher/labs/:labId/submission-overview`。
2. 三栏结果页拉 `listTeacherLabReportQueue()`，前端按 `labId` 过滤；队列为空走 D9 空态。
3. 默认选中队列首项（或 URL `?submissionId` 指定项），中栏加载详情与逐题作答。
4. 点队列其他学生在当前页内切换；有未保存草稿先弹「当前评分尚未保存，确定切换吗？」；过期响应由 `selectionToken` 丢弃。
5. 右栏提交评分（整卷）；中栏逐题确认分；页头可打回 / 批量批改 / 新标签打开纯报告。
6. 页头「班级总览」→ `/teacher/labs/:labId/matrix`；矩阵「批改报告」带 `submissionId` query 回三栏并选中该生。

### 6.2 保留的次级路径

- 学生名 →「历次提交」→「查看报告」→ 评分台 `/teacher/lab-reports/:id`（11-17 D7 明确保留，不变）。
- 题列 →「子题答案墙」→ `/teacher/labs/:labId/items/:itemId/answers`（不变）。

## 14. 风险与后续迭代

### 14.1 风险

- **重复评分实现**：新三栏页与评分台都有逐题评分逻辑，若复制实现会导致口径漂移；由 D5「复用现网评分语义」与配套技术方案写死共享落点兜底。
- **全量队列体量**：前端按 `labId` 过滤需先拉教师全量队列；现网评分台已如此调用，本次不新增请求量，但需在技术方案确认复用同一请求而非双拉。
- **路由语义漂移**：`/teacher/labs/:labId/submission-overview` 从矩阵变三栏，旧书签用户需通过页头进入矩阵；由 D1/D2 与 §10.1 明确告知。
- **矩阵操作列拥挤**：「批改报告」改带参跳转后仍需保留「实验报告」与两个下钻入口；由 D8 写死按钮行为，不新增按钮。

### 14.2 后续迭代

- 评分台 `/teacher/lab-reports/:id` 与新三栏页的关系收敛（是否让评分台重定向到三栏），需另立 PRD；本期保留双入口。
- 三栏选中态 URL 同步（刷新恢复选中学生），需另立 PRD；本期明确为非目标。
