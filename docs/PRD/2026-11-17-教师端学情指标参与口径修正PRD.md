## 2. 背景与现网基线（2026-11-17 实测）

### 2.1 调研结论

三类任务的学生记录都是**惰性创建**，发布时不批量生成：

| 任务 | 记录创建点 | 证据 |
|---|---|---|
| 实验 | 学生首次保存答案 | `lab/service/LabAnswerService.ensureEditableSubmission()` → `LabSubmissionClaimService.claim()`（`REQUIRES_NEW` + 唯一键查重）；`LabConfigService.changeLabStatus()` 只改状态 |
| 考试 | 学生点「开始考试」 | `exam/controller/ExamController` `POST /exams/{id}/start` → `ExamAnswerService.startExam()` 建 `ExamSubmission(IN_PROGRESS)`；`ExamConfigService` 发布只改状态 |
| 作业 | 学生首次提交答案 | `HomeworkAnswerService` → `HomeworkSubmissionClaimService.claim()`；学生侧无 start 端点 |

**结论：该设计合理，不改为发布时预建行**（避免幽灵数据与行数膨胀、兼容发布后入班学生、语义清晰）。问题在统计侧：教师端只数已有提交行，无行学生在教师视角中不存在。

### 2.2 现网统计事实与代码证据

| 编号 | 事实 | 证据 |
|---|---|---|
| N1 | 教师看板指标基于已有记录行，`sectionComparison` 的 `gradedCount` 是「评分记录数」，可作分布参考但不能当完成率 | `analysis/service/AnalysisService.getDashboard()` L36–L76、`getTeacherOverview()` L97–L111；前端 `views/teacher/Analysis.vue:149` 已写「{{ item.gradedCount }} 条评分记录」 |

| N3 | 实验教师总览已按「全体班级成员 × 提交行」对账，无提交学生可见（`submitStatus = null`） | `lab/service/LabReportService.getSubmissionOverview()` L478–L527，`classMemberRepository.findByClassId(lab.getClassId())` + `submissionByStudentId` |

### 2.3 影响面

- **教师无法得出完成率**：分母（应参加人数）在教师侧完全缺失，跨班级 `gradedCount` 不可横向比较。
- **未参与学生不可见**：考试 / 作业报表只列已有提交行，教师无法对「从未打开」的学生催办；实验虽可见，但口径与另两类不统一。
- **指标口径不一致风险**：学生端已有完成进度（按 `class_member` 分母），教师端若继续只看提交行，会出现「学生端显示未完成、教师端查无此人」的割裂。

## 5. 术语

| 术语 | 含义 |
|---|---|
| 应参加人次 | 活动 × 班级成员对账后的学生人次，去重键 `(businessType, businessId, studentUserId)`；不按活动开启时间或学生加入时间过滤 |
| 已参与 | 有提交行，含 `SAVED` / `IN_PROGRESS` 等未终结状态 |
| 已完成 | 实验 / 作业 `SUBMITTED` 或 `GRADED`；考试 `SUBMITTED` / `AUTO_SUBMITTED` / `GRADED` |
| 未开始 | 无提交行；不表示学生「打开过页面」，只表示未产生任何提交行 |
| 参与率 | 已参与人次 ÷ 应参加人次，分母为 0 时为 `0.0` |
| 完成率 | 已完成人次 ÷ 应参加人次，分母为 0 时为 `0.0` |
| 惰性创建 | 学生首次作答 / 开始 / 提交时才写提交行的现行设计 |

## 6. 口径与核心流程

### 6.1 汇总指标计算（教师进入分析页）

1. 取当前教师 `teacherId` / `schoolId`。
2. 按业务类型分别取 `status IN ('PUBLISHED','CLOSED') AND created_by = ? AND school_id = ?` 的活动。
3. 每个活动按 `class_id` 展开 `class_member`，得到应参加人次（去重）。
4. `LEFT JOIN` 对应提交表，按 D3 判定参与与完成状态。
5. 每个活动单独累加得到 `expectedCount` / `participatedCount` / `completedCount` / `notStartedCount`，按 D4 计算比率，作为该类 `activities[]` 的一项；`activities[]` 按活动创建时间倒序，`businessId` 按 FR-1 写死取对应活动主键。
6. 三类分别把 `activities[]` 各项累加得到该类 `expectedCount` / `participatedCount` / `completedCount` / `notStartedCount` 与按 D4 计算的比率，组装 `participationOverview` 的对应行。
7. `notStartedCount`（三类合计）追加为工作台第 5 张卡片。
8. 全程只读；不写任何表，不触发提交行创建。

### 6.2 未开始名单查看（教师点击某活动）

1. 前端按 `businessType + businessId` 调用 D7 端点。
2. 后端依次校验类型、活动存在 / 本校、创建人、任课关系（D9）。
3. 按活动 `class_id` 取 `class_member` 全员，`LEFT JOIN` 提交行，按 D3 / D8 组装 `students[]`，按学号升序。
4. 前端在弹层展示名单；无提交行的学生显示「未开始」且 `submissionId` 为空，不提供批改入口。

### 6.3 学生无感知

学生端接口、页面与提交行为零改动；学生仍按现行规则首次保存 / 开始 / 提交时创建记录。

## 10. 非功能需求

### 10.1 性能

- 汇总最多按三类活动批量聚合，禁止逐学生 / 逐活动 N+1 查询；单次请求查询次数由配套技术方案写死上限。
- 名单端点单次返回该活动全体成员，不分页（沿用实验总览现行规模），禁止在循环中访问数据库。

### 10.2 权限与安全

- 新端点必须校验创建人、学校与任课关系；`CurrentUser` 是唯一身份来源，不信任请求参数中的 `teacherId` / `schoolId`。
- 名单只返回教学必需字段，不返回邮箱 / 手机号等敏感信息。

### 10.3 兼容性

- H2（UT / 路径 B）与 MySQL（local）双方言均可执行；汇总 SQL 不依赖方言专有函数（遵循 `AnalysisService` 现有「Java 内聚合」惯例）。
- 前端既有卡片 / 图表在新增字段后行为不变；`summaryIcons` 按索引取模循环，新增第 5 张卡片可复用现有图标。

### 10.4 数据一致性

- 统计为实时查询，不缓存、不落快照；学生首次提交后教师刷新即见状态变化。
- 统计只读，不改变提交状态与成绩。

## 11. 异常与边界场景

| 场景 | 期望行为 |
|---|---|
| 活动无班级成员（空班） | 应参加 0，已参与 0，比率 `0.0`，名单为空数组 |
| 班级成员全部已提交 | 未开始 0，参与率 / 完成率按实际计算，名单无 `NOT_STARTED` 行 |

| 学生中途转入 / 转出班级 | 以查询时点 `class_member` 为准，不追溯历史快照 |
| 同一学生重复成员行 | 按 `(业务类型, 业务 id, studentUserId)` 去重，只算 1 人次 |
| `businessType` 非法 / 缺失 | `40000`，不查库 |
| 活动跨校 / 不存在 | `40400`；非创建人 / 非任课 `40300` |
| 学生调用新端点 | 403，由方法级 `@PreAuthorize` 拦截 |
| 教师分析页接口超时 / 失败 | 前端展示空态或错误提示，不显示旧假数据 |

## 14. 风险与后续迭代

### 14.1 风险

- 教师看到的「完成率」可能低于此前主观印象（分母包含从未打开的学生），需在卡片描述中明确口径。
- 学生中途换班时名单按当前成员快照，历史活动对账可能与当时实际不符；本期按现时成员处理，不引入历史快照表。
- 大班级活动多时汇总查询压力上升；用批量聚合与查询次数上限控制（由技术方案写死），上线前在双库验证。
- 新增卡片会改变分析页视觉密度，需保持现有卡片风格，不引入新依赖。

### 14.2 后续迭代

- 教师催办通知与消息推送（不在本期）。
- 按时间窗 / 截止日期分层统计（如「截止前完成率」）。
- 学习埋点与课件侧完成度（`courseware_assignment` 现行约束仍为不提供）。
- 清理 `ExamReportService` / `HomeworkReportService` 的 `ClassMemberRepository` 死注入（独立技术债，不在本期）。

## 15. 已否决方案

| 否决项 | 原因 |
