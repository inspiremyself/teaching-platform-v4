### 1.1 已定决策清单

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| D1 | 多空填空题解析口径 | 只改后端 `GradingAdapter`：新增私有 `parseFillBlankAnswers`，并在 `resolveStudentAnswer` 的 `FILL_BLANK` 分支先调用它，仅当返回空列表时回退 `parseAnswerList` / `answerText`；支持 `{"kind":"fill","blanks":[{"index","answer"}]}`，按 `index` 升序提取 `answer`；**保留空串占位**，禁止过滤空答案；忽略 `index <= 0`；**不按 index 数值补空洞**（与前端 `buildBlankSeed` 的“排序后按位置对应”保持一致）。前端提交结构、题库答案结构、评分策略均不改 |

## 2. 背景与问题定位

### 2.1 背景

2026-11-07 第二轮自查覆盖后端鉴权、租户隔离、评分链路、成绩状态机与前端作答链路。对首轮列出的 1 个 P0、9 个 P1 逐条回读代码复核，结论如下：

- 10 条全部成立，无撤销、无降级为误报。
- 需要补充说明的 2 条：
  - N4（实验图片路径穿越）成立，但读取非图片文件需要同时知道目标相对路径与精确文件大小，属“有前置条件的跨边界读取”，仍定 P1。
  - N10（作业无草稿）不是回归缺陷，而是能力缺失导致的数据丢失；与实验、考试已有草稿链路不一致，按 P1 处理。
- 复核未发现新的 P0/P1；此前批次已修复的提交幂等、截止门禁、教师 IDOR 等不在本期重复处理。

### 2.3 影响面

- N1：作业与考试的填空题成绩不可信，且考试客观题无法人工纠正，直接影响成绩发布。
- N2：跨校泄露教学资料元数据，违反租户隔离。
- N3：考试开始前泄题，破坏考试公平性。
- N4：跨边界读取文件，且图片归属校验可被绕过。
- N5：教师人工评分与已发布成绩被自动重判覆盖，产生成绩争议。
- N6：实验总分可被重复累加或写入非法分值，统计与成绩单失真。
- N7：教师无感知地改变成绩可见性，学生可见时点与教师预期不一致。
- N8：作业状态与题目内容可被回退修改，已提交答案与快照脱节。
- N9：发布或到期后的考试成绩可被静默改写，成绩记录与提交状态不一致。
- N10：学生作答过程数据无保全，刷新即丢失，直接影响作业完成率。

## 3. 目标与成功标准

### 3.1 目标

1. 多空填空题按空位正确评分，空位内允许空格与逗号。
2. 学生首页资料统计与列表严格限定在本校。
3. 考试开始前不向学生返回题目内容。
4. 实验图片只能被本人或本实验教师访问，路径不能越出 `lab-answers`。
5. 维护可接受答案不覆盖人工分与已发布成绩。
6. 实验整份批改拒绝重复项与非法分值。
7. 作业编辑不再改变成绩可见性。
8. 作业状态迁移受矩阵约束，有提交时不可回退或换班。
9. 考试成绩发布或到期后不可被直接改分，状态降级不留残留成绩。
10. 作业作答具备服务端草稿保全与前端自动保存。

### 3.2 成功标准

- 配置 2 空与 3 空的填空题，学生填写正确答案后自动得满分；某空含空格或逗号时仍正确。
- 学生 A 校账号调用学生看板，资料数量与最近资料只包含 A 校数据。
- 考试 `startAt` 之前调用 `GET /api/v1/exams/{id}` 返回 `notStarted=true` 且 `questions=[]`；`startAt` 之后返回完整题目。
- `GET /api/v1/labs/answer-images?path=lab-answers/2026-11-07/../../materials/x` 返回 `40000`；学生保存引用他人图片路径返回 `40000`。
- 教师对已批改报告维护可接受答案后，人工分与已发布总分保持不变。
- 整份批改提交重复 `answerId` 返回 `40000`；提交 `-1` 或超过题分的分数返回 `40000`。
- 编辑 `MANUAL_RELEASE` 作业并保存，详情中可见性仍为 `MANUAL_RELEASE`。
- `PUBLISHED` 作业存在提交时调用状态接口回退 `DRAFT` 返回 `40000`；`CLOSED` 作业调用发布返回 `40000`。
- 成绩冻结条件命中（`scoreReleased` 为真，或 `AFTER_DEADLINE` 且 `endAt` 已过）后教师调用改分返回 `40000`；状态降级后 `score_record` 不存在残留行。
- 作业作答过程中刷新页面，已填写答案可恢复；离开页面前草稿已落库。

## 6. 核心流程

### 6.1 多空填空评分

1. 前端按 `blanks[{index, answer}]` 提交 `answerJson`，同时提交逗号拼接的 `answerText` 作为兼容文本。
2. `GradingAdapter` 解析 `answerJson`：识别 `kind == "fill"` 与 `blanks` 数组。
3. 按 `index` 升序提取 `answer`，形成与空位一一对应的列表，空串保留；按排序后的位置对应，不按 `index` 数值补空洞。
4. `FillBlankScoringStrategy` 按空位逐个比对，命中累加该空分值。
5. 任一空位包含空格或逗号时，不再发生切分错位。

### 6.2 学生首页资料

1. 取当前学生 `schoolId`。
2. 资料数量与最近资料查询均追加学校谓词。
3. `schoolId` 为空直接返回 0 与空列表。

### 6.3 考试开考前后详情

1. 学生请求详情，校验已发布且为班级成员。
2. 若 `startAt` 非空且当前时间早于 `startAt`：短路返回基础信息、`questions = []`、`notStarted = true`，不回填任何提交与答案字段。
3. 否则按现有逻辑返回题目（`IN_PROGRESS` 回填草稿答案），但不返回答案与解析。
4. 学生点击开始考试时，`startExam` 继续执行时间窗、状态与重复开考校验。

### 6.4 实验图片访问

1. 上传：目录为 `lab-answers/{yyyy-MM-dd}/{studentId}`，落盘后返回相对路径。
2. 保存答案：校验路径无 `..`、位于 `lab-answers` 下、且含当前学生 `studentId` 段。
3. 预览：同样校验路径；学生仅可预览自己提交中的图片，教师仅可预览自己所创建实验的图片。
4. 历史图片：无 `studentId` 段时仍按答案归属校验，保证存量可读。

### 6.5 维护可接受答案

1. 保存可接受答案后遍历该实验提交，并对每个提交行加悲观写锁后重读。
2. 先判 `scoreVisible(lab, submission)`：为真时只刷新自动分建议字段，冻结 `score / scoreSource / totalScore / score_record`，不刷新提交状态。
3. `SAVED`：正常重判并刷新草稿总分，不写成绩记录。
4. `SUBMITTED`：只重判自动分题项，`TEACHER` 人工分保留，按结果刷新状态。

### 6.6 作业编辑与状态迁移

1. 编辑保存时前端回传 `scoreVisibilityMode`。
2. 后端更新时若该字段为空，保留原值。
3. 状态变更按矩阵校验；存在提交行时禁止回退 `DRAFT` 与变更班级。
4. 前端按状态展示动作：`DRAFT` 显示发布，`PUBLISHED` 显示关闭，`CLOSED` 不再显示状态按钮。

### 6.7 考试成绩冻结

1. `confirmAnswer` 写分前先判冻结条件：`exam.isScoreReleased()` 为真，或 `AFTER_DEADLINE` 且 `endAt` 已过。
2. 命中冻结条件直接返回 `40000`，不写任何表。
3. 未命中允许改分；`IMMEDIATE` / `AFTER_TEACHER_CONFIRM` 下即使已是 `GRADED` 也可纠错。前端当前未接入 `confirm-answer`，本期不新增入口。
4. 重算总分；`allConfirmed == true` 时 upsert 成绩记录。
5. 若原状态为 `GRADED` 且 `allConfirmed == false`，状态降回 `SUBMITTED` 并同事务删除成绩记录。

### 6.8 作业草稿

1. 学生编辑答案，前端 800ms 防抖调用草稿接口。
2. 后端校验发布、班级、时间窗、当前状态，写入 `SAVED` 提交与答案行。
3. 草稿不评分、不查重、不写 `score_record`。
4. 学生刷新页面，详情接口返回已保存答案并回填。
5. 正式提交沿用现有提交链路。

## 8. 业务规则汇总

### 8.1 评分规则

- 填空题学生答案按 `index` 升序与空位一一对应。
- 空串是合法占位，不参与后续空位左移。
- 单空分值与总分沿用题库/实验配置，不因本次修复改变。

### 8.2 可见性规则

- 资料：学生只看本校 `visibility='ALL'`。
- 考试：学生成绩可见性继续由 `canStudentSeeScore` 统一判断。
- 作业：可见性只由显式字段与发布状态决定，编辑不得隐式重置。

### 8.3 作业状态迁移矩阵

| 当前状态 \ 目标状态 | DRAFT | PUBLISHED | CLOSED |
|---|---|---|---|
| DRAFT | 允许（无操作） | 允许 | 拒绝 |
| PUBLISHED | 仅无任何提交时允许 | 允许（无操作） | 允许 |
| CLOSED | 拒绝 | 拒绝 | 允许（无操作） |

补充：
- 存在任意 `homework_submission` 行（含 `SAVED`）视为“已有提交”。
- 有提交时 `classId` 不可变更。
- `updateHomework` 未携带 `status` 时不做迁移，只校验 `classId` 与字段更新。
- 非法迁移统一返回 `40000`，消息包含当前状态与目标状态。

### 8.4 实验图片规则

- 路径必须位于 `storageRoot/lab-answers`。
- 新路径必须包含上传者 `studentId` 段。
- 学生只能访问自己提交中的图片。
- 教师只能访问自己创建实验的图片。

## 10. 非功能需求

### 10.1 性能

- 学生看板 SQL 增加索引列 `school_id`，不新增额外查询。
- 作业草稿保存单次只处理本次提交的题目，不做全量重算。
- 考试详情未开始时跳过题目快照组装，减少查询。

### 10.2 权限与安全

- 所有新增校验沿用现有 `requireTeacher` / `requireStudent`、教师 ownership 与班级成员校验。
- 不新增角色。
- 错误消息不包含文件绝对路径、其他学生姓名或成绩明细。

### 10.3 兼容性

- 旧填空题答案数组与纯文本继续可评分。
- 历史实验图片保持可读。
- 旧客户端不传 `scoreVisibilityMode` 时作业可见性不被重置。
- 旧客户端不传 `status` 时作业状态不被重置。
- 考试详情新增字段不影响现有页面。

### 10.4 数据一致性

- 考试 `confirmAnswer`、作业 `gradeSubmission`、实验 `gradeReport` / `confirmStepScore` / `saveBlankAcceptedAnswers` 的改分与成绩记录写入均在业务提交行悲观写锁内完成。
- 作业状态迁移与 `classId` 校验不额外加锁；与并发首存 `SAVED` 草稿的极小窗口竞态不在本期处理（见 §14.1）。
- 状态降级与成绩记录删除同事务。
- 草稿保存不产生成绩记录。
- 并发重复保存草稿不产生重复提交或重复答案。

## 11. 异常与边界场景

| 场景 | 期望 |
|---|---|
| 多空题学生只填部分空 | 已填空位按对错计分，未填空位按空串比较 |
| 空位答案包含逗号 | 不切分，按单空答案比对 |
| 学生 `schoolId` 为空 | 资料数量 0、最近资料空 |
| 考试 `startAt` 为空 | 不触发未开始逻辑，按现有详情返回 |
| 考试已开始但学生未点开始 | 详情返回题目；`startExam` 负责创建提交 |
| 实验图片路径含 `..` | `40000` |
| 学生引用他人图片路径 | `40000` |
| 维护可接受答案时提交已批改 | 自动分建议字段刷新，人工分、总分与 `score_record` 不变 |
| 整份批改重复 `answerId` | `40000`，无写入 |
| 作业已关闭后编辑 | 后端拒绝修改题目；前端隐藏非法动作 |
| 作业有提交时改班级 | `40000` |
| 作业状态为 `CLOSED` 时保存草稿 | `40000`「作业已关闭，不能保存草稿」 |
| 成绩冻结条件命中后改分 | `40000` 且不写任何表 |
| 草稿保存时作业已截止 | `40000`，不覆盖已有草稿 |
| 草稿保存网络失败 | 前端保留内存内容并提示一次，继续允许重试 |

## 14. 风险与后续迭代

### 14.1 风险

- N1 修复会改变历史错误分数的口径；已产生的错误成绩不会自动重算，需教师按需重新批改或重新发布。
- N3 上线后，学生在开始时间前无法预览题目属于预期行为，需提前告知教师与学生。
- N4 修改上传目录后，新旧路径并存；预览逻辑必须同时兼容，否则会影响存量实验报告。
- N5 冻结分支只覆盖“学生已可见”的提交；`AFTER_TEACHER_CONFIRM` 下未批改完成的提交仍会按自动分刷新，人工分保持不变。
- N8 状态收紧后，历史上处于 `CLOSED` 的作业不能再直接发布，教师需新建作业或等待后续“重新开放”能力。
- N9 冻结仅覆盖 `scoreReleased=true` 与 `AFTER_DEADLINE` 到期两种情形；未命中时 `IMMEDIATE` / `AFTER_TEACHER_CONFIRM` 下仍允许纠错。前端当前未接入 `confirm-answer`，本期不新增入口与二次确认。本期不提供“撤回发布”。
- N10 新增草稿端点会带来更频繁的写请求，需按 800ms 防抖并在离开页面前 flush，避免高频写库。
- 草稿保存复用现有首存幂等模式，必须使用独立事务与提交行锁，避免把唯一约束冲突暴露为 `500`。
- 作业状态迁移的存在性校验未加作业行锁；与并发首存 `SAVED` 草稿的极小窗口内，可能出现“状态已回退 `DRAFT` 后立刻产生 `SAVED` 行”。本期接受该残留风险，不新增仓储锁方法。

### 14.2 后续迭代

- 查重详情姓名脱敏与复核权限收口。
- 作业截止边界口径统一。
- 零题目考试发布校验。
- 教师组卷客观题类型集合与后端 `isObjective` 对齐。
- 统一三域分数范围校验。
- `request.ts` 支持 Blob/204/非 JSON 响应。
- 成绩撤回发布与重新批改工作流。
- 实验已发布成绩的改分冻结（`gradeReport` / `confirmStepScore`）。
- 作业草稿自动保存的前端离线缓存兜底。
