## 2. 背景与目标

### 2.1 背景

题库当前保存 `default_score`，界面上以“N 分”直接展示，产生三个实质问题：

1. **语义错位**：同一道题在实验、作业、考试中实际分值不同，题库里的单一数值没有唯一业务含义。
2. **误导操作**：教师修改题库分值后，已发布考试/作业的得分不变，形成“改了没生效”的认知裂缝。
3. **口径不一**：题库、作业、考试、实验四处对分值的校验强度不同；考试与作业的组卷分值没有范围校验，人工批改也没有上限校验。

同时，组卷页没有计划满分展示，教师无法判断“这套题加起来多少分”，也无法与考试时长、作业分档做基本核对。

### 2.2 目标

1. 确立分值的单一事实来源：题库只存内容，分值只属于组卷配置，发布后由快照冻结。
2. 移除题库分值相关的字段、接口、界面与复制逻辑，消除误导。
3. 统一下游分值校验与展示口径，覆盖组卷、批改、成绩三个环节。
4. 让组卷页可见计划满分，作为发布前的基本自检信息。

### 2.3 成功标准（可测）

- 题库相关页面与接口中检索不到任何“分值/分数/默认分值”字段。
- 从题库选题后，考试、作业、实验的预填分值分别符合 D8 的题型默认分表。
- 考试/作业组卷提交 0、-1、101、2.5 时全部被拒绝；实验步骤分提交 -1、101、2.5 被拒绝，0 允许，文案一致。
- 组卷页计划满分与实际分值求和完全一致，修改任一分值后立即更新。
- 已发布考试的题目分值不可修改；已有学生作答的作业题不可改分值。
- 人工批改提交超过该题分值的分数被拒绝；有题目的作业总评超过计划满分被拒绝；附件型作业与 0 分实验不被误拦。
- 历史考试/作业/实验的成绩、已记录得分与题目快照内的每题满分在改造后保持不变；组卷配置中的存量域外分值按 V28 规范化后，未发布场次的计划满分派生值与批改上限可能随之变化（本机实测域外值 0，无实际变化）。

## 3. 用户角色

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| 教师 | 题库录入者、组卷者、批改者 | 录题不纠结分值；组卷时明确每题分值；批改有清晰上限 |
| 学生 | 作答者、成绩查看者 | 知道每题满分，看到“得分 / 满分”与总分 |
| 校管 | 组织与治理 | 不接触题目与分值配置，无新增入口 |

前置条件：教师已登录且拥有目标班级；学生已加入对应班级；考试/作业/实验已发布。

## 4. 范围

### 4.1 本期范围

- 题库字段、接口、界面、导入、复制链路去分值（P0）。
- 组卷侧分值预填、编辑、校验（P0）。
- 组卷页计划满分展示（P1）。
- 发布后与已有作答的分值锁定（P0，沿用现网机制：考试/实验发布即锁、作业发布仅排序；本期只补校验与文案）。
- 批改逐题上限与作业总评上限（P1）。
- 学生端“得分 / 满分”展示口径统一（P1）。
- 数据库迁移与 `SCHEMA.md` 同步（P0）。

### 4.2 不在本期范围

- 半分制、小数分值、按题给分的阶梯评分。
- 题型默认分的管理端配置能力（本期为前端常量）。
- 记忆教师上次使用分值、按班级/课程差异化默认分。
- 自动组卷、按总分自动配平、题目预计作答时长。
- 得分率、班级分差、题目区分度等分析指标改造。
- 共享题库、题目审核流、题目版本管理。
- 历史数据中 `default_score` 的回填、迁移与保留（随列删除丢失，备份可查）。

## 5. 术语

| 术语 | 定义 |
|---|---|
| 题库分值（已废止） | 原 `question_bank.default_score`，本次改造后不存在 |
| 配置分值 | 考试/作业/实验组卷时，教师为每道题设置的分值，是计分的唯一输入 |
| 题型默认分 | 前端常量表，仅在选题加入组卷时用于预填，不落库、不作为计分依据 |
| 计划满分 | 组卷配置中所有题目分值之和，随编辑实时变化；只在前端派生，不落库 |
| 学生总分 | 学生实际得分（考试/实验由逐题汇总，作业为 `homework_submission.total_score`），**不是**计划满分，不得互为分母 |
| 快照分值 | 加入或更新组卷时写入题目快照的 `score`，发布后冻结，是批改、成绩与分析的事实依据；实验以锁定的 `lab_step.step_score` 为准 |
| 逐题给分 | 教师对单题提交的得分，范围 `0 ~ 该题配置分值`；采纳推荐分时为推荐值本身 |
| 总评 | 作业提交的整体得分；有题目作业范围 `0 ~ 计划满分`，附件型作业不设上限 |

## 6. 核心流程

### 6.1 题库录题

1. 教师进入题库，新增或编辑题目。
2. 填写题型、题干、选项、标准答案、解析、难度、评分参数；**没有分值输入项**。
3. 保存后题库仅保存内容，不产生任何分值字段。
4. 题库列表、编辑弹窗与选题弹窗的题库候选区均不展示分值。

### 6.2 组卷

1. 教师创建考试/作业/实验，打开题目选择器。
2. 选中题目加入配置清单，前端按“本次已有值 > 题型默认分”生成初始分值。
3. 教师在配置清单中逐题调整分值（考试/作业 1–100 整数，实验题项 0–100 整数），计划满分实时更新。
4. 保存草稿或发布，请求体显式携带每题分值。

### 6.3 发布与快照

1. 考试/作业在题目加入或更新时把该题分值写入题目快照（`questionScore`），发布时随题目结构一并冻结；实验不写题目快照，以锁定的 `lab_step.step_score` 为冻结值。
2. 发布后题目结构与分值均不可修改。
3. 题库后续编辑、删除不影响已发布内容与已生成成绩。

### 6.4 作答、批改与成绩

1. 学生作答页每题展示“满分 X 分”。
2. 客观题按快照分值自动判分。
3. 教师逐题给分受 `0 ~ 该题分值` 限制；有题目的作业总评受 `0 ~ 计划满分` 限制，附件型作业不受上限约束。
4. 学生成绩页展示每题“得分 / 满分”与总分；计划满分为 0 时只显示得分。

## 7. 功能需求

### FR-1 分值归属模型

| 层 | 存什么 | 谁可改 | 是否影响计分 |
|---|---|---|---|
| 题库（`question_bank`） | 题型、题干、选项、答案、解析、难度、评分参数 | 题目归属教师 | 否 |
| 组卷配置（`exam_question` / `homework_question` / `lab_step`） | 每题分值、排序、配置专属属性 | 组卷教师，受状态限制 | 是（唯一输入） |
| 快照（考试/作业 `question_snapshot_json`） | 题干、选项、答案、分值 | 不可改 | 是（事实依据） |
| 作答记录（`exam_answer` / `homework_answer` / 实验答题） | 得分、自动分、推荐分、来源 | 教师批改 | 结果 |

要求：

- 任何页面不得把“题库分值”与“计分分值”混用同一文案。
- 组卷请求必须显式包含分值；后端不得在缺失时静默取默认值。
- “计划满分”是配置侧派生值，“学生总分”是作答侧得分，二者的展示与校验不得互换（例如不得用 `homework_submission.total_score` 反推计划满分）。

### FR-2 题库去分值

**字段与接口**

- 删除 `question_bank.default_score`，同步删除实体字段、DTO 字段、视图映射与所有 SQL 引用。
- 题库创建/更新请求只接受白名单字段；携带 `defaultScore` 或任意未知字段一律返回 40000，不保存。
- 题库列表与创建/更新响应不再返回 `defaultScore`。

**界面**

- 题库编辑器移除“默认分值”输入项。
- 题库列表移除“N 分”标签。
- 选题弹窗移除“默认分值”列；分值只在“已选题目”面板中配置。

**导入**

- 导入 JSON 只接受 7 个白名单字段：`code`、`type`、`stem`、`difficulty`、`options`、`answer`、`analysis`。
- 任何白名单外字段（含历史 `score`）使该行进入 `ERROR` 并提示字段名；不静默忽略、不补默认值。
- 导入界面的示例 JSON 与字段说明同步移除 `score`。
- 导入保存后题库无分值；后续加入组卷时按 D8 预填。

**复制**

- 作业内联题、实验题项复制到题库时只复制内容字段，不再做分值取整、补 1 等处理。
- 题库预填到实验题项时，步骤分按 D8 预填，教师可改。

### FR-3 组卷分值预填

- 预填只发生在前端，优先级为：本次配置已有值 > 题型默认分。
- 默认分表（D8）作为唯一常量来源，考试、作业、实验三处共用。

| 题型 | 默认分 |
|---|---|
| 单选 `SINGLE` | 2 |
| 多选 `MULTI` | 3 |
| 判断 `JUDGE` | 2 |
| 填空 `FILL` | 4 |
| 简答 `SHORT` | 10 |
| 代码（实验内部 `CODE`） | 10 |
| 其他/未知题型 | 5 |

- 已选题目分值不因重新打开选择器而被重置。
- 新增题目（含内联题）时按题型默认分初始化；后续修改题型不自动改分值，避免覆盖教师已填内容。
- 编辑已有题目的题干、选项、答案或解析时，保留该题在组卷配置中的原分值，不得按题型默认分重置。

### FR-4 组卷分值编辑与校验

- 考试、作业每题分值输入为整数步进，范围 1–100；实验题项步骤分为整数步进，范围 0–100。
- 前端即时拦截非法值并提示；后端为最终判定。
- 后端对考试、作业（含从题库加题与内联题）、实验步骤分执行同一套范围校验，仅上下限按 D9 区分。
- 错误码统一 40000，文案见 §9.2。

### FR-5 计划满分与发布冻结

- 考试、作业、实验组卷页展示“计划满分 X 分”，由已选题目分值求和得出。
- 不强制计划满分等于 100；超过 100 或不足 100 均允许保存。
- 考试/作业发布后计划满分随题目快照冻结；实验随 `lab_step.step_score` 锁定，均不再随题库变化。
- 组卷页不新增后端总分字段，避免与求和不一致。
- 计划满分为 0 时（附件型作业、全 0 分实验）如实显示 0，并按下文隐藏成绩页分母。

### FR-6 批改分值边界

- 逐题显式给分：`0 ≤ 得分 ≤ 该题配置分值`；负数或超出上限拒绝。
- 采纳推荐分/确认分数：`acceptSuggested=true` 时忽略请求中的 `score`，直接取推荐值；推荐分为空时按现有错误处理。
- 作业总评：有题目的作业 `0 ≤ 总评 ≤ 计划满分`；附件型作业（无题目、计划满分 = 0）不设上限，沿用现状。
- 考试总分由逐题得分汇总，不单独接受教师直接改总分。
- 实验总分为题项得分汇总；逐题上限与错误文案沿用现有实现（已是“分数必须在 0 到该题分值之间”）；计划满分为 0 时不校验上限。

### FR-7 学生端展示口径

- 作答页：每题显示“满分 X 分”。
- 成绩页：计划满分 > 0 时，每题显示“得分 / 满分”，总分显示“总分 X / 计划满分 Y”。
- 计划满分 = 0 时，只显示得分/总分，不显示 `/ 满分`，不得出现 `X / 0`。
- 未发布成绩时，不展示得分，但仍可展示每题满分（沿用现网可见性规则）。

## 8. 业务规则汇总

### 8.1 分值校验矩阵

| 场景 | 规则 | 前端 | 后端 |
|---|---|---|---|
| 考试组卷每题分值 | 1–100 整数 | 拦截 | 拒绝（40000） |
| 作业从题库加题 | 1–100 整数 | 拦截 | 拒绝（40000） |
| 作业内联题 | 1–100 整数 | 拦截 | 拒绝（40000） |
| 实验题项步骤分 | 0–100 整数（0 = 不计分步骤） | 拦截 | 拒绝（40000） |
| 逐题显式批改给分 | `0 ~ 该题分值` | 提示 | 拒绝（40000） |
| 采纳推荐分 / 确认分数 | `acceptSuggested=true` 时忽略请求 `score`，取推荐值 | 不适用 | 不校验自填值；推荐值由评分引擎保证在 `0 ~ 该题分值` |
| 作业总评（有题目） | `0 ~ 计划满分` | 提示 | 拒绝（40000） |
| 作业总评（附件型，无题目） | 不设上限 | 不限制 | 不校验 |
| 题库录题/导入 | 无分值 | 无输入 | 无字段 |

### 8.2 状态与分值编辑权

| 状态 | 分值可改 | 说明 |
|---|---|---|
| 草稿 · 考试 | 可改 | 考试草稿阶段不会产生学生提交 |
| 草稿 · 作业该题无作答 | 可改 | 组卷阶段自由调整 |
| 草稿 · 作业该题已有作答 | 该题不可改 | 其余未作答题目仍可改 |
| 草稿 · 实验已有任意提交 | 不可改 | 实验题项结构全局锁定（`assertLabStructureEditable`） |
| 已发布 | 不可改 | 作业已发布仅允许排序，即使无提交也不能改分值；考试/实验同 |
| 已截止 / 已归档 | 不可改 | 只读 |

> 2026-11-06 PRD §6.1 旧表述“发布后仅允许调分与排序”与现网实现（`HomeworkConfigService.isContentUnchanged` 比较 `questionScore`）冲突，以本表为准；该旧表述已同步修正。

### 8.3 展示口径规则

| 位置 | 展示内容 | 禁止内容 |
|---|---|---|
| 题库列表 / 题库编辑 / 选题弹窗的题库候选区 | 题型、难度、来源、题干 | 任何分值 |
| 组卷配置清单 / 选题弹窗的已选面板 | 每题分值（计划满分在组卷页展示） | 题库默认分 |
| 学生作答页 | 每题“满分 X 分” | 题库信息 |
| 成绩页（计划满分 > 0） | “得分 / 满分”、总分 | 题库分值 |
| 成绩页（计划满分 = 0） | 仅得分/总分 | `/ 0`、题库分值 |

### 8.4 数值口径

- 考试、作业每题分值为整数，范围 1–100；实验步骤分为整数，范围 0–100。
- 教师批改输入为整数（本期不引入 0.5 分）。
- 自动评分可能产生小数（如填空题按空均分），得分展示最多两位小数，去掉无意义的 `.0` 后缀。
- 组卷页计划满分按整数展示；0 分如实显示。

## 9. 数据与契约变更

### 9.1 数据变更

新增迁移 `V27__drop_question_bank_default_score.sql`：

```sql
ALTER TABLE question_bank DROP COLUMN default_score;
```

- 不修改 V1–V26 历史脚本；V2 种子中的 `default_score` 在 V27 之前已执行，删除列后不影响启动。
- 迁移编号以实施时 `db/migration/` 实测最大编号 +1 为准（编写本 PRD 时最大为 V26，故记为 V27）。
- MySQL 与 H2 均支持该语句，无需方言占位符。
- 执行迁移属于破坏性操作，实施前必须按 `path-b-data-backup-gate.mdc` 完成备份并回报备份路径。
- `backend/src/main/resources/db/migration/SCHEMA.md` 同步删除 `default_score` 行。
- 历史快照 JSON 不包含 `defaultScore`，无需数据清洗。

### 9.2 接口契约变更

| 接口/类型 | 变更 | 说明 |
|---|---|---|
| `POST/PUT /api/v1/questions` | 请求体移除 `defaultScore`，只接受 7 个白名单字段 | 未知字段一律 40000 拒绝，文案「题库请求不支持字段：{name}」；不再有“默认分值不能为空”校验 |
| `GET /api/v1/questions` | 响应移除 `defaultScore` | 前端类型 `QuestionItem` 同步删除 |
| 题库导入 | 白名单外字段（含 `score`）使该行 `ERROR` | 不再静默忽略；历史 JSON 需删掉废止字段后导入 |
| 考试组卷请求 | `questionScore` 增加 `@Min(1) @Max(100)` 与整数校验 | 缺失仍按 `@NotNull` 拒绝 |
| 作业从题库加题 | `questionScore` 增加同等校验 | 现为无校验 |
| 作业内联题 | 现有 `@Positive` 补齐上限与整数校验 | 现允许 0.5 与 >100 |
| 实验题项步骤分 | 无变更，保持 `@Min(0) @Max(100)` 的 `Integer` 字段 | 0 合法，不得改成 1 |
| 作业总评 | 有题目作业增加 `0 ~ 计划满分` 校验；附件型作业不校验上限 | 现为无校验 |
| 批改逐题给分 | 增加 `0 ~ 该题分值` 校验 | 考试、作业补齐；实验已实现且文案一致；采纳推荐分路径不受理自填分数 |

统一错误文案：

| 场景 | 文案 |
|---|---|
| 考试/作业组卷分值非法 | 分值必须为 1–100 的整数 |
| 实验步骤分非法 | 步骤分必须为 0–100 的整数 |
| 组卷分值缺失 | 请设置题目分值 |
| 已有作答改分 | 该题目已有学生作答，不能修改分值 |
| 批改越界 | 分数必须在 0 到该题分值之间 |
| 总评越界 | 总评不能超过计划满分 {X} 分 |
| 题库请求含未知字段 | 题库请求不支持字段：{name} |
| 导入含未知字段 | 不支持的字段：{keys}（题库只接受内容字段） |

### 9.3 契约边界（不兼容声明）

- **不兼容旧客户端**：题库创建/更新请求与两个复制到题库入口中任何未知字段（含 `defaultScore`）一律 40000 拒绝，不静默忽略、不保证保存成功。
- **不兼容旧前端**：题库列表与选择器不提供 `defaultScore` 的跨版本展示兜底；旧前端必须同版本升级，不承诺 `undefined 分` 的兼容处理。
- **不兼容历史导入 JSON**：含 `score` 或其它未知字段的行明确 `ERROR` 并提示字段名，删掉废止字段后方可导入。
- **不兼容历史非法分值**：组卷配置分值一律按 D9 校验，越界/非整数一律拒绝；V28 已把存量域外值钳制到域内并加 CHECK 约束，不存在「未修改即可保存」的特例路径。
- **数据保全（非兼容口径）**：历史考试/作业/实验的题目快照、每题得分与成绩保持不变；不改写快照结构，不清洗快照内分值。

## 10. 非功能需求

### 10.1 权限

- 题库与组卷分值仅题目归属教师可读写；学生只读作答与成绩。
- 校管端不新增题目或分值入口。

### 10.2 数据一致性

- 组卷保存（新增/更新题目）与题目快照写入同一事务。
- 发布只变更状态，不重写快照；快照内的分值已在草稿阶段写完并在此后锁定。
- 前端计划满分只做展示，不作为提交字段，避免与后端求和不一致。

### 10.3 审计

- 现网 `AuditAction` 没有组卷更新类动作（仅 `QUESTION_CREATE/UPDATE/DELETE`、`HOMEWORK_SUBMISSION_RETURN` 等），本 PRD 不新增组卷分值审计，也不声称沿用不存在的审计。
- 题库创建/更新的审计明细只含 `code`，不含分值，删除字段后无需改审计结构。
- 批改分值变更沿用现有批改接口的留痕字段（逐题 `scoreSource` / `acceptedAutoScore`，提交级 `gradedAt`），不新增审计类型。

### 10.4 性能

- 计划满分由前端对已选题目求和，O(n)，不新增请求。
- 题库列表响应体减少一个字段，不增加查询开销。

## 11. 异常与边界场景

| 场景 | 预期行为 |

| 已有作答的作业题改分值 | 拒绝，提示已有学生作答 |

| 附件型作业总评任意数值 | 允许（沿用现状不设上限） |
| 题库题被删除 | 组卷配置与快照不受影响（沿用现有规则） |
| 题库题被修改 | 已发布内容不变，新引用使用新内容（沿用现有规则） |
| 从作业/实验复制到题库 | 只复制内容，题库不出现分值 |
| 历史数据中的 `default_score` | 随列删除丢失，不做迁移；如需追溯从备份获取 |

### 14.1 风险

| 旧客户端携带废止字段 | 直接 400，旧版本无法保存题库题 | 不提供跨版本兼容；错误文案明确列出字段名，按提示删除后重试 |
| 计划满分仅前端展示 | 与服务端统计口径不一致风险 | 组卷请求逐题分值即事实来源，展示仅求和 |
| 范围校验收紧 | 存量域外分值会阻塞编辑 | V28 迁移已把存量钳制到域内并加 CHECK 约束；迁移前强制备份，不存在放行特例 |
| 批改上限误伤附件型作业 | 无题目作业总评被 `≤ 计划满分(0)` 拦截 | 仅对有题目的作业校验上限，附件型作业沿用现状 |
| 0 分实验除零 | 成绩页 `得分 / 0` 或统计异常 | 计划满分为 0 时隐藏分母，不参与除法 |
