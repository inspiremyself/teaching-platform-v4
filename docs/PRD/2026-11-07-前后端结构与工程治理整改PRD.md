## 2. 背景与问题定位

### 2.1 调研结论

前端 `api / types / utils / stores / layout / views` 分层、后端「业务域 → 技术层」分包（188 个 `.java`、16 个业务包）与当前项目规模、三角色边界匹配，**顶层目录骨架不需要调整**。真正需要治理的是：知识库事实漂移、契约与权限缺口、巨型文件与半途重构、共享层名不副实、迁移治理风险、工程化门禁缺失。

### 2.2 证据边界

调研为只读静态检索，未运行 `./mvnw test` 与 `npm run build`；`ExamService.listExams` 是否在 service 层做角色过滤未验证；千行级文件行数由检索工具统计并在超 1000 行处用尾部读取复核，属约数；两套备份恢复脚本的行为差异未逐行比对。本文各 FR 的「现象与证据」均为静态事实，实施阶段的动态复现由对应技术方案补充。

## 3. 目标与成功标准

### 3.1 目标

1. 让知识库、README、规则文档与仓库实际结构一致，消除「按错误地图开发」的风险。
2. 让权限声明、API 契约、状态枚举有单一真相，前后端不再各自硬编码。
3. 让共享层依赖方向单向、无环，共享能力被三闭环真实复用。
4. 降低巨型 SFC 与巨型 service 的职责密度，且不改变业务行为。
5. 建立可重复执行的迁移校验、前端测试、lint 与 CI 门禁。
6. 清理死代码、工具产物与重复脚本，补齐知识库分层与缺测域。

### 3.2 全局成功标准

- `cd backend && ./mvnw test`：58 个既有测试全绿，新增测试一并纳入。
- `cd frontend && npm run build`（含 `vue-tsc --noEmit`）通过；`npm test`、`npm run lint` 无失败。
- CI 工作流中后端测试与前端构建同时通过。
- 路径 B 联调：`./scripts/path-b/backend.sh` + `./scripts/path-b/frontend.sh` + `./scripts/common/healthcheck-login.sh` 通过，三角色演示账号登录与主页跳转不变。
- 全仓 `db/migration/V*.sql` 中 `V1`–`V24` 的内容与本文落盘时一致（用 git diff 校验 0 改动）。
- 修改任一历史迁移的 checksum 后，后端启动失败并报 Flyway 校验错误；未改动时启动日志无 repair。
- 三角色路由、`/api/v1` 前缀、`code/message/data/timestamp` 响应结构与 `PagedResult<T>` 分页结构不变。

### 4.3 保持约束与非目标

**保持约束（合理点，本期不得改动）**

1. `frontend/src/api/` + `utils/request.ts` 的统一请求边界；`views` 不得直连 axios。
2. 三套角色路由（`meta.role` 守卫 + 单一 `layout/index.vue`），不得合并、不得复制成三套布局。
3. 后端 controller 不直连 repository / entity，`CurrentUser` 统一由 controller 传入 service。
4. `grading/` 的策略引擎与三闭环调用关系。
5. 后端测试按业务包镜像组织；`src/test/resources/application-test.yml` 保持 H2 mem，路径 B 保持 H2 file / MySQL local。
6. `docker-compose.yml` 与 `scripts/` 的职责分工，`JWT_SECRET` 必填约束。

**非目标**

1. 不重排顶层目录，不把后端改成按技术层分包，不做一次性全量重构。
2. 不合并三套角色壳层，不合并实验 / 作业 / 考试为通用提交模块。
3. 不修改 `V1`–`V24` 已应用脚本，不改运行中 schema，不删 `data/` 整树。
4. 不恢复 `design/`、`design-prototypes/`，不新建原型资产。
5. 不改后端响应字段名、不新增业务接口、不改状态机与评分口径、不改演示账号。
6. 不重复 `docs/PRD/2026-11-07-P1P2P3缺陷分级修复PRD.md` §1.1 中单独跟踪的 4 个 P0 缺陷。
