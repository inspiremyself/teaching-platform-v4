### 1.1 已定决策清单

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| D1 | 范围裁定 | 只做“同一件事被写了多份”的收敛，且默认**不改变任何可观察行为**。凡是收敛必须改变文案、状态、错误提示或判定结果的，一律移入 §5 非目标，不在本期夹带 |
| D2 | 前端日期格式化 | 新增 `frontend/src/utils/format.ts`，提供 `formatDateTime`（`YYYY-MM-DD HH:mm`）、`formatShortDateTime`（`M/D HH:mm`）、`formatScore`。全站各定义点与调用点改为调用该工具，逐文件清单以 Phase 1 技术方案 §5.1 为准；**业务控制文案型**格式化（见 FR-1.5）不迁移 |
| D3 | 格式化口径与兜底 | 口径统一为**按浏览器本地时区渲染**；`fallback` 为可选参数、缺省 `'-'`，现网使用 `'未设置'` / `'时间待定'` 等文案的调用点显式传入；`null` / 空串 / 非法时间串统一走 fallback，不再返回原始串。`formatScore` 提供 `stripTrailingZero` 开关，`digits` 默认 1；SVG 坐标类 `toFixed(2)` 不迁移 |
| D4 | 前端状态展示映射 | 新增 `frontend/src/components/ui/statusPresentation.ts` 作为唯一事实来源，按 `module + kind + scene` 查表、以 `status` 为键输出 `{ label, tone }`；`module ∈ lab / homework / exam / workbench`，`kind ∈ activity / submission / examSubmission`，`scene ∈ teacher / student`，`tone` 只取 `neutral / success / info / warning / danger`。解析顺序为「模块覆盖表 → 模块无关基表 → `{ label: 原值, tone: 'neutral' }`」。范围只覆盖状态到文案/颜色的映射；`workbench/StatusPill` 的 tone（`draft / published / closed / warning`）不在本期统一范围（11-24 PRD D13 已列为非迁移项）。原生 `el-tag :type` 宿主必须经 `toElTagType(tone, neutralAs)` 转成 Element Plus 五值，`neutral` 按各页现网默认落 `'info'` 或 `'primary'`，不得直接绑定 `tone` |
| D5 | 状态标签宿主组件 | **不扩展 `AppStatusTag`，也不把页面上的原生 `el-tag` 换成 `AppStatusTag`**。`components/ui/AppStatusTag.vue` 与 `assets/layout.css` 的状态标签样式在本期零改动；页面继续使用现有 `el-tag :type` / 既有 `AppStatusTag` 调用，只把文案与 tone 的取值改为调用 `resolveStatusPresentation`（原生 `el-tag` 的 `:type` 再经 `toElTagType` 转换） |
| D6 | 状态文案不得被“统一” | 同一状态在不同**模块**与**角色**下的既有文案差异（如 `PUBLISHED` 教师「已发布」/ 作业学生「进行中」/ 考试学生「已发布」；`SAVED` 作业教师「已保存」/ 工作台队列「草稿」）**一律用 `module` + `scene` 覆盖固化**，本期不合并措辞、不做文案优化 |
| D7 | 后端运行期门禁组件 | 新增 `common/util/WritableWindow`（record，落包遵循 `backend-package-layout.mdc` §3「通用工具 → `common/util/`」），只承担“未开始 / 已截止”两个**判定**并返回违例枚举；**组件内不出现任何域前缀文案**，错误文案仍由各域调用点持有；只服务**学生写入口**（保存草稿、提交、上传图片、逐步保存） |
| D8 | 后端门禁接入边界 | **只接入 lab 与 homework**。exam 不接入：其写入门禁含个人限时封顶（`now + durationMinutes` 且被 `endAt` 截断）与 `IN_PROGRESS` 免检分支，属真实语义差异，与 11-20 PRD D9 同口径。配置期窗口合法性校验（lab / exam / content 三处）不并入运行期组件 |
| D9 | 截止边界口径 | 组件以显式参数 `deadlineInclusive` 表达“`now == 截止时刻` 是否视为已截止”。本期按现网各自取值：lab `true`（`now == endAt` 视为截止）、homework `false`（`now == dueAt` 仍放行）。**口径差异登记为 §5 后续独立决策项，本期唯一结论为保持现状** |

| D12 | 契约与数据 | 后端零 HTTP 契约、零错误码、零权限、零 Flyway、零表结构变更。前端不改 `types/**`、`api/**` 既有定义；新增的展示映射放在 `components/ui/statusPresentation.ts`，不进入 `types/` |

## 4. 需求明细

### 4.1 Phase 1 · FR-1 全站日期与数字格式化统一

1. 新增 `frontend/src/utils/format.ts`，导出三个函数：
   - `formatDateTime(value, options?)`：输出 `YYYY-MM-DD HH:mm`；
   - `formatShortDateTime(value, options?)`：输出 `M/D HH:mm`；
   - `formatScore(value, options?)`：`digits` 默认 1，`stripTrailingZero` 默认 `false`。
2. `options.fallback` 为可选参数，缺省 `'-'`；调用方按现网文案显式传入（如 `'未设置'`、`'时间待定'`）。`null`、空串、非法时间串、非有限数字统一返回 fallback，不再回显原始串。
3. 时间口径统一为浏览器本地时区渲染；不引入 `dayjs` 等新依赖，使用原生 `Date` 与 `padStart`。
4. 迁移范围：N2 的 9 处逐字实现、`new Date()` 实现（含 `student/Dashboard.vue` 的 `formatTimeLabel` 与 `teacher/exams/Results.vue` 的 `submissionTimeLabel`），以及 N2 中其余调用点；逐文件清单以 Phase 1 技术方案 §5.1 为准。
5. **不迁移**：返回业务控制文案而非时间的函数，例如 `StudentLabSubmissions.vue:85-96` 的「已保存，尚未正式提交」「尚未提交」及其内部 `toLocaleString('zh-CN')`；`admin/AuditLogs.vue:104-107` 的 `formatTime`（`toLocaleString()`）、`admin/Schools.vue:164` 与 `teacher/components/behaviorDisplay.ts:198-199`（`slice(0, 19)` 含秒）、`components/typed-editor/adapters/questionAdapter.ts:22-23`（时间戳 ID）、`dueHint` / `countdownLabel` 等倒计时文案。上述属于状态表达、另一套展示格式或非展示用途，不在本期格式化口径内。
6. 迁移后每个调用点的可见文本必须与迁移前逐字符一致（N4 的兜底差异通过 `fallback` 参数保留）。
7. 页面/composable 内与被抽工具同名的本地定义（如 `formatDateTime`、`formatScore`）在迁移时**删除**，避免局部声明遮蔽导入；删除后该文件内所有引用统一指向 `utils/format.ts`。
8. `formatScore` 迁移时逐点保留现状：`useScores.ts:202` 传 `stripTrailingZero: true`，其余 `toFixed(1)` 调用传 `false`；`Analysis.vue:235` 的 SVG 坐标 `toFixed(2)` 不迁移。

### 4.2 Phase 1 · FR-2 状态展示映射唯一化

1. 新增 `frontend/src/components/ui/statusPresentation.ts`，导出唯一解析入口与三类枚举：

```ts
type StatusModule = 'lab' | 'homework' | 'exam' | 'workbench'
type StatusKind = 'activity' | 'submission' | 'examSubmission'
type StatusScene = 'teacher' | 'student'
type StatusTone = 'neutral' | 'success' | 'info' | 'warning' | 'danger'
interface StatusPresentation { label: string; tone: StatusTone }
interface StatusPresentationInput {
  module: StatusModule
  kind: StatusKind
  scene: StatusScene
  status: string
  unknownLabel?: string
}
type ElTagType = 'primary' | 'success' | 'info' | 'warning' | 'danger'
function resolveStatusPresentation(input: StatusPresentationInput): StatusPresentation
function toElTagType(tone: StatusTone, neutralAs: 'primary' | 'info'): ElTagType
```

2. `kind` 与状态枚举固定对应：`activity` → `ActivityStatus`；`submission` → `SubmissionStatus`（`LabReportStatus` 是其后者的类型别名）；`examSubmission` → `ExamSubmissionStatus`。
3. 解析顺序固定为「`module:kind:scene` 覆盖表 → `kind:scene` 基表 → `{ label: 原值, tone: 'neutral' }`（传入 `unknownLabel` 时用其替代原值）」。覆盖表只登记与基表不同的条目，禁止在调用点再做状态判断。原生 `el-tag :type` 必须经 `toElTagType` 转换，`neutral` 按各页现网默认值落 `'info'`（三个 lab 页面）或 `'primary'`（学生作业页）。
4. 映射内容以现网文案为准，按 N6 用 `module` + `scene` 覆盖表达差异；`tone` 只输出五值。N7 的 `StatusPill` 词表（三个 `toneOf`）不迁移，由工作台组件自行维护。
5. 迁移范围：N5 中承担“状态 → 文案/颜色”的函数与常量。页面继续使用现有标签宿主组件（原生 `el-tag` 或既有 `AppStatusTag`），只用解析结果填充 `label` / `tone`；原生 `el-tag` 的 `:type` 再经 `toElTagType` 转换。
6. 空状态（`null` / `undefined` / 空串）不进入解析器，由调用点保留原兜底（`'-'`、`'未开始'`、`'未知'`、`'primary'`、`'info'`）；这类分支只允许是单行三元表达式，不得出现状态枚举判断。
7. **不迁移**：派生可操作性（`canStart / canResume / canViewResult` 等）、`taskStageLabel`、`Results.vue` 的 `questionStatusLabel` 这类组合逻辑、`useStudentLabSteps.ts` 的 `submissionTagType`（标签文本为 `只读 / 可编辑`，且 `SAVED` 取 `primary`）、`student/Labs.vue` 的任务筛选文案、`useScores.ts` 的 `typeLabel / scoreLevelLabel / performanceLabel`、`StatusPill` 的 `toneOf`。
8. 迁移后同一位置的标签文本与颜色必须与迁移前一致；如发现未登记的差异，先在覆盖表补条目，不得改文案。

## 5. 非目标与否决项

| 项 | 结论 | 理由 |
|---|---|---|
| exam 写入门禁接入 `WritableWindow` | **不纳入**（D8） | 个人限时封顶、自动交卷、`IN_PROGRESS` 免检是真实语义差异；共用单一规则会丢信息 |
| 补齐 homework 配置期窗口顺序校验 | **不纳入**（N15 登记） | 会新增一个此前不存在的 `40000` 拒绝，属行为变更；需单独评估存量脏配置 |
| 统一 lab / exam / content 三套配置期校验 | **不纳入** | 三者约束不同：lab 只校验先后、exam 要求结束时间在未来、content 要求成对填写；强行合并会把“发布前必须设置未来结束时间”误加到其它域 |
| 对齐 `now == 截止时刻` 口径 | **不做，移入后续决策**（D9） | homework 现为放行、lab 为拦截；统一必须改变其中一方行为。本期只把差异参数化并显式登记，留待独立决策 |
| 统一同一状态在不同模块与角色的文案 | **否决**（D6） | 「进行中 / 已发布」「已提交 / 待批改 / 待评分」是模块与角色语境差异，不是重复；合并会降低可读性 |
| 合并 `SubmissionStatus` 与 `ExamSubmissionStatus` | **否决** | 与 11-20 PRD D9 一致：`IN_PROGRESS` / `AUTO_SUBMITTED` 有真实消费点 |
| 把状态映射放进 `types/` | **否决**（D12） | 与 11-24 PRD D20 冲突；展示映射属 UI 层职责，应留在 `components/ui/` |
| 扩展 `AppStatusTag` 或将页面 `el-tag` 换成 `AppStatusTag` | **不纳入**（D5） | `AppStatusTag` 带自定义圆角、字重与配色，换宿主会改变可见样式；本期只收口取值来源 |
| 引入 `dayjs` / `date-fns` | **否决** | 现有需求只覆盖两种格式，新增依赖不划算 |
| 迁移 SVG 坐标类 `toFixed(2)` | **不纳入** | 是绘图计算，不是展示口径 |
| 列表页骨架、弹窗 footer、上传下载、硬编码样式 | **不纳入本期** | 属调研中的 P1/P2，风险与联动面大于本期；另立项 |
