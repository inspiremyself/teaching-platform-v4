### 1.1 已定决策清单

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| D1 | 作业截止判定 | 服务端 `submitHomework` 以服务端时钟判定：`dueAt != null && now.isAfter(dueAt)` 时返回 `40000`「作业已截止，不能提交」；`dueAt == null` 视为不限时 |
| D2 | 作业截止边界 | `now == dueAt` 允许提交（与考试 `now.isAfter(deadline)` 口径一致）；截止后不产生任何提交、查重、成绩副作用 |
| D3 | 作业前端只读 | 学生作业详情页新增响应式时钟，`readonly = 已提交/已批改 || (dueAt != null && 当前时间 > dueAt)`；倒计时归零时前端立即切只读，无需刷新页面 |
| D4 | 作业状态与截止解耦 | `status=CLOSED` 与 `dueAt` 是两条独立门禁，任一命中即拒绝；`dueAt` 到期不自动改 `status`，本期不引入定时任务 |
| D5 | 教师看板查重归属 | `highRiskPlagiarismCount` 收敛为「当前教师创建的作业」：`plagiarism_task` 当前仅由作业提交写入（`business_type = HOMEWORK`），且其 `business_id` 存的是 `homework_submission.id`，因此必须两级关联 `homework_submission hs ON hs.id = pt.business_id` → `homework h ON h.id = hs.homework_id`，再校验 `h.created_by = teacherId`；当前不存在 `LAB` / `EXAM` 类型任务，不为其编写空分支，后续新增类型时必须同步扩展 |
| D6 | 教师看板趋势归属 | `loadScoreTrendLast7Days(Long teacherId, Long schoolId)` 以 `score_record.class_id` 关联 `class_room`（`school_id = teacher.schoolId`），并用 `EXISTS` 关联 `class_teacher`（`teacher_user_id = teacherId`）；`class_teacher` 已有唯一约束 `uk_class_teacher(class_id, teacher_user_id)`，本方案统一使用 `EXISTS` 作为唯一写法，禁止写成不带 `teacher_user_id` 条件的 `JOIN` |
| D7 | 看板隔离硬约束 | 教师看板任何指标不得出现无 `teacherId` / `schoolId` 约束的全表聚合；新增指标必须满足「教师创建的活动」或「教师所带班级」其一 |
| D8 | 交卷失败计时恢复 | `doSubmit` 失败后若 `remainingSeconds > 0`，按已保存的 `deadlineAt` 重新启动计时器；`remainingSeconds == 0` 时保持 0 并进入「自动交卷失败」态 |
| D9 | 自动交卷失败重试 | 到点自动交卷失败后，仅对**可重试失败**每 10 秒自动重试一次，最多 6 次：网络/超时（异常不是 `ApiError`）与 `ApiError.code >= 50000` 的服务端 5xx；`ApiError.code < 50000` 的业务拒绝（如 `40000`、`40300`）不自动重试，仅保留手动重试；用户点击「重新交卷」立即重试并重置计数；提交成功或离开页面即停止；重试期间与 `submitting` 互斥；交卷请求以 `silent: true` 调用，提示由页面统一呈现 |
| D10 | 截止后只读 | `remainingSeconds == 0` 时（含自动交卷失败态）所有作答控件置为只读/禁用，禁止继续编辑；服务端 `deadlineAt + 120s` 后仍拒绝提交（沿用现状，不扩大宽限） |
| D11 | 截止后兜底提示 | 自动重试全部失败后，页面展示常驻错误条「考试已结束，自动交卷失败，请立即重试或联系教师」并提供「重新交卷」按钮；不得静默停留在 `00:00` |
| D12 | 实验批改状态门禁 | `gradeReport` 与 `confirmStepScore` 仅允许 `SUBMITTED` / `GRADED`；`SAVED` 返回 `40000`「学生尚未提交实验报告，不能批改」；错误码与 `returnReport` 的既有限制保持一致 |

## 2. 背景与问题定位

### 2.1 背景

前一份 PRD 已修复 5 个作答数据保全与成绩可见性缺陷。本次自查回到代码逐行核对上一份 PRD §4.2 列为「不在本期范围」的条目，确认其中三项是**真实可触发**的缺陷，并另发现一项与截止时间强相关的交卷恢复缺陷。四项均未被现有测试覆盖（后端 498 个用例全绿、前端 build 通过）。

### 2.2 缺陷清单与代码证据

| 编号 | 严重级别 | 现象 | 代码证据 | 结论 |
|---|---|---|---|---|
| N1 | P0 | 作业超过 `dueAt` 仍可正常提交，逾期答案进入批改、查重与成绩统计 | 后端 `HomeworkService.java` L394-L399 `submitHomework` 只判 `status == CLOSED`，全流程未读取 `dueAt`；`accessiblePublishedHomework` L625-L636 只校验非 `DRAFT` 与班级成员。前端 `HomeworkDetail.vue` L375 `readonly` 只依赖 `submissionStatus`，L434-L468 `submitForm` 无截止判断；L390-L408 `countdownLabel` 依赖 `Date.now()` 但页面无响应式时钟（无 `setInterval`），停留跨过截止时间时文案与按钮都不会变化；`Homeworks.vue` 仅在列表层用 `dueHint`（L196-L204）渲染「已截止 N 天」文案，不参与详情页只读控制 | 确认缺陷，服务端与前端双重缺失 |

### 2.3 影响面

- N1：截止时间对教学约束完全失效。逾期提交会触发查重分析并写入成绩，直接扭曲作业成绩分布与统计分析；教师无法用截止时间收口。
- N2：跨教师、跨学校数据泄露。高风险查重数量与成绩趋势属于敏感教学数据，任何教师账号都能读到全局值；学校管理员视角下也会造成统计失真。
- N3：考试主链路的不可恢复故障。网络抖动或服务端瞬时错误即可让整场考试无法交卷，且学生无任何自救入口；结合服务端 120 秒宽限，超过后手动交卷同样失败，等同于答卷丢失。
- N4：成绩有效性被破坏。未提交的草稿被提前终结为 `GRADED`，学生无法再补充作答，且 `score_record` 已写入，需人工回滚；同时与 `returnReport` 的状态门禁语义冲突。

## 3. 目标与成功标准

### 3.1 目标

1. 作业截止时间成为真实业务门禁：服务端强制、前端同步只读。
2. 教师工作台的所有指标都限定在当前教师归属范围内，不存在全表聚合。
3. 考试交卷失败可自愈：计时器恢复、截止后只读、失败可重试且有明确提示。
4. 实验批改只发生在学生已提交的报告上，`SAVED` 状态不可被评分终结。

### 3.2 成功标准

- 作业过了 `dueAt` 后调用提交接口返回 `400`，不产生提交与查重记录。
- 学生停留在作业详情页直到倒计时归零时，编辑区立即变为只读，提交按钮不可点击。
- 教师 A 的看板查重数量与成绩趋势只包含教师 A 创建的活动与其所带班级；教师 B 的数据不可见。
- 考试交卷请求失败后，倒计时继续走动；到点后自动重试；页面不再出现静止的 `00:00`。
- 对 `SAVED` 实验报告调用批改接口返回 `400`，不写 `score_record`，提交状态保持 `SAVED`。
- 批改队列与批量批改页对 `SAVED` 报告不提供评分操作。

| 术语 | 定义 |

## 6. 核心流程

### 6.1 作业提交（含截止校验）

1. 学生打开作业详情，前端按 `dueAt` 计算是否截止，并每 1 秒刷新一次倒计时文案与只读态。
2. 倒计时归零时前端立即切换为只读态：编辑区禁用、提交按钮禁用。
3. 学生点击提交时，前端再次校验截止时间；已截止直接提示并不发请求。
4. 服务端 `submitHomework` 依次校验：作业存在且非 `DRAFT`、学生属于班级、`status != CLOSED`、`dueAt` 未过。
5. 全部通过后写入提交、执行查重分析、保存查重任务。
6. 任一校验失败返回 `40000`，不产生任何写操作。

### 6.2 教师工作台看板

1. 教师进入工作台，请求 `GET /api/v1/analysis/dashboard`。
2. 教学活动数、待批改数沿用 `created_by = teacherId` 口径。
3. 平均分沿用「教师所带班级 + 学校」口径。
4. 高风险查重数量改为「教师创建的作业」口径：`plagiarism_task.business_id` 是提交主键，必须先关联 `homework_submission`，再关联 `homework`，校验 `homework.created_by = teacherId`。
5. 近 7 天成绩趋势改为「教师所带班级 + 学校」口径，使用 `EXISTS` 关联任课关系。
6. 以上所有指标在同一响应内保持口径自洽，不出现全局值。

### 6.3 考试交卷与失败恢复

1. 学生点击交卷或倒计时归零触发自动交卷，前端 `stopTimer()` 进入提交态。
2. 提交成功：加载最新详情，进入结果页或阅卷中/待发布态，计时器不再需要。
3. 提交返回 `40000`「考试已提交，不能重复提交」：视为交卷已成功，执行 `loadExam()` 进入结果态，停止计时与重试。
4. 可重试失败（网络/超时/服务端 5xx）且尚有剩余时间：按保存的 `deadlineAt` 重新启动计时器，恢复作答。
5. 可重试失败且已到截止时间：页面进入截止只读态，展示「自动交卷失败」错误条，启动 10 秒间隔、最多 6 次的自动重试。
6. 业务拒绝（`ApiError.code < 50000`）：不自动重试，展示服务端文案并保留「重新交卷」按钮。
7. 用户点击「重新交卷」：立即重试并重置重试计数。
8. 重试成功：进入结果态并停止重试；重试全部失败：保留错误条与重试按钮，不静默。

### 6.4 实验报告批改

1. 教师从报告队列进入批改。
2. 服务端在取到提交行锁后校验 `submitStatus`：仅 `SUBMITTED` / `GRADED` 允许。
3. `SAVED` 直接返回 `40000`「学生尚未提交实验报告，不能批改」。
4. 通过后按现有逻辑逐项评分、汇总、置 `GRADED` 并写 `score_record`。

## 7. 功能需求

### FR-1 作业截止时间门禁（N1）

#### 7.1.1 后端

- `HomeworkService.submitHomework` 在 `status` 校验之后增加截止校验：`dueAt != null && OffsetDateTime.now().isAfter(dueAt)` 时抛出 `BusinessException(40000, "作业已截止，不能提交")`。
- 校验位置必须在任何写操作（提交、答案、查重任务、成绩）之前。
- `dueAt == null` 不限制提交。
- `accessiblePublishedHomework` 保持现有职责不变，不在此处混入时间判断。
- 不修改 `changeHomeworkStatus` 与自动关闭逻辑。

#### 7.1.2 前端

- `HomeworkDetail.vue` 新增 `isOverdue` 计算属性：`dueAt` 存在且当前时间晚于 `dueAt`。
- `readonly` 改为 `submissionStatus` 为 `SUBMITTED`/`GRADED` **或** `isOverdue`。
- 倒计时归零时通过定时器把 `isOverdue` 置为真，编辑区与提交按钮立即禁用，无需刷新。
- `submitForm` 首行增加截止判断，已截止直接 `ElMessage.warning('作业已截止，不能提交')` 并返回。
- 已截止页面的提示文案与现有「已截止」样式保持一致，不新增页面。

#### 7.1.3 验收标准

- `dueAt` 已过时调用提交接口返回 `400`，数据库无新增 `homework_submission`、`homework_answer`、`plagiarism_task`、`score_record`。
- `dueAt` 为空时提交成功。
- 学生停留在详情页跨过 `dueAt` 后，输入框与提交按钮立即变为不可用。
- 已 `SUBMITTED`/`GRADED` 的作业不受截止判断影响，仍按现有只读逻辑展示。

### FR-2 教师看板归属隔离（N2）

#### 7.2.1 高风险查重数量

- 统计范围：`plagiarism_task.similarity_rate > 50`，且该任务对应的作业由当前教师创建。
- 关联方式（唯一口径）：`plagiarism_task pt JOIN homework_submission hs ON hs.id = pt.business_id JOIN homework h ON h.id = hs.homework_id`，条件为 `pt.business_type = 'HOMEWORK' AND pt.similarity_rate > 50 AND h.created_by = ?`。`business_id` 是提交主键而非作业主键，禁止直接关联 `homework.id`。
- 当前不存在 `LAB` / `EXAM` 类型的查重任务，不为其编写空分支。
- 不允许使用无 `WHERE` 归属条件的 `COUNT(*)`。
- 卡片描述文案由「相似度超过 50% 的记录」改为「我布置的作业中相似度超过 50% 的记录」。

#### 7.2.2 近 7 天成绩趋势

- 时间窗保持「最近 7 天」。
- 方法签名调整为 `loadScoreTrendLast7Days(Long teacherId, Long schoolId)`，由 `getDashboard(CurrentUser teacher)` 传入 `teacher.id()` 与 `teacher.schoolId()`。
- 数据范围：`score_record` 关联 `class_room`，要求 `class_room.school_id = teacher.schoolId`，且存在 `class_teacher` 行满足 `class_id = score_record.class_id AND teacher_user_id = teacherId`。
- 任课关系统一使用 `EXISTS` 子查询，作为唯一写法；`class_teacher` 已有 `uk_class_teacher(class_id, teacher_user_id)`，若改用 `JOIN` 必须把 `teacher_user_id` 写进关联条件，禁止写成无教师条件的 `JOIN`。
- 按天聚合逻辑与返回结构（`date` / `scoreCount` / `avgScore`）保持不变。

#### 7.2.3 口径自洽

- `activityCount`、`pendingGradeCount` 保持 `created_by` 口径。
- `averageScore`、`sectionComparison`、`businessBreakdown` 保持「教师所带班级 + 学校」口径。
- 新增或修改的指标必须能在同一响应中与上述口径共存，不引入第三种归属定义。

#### 7.2.4 验收标准

- 构造两所学校、两名教师、各自班级与成绩数据：教师 A 的 `highRiskPlagiarismCount` 只统计 A 创建活动的高相似度任务。
- 教师 A 的 `trend` 只包含 A 所带班级的 `score_record`。
- 同一班级配置两名教师时，`scoreCount` 不因教师人数翻倍。
- 无任何教研活动的新教师：查重数量为 0，趋势为空数组，不报错。

### FR-3 考试交卷失败恢复（N3）

#### 7.3.1 计时器恢复

- `doSubmit` 失败时，若 `remainingSeconds > 0`，使用当前提交的 `deadlineAt` 重新 `startTimer`；该恢复逻辑对所有失败类型生效，保证任何失败后都不会停在 `00:00`。
- `deadlineAt` 必须保存在组件状态中（启动考试响应与详情响应均写入），失败恢复不得依赖重新请求。
- 重新启动后倒计时继续按真实剩余时间递减，不重置为原始时长。
- 恢复计时必须在 `submitting` 复位之后执行，避免计时器立即触发 `autoSubmit` 时被 `submitting` 拦截。

#### 7.3.2 截止只读与重试

- `remainingSeconds == 0` 时，作答控件全部禁用，提交按钮切换为「重新交卷」。
- 仅对可重试失败触发自动重试：网络/超时（异常不是 `ApiError`）与 `ApiError.code >= 50000` 的服务端 5xx；间隔 10 秒，最多 6 次；重试期间 `submitting=true`，禁止用户重复点击。
- `ApiError.code < 50000` 的业务拒绝（如 `40000`、`40300`）不自动重试，避免对确定性 `400` 反复请求；仅保留手动「重新交卷」。
- 收到 `40000`「考试已提交，不能重复提交」时按 D16 视为成功，调用 `loadExam()` 并停止重试。
- 用户点击「重新交卷」立即触发一次提交并重置重试计数。
- 重试成功或页面卸载时清理定时器。
- 重试全部失败后展示常驻错误条：「考试已结束，自动交卷失败，请立即重试或联系教师」。
- 交卷请求使用 `silent: true`，由页面统一展示一条错误信息，避免重试期间重复弹出全局提示。

#### 7.3.3 提交内容

- 交卷 payload 与草稿 flush 逻辑保持现状；`flushDraft` 返回布尔值且不抛异常，不阻断交卷。
- `remainingSeconds == 0` 时跳过 `flushDraft`：此时草稿接口必然被服务端拒绝，跳过可避免每次重试都产生一次注定失败的请求与重复提示；交卷仍由服务端按已持久化草稿兜底。
- 重试复用同一 `buildSubmitPayload`，不使用过期草稿。

#### 7.3.4 验收标准

- 模拟交卷接口 500：页面停留在作答态，倒计时继续递减，可再次提交成功。
- 模拟截止时自动交卷 500：页面进入只读态，出现错误条与「重新交卷」按钮，10 秒后自动重试。
- 自动重试 6 次后仍失败：错误条保持，按钮可点击，无无限请求。
- 点击「重新交卷」成功后进入结果态，重试定时器停止。
- 首次请求已成功但响应丢失、重试返回「考试已提交」：页面进入结果态，不显示失败。
- 服务端返回业务错误（如 `40300`）：不触发自动重试，页面展示服务端文案。
- 截止后编辑区不可修改。

### FR-4 实验报告批改状态门禁（N4）

#### 7.4.1 后端

- `gradeReport`：在取得 `findByLabIdAndStudentIdForUpdate` 行锁后，校验 `submission.getSubmitStatus()` 为 `SUBMITTED` 或 `GRADED`，否则抛出 `40000`「学生尚未提交实验报告，不能批改」。
- `confirmStepScore`：同样在行锁后增加相同校验。
- 门禁必须位于任何 `LabStepAnswer` 写分、`totalScore` 更新、状态变更与 `upsertScoreRecord` 之前。
- `refreshSubmissionAfterScoring` 的既有行为保持不变，由入口门禁保证不会被 `SAVED` 触发。
- 不做「自动把 SAVED 当提交」的兼容处理。

#### 7.4.2 前端

- `LabReports.vue`：`submitStatus === 'SAVED'` 的行不渲染「进入批量批改」按钮，仅保留现有「实验报告」按钮（`openReportView` → `teacher-lab-report-view`，新标签打开）；不新增第二个只读按钮，筛选与统计口径不变。
- `LabReportBatchGrade.vue`：当 `detail.submitStatus === 'SAVED'` 时，逐项「确认」「采纳」与总评提交按钮全部禁用（保留占位，不隐藏），页面顶部展示「学生尚未提交，当前为只读预览」。
- `LabReportDetail.vue`：该页同样包含逐项确认与总评提交（L161-L162、L458），`SAVED` 时全部禁用并展示只读提示。
- 只读预览仍可查看学生答案内容，不允许触发任何批改接口。
- 填空自动重判（`ExperimentBlankAnswerOverride`）路径按 D17 保持现状，不纳入本门禁。

#### 7.4.3 验收标准

- 对 `SAVED` 报告调用总评接口返回 `400`，提交状态仍为 `SAVED`，`score_record` 无新增。
- 对 `SAVED` 报告调用逐项确认接口返回 `400`。
- 对 `SUBMITTED` 报告批改成功，状态变为 `GRADED`。
- 对 `GRADED` 报告重复批改按现有逻辑成功（允许重判）。
- 批改队列中 `SAVED` 行无批改入口，只能查看。

## 8. 业务规则汇总

| 编号 | 规则 |
|---|---|
| R1 | 作业提交必须同时满足：非 `DRAFT`、属于该班级、`status != CLOSED`、未超过 `dueAt` |
| R2 | 作业截止以服务端时钟为准；前端只读仅作体验层配合，不作为唯一防线 |
| R3 | 教师看板指标只能来自「教师创建的活动」或「教师所带班级」，不存在全局聚合 |
| R4 | 班级与教师是多对多关系，班级维度的计数必须用 `EXISTS` 去重 |
| R5 | 考试交卷失败后必须恢复计时或进入可重试的截止态，不允许静默停摆 |
| R6 | 截止后学生不可继续编辑答案，只允许重试交卷 |
| R7 | 实验报告只有 `SUBMITTED` / `GRADED` 可被评分，`SAVED` 一律拒绝 |
| R8 | 本期不改数据库结构，不新增迁移 |

## 10. 非功能需求

### 10.1 性能

- 看板查重查询当前仅一次 `COUNT`（`business_type = 'HOMEWORK'`），结果集为标量，不引入 N+1。
- 趋势查询保持单次查询 + Java 内存按天聚合。
- 前端重试最多 6 次、间隔 10 秒，避免失败时请求风暴。

### 10.2 权限与安全

- 作业截止校验在服务端执行，不信任前端时间。
- 看板所有指标必须携带教师身份参数，禁止无参全表统计。
- 实验批改门禁必须在所有权校验之后、写操作之前执行。

### 10.3 兼容性

- 历史作业 `dueAt` 为空的行为不变。
- 历史 `SAVED` 实验报告在批改队列中降级为只读，不丢数据。
- 看板响应字段与结构不变，前端无需同步发版。

### 10.4 数据一致性

- 作业逾期提交被拒后，不产生半写入数据。
- 实验 `SAVED` 批改被拒后，`LabStepAnswer` 分数、提交状态、`score_record` 均不变。
- 交卷重试复用幂等提交逻辑，不产生重复 `exam_answer` 或 `score_record`。

## 11. 异常与边界场景

| 场景 | 期望行为 |
|---|---|
| 作业 `dueAt` 已过且 `status=PUBLISHED` | 提交返回 `40000`「作业已截止，不能提交」 |
| 作业 `dueAt` 为空 | 正常提交 |
| 学生页面停留在截止瞬间 | 前端立即只读，提交按钮不可用 |
| 作业截止后再次打开详情 | 直接只读，展示「已截止」 |
| 教师无任何教学活动 | 查重数量为 0，趋势为空数组 |
| 一个班级配置两名教师 | 两人都能看到该班数据，但计数不翻倍 |
| 交卷失败且剩余时间大于 0 | 计时器恢复，继续作答与提交 |
| 交卷失败且已到截止时间 | 只读 + 错误条 + 自动重试 + 手动重试 |
| 重试期间用户刷新页面 | 按 `IN_PROGRESS` 详情重新加载，倒计时继续，不做特殊补偿 |
| 实验报告为 `SAVED` | 批改接口返回 `40000`，页面只读预览 |
| 交卷响应丢失、重试返回「考试已提交」 | 视为成功，进入结果态 |
| 交卷返回业务错误（如 `40300`） | 不自动重试，展示服务端文案，保留手动重试 |
| 交卷返回服务端 5xx（`50000`） | 按可重试失败进入 10 秒自动重试，最多 6 次 |
| 超过 `deadlineAt + 120s` 后手动重试 | 返回 `40000`「考试已结束，无法提交」，保留错误条并提示联系教师 |
| 实验报告为 `SUBMITTED` | 正常批改，置 `GRADED` |
| 实验报告为 `GRADED` 再次批改 | 按现有逻辑允许重判 |

## 14. 风险与后续迭代

### 14.1 风险

- 作业截止改为服务端强制后，此前依赖逾期提交的历史学生行为会变为失败，需要产品侧提前告知。
- 看板口径收紧后，教师看到的查重数量与趋势会小于改造前，属预期变化。
- 考试重试逻辑需与既有 `submitting` 互斥配合，若处理不当可能出现重复提交；需以提交接口幂等性兜底验证。
- 实验 `SAVED` 批改入口收紧后，教师若已习惯对草稿评分会感到不便，需在页面给出明确只读提示。

### 14.2 后续迭代

- 服务端定时自动交卷，覆盖学生长期不打开页面的场景。
- 实验时间窗 `startAt/endAt` 的配置与校验。
