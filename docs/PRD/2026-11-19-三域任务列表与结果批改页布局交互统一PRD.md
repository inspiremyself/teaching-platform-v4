## 3. 目标与非目标

### 3.1 目标

1. 教师在三域之间切换时，列表页的骨架、列结构、筛选位置、状态表达与按钮位置完全一致。
2. 教师从任一域「查看结果」进入后，看到同一套「队列 / 逐题详情 / 评分汇总」三栏，批改动作在页面内完成，不再有弹窗遮挡队列。
3. 域专属能力（实验步骤配置、批量重判、批量批改、行为指标、图片作答、作业逐题保存、考试单一保存）全部保留，通过 Adapter 与 Strategy 融入统一骨架。
4. 共享组件与样式只有一份事实来源；三域页面模板不再各自实现同名 UI 结构。
5. 无后端、数据库、权限、契约变更；真实服务与真实账号下三域链路全绿。

### 3.2 非目标（明确否决）

| 非目标 | 结论与理由 |
|---|---|
| 合并三域业务路由、删除实验两级结果页 | 否决：继承 11-17 PRD D2 / D8，路由是既有入口契约，合并会破坏书签与返回语义 |
| 合并三域后端 DTO / API / 状态机 | 否决：本期是前端布局与交互统一，不涉及数据契约；11-17 PRD D8 继续单独立项 |
| 删除实验批量批改、批量重判、行为指标、图片查看 | 否决：均为高频域专属能力，通过模板内容插槽保留 |

## 4. 需求明细

### 4.1 列表页统一（Phase A）

**FR-1 骨架顺序**：三域列表页与实验总览页的模板顶层结构固定为 `WorkbenchShell`，插槽填充顺序严格为 `breadcrumb → title → description → actions → meta → toolbar → content`。面包屑文案按 D7 写死；列表页标题分别为「考试管理」「作业管理」「实验台账」，实验总览页标题为「实验结果」，描述沿用各域现网句子，不新增域外文案。

**FR-2 表格列**：`el-table` 四列按 D4 固定，列宽写死为：任务信息 `min-width 340`、任务节奏 `min-width 260`、提交概览 `width 200`、操作 `width 260` 且 `fixed="right"`。任务信息单元格 = 图标 + `StatusPill` + 标题 + 班级 / 时间窗 / 题项数 / 描述 meta；任务节奏单元格 = 开始 / 结束 / 时长三段；提交概览单元格 = 大数字提交数（`null` 显示「—」）+ 辅助行（作业有 `gradedCount` / `pendingCount` 时显示「已批改 x / 待批改 y」，其余显示「暂无统计」）。三域接口均无均分字段，本列不展示均分。实验动态题项数不放进列表列，留在总览页。

**FR-3 Adapter 契约**：`TaskRowVM` 字段按 D5 写死。`taskAdapters.ts` 唯一导出 `taskAdapterOf(domain)`，返回对象含 `adapt(raw): TaskRowVM` 与 `filtersOf(raw): { classId, status, deadlineBucket }`；三域原始字段到视图字段的映射在技术方案中逐字段写死，页面不得再写 `raw.xxx ?? 0` 兜底。适配 `null` 时返回空标题、状态「未知」、数值 0 的行，不抛异常。

**FR-4 操作策略**：`taskActionStrategies.ts` 唯一导出 `taskActionStrategyOf(domain, status)`，返回 `{ actions: TaskActionVM[], primaryKey: string }`。`TaskActionVM` 固定 `{ key, label, tone, handler }`，`tone` 取 D10 四档。策略表按域与状态完整枚举，不写「其余同考试」式省略；`handler` 由页面注入各动作的既有函数，路由跳转与 API 调用的细节由技术方案逐动作写死，策略只决定有哪些动作。发布态与关闭态由策略明确给出，页面不重复判断。

**FR-5 筛选与统计**：筛选区按 D8 渲染四项固定控件，meta 行按 D9 渲染 6 枚 chip。搜索为本地按标题 / 描述 / 班级名匹配，状态 / 班级 / 时效为本地筛选；时效判定以 `TaskRowVM.endAt` 为准，实验取 `dueAt` 后与作业同规则，筛选结果数实时更新。考试与作业列表页已有「锁定状态」提示继续保留在 meta 行。

**FR-6 编辑弹窗**：三域编辑弹窗统一复用新增共享组件 `workbench/TaskEditorDialog.vue`，固定 1040px、统一 shell 与徽章区、统一左右两栏（左表单与题目配置，右已选题目清单）。`WorkbenchShell` 只负责页面骨架，不提供弹窗。实验「步骤配置」沿用独立页面路由，不塞进弹窗；作业题目配置继续复用 `QuestionConfigList` 系列组件。各域只向 `TaskEditorDialog.vue` 提供表单内容。

### 4.2 结果页与批改统一（Phase B）

**FR-7 三栏工作区**：`GradingWorkspace` 的三个插槽固定名 `queue` / `detail` / `summary`，宽度与窄屏规则按 D3。队列插槽只接受 `SubmissionQueue`；汇总插槽统一渲染「客观题自动得分 / 主观题人工得分 / 总分」三行与评分进度，算法继续调用 11-19 已交付的 `buildScoringSummary`。中栏按域提供内容：考试逐题卡、作业逐题卡、实验逐题卡 / 批量题项表。

**FR-8 队列归一化**：`submissionAdapters.ts` 唯一导出 `submissionAdapterOf(domain)`，`adapt(raw): QueueItemVM` 按 D11 写死。考试直接读条目的 `autoScore` / `manualScore` / `totalScore`；作业从条目 `questions` 按 `scoreSource` 分流后汇总，无明细时两段为 `null`；实验队列条目无逐题字段，两段初始为 `null`，当前详情加载后由 Facade 用 `buildScoringSummary` 回填。三段中的总分始终取条目的 `totalScore ?? null`，禁止用 `totalScore` 反推客观 / 主观分。`draftFlag` 在 Adapter 出口由 Facade 注入。状态中文标签沿用三域现网状态机，Adapter 内集中映射。

**FR-9 队列交互**：左队列顶部固定搜索框与状态筛选，条目点击后在中栏加载详情；切换前按 D15 执行草稿保护确认。考试现网 `selectionToken` 竞态防护、作业 `guardDraft`、实验详情与批量页翻页守卫全部保留，由 `useWorkbench` Facade 统一暴露 `selectSubmission` 与 `guardBeforeSwitch`。

## 6. 已否决方案

| 方案 | 否决理由 |
|---|---|
| 只做 CSS 类名合并，保留三套 DOM 结构 | 结构差异（卡片行 / 表格 / 弹窗）无法通过样式收敛，教师仍需三套心智模型 |
| 把三域页面合成一个带大量 `v-if` 巨型组件 | 域差异会渗进模板，违反 Adapter + Strategy 的分工；可维护性低于共享层方案 |
| 统一后端 DTO 与 API，让前端天然同形 | 触及契约、权限、迁移与既有测试，超出布局需求，风险与收益不成比例 |
| 删除实验总览矩阵，只保留评分台 | 矩阵承载全班 × 题项作答分布与行为指标，删除即功能回归，且与 11-17 PRD D2 冲突 |
| 把作业逐题保存与批量批改一并改成考试式单一整卷保存 | 11-19 PRD D1 明确保留域粒度差异，删除高频能力属回归 |
| 新增通用 UI 组件库或引入 CSS-in-JS | 无需求输入，新增依赖违背现有工具链约束 |
| 修改 `assets/global.css` 承接全部共享样式 | 与 11-19 技术方案 TD20 冲突；样式应随共享组件落 `workbench/` 目录 |
