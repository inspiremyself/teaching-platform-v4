## 2. 背景与问题定位

### 2.1 背景

教师端“考试批改工作流”页面（`frontend/src/views/teacher/exams/Results.vue`）用于按提交队列批改学生答卷。现有纯客观题考试在交卷后出现三个连锁问题：队列长期显示“待评分”、点击“保存评分”报错、学生答案显示为 `[object Object]`。

本次问题不是数据缺失：学生已正常交卷（`submittedAt` 有值），客观题也已自动判分（自动分、总分、对错标记均已落库）。

### 2.2 根因

| 编号 | 现象 | 根因 |
|---|---|---|
| P1 | 点击“保存评分”提示“不能为空” | 前端 `submitGrade` 只收集“无客观对错标记”的主观题（`isManualQuestion = isCorrect === null`）；全客观题答卷收集结果为空数组。后端 `GradeExamSubmissionRequest.answers` 标注 `@NotEmpty`，空数组直接返回 400，校验默认文案为“不能为空” |
| P2 | 学生已提交仍显示“待评分” | `submitExam` 先按截止时间把状态置为 `SUBMITTED` / `AUTO_SUBMITTED`；随后全客观题自动评分完成时没有把状态提升为 `GRADED`。状态只在教师批改/确认后由 `recomputeSubmissionAfterTeacherConfirmation` 改写。叠加 P1 后按钮必然失败，形成死循环 |
| P3 | 学生答案显示 `[object Object]` | 学生端提交的 `answerJson` 为结构化载荷（如 `{"kind":"single","selectedKey":"B"}`）；教师端格式化函数只处理 JSON 数组，对象分支直接 `String(parsed)` |
| P4 | 建议分恒为 `-`、判题说明恒为兜底文案 | 提交详情接口只返回 `studentAnswer` / `isCorrect` / `score` / `teacherComment`，未返回 `suggestedScore`、`judgeDetail`、`scoreSource`、`autoScore` |
| P5 | 超时提交状态显示英文枚举 | 前端使用 `TIMEOUT` 这一后端不存在的状态值，后端实际值为 `AUTO_SUBMITTED`，导致筛选失效且标签直出枚举名 |
| P6 | 全客观题提交不写成绩记录（部分可见性下） | 交卷链路仅在“无主观题且当前可见”时写入 `score_record`；状态未结案导致 `AFTER_TEACHER_CONFIRM` 下始终不写，学生成绩也无法产生 |

参考既有产品口径：同目录《Linux 随堂客观题考试与题目导入 PRD》FR-7 已明确“纯客观题试卷提交后即有成绩，无需人工确认”；作业链路也已在答案全部有分时自动置为 `GRADED`（`HomeworkService`）。本次修复是把该口径落到考试链路。

## 3. 目标与成功标准

### 3.1 目标

1. 全客观题答卷交卷后即为“已评分”，教师无需再做无意义的人工评分动作。
2. 教师端“保存评分”不再因空请求报错；历史卡住的全客观题提交可通过同一按钮结案。
3. 教师端可正确阅读学生答案与标准答案，不出现 `[object Object]`。
4. 建议分、判题说明、分数来源等自动评分信息在批改页可见。
5. 提交状态展示与后端枚举完全一致，超时提交可被筛选。

### 3.2 成功标准

- 纯客观题考试交卷后，教师端队列立即显示“已评分”，待处理数不包含该提交。
- 对历史仍为“待评分”的纯客观题提交，点击“保存评分”返回成功并结案，分数不变。
- 含主观题的考试仍显示“待评分”，教师批改后变为“已评分”。
- 学生答案展示为可读选项（如 `B`），标准答案同样可读。
- 批改页“建议分”显示实际推荐分，判题说明显示后端落地文案。
- 超时提交显示“超时提交”，筛选下拉选项值为 `AUTO_SUBMITTED`。

| 术语 | 定义 |
|---|---|
| 主观题 | 需要人工评阅的题型；交卷时 `isCorrect` 为 `null`、`score` 为 `null` |

| 结案 | 提交状态变为 `GRADED`，分数与成绩记录确定 |

## 6. 核心流程

### 6.1 学生交卷（全客观题）

1. 学生提交答卷，后端逐题自动判分。
2. 若所有题目均为客观题，提交状态直接置为 `GRADED`。
3. 按 `canStudentSeeScore` 判定是否写入 `score_record`。
4. 学生端按考试成绩可见性展示结果；教师端队列立即显示“已评分”。

### 6.2 学生交卷（含主观题）

1. 客观题自动判分，主观题 `score` / `isCorrect` 置空。
2. 提交状态保持 `SUBMITTED`（超时为 `AUTO_SUBMITTED`）。
3. 教师在批改页逐题录入分数与评语，点击“保存评分”。
4. 全部主观题均有分后状态变为 `GRADED`，写入成绩记录。

### 6.3 历史卡单结案

1. 教师打开仍显示“待评分”的纯客观题提交。
2. 点击“保存评分”（此时人工评分项为空）。
3. 后端接受空列表，重算分数并按“全部已评分”结案为 `GRADED`。
4. 页面刷新后该提交显示“已评分”。

## 7. 功能需求

### FR-1 全客观题自动结案

#### 7.1.1 规则

- `submitExam` 完成逐题评分后，若 `hasManualGrading=false`，提交状态置为 `GRADED`。
- 若存在主观题，状态保持交卷时按截止时间判定的 `SUBMITTED` / `AUTO_SUBMITTED`。
- 状态覆盖发生在分数汇总与 `submittedAt` 落库之后，返回体 `status` 与落库一致。
- 不改动 `in_progress` 判定、重复提交拦截、截止时间判定。

#### 7.1.2 成绩记录

- 结案后按现有 `canStudentSeeScore` 判定写入 `score_record`，遵循“存在则更新、不存在则创建”的现状实现。
- `MANUAL_RELEASE` 下全客观题结案后不写成绩记录（`canStudentSeeScore=false`），发布成绩链路本期不补写；该行为与现网一致，列入非目标。
- `AFTER_DEADLINE` 按交卷时的 `canStudentSeeScore` 即时结果决定：截止时间已过则写，未过则不写且本期不补写。
- 自动分、人工分、总分口径不变：全客观题人工分为 0，总分为自动分。

#### 7.1.3 验收标准

- 纯客观题、`IMMEDIATE` 考试交卷后状态为 `GRADED`，存在成绩记录。
- 纯客观题、`AFTER_TEACHER_CONFIRM` 考试交卷后状态为 `GRADED`，存在成绩记录。
- 纯客观题、超时自动交卷（`AFTER_TEACHER_CONFIRM`）后状态为 `GRADED`，存在成绩记录。
- 含主观题考试交卷后状态为 `SUBMITTED`，无成绩记录（`AFTER_TEACHER_CONFIRM` 下）。
- 自动结案后教师端队列该提交显示“已评分”，待处理数减 1。

### FR-2 保存评分兼容空人工评分

#### 7.2.1 请求约束

- `GradeExamSubmissionRequest.answers` 允许为空数组，不再返回 400“不能为空”。
- 题目项字段约束不变：`questionId` 非空、`score` 非空。

#### 7.2.2 处理规则

- 空数组时跳过逐题更新，直接重算该提交的自动分、人工分、总分。
- 重算判定“全部主观题是否均有分”：是则置 `GRADED` 并写成绩记录；否则状态统一置为 `SUBMITTED`。
- 空数组重算后仍未结案时，原 `AUTO_SUBMITTED` 不再保留，降为 `SUBMITTED`；此为本期沿用现网 `recomputeSubmissionAfterTeacherConfirmation` 的行为，不新增状态保持逻辑。
- 非空数组时行为不变：仅更新主观题，客观题自动分不允许被覆盖。
- 自动结案为 `GRADED` 后，逐题确认接口 `confirmAnswer` 仍按现网规则可用，不因本期新增状态拦截。

#### 7.2.3 前端行为

- 无主观题时，“保存评分”仍调用同一接口，请求体为 `{ "answers": [] }`。
- 成功后提示“评分保存成功”并刷新队列。
- 请求进行中按钮置禁用态（复用现有 `submitting` 状态），禁止并发重复提交；请求结束后恢复。
- 含主观题时按现有逻辑逐题提交分数与评语。

#### 7.2.4 验收标准

- 全客观题历史卡单点击“保存评分”返回 200，状态变为 `GRADED`，分数前后一致。
- 连续点击“保存评分”时按钮在请求期间禁用，只产生一次结案请求，分数与状态一致。
- 含未评分主观题的答卷提交空数组时返回 200，但状态为 `SUBMITTED`。
- 含主观题的答卷正常评分后状态为 `GRADED`。
- 客观题分数不会被人工评分请求覆盖。

### FR-3 教师端答案展示

#### 7.3.1 学生答案格式

按以下顺序解析 `studentAnswer` / `standardAnswer`：

1. 空值 → “未作答”。
2. JSON 解析失败 → 原样展示字符串。
3. JSON 数组 → 元素以“，”连接。
4. JSON 对象含 `kind` 字段：
   - `single` → `selectedKey`
   - `multiple` → `selectedKeys` 以“，”连接
   - `judge` → `TRUE` 显示“正确”，`FALSE` 显示“错误”
   - `fill` → `blanks[].answer` 非空项以“，”连接
   - `code` → `code`
   - `text` → `text`
5. JSON 对象为答案描述（无 `kind`）→ 按 `correctAnswer` → `correct` → `answer` → `answers` → `blanks` 顺序取第一个非空字段：
   - 字段值为数组 → 各元素以“，”连接；
   - 数组元素或字段值为对象 → 取其中的 `answer` / `text` / `value` 字段；
   - `blanks` 元素为字符串时取自身，为对象时取 `answer`；
   - 上述步骤仍无法得到标量 → 原样展示该字段的 JSON 字符串。
6. 其他 JSON 标量 → 字符串化展示。

#### 7.3.2 展示要求

- 空字符串、空白字符串、解析后无有效内容均显示“未作答”。
- 不得出现 `[object Object]`、`undefined`、`null` 字样。
- 只读展示，不在批改页编辑学生答案。

#### 7.3.3 验收标准

- `{"kind":"single","selectedKey":"B"}` 显示 `B`。
- `{"kind":"multiple","selectedKeys":["A","C"]}` 显示 `A，C`。
- `{"kind":"judge","value":"TRUE"}` 显示 `正确`。
- `{"kind":"fill","blanks":[{"index":1,"answer":"pwd"}]}` 显示 `pwd`。
- `["A"]` 显示 `A`。
- `null` 显示“未作答”。

### FR-4 提交详情补全自动评分字段

#### 7.4.1 接口字段

`GET /api/v1/teacher/exam-submissions/{id}` 的 `answers[]` 在现有字段基础上补充：

| 字段 | 来源 | 说明 |
|---|---|---|
| `autoScore` | `exam_answer.auto_score` | 自动评分得分 |
| `suggestedScore` | `exam_answer.suggested_score` | 推荐分 |
| `scoreSource` | `exam_answer.score_source` | 分数来源（`AUTO` / `RECOMMENDED` / `TEACHER` / `AUTO_ACCEPTED`） |
| `judgeDetail` | `exam_answer.judge_detail` | 判题说明 |
| `acceptedAutoScore` | `exam_answer.accepted_auto_score` | 是否已采纳自动评分 |

- 字段缺失时返回 `null`；前端映射固定为：`suggestedScore` 缺失显示 `-`，`judgeDetail` 缺失或空白显示“当前无自动判题说明。”，其余字段缺失不渲染。
- 不改变现有字段语义与权限校验。

#### 7.4.2 验收标准

- 客观题“建议分”显示实际数值，不再恒为 `-`。
- 有判题说明时展示后端文案，无说明时才展示兜底文案。
- 学生端、教师成绩页现有字段不受影响。

### FR-5 提交状态枚举对齐

#### 7.5.1 状态映射

| 后端状态 | 展示文案 | 色调 |
|---|---|---|
| `IN_PROGRESS` | 进行中 | info |
| `SUBMITTED` | 待评分 | warning |
| `AUTO_SUBMITTED` | 超时提交 | danger |
| `GRADED` | 已评分 | success |

#### 7.5.2 筛选与计数

- 状态下拉选项为上述四项，值与后端枚举一致。
- 移除 `TIMEOUT` 选项及其分支。
- 待处理计数口径为 `SUBMITTED` + `AUTO_SUBMITTED`。

#### 7.5.3 验收标准

- 超时提交在队列显示“超时提交”。
- 选择“超时提交”能筛出对应记录。
- 顶部“待人工处理”数量与实际待处理记录一致。

|---|---|
| `POST /api/v1/exams/{id}/submit` | 返回体 `status` 可能为 `GRADED`（全客观题）；字段结构不变 |
| `POST /api/v1/teacher/exam-submissions/{id}/grade` | 请求 `answers` 允许空数组；行为见 FR-2 |
| `GET /api/v1/teacher/exam-submissions/{id}` | `answers[]` 增加 `autoScore` / `suggestedScore` / `scoreSource` / `judgeDetail` / `acceptedAutoScore` |
| `GET /api/v1/teacher/exams/{id}/results` | 无契约变更，仅状态值可能出现 `GRADED` |

### 9.3 前端契约

- `frontend/src/types/exam.ts` 中 `ExamAnswerDetail` 已声明上述可选字段，无需新增类型；`ExamSubmissionListItem.status` 与 `ExamSubmissionDetail.status` 现为 `string`，本期不新增状态联合类型。
- 只在 `Results.vue` 内移除 `TIMEOUT` 字面量并改为 `AUTO_SUBMITTED`，状态下拉、标签映射、待处理计数三处同步。
- 请求仍统一通过 `frontend/src/utils/request.ts`。

## 10. 非功能需求

### 10.1 性能

### 10.2 权限与安全

- 仅考试创建教师可查看提交详情与评分，沿用现有校验。
- 状态流转不改变角色权限。

### 10.3 兼容性

- 历史 `SUBMITTED` / `AUTO_SUBMITTED` 记录可继续批改与结案。
- 旧客户端提交空 `answers` 由本期修复后合法；旧客户端提交非空 `answers` 行为不变。
- 学生端已有 `AUTO_SUBMITTED` 展示逻辑，不受影响。

### 10.4 数据一致性

- 结案后总分 = 自动分 + 人工分，且与逐题得分之和一致。
- 成绩记录与提交状态在同一事务内完成。

## 11. 异常与边界场景

| 场景 | 预期行为 |
|---|---|
| 全客观题交卷 | 状态 `GRADED`；教师端可查看成绩；学生端按考试可见性规则决定，`MANUAL_RELEASE` 下不可见 |
| 超时全客观题交卷 | 状态 `GRADED`，队列不再出现待处理 |
| 含主观题且未批改 | 状态保持 `SUBMITTED`，显示“待评分” |
| 含主观题部分批改 | 已批改题目落分，未批改题目保持空分，状态仍为“待评分” |
| 对全客观题提交空批改 | 返回 200 并结案，不报“不能为空” |
| 对学生答案为空 | 显示“未作答” |
| 答案 JSON 损坏 | 原样展示原始字符串，不报错 |
| 标准答案为 `{"correctAnswer":"B"}` | 显示 `B` |
| 题目为非题库题或快照缺失 | 沿用现有 `resolveQuestionSnapshot` 异常处理，本期不改 |
| 重复点击“保存评分” | 已结案提交再次提交时按后端状态校验返回业务提示，不重复写成绩记录 |
| 状态值未知 | 原样展示后端值，不抛错 |

## 13. 现状差距与改造点

| 差距 | 现状 | 改造方向 |
|---|---|---|
| 全客观题不结案 | 交卷状态恒为 `SUBMITTED` / `AUTO_SUBMITTED` | 评分完成后无主观题即置 `GRADED` |
| 空批改被拒 | `answers` 标注 `@NotEmpty` | 允许空数组并按重算结果结案 |
| 答案对象化 | 教师端只处理数组，对象输出 `[object Object]` | 与学生端共用 `kind` 解析口径 |
| 自动评分信息缺失 | 详情接口未返回推荐分与判题说明 | 补齐五个逐题字段 |
| 状态值不一致 | 前端使用后端不存在的 `TIMEOUT` | 对齐四值枚举，`AUTO_SUBMITTED` 显示“超时提交” |
| 成绩记录缺失 | `AFTER_TEACHER_CONFIRM` 下全客观题永不写成绩 | 结案后按现有可见性规则写入 |

## 14. 风险与后续迭代

### 14.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 纯客观题交卷即可见成绩 | 选择“教师确认后可见”的教师会看到学生交卷即出分 | 该模式对纯客观题不存在待确认动作；如需延迟发布，后续开放 `MANUAL_RELEASE` 入口 |
| 历史卡单需逐条结案 | 教师需对存量记录各点一次“保存评分” | 数量有限且操作幂等；本期不做批量修复脚本 |
| 客观题教师复核 | `gradeSubmission` 仅更新主观题，客观题自动分不会被人工评分请求覆盖；`confirmAnswer` 的逐题确认能力保持现网行为 | 批改页不提供客观题改分输入，自动结案不阻断教师逐题确认，影响可接受 |
| 答案格式继续演进 | 后续新增题型载荷可能导致展示缺失 | 格式化规则集中收敛，新增 `kind` 时同步扩展 |

### 14.2 后续迭代

- 教师端开放“手动发布成绩”，支持纯客观题延迟发布。
- 历史卡单批量结案工具。
- 批改页批量评分与评分模板。
- 逐题自动评分明细可视化。
