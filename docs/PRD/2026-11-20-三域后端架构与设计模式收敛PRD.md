## 4. 需求明细

### 4.1 Phase 1 · D3：删除隐式降级，改强注入

1. `assessment/service/GradingAdapter.java` 删除 `@Autowired ObjectProvider` 构造器（L43-46）与 `fallbackResult()`（L92-113）及其在 `grade()` L69-71 的调用分支；保留 `(ScoringEngine)` 单参构造器与 `(ScoringEngine, ObjectMapper)` 双参构造器，**仅单参构造器标注 `@Autowired`**（Spring 用它在两个 `@DataJpaTest` 切片中只依赖已 import 的 `ScoringEngine`；双参构造器专供纯 UT，不标注注解）。
2. 8 个业务 service 删除 `gradingAdapterProvider` 字段/构造器参数/赋值与 `new GradingAdapter(...)`，改为构造器强注入 `GradingAdapter`。
3. `ObjectMapper` 按现网真实用途分两类处理，写死如下：
   - **保留原样**：`ExamServiceSupport`（L140/167/169/200/256）、`HomeworkServiceSupport`（L170/180）、`HomeworkConfigService`（L597/640）的 `objectMapper` 字段与 `objectMapperProvider.getIfAvailable(ObjectMapper::new)` 装配逻辑完全不动，仅不再把 `objectMapper` 传给 GradingAdapter。
   - **整段删除**：`ExamAnswerService`、`ExamConfigService`、`ExamReportService`、`HomeworkReportService`、`HomeworkAnswerService` 的 `objectMapper` 字段、`objectMapperProvider` 构造器参数与赋值、对应 import——这五个类的 `objectMapper` 现网仅用于构造 GradingAdapter（2026-11-20 实测）。
4. 测试连带按 D4 执行：`ExamServiceTests`、`HomeworkServiceTests` 的 `@Import` 增加 `GradingAdapter.class`，使真实 bean 进入切片；不得用 `@MockBean GradingAdapter`（会让自动判分断言失效）。
5. 验收：`./mvnw test` 全绿；全仓生产代码 grep `new GradingAdapter` 为 0 命中；`getIfAvailable` 仅允许上述三个保留类的 `ObjectMapper::new`，不出现 GradingAdapter / ScoringEngine 的隐式降级构造。

### 4.2 Phase 1 · D5：成绩可见性策略收敛

1. 新增 `grading/support/ScoreVisibilityPolicy`，形态为 record 配置 + 单一判定方法，配置常量三个：`LAB(finalStateGate=false, immediateRequiresScore=true)`、`HOMEWORK(false, false)`、`EXAM(true, false)`。
2. 判定输入：`mode`、`submissionPresent`、`finalState`、`scorePresent`、`deadline`、`released`；`mode == null` 统一按 `AFTER_TEACHER_CONFIRM` 处理（D11 行为变化①）。
3. 判定逻辑逐格对齐现网：`submissionPresent == false → false`；`finalStateGate && !finalState → false`；`IMMEDIATE → immediateRequiresScore ? scorePresent : true`；`AFTER_TEACHER_CONFIRM → finalState`；`AFTER_DEADLINE → deadline != null && !now.isBefore(deadline)`；`MANUAL_RELEASE → released`。
4. 三个业务方法改为委派：`LabServiceSupport.scoreVisible`、`HomeworkConfigService.isStudentScoreVisible`、`ExamServiceSupport.canStudentSeeScore`；各自构造入参时只负责取本域 deadline 字段（`lab.endAt` / `homework.dueAt` / `exam.endAt`）与 `finalState` 判定（`lab`/`homework` 为 `submitStatus == GRADED`，exam 为 `isFinal`）。
5. N6 列出的 8 处调用方方法体零改动；策略组件不接收 `CurrentUser`，不做角色鉴权。
6. 允许的行为变化仅 D11①：homework 的 mode null 从 NPE 改为 `AFTER_TEACHER_CONFIRM` 判定，须在 `ScoreVisibilityPolicyTests` 用特征用例锁定。

### 4.3 Phase 1 · D8：题型别名收敛

1. `grading/enums/QuestionType` 新增三个静态方法/实例方法：
   - `fromAlias(String)`：`trim().toUpperCase(Locale.ROOT)`，null/blank 返回 null；
   - `isObjective()`：`SINGLE_CHOICE` / `MULTIPLE_CHOICE` / `TRUE_FALSE` / `FILL_BLANK` 返回 true，其余 false（考试/判分语义，N14）；
   - `legacyCode()`：返回 `SINGLE` / `MULTI` / `JUDGE` / `FILL` / `SHORT` 五个字符串规范值。
2. `fromAlias` 必须完整接受 14 个别名：`SINGLE`、`SINGLE_CHOICE`、`MULTI`、`MULTIPLE`、`MULTIPLE_CHOICE`、`JUDGE`、`TRUE_FALSE`、`FILL`、`FILL_BLANK`、`SHORT`、`TEXT`、`SUBJECTIVE`、`CODE`、`SHORT_ANSWER`；未知值返回 null。
3. 四处调用点改为委派：
   - `GradingAdapter.toGradingQuestionType` → `QuestionType.fromAlias`，null/blank 仍返回 null，不改 `grade()` 对未知题型抛异常的行为；
   - `QuestionContentValidator.normalizeType` → `QuestionType.fromAlias(...).legacyCode()`，其内部 `switch` 与 `SINGLE/MULTI/...` 常量保持不变。写死映射：`CODE` / `SHORT_ANSWER` 经 `fromAlias` 归 `SUBJECTIVE`、`legacyCode()` 归一为 `SHORT`，因此这两种题型现网抛 40000 的输入将改为按简答题规则校验（D11④），其余 12 个别名与现网逐字符一致；
   - `ExamScoringService.isObjective` → `QuestionType.fromAlias(type)` 后调用 `isObjective()`，null/未知仍返回 false；
   - `LabScoringSupport.resolveQuestionType` → `QuestionType.fromAlias(rawType)`，保留 snapshot/legacy/step 三级取值来源与 `rawType == null → null` 的行为。
4. `LabConfigService.isObjectiveQuestion` 保留局部实现，不换成全局 `isObjective()`（因其排除填空题，N14）。
5. 允许的行为变化为 D11②–⑤：lab 侧新增识别 6 个简写；homework/exam 入口经 `GradingAdapter.toGradingQuestionType` 新增识别 `CODE`/`SHORT_ANSWER`；`QuestionContentValidator` 新增接受 `CODE`/`SHORT_ANSWER` 并按 `SHORT` 校验；`ExamScoringService.isObjective` 改用 `Locale.ROOT` 并 trim（`" SINGLE "` 由 false 变 true）。其中 D11②③⑤ 在 `QuestionTypeTests` 用特征用例锁定；D11④ 的 validator 入口在 `QuestionContentValidatorTests` 用 2 个新用例锁定，其既有 9 个用例断言保持不变（含 `UNKNOWN` 仍抛 40000）。

### 4.4 Phase 2 · D6：提交结算骨架收敛（承接 2026-11-17 PRD D8）
