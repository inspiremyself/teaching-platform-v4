**状态**：已定稿（决策写死，可直接编码）
**范围**：前端 axios 拦截器不再越俎代庖地弹错误/跳登录页；后端区分"账号被禁用"场景给出明确提示；登录页面内联 alert 成为唯一提示入口

## 1. 背景与诉求

### 1.1 现状问题

密码（或用户名/角色）登录失败时，用户遭遇**三层逻辑叠加**导致的混乱体验：

```
用户输入错误密码
  → 后端 AuthService 抛 BusinessException(40101, "用户名、密码或角色错误")
  → GlobalExceptionHandler 返回 HTTP 400 + ApiResponse
  → 前端 axios 错误拦截器执行：
      ① ElMessage.error(...)              ← 第一次弹窗
      ② authStore.logout()
      ③ window.location.href = '/login'   ← 强制刷新，用户已在登录页
  → Login.vue catch 块尚未来得及执行，或页面上出现双重提示
```

### 1.2 目标

1. 登录失败只由登录页的内联 alert 提示，拦截器不再介入。
2. 账号被禁用时给出明确文案，便于用户理解"为什么登不上"。
3. 用户名不存在 / 密码错误 / 角色不匹配 继续共用模糊文案，防用户名枚举。
4. 改动面收敛，不引入新依赖、新表、新迁移。

## 6. L3 必做：错误码与文案收敛（继承 L1+L2）

### 6.1 后端：常量自然收敛

L2 已新增 `LOGIN_DISABLED_CODE = 40103` 与 `LOGIN_DISABLED_MESSAGE`。`AuthService.java:35-38` 将有以下 4 个 `private static final` 常量，全部保留现状（不提取为 enum 或独立类——auth 包内仅 AuthService 引用，过度抽象无收益）：

```java
private static final int LOGIN_ERROR_CODE = 40101;
private static final String LOGIN_ERROR_MESSAGE = "用户名、密码或角色错误";
private static final int LOGIN_CONFLICT_CODE = 40901;
private static final String LOGIN_CONFLICT_MESSAGE = "该账号已在其他设备登录，继续登录将使旧设备下线";
private static final int LOGIN_DISABLED_CODE = 40103;         // L2 新增
private static final String LOGIN_DISABLED_MESSAGE = "该账号已被停用，请联系管理员";  // L2 新增
```

### 6.2 前端：LOGIN_ERROR_MAP 收敛

Login.vue 内声明常量映射表，`resolveLoginError` 改为查表优先：

**新增常量（script setup 顶层）**：

```typescript
const LOGIN_ERROR_MAP: Record<number, string> = {
  40101: '用户名、密码或角色错误',
  40103: '账号已停用，如有疑问请联系学校管理员',
  40901: '该账号已在其他设备登录，继续登录将使旧设备下线'
};
```

**改造后的 resolveLoginError**：

```typescript
const resolveLoginError = (error: unknown) => {
  if (error instanceof ApiError) {
    return LOGIN_ERROR_MAP[error.code] || error.message || '登录失败，请检查账号、密码和当前身份是否正确';
  }
  const message = error instanceof Error ? error.message : '';
  return /status code 400/i.test(message)
    ? '登录失败，请检查账号、密码和当前身份是否正确'
    : message || '登录失败，请检查账号、密码和当前身份是否正确';
};
```

**改造收益**：
- 所有登录错误码 → 文案映射集中在一处新增量，后续加码（如频率限制）只需追加一行
- 消除当前 `resolveLoginError` 中隐式依赖 `error.message` 完整返回后端原始消息的假设
