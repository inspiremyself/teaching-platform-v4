现网核对结论：

1. `plagiarism_task.business_type` 为 `@Enumerated(EnumType.STRING)`，库内值为 `'HOMEWORK'`；`business_id` 由 `HomeworkService` 写入的是 `homework_submission.id`，故 TD5 的两级关联成立。
2. `homework.created_by`、`homework_submission.homework_id`、`score_record.class_id`、`class_room.school_id`、`class_teacher.teacher_user_id` 均为现网已有列，无需 DDL。
3. `class_teacher` 存在唯一约束 `uk_class_teacher(class_id, teacher_user_id)`，TD6 的 `EXISTS` 不会放大 `scoreCount`。
4. `ExamService.submitExam` 对非 `IN_PROGRESS` 返回 `40000`「考试已提交，不能重复提交」，文案与 TD12 匹配；超过 `deadlineAt + 120s` 返回 `40000`「考试已结束，无法提交」。
5. `request.ts` 对 HTTP 400 且 `code=40000` 的响应 reject `ApiError(40000, message)`，对 5xx 未捕获异常返回 `ApiError(50000, ...)`；TD10 的 `code >= 50000` 分类与现网一致。
6. `PlagiarismService.ownsHomeworkSubmission` 已采用 `homework_submission hs JOIN homework h ON hs.homework_id = h.id WHERE hs.id = ? AND h.created_by = ?` 的归属口径，TD5 与其完全一致，无需新增私有方法。

```java
private List<Map<String, Object>> loadScoreTrendLast7Days(Long teacherId, Long schoolId) {
    OffsetDateTime since = OffsetDateTime.now().minusDays(7);
    Map<LocalDate, List<Double>> scoresByDay = new TreeMap<>();
    jdbcTemplate.query(
            "SELECT sr.graded_at, sr.score FROM score_record sr " +
                    "JOIN class_room cr ON cr.id = sr.class_id " +
                    "WHERE sr.graded_at >= ? AND cr.school_id = ? " +
                    "AND EXISTS (SELECT 1 FROM class_teacher ct WHERE ct.class_id = sr.class_id AND ct.teacher_user_id = ?)",
            (rs, rowNum) -> {
                var timestamp = rs.getTimestamp("graded_at");
                if (timestamp != null) {
                    LocalDate day = timestamp.toLocalDateTime().toLocalDate();
                    scoresByDay.computeIfAbsent(day, ignored -> new ArrayList<>()).add(rs.getDouble("score"));
                }
                return null;
            },
            since, schoolId, teacherId
    );
    // 其余按天聚合代码保持不变
}
```

```ts
function clearRetryTimer() {
  if (retryTimer) {
    window.clearTimeout(retryTimer)
    retryTimer = undefined
  }
}

function resetSubmitFailure() {
  clearRetryTimer()
  retryCount.value = 0
  deadlineSubmitFailed.value = false
}

function isAlreadySubmittedError(error: unknown): boolean {
  return error instanceof ApiError
    && error.code === 40000
    && error.message.includes('考试已提交，不能重复提交')
}

function isRetryableFailure(error: unknown): boolean {
  return !(error instanceof ApiError) || error.code >= 50000
}

function scheduleAutoRetry() {
  if (retryTimer || retryCount.value >= MAX_AUTO_RETRIES) return
  retryTimer = window.setTimeout(() => {
    retryTimer = undefined
    retryCount.value += 1
    void doSubmit()
  }, RETRY_INTERVAL_MS)
}
```

`doSubmit` 重写为：

```ts
async function doSubmit(options: { manual?: boolean } = {}) {
  if (submitting.value) return
  if (options.manual) {
    clearRetryTimer()
    retryCount.value = 0
    deadlineSubmitFailed.value = false
  }
  submitting.value = true
  stopTimer()
  try {
    if (!deadlineReached.value) {
      await flushDraft()
    }
    await submitExam(examId, buildSubmitPayload(), { silent: true })
    resetSubmitFailure()
    ElMessage.success('交卷成功')
    try {
      await loadExam()
    } catch {
      // 交卷已成功，结果页加载失败不得回退为「交卷失败」；下次进入页面重新加载
    }
  } catch (error) {
    if (isAlreadySubmittedError(error)) {
      // 先加载结果再清失败态；loadExam 自身可能 reject，必须就地捕获，避免异常逃出 catch
      try {
        await loadExam()
      } catch {
        // 加载失败：继续走下方失败态，保留手动重试入口
      }
      if (state.value !== 'B') {
        resetSubmitFailure()
        return
      }
      // 加载失败或服务端仍报 IN_PROGRESS：保留失败态与手动重试，不得清空错误条
      deadlineSubmitFailed.value = true
      ElMessage.error('交卷结果未同步，请重试')
      // 未到点时必须继续倒计时，否则 finally 因 deadlineSubmitFailed 为真而跳过恢复
      if (!deadlineReached.value && deadlineAt.value) {
        startTimer(deadlineAt.value)
      }
      return
    }
    if (!deadlineReached.value) {
      ElMessage.error(error instanceof Error ? error.message : '交卷失败')
    } else {
      deadlineSubmitFailed.value = true
      if (isRetryableFailure(error)) {
        scheduleAutoRetry()
      } else {
        ElMessage.error(error instanceof Error ? error.message : '交卷失败')
      }
    }
  } finally {
    submitting.value = false
    if (!deadlineSubmitFailed.value && state.value === 'B' && !deadlineReached.value && deadlineAt.value) {
      startTimer(deadlineAt.value)
    }
  }
}
```

## 10. 风险与回滚

| 风险 | 处理 |
|---|---|
| 前端时间与服务端存在时钟偏差 | 服务端为准；前端只读只作体验层，逾期请求仍由后端拒绝 |
| 交卷 120 秒宽限用尽后重试必然失败 | 错误条保留并提示联系教师；不扩大宽限 |
| 重试与 `submitting` 竞态 | `doSubmit` 首行 `if (submitting.value) return`；重试定时器回调同样走该守卫 |
| 响应丢失后重试被误判失败 | TD12 按精确文案回收为成功 |
| 交卷成功但结果页 `loadExam` 失败 | 保留「交卷成功」提示，不把结果加载失败改判为交卷失败；`loadExam` 失败被就地吞掉，不进入 `catch`。未到点：`finally` 恢复倒计时，仍在作答态，下一次提交由 TD12 按「已提交」回收进入结果态；已到点：页面保持只读且不显示失败条，用户刷新页面即进入结果态。本期不新增本地「已交卷待同步」状态 |
| 实验 `SAVED` 入口收紧影响教师习惯 | 页面展示明确只读提示，数据不丢 |
| `IN_PROGRESS` 但 `deadline_at` 为空的历史异常数据 | `deadlineReached` 要求 `deadlineAt != null`，该类数据保持可作答且不自动交卷；现网 `startExam` 必然写入 `deadline_at`，种子数据无此情况 |
| 看板数字变小 | 预期行为，口径收紧；不回滚 |

回滚方式：本次改动均为行为分支与前端状态，无 schema 变更；回滚只需还原对应文件。

## 12. 已否决方案

| 否决项 | 原因 |
|---|---|
| 在 `accessiblePublishedHomework` 内混入 `dueAt` 校验 | 该方法同时服务详情读取，加入时间判断会误伤「截止后仍可查看详情」 |
| 查重计数直接 `plagiarism_task.business_id = homework.id` | `business_id` 实际存 `homework_submission.id`，会漏计或错配 |
| 趋势使用 `JOIN class_teacher` 去重 | 虽在唯一约束下不放大，但本方案统一以 `EXISTS` 为唯一写法，避免后续误写无教师条件的 JOIN |
| 仅以「异常不是 `ApiError`」判定可重试 | 5xx 也会被 `request.ts` 包装成 `ApiError(50000)`，会漏掉服务端瞬时错误 |
| 对所有失败都自动重试 | 确定性 `400` 重试无意义，且会产生请求风暴与重复提示 |
| 交卷失败后统一 `startTimer` 而不判剩余时间 | 到点后重启会立即再次触发 `autoSubmit`，形成循环 |
| 实验 `SAVED` 行隐藏按钮并新增「查看作答」按钮 | 现有「实验报告」按钮已提供只读入口，新增按钮重复 |
