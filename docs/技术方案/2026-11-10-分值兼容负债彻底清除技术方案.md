### 0. 问题定义（本次清除对象）

分值规范 PRD §9.3「兼容性」5 条口径中，4 条属于兼容负债，1 条属于必须保留的数据保全约束：

| §9.3 条目 | 定性 | 本方案处置 |
|---|---|---|
| ① 旧客户端传 `defaultScore` 被忽略且保存成功 | 负债：为幽灵字段保留成功承诺 | 取消，改为严格拒绝 |
| ② 旧前端读不到 `defaultScore`，需同版本发布 | 负债：把旧前端纳入契约 | 取消，删除该承诺 |
| ③ 历史题目快照与成绩不变 | **非负债**，数据保全硬约束 | 保留，改写为独立「数据保全」条款 |
| ④ 导入历史 JSON 含 `score` 被静默忽略 | 负债：为废止字段保留可导入承诺 | 取消，改为白名单严格校验并明确报错 |
| ⑤ 历史非法分值「打开原样展示、未修改可正常保存」 | 负债，且与实现矛盾（现网 `@Valid` 一律拒绝） | 取消，统一拒绝 + 存量规范化 + DB 域约束 |

现网实测（2026-11-10，本机 MySQL 8.0.45）：V27 已应用，`question_bank.default_score` 列不存在；`exam_question` 25 行、`homework_question` 0 行、`t_experiment_item` 113 行，非法分值均为 0；三张配置表分值列为 `DOUBLE` / `INT`，**无任何 CHECK 约束**。

## 2. 数据变更

### 2.1 `V28__enforce_question_score_domain.sql`

按顺序执行 6 条 DML + 3 条 DDL：

```sql
UPDATE exam_question SET question_score = 1 WHERE question_score IS NULL;
UPDATE homework_question SET question_score = 1 WHERE question_score IS NULL;
UPDATE exam_question SET question_score = LEAST(100, GREATEST(1, ROUND(question_score)))
 WHERE question_score < 1 OR question_score > 100 OR question_score <> FLOOR(question_score);
UPDATE homework_question SET question_score = LEAST(100, GREATEST(1, ROUND(question_score)))
 WHERE question_score < 1 OR question_score > 100 OR question_score <> FLOOR(question_score);
UPDATE t_experiment_item SET experiment_item_score = 0 WHERE experiment_item_score IS NULL;
UPDATE t_experiment_item SET experiment_item_score = LEAST(100, GREATEST(0, experiment_item_score))
 WHERE experiment_item_score < 0 OR experiment_item_score > 100;

ALTER TABLE exam_question ADD CONSTRAINT ck_exam_question_score_domain
 CHECK (question_score >= 1 AND question_score <= 100 AND question_score = FLOOR(question_score));
ALTER TABLE homework_question ADD CONSTRAINT ck_homework_question_score_domain
 CHECK (question_score >= 1 AND question_score <= 100 AND question_score = FLOOR(question_score));
ALTER TABLE t_experiment_item ADD CONSTRAINT ck_experiment_item_score_domain
 CHECK (experiment_item_score >= 0 AND experiment_item_score <= 100);
```

- 属于 `backend-db-and-config.mdc` §2.2 允许的结构性数据回填：只把域外值钳制到域内，不写演示 seed、不删除业务数据、不改任何合法值。
- 已发布场次的题目快照 `question_snapshot_json` 与 `exam_answer` / `homework_answer` / 实验答题得分**一律不读写**；钳制仅影响该场次的计划满分派生值与批改上限，已记录得分不变。
- 迁移前门禁按 CD14。

### 2.2 SCHEMA.md

精确落点：列说明 `:178`（`homework_question`）、`:263`（`exam_question`）改为「分值（1–100 整数）」，`:355`（`t_experiment_item`）改为「分值（0–100 整数）」；约束段 `:183`（homework_question）追加 `ck_homework_question_score_domain`、`:268`（exam_question）追加 `ck_exam_question_score_domain`（两者表达式同为 `question_score >= 1 AND question_score <= 100 AND question_score = FLOOR(question_score)`）、`:367`（t_experiment_item）追加 `ck_experiment_item_score_domain CHECK (experiment_item_score >= 0 AND experiment_item_score <= 100)`。三张表的表锚点实测为 `:170` / `:255` / `:344`（按本句顺序）。

## 9. 已否决方案

| 否决项 | 原因 |
|---|---|
| 只删除 §9.3 文档措辞、不改运行行为 | 幽灵字段仍会被静默接受，负债未清除 |
| 全局 `spring.jackson.deserialization.fail-on-unknown-properties=true` | 影响全部接口，破坏面不可控；`@JsonAnySetter` 可精确限定题库 DTO |
| 把 `DOUBLE` 列改为 `INT` / `DECIMAL` | 实体为 `Double`，`ddl-auto=validate` 会冲突；CHECK 已能锁死域 |
| 清洗 `question_snapshot_json` 里的分值 | 违反 CD1③，会改动历史满分与成绩口径 |
| 快照/配置分值缺失时直接拒绝批改 | 会让历史缺分值的题目无法批改，属数据保全能力退化 |
| 为 `score` 单独写一条导入校验分支 | 又造一个幽灵字段特例；白名单校验覆盖所有未知字段 |
