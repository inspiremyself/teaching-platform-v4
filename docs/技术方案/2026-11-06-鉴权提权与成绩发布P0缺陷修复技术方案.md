## 4. 后端设计

### 4.1 JWT 载荷（TD2）

```java
public String issueToken(SysUser user, String sessionKey, Instant issuedAt) {
    Instant expiresAt = calculateExpiration(issuedAt);
    return Jwts.builder()
            .subject(user.getUsername())
            .claim("uid", user.getId())
            .claim("sid", sessionKey)
            .issuedAt(Date.from(issuedAt))
            .expiration(Date.from(expiresAt))
            .signWith(secretKey)
            .compact();
}
```

- 删除 `role` / `displayName` / `schoolId` 三个 claim。
- 删除 `issueToken(SysUser)` 单参重载（现网无调用）；保留 `issueToken(SysUser, String)` 两参重载。
- `sub` 仅用于日志追踪，过滤器不读取。

### 4.2 `JwtAuthenticationFilter`（TD1 / TD3 / TD4 / TD5）

构造参数改为 3 个，删除 `SysUserRepository` 依赖：

```java
public JwtAuthenticationFilter(
        JwtTokenService jwtTokenService,
        UserLoginSessionRepository userLoginSessionRepository,
        ObjectMapper objectMapper
) { ... }
```

`doFilterInternal` 主体：

```java
Claims claims = jwtTokenService.parse(token);
Object uidClaim = claims.get("uid");
String sessionKey = claims.get("sid", String.class);
if (!(uidClaim instanceof Number) || sessionKey == null || sessionKey.isBlank()) {
    writeUnauthorized(response, 40100, "未登录或登录已过期");
    return;
}
Long userId = ((Number) uidClaim).longValue();

UserLoginSession loginSession = userLoginSessionRepository.findBySessionKey(sessionKey).orElse(null);
if (loginSession == null || loginSession.getUser() == null
        || !userId.equals(loginSession.getUser().getId())) {
    writeUnauthorized(response, 40100, "未登录或登录已过期");
    return;
}
SysUser user = loginSession.getUser();

if (user.getStatus() != UserStatus.ACTIVE) {
    writeUnauthorized(response, 40100, "未登录或登录已过期");
    return;
}
if (loginSession.getStatus() == LoginSessionStatus.KICKED) {
    writeUnauthorized(response, SESSION_KICKED_CODE, SESSION_KICKED_MESSAGE);
    return;
}
if (loginSession.getStatus() != LoginSessionStatus.ACTIVE) {
    writeUnauthorized(response, 40100, "未登录或登录已过期");
    return;
}
OffsetDateTime now = OffsetDateTime.now();
if (loginSession.getExpiresAt().isBefore(now)) {
    loginSession.setStatus(LoginSessionStatus.EXPIRED);
    loginSession.setInvalidatedAt(now);
    userLoginSessionRepository.save(loginSession);
    writeUnauthorized(response, 40100, "未登录或登录已过期");
    return;
}

CurrentUser currentUser = new CurrentUser(
        user.getId(),
        user.getUsername(),
        user.getDisplayName(),
        user.getRole(),
        user.getSchoolId(),
        sessionKey
);
UsernamePasswordAuthenticationToken authenticationToken = new UsernamePasswordAuthenticationToken(
        currentUser,
        null,
        List.of(new SimpleGrantedAuthority("ROLE_" + user.getRole().name()))
);
SecurityContextHolder.getContext().setAuthentication(authenticationToken);
```

- 用户、角色、学校、显示名、状态全部以数据库为准；token 只剩“你是谁 + 哪个会话”。
- `sys_user.school_id`、`role` 在 schema 中非空，不新增空值分支。
- 401 文案与 `KICKED` 专用码保持不变，登录与 `/auth/me` 链路协议不变。

```java
        throw new IllegalStateException("app.jwt-secret 未配置，请通过环境变量 JWT_SECRET 注入");
    }
    byte[] secretBytes = secret.getBytes(StandardCharsets.UTF_8);
    if (secretBytes.length < MIN_SECRET_BYTES) {
        throw new IllegalStateException("app.jwt-secret 长度不足，UTF-8 字节长度需不少于 32");
    }
    this.secretKey = Keys.hmacShaKeyFor(secretBytes);
}
```

## 10. 风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 生产未注入 `JWT_SECRET` | 后端启动失败 | 发布清单强制检查；Compose 使用 `:?` 必填变量；错误信息直指 `app.jwt-secret` |
| 本地默认密钥变化 | 路径 A/B/C 历史开发 token 失效 | 重新登录即可；不涉及数据 |
| 旧 token 中残留角色声明被客户端使用 | 依赖 token 的外部调用方失效 | 前端已确认不解析 token；对外以 `/auth/me` 为准 |
| 解析器与详情页判定漂移 | 同一成绩两处展示不一致 | 解析器按同一矩阵实现；矩阵用例覆盖三域四模式 |
| 工作台漏改 | 未发布成绩仍从工作台泄露 | 三个学生端接口统一走解析器；工作台用例覆盖平均分与最近反馈 |
| H2 悲观锁等待 | 并发测试偶发超时 | 独立上下文 + `LOCK_TIMEOUT=10000`；锁粒度为单学生单实验行 |
| 剔除孤儿成绩记录 | 开发环境学生成绩条数减少 | 属 D21 预期；测试与验收均已覆盖，不回填 |
| 路径 A 直接 `docker compose up` 未设密钥 | Compose 直接报错退出 | 使用 `up.sh`；运维文档注明必填 |

回滚策略：代码整体回滚至上一版本即可恢复；已发布成绩的 `score_released` 属业务数据，回滚代码不会自动回收，需人工确认后处理。仅密钥配置导致的问题优先修正环境变量，不回退代码。

## 附录 A 已否决方案

| 方案 | 否决原因 |
|---|---|
| 保留 token 中 `role`，仅与数据库比对 | 仍存在两处身份真相源，客户端可观察到与授权无关的角色声明，违反 D1/D2 |
| 过滤链分别查会话与 `sys_user` | 多一次数据库往返；`findBySessionKey` 已带 `@EntityGraph(user)`，一次查询即可 |
| 在 `JwtTokenService` 中保留 `issueToken(SysUser)` | 现网无调用，且会绕过会话参数构造 token，属死代码 |
| 用唯一约束防止重复提交 | `uk_experiment_submission` 只防同学生同实验重复行，不能阻止状态被重复推进；且本期不允许新增迁移 |
| 在 `AnalysisService` 内用一条三表 `UNION` SQL | 字段与方言差异大、可读性差，且 H2/MySQL 兼容风险高于三条固定 SQL |
| 复用 `exam` / `homework` / `lab` 的 Service 做可见性判定 | 引入跨域依赖与循环依赖风险，且逐条调用会产生 N+1 |
| 给 `score_record` 增加可见性字段 | 违反 D17，且发布状态应以业务表为真相源 |
| 只在前端禁用提交按钮 | 后端仍可被直接调用，违反 D8 |
| 删除或回填历史 `score_record` | 违反 D16；孤儿记录按 D21 读取侧剔除即可 |
| 引入双密钥灰度轮换 | 超出本期范围，PRD 已明确列入后续迭代 |
