# 多租户能力群阶段 0 决策总纲技术方案

- **日期**：2026-11-07
- **当前版本**：V7.0
- **状态**：已定稿（决策写死，跨期不可漂移）
- **性质**：跨 5 项需求、6 个阶段的**唯一决策源**。本文只写死跨阶段不可漂移的决策与边界；各期的 API 形态、表字段、页面落点、测试用例与验收步骤由该期独立 PRD / 技术方案写死，本文不替代。
- **输入需求**：① 多租户学校与一个管理员管理多个学校；② 知识点可挂教材 / 教材小节 / 课件小节（多对多，支持暂不挂载、后续挂载、挂多个教材与多个小节）；③ 教师自有题与学校公有题；④ 平台超管 / 校管按教材与科目制作讲解课件（音频 + 分小节图文）并共享给学校，教师按小节布置；⑤ 同上制作题目并共享、按小节布置。
- **范围结论**：平台超管是平台级操作者，学校组织与业务数据由本校 `SCHOOL_ADMIN` 管理；「给学校开通功能」= 按学校集合授权课件与题库（`content_share_grant`），不设功能开关 / 套餐模型；教师统一使用内容、不制作统一教材内容，教师自制课件为未来能力；学生「错题本」为后续独立能力，不纳入六期。

- **流程引用**：`.cursor/rules/feature-dev-workflow.mdc`、`.cursor/rules/tech-spec-decisive.mdc`、`.cursor/rules/path-b-data-backup-gate.mdc`、`.cursor/rules/backend-db-and-config.mdc`

## 1. 已定决策清单

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| D01 | 角色模型与职责边界 | 新增第 4 个角色 `PLATFORM_ADMIN`（平台超管），定位为**平台级操作者**：开通 / 停用学校、创建首位校管、阶段 3 制作平台内容并按学校集合授权课件与题库。学校组织与业务数据由本校 `SCHOOL_ADMIN` 管理，平台超管不读取、不代管。「一个管理员管理多个学校」= 一个账号开通并维护多个学校租户；不引入 `SCHOOL_ADMIN` 多校关联表、不做跨校汇总报表 |
| D02 | 平台超管数据边界 | 平台超管无学校归属：`sys_user.school_id` 与 `CurrentUser.schoolId` 均为 `NULL`，取值一致、不按角色特判。JWT claims、`CurrentUser` 组件数、`user_login_session` 结构保持不变，三角色取值不变；平台超管相关测试必须显式传 `null` 构造 `CurrentUser`，不得用便捷构造（其默认 `schoolId=1L` 仅供三角色测试）。`audit_log.school_id`（`V18`）与 `http_access_log.school_id`（`V17`）可空，平台超管登录审计与业务操作审计一律写 NULL |
| D03 | 平台超管账号无学校归属 | `V25` 用 `${alterModifyColumn}` 放开 `sys_user.school_id` 的 `NOT NULL`（复用 `V18` 范式，不改 `FlywayPlaceholdersConfig`），平台超管种子行写 `school_id = NULL`；三角色历史行取值不变，`uk_sys_user_school_username(school_id, username)` 保持原样，不加部分索引 / 生成列 / DB CHECK。平台超管账号全局唯一由「仅迁移种子创建 + 不提供新增接口」保证（NULL 不参与唯一约束）；开放新增接口属 §6 非目标，本期及后续阶段均不引入额外索引 / 生成列 / DB CHECK。`JwtAuthenticationFilter` 直接取 `user.getSchoolId()` 构造 `CurrentUser`，不写按角色置 null 的分支。登录审计（`SecurityAuditEvent` / `logLoginFailure`）与业务操作审计均写 NULL，目标学校 id 写 `detail_json.targetSchoolId`。按 `school_id` 等值过滤的现有查询一字不改，NULL 行天然不匹配、不进入任何学校数据范围；未来新增按 `school_id` 分组的统计 / 报表须把 NULL 单列为「平台级」，不得并入任何学校分组，也不得给平台级账号补学校默认值。`DemoAccountProdGuard` 的 `WHERE school_id = 1` 不覆盖 NULL 行，必须显式覆盖 `school_id IS NULL` 且按用户名追加 `platform9001`（SQL 形态见 §5）。账号由迁移种子创建，不提供新增平台超管的接口 |
| D04 | 学校开通 / 停用 | 复用 `school.status`（`ACTIVE` / `DISABLED`）与全局唯一 `school.code`。开通学校时同时创建该校首位 `SCHOOL_ADMIN`，这是创建校管的唯一入口。停用只影响该校账号登录，不清数据、不删用户、不停用 `id=1` 演示学校、不改会话表 |
| D05 | 停用后的行为 | `DISABLED` 学校下所有账号登录返回 `40103`，文案沿用现网；停用演示学校返回 `40028`；学校不存在返回 `40400`；`40300` 保持现网越权语义 |
| D06 | 权限与鉴权 | 4 个角色的 `permissions` 以 1A PRD §4.2 的完整枚举为准。现有 6 个 admin controller 保持 `hasRole('SCHOOL_ADMIN')`，平台超管访问一律 403；新增学校管理 Controller 用 `hasRole('PLATFORM_ADMIN')`；教师端、学生端端点注解保持三角色原状。阶段 3 为 `PLATFORM_ADMIN` 追加 `CONTENT_WRITE` / `CONTENT_SHARE`、为 `SCHOOL_ADMIN` 追加 `CONTENT_WRITE`，教师 / 学生两组不变 |
| D07 | 平台超管可达端点 | 平台超管只可达三类端点：登录、账号自身（个人信息 / 改密 / 登出）、平台级学校管理；阶段 3 追加平台内容端点。其余 `/api/v1/**` 由现有 `@PreAuthorize` 角色注解拒绝（403）。内容授权里的 `school_id` 是 `content_share_grant` 的数据字段，不是会话上下文。完整路径见 1A PRD §4.3 |
| D08 | 端点契约 | 新增学校管理端点由 1A 方案写死。现有三角色端点、登录响应字段、`/api/v1` 前缀、`ApiResponse` 与 `PagedResult<T>` 形态不变 |
| D09 | 前端入口 | 平台超管复用 `/admin` 壳层，不新建第四套壳层、不合并三套角色壳层。侧栏仅「学校管理」1 项，`/admin/schools` 是学校列表 / 开通 / 停用的**唯一业务入口**，`homePath` → `/admin/schools`。阶段 3 追加「平台内容」1 项。路由与导航细节见 1A PRD FR-6 |
| D10 | 题目三层归属 | 阶段 2。`question_bank` 的 `school_id` 由 1B 作为**唯一租户隔离列**（非空、按校过滤只认它）；阶段 2 再补 `owner_scope`（`TEACHER` / `SCHOOL` / `PLATFORM`）与可空 `owner_school_id`（`PLATFORM` 行 NULL），两列并存、语义分离。`TEACHER` 自有题保留现网 CRUD 且仅创建者可见；`SCHOOL` 题仅本校校管可见可改删；`PLATFORM` 题仅平台超管可改删、被授权学校按 D21 只读。不引入题目审核流；`question_bank.code` 的唯一性由阶段 2 启用门禁「题库编码作用域收敛」先行收敛为 `UNIQUE (school_id, created_by, code)`（归属维度唯一，见 D15 / `docs/PRD/2026-11-10-题库编码作用域收敛与发号规则PRD.md`），阶段 2 在此基础上加 `owner_scope` / `owner_school_id` 并换唯一键、数据零改写；阶段 2 不得在全局唯一 `code` 上直接建三层归属 |
| D11 | 学科与教学任务 | 阶段 2。新建平台级 `subject` 字典（平台超管维护、跨校共享），`school_subject` 增可空 `global_subject_id` 表示本校启用映射；作业 / 实验 / 考试 / 题库 / 资料表增可空 `subject_id`，新建任务必填且校验属于本校已启用映射，历史数据为 NULL。学科错误码沿用现网 `40025` / `40026` / `40901` |
| D12 | 目录与统一挂载 | 阶段 2 一次建成教材 / 教材小节 / 学校启用教材 / 课件 / 课件小节等目录表，阶段 3 / 4 只写数据与页面、不再建表；教材与课件按 D25 带学科归属列并支持同一学科下多条记录。挂载关系统一由 `content_mount` 多态多对多表承载（D23），挂载与可见性、授权、布置三者解耦（D24），且与学科归属正交（D25） |
| D13 | 按小节布置题目 | 阶段 4。教师不制作统一教材题目，改为按五类筛选（含「全部」与「未挂载」）浏览 D21 可见内容后布置给学生；仍走现有三闭环 `question_snapshot_json` 快照与 `assessment` / `grading` 评分链路，不新建第四套任务闭环。题目布置唯一入口为现有三闭环配置页 |
| D14 | 讲解课件 | 课件由平台超管 / 校管在阶段 3 制作，教师本期不制作。阶段 2 建 `courseware` / `courseware_section` / `courseware_assignment`（`section_id` 可空，整份未挂载课件布置写 NULL）；阶段 4 教师按小节布置、学生在 `/student/content` 阅读图文与播放音频。课件无作答、无评分，不接入题项与评分链路。音频存储、校验与 `Range` 响应由阶段 4 方案写死 |
| D15 | 分期与启用门禁 | 六期顺序固定 **0 → 1A → 1B → 2 → 3 → 4**，**不新增第 7 个阶段编号、不改写六期交付**；逐期独立 PRD + 技术方案 + 方案自查收敛 + 实现自查收敛 + 验证，不合并、不跳期。1A 只开放平台级学校管理；1B 紧接 1A 且为 2 / 3 / 4 前置，只做 6 张存量业务表的 `school_id` 收口与全量跨校回归；1B 交付前不得导入多校真实教学业务数据。**阶段 2 启用门禁（非阶段、不占编号）**：1B 交付后、阶段 2 启用前，必须先完成「题库编码作用域收敛与平台编码规则」独立交付项，需求基线为 `docs/PRD/2026-11-10-题库编码作用域收敛与发号规则PRD.md`（版本与状态以该 PRD 文首为准，总纲不写易过时的绝对版本号）；执行链写死为 `0 → 1A → 1B →〔阶段 2 启用门禁：编码收敛〕→ 2 → 3 → 4`。该门禁项按逐期同等纪律独立走 PRD + 技术方案 + 两次自查收敛 + 备份 + `V29` + 验证，不并入 1B、不并入阶段 2、不提前交付阶段 2 能力；该门禁项不新增第 6 项输入需求、不改变文首 5 项需求范围。依赖理由写死：阶段 2 要在 `question_bank` 加 `owner_scope` / `owner_school_id` 并换唯一键，若在全局唯一 `code` 上先建三层归属，后续收敛唯一性会返工；先收敛为 `UNIQUE (school_id, created_by, code)` 后，阶段 2 只需加列换键、数据零改写（D10）。阶段 2 建目录、三层归属、共享授权与挂载模型；阶段 3 做内容制作、授权、挂载编辑与教师只读浏览；阶段 4 做按小节 / 未挂载筛选布置与学生学习 |
| D16 | 迁移与备份纪律 | 新迁移从 `V25` 起：`V25` 由 1A 独占，仅含两件事——按 D03 放开 `sys_user.school_id NOT NULL` 的一条 `ALTER`（复用 `V18` 的 `${alterModifyColumn}` 范式）与 `platform9001` 一条 `school_id=NULL` 的种子 `INSERT`；角色枚举属 Java 代码、无 DDL。不含 1B 补列与任何内容 / 挂载表。1B 从 `V26` 起；`V27` / `V28` 由题目分值规范两份方案占用（阶段外独立交付，不占 D15 编号）；D15 的阶段 2 启用门禁「编码收敛」独占 `V29`（`V29__question_code_owner_scope.sql`）；阶段 2 从 `V30` 起，3 / 4 顺延，所有编号以 `db/migration/` 目录实测为准。1B 补列沿用 `V24` 的「清孤儿 → 加可空列 → 回填 → 收紧 NOT NULL → 建索引」范式；双方言差异语句只用 `FlywayPlaceholdersConfig` 注入的占位符，不新增占位符。`V1`–`V24` 只读冻结。每期动迁移前执行 `./scripts/common/backup-local-data.sh --label <阶段> --with-files` 与 `./scripts/common/verify-local-backup.sh --latest`；禁止裸删 `data/` 整树 |
| D17 | 演示账号与文档同步 | 新增 `platform9001/123456`（`PLATFORM_ADMIN`、`school_id = NULL`），现有 5 个种子账号与 3 个演示账号口令不变。同步清单见 §5 |
| D18 | 真实系统约束 | 全程真实前后端、真实数据库、真实权限、真实测试；不引入 mock 页面、假接口、静态假数据闭环 |
| D19 | 内容生产者与消费者 | 平台超管针对不同教材 / 科目制作课件与题目并授权给指定学校集合；校管制作本校一套供本校教师使用；教师统一使用、按小节布置，不制作 `SCHOOL` / `PLATFORM` 归属的统一教材内容。现有题库教师自有题（需求 ③，`TEACHER` 归属）保留 CRUD 且可按 D23 / D24 以 0..N 行挂小节，仅创建者可见、不参与跨校共享。教师自制**课件**为未来能力，本期仅以 `owner_scope=TEACHER` 预留模型；课件侧不产生 `TEACHER` 行、不提供制作入口。同一科目下可制作多个教材 / 课件，按 D25 各自独立归属、独立授权 |
| D20 | 三层归属与跨校共享 | 课件与题目统一带 `owner_scope`（`PLATFORM` / `SCHOOL` / `TEACHER`）与 `owner_school_id`（`PLATFORM` 行 NULL）。平台内容对学校的授权用 `content_share_grant(content_type, content_id, school_id, granted_by, created_at)`，`content_type` 取 `COURSEWARE` / `QUESTION`（全仓唯一枚举，D23 直接复用），唯一键 `(content_type, content_id, school_id)`；仅平台超管可写，取消授权删单行不删内容，删除平台内容时同事务清该内容全部 grant 行。共享是**同一条记录只读引用**、不做跨校复制；`SCHOOL` 内容不得跨校共享。多态 `content_id` 不建外键，`owner_school_id` 不加 DB CHECK，由应用层强制 |
| D21 | 内容可见性 | 教师可见 = 本校 `SCHOOL` 内容（全部）+ `TEACHER` 且 `created_by=自己` 的题目 + `PLATFORM` 且已授权本校的内容；校管可见 = 本校 `SCHOOL` 内容（可读可写）+ 已授权本校的 `PLATFORM` 内容（只读），`TEACHER` 题仅创建教师可见；平台超管可见全部 `PLATFORM` 内容（含未授权）与平台级教材目录，不读取 `SCHOOL` 内容、`TEACHER` 私有题及任何学校的组织 / 教学业务数据（D01）。跨校或未授权访问一律 `40400`，不泄露存在性。授权取消后：已布置题目靠快照、已布置课件靠 `courseware_id` 继续可用，仅新浏览与新布置不可见。挂载行数不参与可见性判定：未挂载内容按本表照常可见与授权 |
| D22 | 内容入口（唯一） | 平台超管「平台内容」`/admin/platform-content`（制作 + 授权学校）；校管「本校内容」`/admin/school-content`；教师「教学内容」`/teacher/content`（只读浏览 + 课件按小节布置）；学生「学习内容」`/student/content`（阅读图文、播放音频）。题目布置唯一入口仍为现有 `homework` / `exam` / `lab` 配置页，已布置题目仍在三闭环学生页作答。后端按角色设置类级注解：平台 / 校管 Controller 覆盖 create / update / delete 兄弟操作，教师 / 学生 Controller 只提供 GET 浏览端点。挂载编辑落在内容编辑动作内，不新增挂载专用 Controller / 端点 / 页面入口。四个入口由阶段 3 / 4 交付，均复用现有三套壳层 |
| D23 | 知识点术语与统一挂载模型 | 「知识点」写死为**全部可挂载内容单元的业务称谓**，物理上即 `COURSEWARE`（课件一行）与 `QUESTION`（题库一行，含教师自有题）两类记录，与 D20 同枚举；不新建独立 `knowledge_point` 实体、知识点层级树或掌握度分析。挂载关系唯一由 `content_mount` 承载：`mount_type` 三值 `TEXTBOOK` / `TEXTBOOK_SECTION` / `COURSEWARE_SECTION`，`content_id` 与 `mount_target_id` 为多态列、不建 DB 外键，唯一键 `(content_type, content_id, mount_type, mount_target_id)`。一个内容单元的挂载行数为 **0..N**（0 行即「暂不挂载」，多行可同时挂多个教材、多个教材小节、多个课件小节）。课件不得挂到自身 `courseware_section`（应用层拒绝）。课件与教材的对应唯一由 `content_mount` 表达，不设单值 `textbook_id` / `textbook_section_id` 双源列。教材 / 课件的学科归属由 D25 的 `global_subject_id` 单值列表达，与 `content_mount` 挂载关系正交：挂载不改变归属学科，归属不产生挂载行 |
