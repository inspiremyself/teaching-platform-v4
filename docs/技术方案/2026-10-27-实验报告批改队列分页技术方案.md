# 实验报告批改队列分页技术方案

- **日期**：2026-10-27
- **状态**：已定稿（决策写死，可直接编码）
- **范围**：`GET /api/v1/teacher/lab-reports` 查询链路（后端）+ 教师端实验报告批改队列页（前端 `LabReports.vue`）+ 两个复用该接口的报告详情/批量批改页
- **性质**：查询链路改造，**无数据库迁移、无 schema 变更**

---

## 1. 背景与问题

教师端「实验报告批改队列」（`frontend/src/views/teacher/LabReports.vue`）当前存在三个问题：

1. **接口无分页契约**：`GET /teacher/lab-reports` 全量返回 `LabReportItem[]`，不符合项目约定（后端"分页返回统一使用 `PagedResult<T>`"、前端 `PageResult<T>` 已存在但此接口未跟进）。
2. **后端全量加载 + 内存过滤**：`LabService.listTeacherReports` 先 `findByLabIdIn(ownedLabIds)` 拉全部提交，再在 Java 内存里做 keyword/status 匹配；数据量随实验数 × 班级人数线性增长。
3. **前端全量渲染**：`LabReports.vue` 将全部行渲染为卡片列表，无 `el-pagination`；且 `labId` 筛选在前端 `computed` 二次过滤——一旦数据量大，渲染与筛选都会卡。

## 2. 消费方盘点（关键约束）

`listTeacherLabReports` 在前端共有 **3 个消费方**，语义不同：

| 消费方 | 调用方式 | 实际诉求 |
|---|---|---|
| `LabReports.vue` | 带 keyword/status | **分页列表** + 筛选 + 全局统计（头部"报告总量/待批改/已批改"三卡 + 第 4 卡"当前筛选 N 条"） |
| `LabReportDetail.vue` | 无参 | 全量报告列表构建 `reportQueue`（按班级 → 学号排序），支撑**上一份/下一份报告导航** |
| `LabReportBatchGrade.vue` | 无参 | 同上，导航队列 |

结论：**分页是队列页的诉求，导航队列的诉求是全量轻量列表**。两种诉求必须拆开，不能让详情/批改页去适配分页接口（pageSize 上限会截断导航队列）。

## 3. 决策清单

| # | 决策 | 已否决方案（原因） | 选择理由 |
|---|---|---|---|
| D1 | 分页下沉 DB：`LabSubmissionRepository` 增加 `JpaSpecificationExecutor`，Service 用 Specification 动态拼条件 + `Pageable` 查询 | JPQL `@Query` 跨表 JOIN（可空参数在 Hibernate 6 + H2/MySQL 双态下有空参类型推断坑）；内存 subList 分页（不解决全量加载，只是假分页） | 与 `AdminAuditLogQueryService` 既有分页先例同构；条件动态可选；双方言安全 |
| D2 | 维度解析用混合策略：教师 ownedLabIds、keyword 命中的 labIds / studentIds 在内存解析（基数小），提交表上仅做 `labId IN + studentId IN + submitStatus =` 的 DB 分页 | 全部用跨表子查询（可读性差、调试难） | 提交表是唯一大表，DB 分页收益全部落在它身上；教师实验数（几十）与学生关键词命中集（百级）在内存解析简单可靠 |
| D3 | 排序：DB 层 `ORDER BY id DESC`（新提交在前） | SUBMITTED 优先排序（改变现有批改心智）；维持现状无序（行为不确定） | 现状 `findByLabIdIn` 本就无确定顺序；`id DESC` 确定性最强。`LabReportDetail` 导航队列的前端排序口径（班级→学号）不受影响，二者用途不同 |
| D4 | `TeacherLabReportQuery` 扩展为 `keyword/status/labId/page/pageSize`；`page` 空 → 1、`pageSize` 空 → 10、上限 100；越界抛 `BusinessException(40000, "参数不合法")` | 自定义上限/默认值 | 与 `AdminAuditLogQueryService` 的 `MAX_PAGE_SIZE=100` 及校验规则对齐 |
| D5 | 响应契约一次性切换为 `PagedResult`（`items/page/pageSize/total`），**不做兼容 shim、不保留旧数组形态** | 无参时返回数组、有参时分页（union 类型，双口径维护） | 前后端同仓同发布，3 个消费方全部同批迁移；符合"删除兼容包装"的工程约定 |
| D6 | 新增 `GET /teacher/lab-reports/queue`：无分页、全量、复用同一行结构，承接 Detail/BatchGrade 导航队列 | 详情页用 pageSize=100 拉（>100 条截断，导航断链）；把队列塞进 detail 响应（detail 契约膨胀） | 导航队列语义就是全量轻量列表；拆开后各接口职责单一 |
| D7 | 新增 `GET /teacher/lab-reports/stats`：返回 `{total, submitted, graded}`（教师维度全量口径，**不受筛选影响**，`total` 含 `SAVED`），承载队列页三个全局汇总卡 | 前端从分页结果推算（只见当前页，不可能）；给 `PagedResult` 加 stats 字段（污染通用分页结构，影响所有消费方） | 保持现有信息架构（全局总量与筛选后条数并存）；一条 group by 查询，成本可忽略 |
| D8 | `labId` 筛选从前端 computed 下沉为后端 DB 条件 | 保留前端过滤（分页后只能过滤当前页，语义错误） | 分页后前端过滤必然失效 |
| D9 | 行映射批量化且**全链路只保留一份实现**：新增私有方法 `toReportListViews(List<LabSubmission>)`，分页与 queue 共用；删除现有单行 `toReportListView(LabSubmission)` | 保留逐行 `findById`（每页最多 3×100 次 PK 查询；queue 全量 300 行即 900 次） | 统一批量后分页与队列映射口径不可能漂移，N+1 彻底消除 |
| D10 | keyword 匹配语义与现网**完全一致**：labTitle / studentName / studentNo / studentUsername / className 五字段、忽略大小写包含匹配、**五字段之间为 OR**；SQL 与内存统一用 `LOWER(...)` 比对 | SQL 直接 LIKE（H2 默认区分大小写，与 MySQL ci 排序规则行为漂移） | 语义不变是硬要求；`LOWER()` 在两种方言下行为一致 |
| D11 | 前端：`el-pagination`（layout `total, sizes, prev, pager, next`），默认 pageSize=10，可选 [10, 20, 50]；改 `pageSize` 时 `page` 重置为 1；筛选/刷新触发的 fetch 将 `page` 重置为 1；当前页越界自动回退 | 下拉/回车立即触发筛选（本次不改触发模型，仍由「刷新队列」按钮触发） | 聚焦分页本身，不夹带交互模型变更 |
| D12 | 无数据库迁移 | — | 纯查询链路改造，schema 零变更 |

> 已否决方案统一在上表「已否决方案（原因）」列，正文只保留选定路径。

## 4. 接口定义

### 4.1 `GET /api/v1/teacher/lab-reports`（改造）

分页 + 筛选的报告队列，仅供队列页使用。

**Query 参数**（全部可选）：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `keyword` | string | 空 | 匹配实验名 / 学生姓名 / 学号 / 用户名 / 班级名，忽略大小写包含，五字段 OR |
| `status` | string | 空 | `SAVED` / `SUBMITTED` / `GRADED`；**非法值按空结果处理，不抛异常**（与现网字符串等值匹配行为一致） |
| `labId` | Long | 空 | 单实验过滤（**新增**，自前端下沉） |
| `page` | int | 1 | 空值视为 1；`< 1` 抛 40000 |
| `pageSize` | int | 10 | 空值视为 10；`[1, 100]` 之外抛 40000 |

**成功响应**（`ApiResponse<PagedResult<...>>`）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [ { "id": 1, "labId": 1, "labTitle": "...", "studentId": 2, "studentName": "...", "studentNo": "20260001", "className": "SE2026-1", "submitStatus": "SUBMITTED", "totalScore": null, "summaryRequired": true, "submittedAt": "...", "gradedAt": null } ],
    "page": 1,
    "pageSize": 10,
    "total": 57
  }
}
```

行字段与现网 `toReportListView` 完全一致，不增不减。

### 4.2 `GET /api/v1/teacher/lab-reports/queue`（新增）

全量轻量报告列表，供 Detail / BatchGrade 构建导航队列。无参数、无分页，行结构与 4.1 一致，排序 `id DESC`（前端 `sortReports` 继续按班级→学号重排，行为不变）。返回 `ApiResponse<List<...>>`。

### 4.3 `GET /api/v1/teacher/lab-reports/stats`（新增）

教师维度全局统计，不受任何筛选影响：

```json
{ "total": 57, "submitted": 12, "graded": 30 }
```

> 路由说明：`/queue`、`/stats` 为字面量路径，Spring MVC 优先于 `/teacher/lab-reports/{id}` 模板匹配，无冲突。

## 5. 实现逻辑

### 5.1 后端

**DTO**（`LabRequests.java`）：

```java
public record TeacherLabReportQuery(
        String keyword,
        String status,
        Long labId,
        Integer page,
        Integer pageSize
) {}
```

**Repository**：

```java
// LabSubmissionRepository
public interface LabSubmissionRepository extends JpaRepository<LabSubmission, Long>,
        JpaSpecificationExecutor<LabSubmission> {
    // stats 用：按状态分组计数
    @Query("""
            select s.submitStatus, count(s) from LabSubmission s
            where s.labId in :labIds group by s.submitStatus
            """)
    List<Object[]> countGroupByStatus(@Param("labIds") Collection<Long> labIds);
}

// SysUserRepository（新增，跨字段 OR 只能用 @Query，派生查询无法表达）
@Query("""
        select u.id from SysUser u
        where lower(u.displayName) like :pattern or lower(u.username) like :pattern
        """)
List<Long> findIdsByKeyword(@Param("pattern") String pattern);
```

`pattern` = `"%" + keyword.toLowerCase(Locale.ROOT).trim() + "%"`。**不加 `role` 过滤**：现网不区分角色，且误命中的教师 id 不会出现在 `lab_submission.student_id` 中，保持行为等价。

**Service（`LabService.listTeacherReports` 重写）**：

```text
1. requireTeacher(currentUser)
2. 归一化并校验分页参数：
   page     = query.page     == null ? 1  : query.page
   pageSize = query.pageSize == null ? 10 : query.pageSize
   page < 1 或 pageSize < 1 或 pageSize > 100 → BusinessException(40000, "参数不合法")
3. ownedLabs = labRepository.findByCreatedByOrderByIdDesc(currentUser.id())
   ownedLabIds 为空 → return new PagedResult<>(List.of(), page, pageSize, 0)
4. scopeLabIds = query.labId == null ? ownedLabIds : (ownedLabIds ∩ {query.labId})
   scopeLabIds 为空 → return new PagedResult<>(List.of(), page, pageSize, 0)
5. keyword = 归一化(query.keyword)；为空则跳过 5.1/5.2，keywordPredicateAbsent = true
   5.1 labKeywordHitIds = scopeLabIds 中满足
       LOWER(lab.title) 含 keyword OR LOWER(classRoom.name) 含 keyword 的 labId
   5.2 studentKeywordHitIds = sysUserRepository.findIdsByKeyword(pattern)
6. Specification（root = LabSubmission）：
   labId IN scopeLabIds
   AND [status 非空 → submitStatus = SubmissionStatus.valueOf(status.trim().toUpperCase(Locale.ROOT))；
        解析失败 → 直接返回空 PagedResult（不抛异常，对齐现网"等值匹配不到即空"）]
        注：现网 normalize() 对两侧都做 toLowerCase，故 status 大小写不敏感；
            这里先 toUpperCase 再 valueOf 才能保持等价，禁止直接 valueOf 原始入参
   AND [keyword 非空 → keywordPredicate]
       keywordPredicate 按命中集是否为空分四种情况写死（不得对空集合拼 IN）：
         labHit 非空 且 studentHit 非空 → cb.or(labId IN labHit, studentId IN studentHit)
         labHit 非空 且 studentHit 为空 → labId IN labHit
         labHit 为空 且 studentHit 非空 → studentId IN studentHit
         两者均为空                    → cb.disjunction()（恒假 → 空结果）
   注意：keyword 的各字段之间必须是 OR，不能写成 AND；labHit 也不得折叠进 scopeLabIds
7. PageRequest.of(page - 1, pageSize, Sort.by(Sort.Direction.DESC, "id")) → findAll(spec, pageable)
8. items = toReportListViews(pageResult.getContent())      // 见 5.1.1
9. return new PagedResult<>(items, page, pageSize, pageResult.getTotalElements())
```

#### 5.1.1 `toReportListViews(List<LabSubmission>)`（分页与 queue 共用，唯一映射实现）

```text
1. 收集 rows 的 labIds / studentIds 去重
2. labById      = labRepository.findAllById(labIds)        → Map<Long, Lab>      （一次）
3. userById     = sysUserRepository.findAllById(studentIds) → Map<Long, SysUser> （一次）
4. classById    = classRoomRepository.findAllById(labById 的 classId 去重)        （一次）
5. 逐行组装，字段与现网 toReportListView 完全一致：
   id / labId / labTitle / classId / className / studentId / studentName /
   studentUsername / studentNo(=username) / submitStatus / totalScore /
   summaryRequired / submittedAt / gradedAt
   lab/class/user 缺失时按现网语义取空（labTitle 为空、className 为空串）
6. 删除现有单行 toReportListView(LabSubmission)
```

**queue 接口（`LabService.listTeacherReportQueue`）**：

```text
1. requireTeacher(currentUser)
2. ownedLabIds = labRepository.findByCreatedByOrderByIdDesc(currentUser.id())
   为空 → return List.of()
3. submissions = labSubmissionRepository.findByLabIdIn(ownedLabIds)
   按 id DESC 排序
4. return toReportListViews(submissions)     // 同一批量映射，无 N+1
```

**stats 接口（`LabService.getTeacherReportStats`）**：

```text
1. requireTeacher(currentUser)
2. ownedLabIds = ...；为空 → return {total: 0, submitted: 0, graded: 0}
3. rows = labSubmissionRepository.countGroupByStatus(ownedLabIds)   // List<Object[]>{status, count}
4. submitted = status == SUBMITTED ? count : 0 的累加
   graded    = status == GRADED    ? count : 0 的累加
   total     = rows 全部 count 累加（含 SAVED，对齐现网 rows.length 口径）
5. return {total, submitted, graded}
```

## 6. 筛选语义矩阵

| 条件 | 解析位置 | 谓词形态 | 备注 |
|---|---|---|---|
| 教师数据域 | 内存（ownedLabs） | `labId IN scopeLabIds` | 沿用现状权限口径 |
| `labId` | 内存（交集） | `scopeLabIds = owned ∩ {labId}` | 自前端下沉 |
| `status` | DB | `submit_status = ?`；非法值 → 空结果 | 枚举等值 |
| keyword → 实验名 / 班级名 | 内存（lab / classRoom 命中） | `labId IN labKeywordHitIds` | 与下一行 **OR** |
| keyword → 姓名 / 学号 / 用户名 | DB（`SysUserRepository.findIdsByKeyword`） | `studentId IN studentKeywordHitIds` | 与上一行 **OR** |
| 排序 | DB | `ORDER BY id DESC` | 确定性 |

keyword 复合谓词展开：`(labId IN labKeywordHitIds OR studentId IN studentKeywordHitIds)`。**不可**把 `labKeywordHitIds` 折叠进 `scopeLabIds` 后与 `studentId IN` 做 AND——那会误杀"实验名命中但学生名不命中"与"学生名命中但实验名不命中"两类报告。

行为保持不变的部分：行字段集、keyword 五字段 OR 语义、非法 status 空结果、教师权限域、`ApiResponse` 包装。

行为变化的部分：响应结构（数组 → PagedResult）、列表顺序（无序 → id DESC）、labId 过滤时机（前端 → 后端）。

## 7. 测试用例

### 7.1 后端（`LabServiceTests` + `LabTeacherControllerTests`）

**改造现有**：

1. `teacherCanReadSeededLabReports` — 适配 `PagedResult` 返回，断言 `items()` 内容不变；**构造参数由 2 个补齐为 5 个**：`new TeacherLabReportQuery(null, null, null, null, null)`。

3. `LabTeacherControllerTests` 中 2 个 `/teacher/lab-reports` 用例 — mock 返回 `PagedResult`，断言 JSON 含 `items/page/pageSize/total`、query 参数透传。

**新增（Service）**：

4. 默认分页：不传 `page/pageSize` → `page=1`、`pageSize=10`，且 `items` 不超过 10 条。
5. 分页切片：>pageSize 的数据集下，`page=1/pageSize=1` 与 `page=2/pageSize=1` 返回不同且不重叠的行；`total` 为全量命中数。
6. **keyword OR 语义回归**：构造"实验名含关键词、学生姓名不含关键词"的报告 → 仍被返回；再构造"学生姓名含关键词、实验名不含"的报告 → 也返回。
7. keyword 命中班级名 → 返回对应学生报告。
8. keyword 无命中 → 空 items、total=0，不抛异常。
9. status 大小写等价：传 `graded`（小写）→ 结果与 `GRADED` 完全一致（覆盖现网 `normalize` 的大小写不敏感行为）。
9b. 非法 status（如 `GRADEDX`）→ 空 items、不抛异常。
10. `page=0` / `pageSize=0` / `pageSize=101` → 抛 `BusinessException`，message="参数不合法"。
11. `labId` 过滤 → 仅返回该实验的提交。
12. 教师无实验 → 分页/queue/stats 均返回空结构（`total=0`、空数组、`{0,0,0}`），不抛异常。
13. `queue`：返回全量行、行字段与分页接口一致、按 `id DESC`。
14. `stats`：种子数据下 `total/submitted/graded` 正确，且 `total` 含 `SAVED`（= 各状态计数之和）。

**新增（Controller）**：

15. `GET /teacher/lab-reports?page=2&pageSize=5&labId=1` — 200，参数透传断言。
16. `GET /teacher/lab-reports/queue` — 200，`data` 为数组。
17. `GET /teacher/lab-reports/stats` — 200，`data` 含 `total/submitted/graded` 三键。

## 8. 验收标准（P4 执行，逐条打勾）

| # | 场景 | 通过条件 |
|---|---|---|
| A1 | 队列页首屏 | 默认每页 10 条，底部分页显示"共 N 条"，实际行数 = min(10, N) |
| A2 | 翻页 | 点第 2 页，行内容与第 1 页不重叠；`item` 数正确 |
| A3 | keyword OR 语义 | 输入只命中实验名（不含学生名）的关键词，结果非空且包含该实验的报告 |
| A4 | status 筛选后翻页 | 选"已提交"后翻到第 2 页，当前页全部为"已提交" |
| A5 | labId 筛选 | 选单个实验，只剩该实验行，分页总数随之变小 |
| A6 | 改 pageSize | 切 20 条/页，每页 20 条且回到第 1 页 |
| A7 | 打回联动 | 对一条已提交报告点"打回"，成功后列表刷新、头部"待批改"减 1、页码不越界 |
| A8 | 导航队列不受分页影响 | 详情页 / 批量批改页"上一份/下一份"可跨全部报告正常跳转 |
| A9 | 空态 | 教师无实验或筛选无结果时，列表显示空态，头部统计不报错 |
| A10 | 越界回退 | 在末页执行收紧筛选，页码自动回退到最后一个有效页，不出现空白页 |

## 9. 兼容性与风险

| 风险 | 评估 | 缓解 |
|---|---|---|
| 响应结构 breaking change | 低：前后端同仓同发布，3 个消费方全部同批迁移；已 grep 确认无其他调用方 | 编译期强类型兜底；不做兼容 shim |
| keyword 命中学生集合过大（如单字关键词）导致 IN 集合膨胀 | 低：当前校级学生规模百级；IN 集合数百到千级在 H2/MySQL 均无压力 | 已知边界记录在案；未来万人规模时将 studentId 维度下沉为子查询（D2 的备选路径） |
| 列表顺序从无序变为 id DESC | 极低：属行为修正；前端无顺序依赖（priority 标签按状态渲染） | A2/A8 冒烟确认 |
| stats 与分页请求时序差导致头部数字短暂不一致 | 低：打回/批改后同步双刷 | 可接受，不做轮询 |
| `/queue`、`/stats` 与 `/{id}` 路由冲突 | 无：Spring MVC 字面量路径优先于模板；`{id}` 为 Long 也不会匹配字符串 | 用例 16/17 覆盖 |
