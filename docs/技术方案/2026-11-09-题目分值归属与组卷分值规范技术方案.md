### 3.3 批改分值边界（Service 兜底）

统一写法：每个校验点就地 `if (...) throw new BusinessException(40000, 文案)`，不新建工具类（三处服务的错误文案与取数上下文不同，共用反而增加耦合）。

**考试 `ExamReportService`**（两条显式给分路径，同一校验）：

- `gradeSubmission`（:240-257 循环内，主观题分支；客观题 `continue` 现状保留）；
- `confirmAnswer` 的 `acceptSuggested=false` 分支（:326-330，`setScore` 之前）。

```java
// snapshot 为 QuestionSnapshot record，分值字段是 score()（实测 QuestionSnapshot.java:9）
if (item.score() == null || item.score() < 0 || item.score() > snapshot.score()
        || item.score() % 1 != 0) {
    throw new BusinessException(40000, item.score() % 1 != 0 ? "分数必须为整数" : "分数必须在 0 到该题分值之间");
}
```

快照 `score` 为 null（历史脏数据）时跳过上限，只校验非负与整数。

**作业 `HomeworkReportService.gradeAnswer`**（:240-243 的 else 分支内）：

- 先 `HomeworkQuestion hq = homeworkQuestionRepository.findById(answer.getHomeworkQuestionId()).orElseThrow(...40400 "作业题目不存在")`（`HomeworkAnswer.homeworkQuestionId` 字段实测存在）；
- `acceptSuggested=false` 时：`score == null` 维持现文案；`score < 0 || score > hq.getQuestionScore()` → “分数必须在 0 到该题分值之间”；`score % 1 != 0` → “分数必须为整数”；
- `acceptSuggested=true` 分支不动（忽略 `request.score()`）。

**作业 `HomeworkReportService.gradeSubmission`**（:133-149，`setTotalScore` 之前）：

- `List<HomeworkQuestion> questions = homeworkQuestionRepository.findByHomeworkIdOrderBySortOrder(homework.getId())`（方法实测存在）；
- `questions` 非空：`planTotal = questions.stream().mapToDouble(q -> q.getQuestionScore() == null ? 0 : q.getQuestionScore()).sum()`；`totalScore == null || totalScore < 0` → “总评不能为负数”；`totalScore > planTotal` → “总评不能超过计划满分 {(long) planTotal} 分”；`totalScore % 1 != 0` → “分数必须为整数”；
- `questions` 为空（附件型）：不校验，沿用现状。

**实验 `LabReportService`**：

- `gradeSteps`（:589-590 现有范围校验后追加）：`item.score() % 1 != 0` → 40000 “分数必须为整数”；
- `confirmStepScore` 的 `acceptSuggested=false` 分支（:642-648，现网只有 null 校验，且该方法**尚未加载 `LabStep`**）：先新增 `LabStep step = labStepRepository.findByIdAndLabId(answer.getLabStepId(), lab.getId()).orElseThrow(...40400 "实验题项不存在")`（与 `gradeSteps` :583 同法），再在 null 校验后新增 `score < 0 || score > step.getStepScore()` → “分数必须在 0 到该题分值之间”，以及 `score % 1 != 0` → “分数必须为整数”；
- `acceptSuggested=true` 路径不动。

## 7. 验收标准（对照 PRD §12）

1. 题库列表、编辑弹窗、选题弹窗题库候选区无任何分值文案；已选面板保留分值输入。
2. 题库接口响应无 `defaultScore`；请求携带该字段返回 400 / 40000 且文案含字段名（create 与 update 均覆盖）。
3. 导入含 `score` 的历史 JSON 时该行 `ERROR` 并显示字段名；删除废止字段后导入成功，题库无分值。
4. 作业内联题、实验题项复制到题库成功，题库无分值。
5. 备份 → 应用 V27、V28 → `./scripts/path-b/backend.sh` 启动正常，历史题库题可读可用，三张配置表存在 3 个 CHECK 约束。
6. 考试/作业分值 0、-1、101、2.5 被拒且文案一致；1、100 成功；实验步骤分 0、100 成功，-1、101、2.5 被拒。
7. 考试/作业组卷页显示“计划满分 X 分”，随增删改题实时更新；实验页文案为“计划满分 X 分”。
8. 已发布考试/作业/实验改分被拒；作业草稿有作答题改分被拒、其余题可改。
9. 考试/作业批改越界、负数、非整数被拒；附件型作业总评任意值通过；全 0 分实验可批改且成绩页无 `/ 0`。
10. 学生成绩页：计划满分 > 0 显示“总分 X / 计划满分 Y”；= 0 只显示总分。
11. `cd frontend && npm run build && npm test`、`cd backend && ./mvnw test` 全绿；`./scripts/common/healthcheck-login.sh` 通过（演示账号 `t9001/123456`、`20260001/123456` 手工走查验收 1–10）。

## 9. 已否决方案

| 否决项 | 原因 |
|---|---|
| 保留 `default_score` 列改名 `reference_score` | PRD D2：题库不保留任何形式分值；双字段必生漂移 |
| Service 层手写 `score >= 1 && score <= 100 && score == Math.floor(score)` 替代 Bean Validation | 三处 DTO 重复代码；Bean Validation 是现网组卷校验的既有形态 |
| 计划满分由后端返回字段 | PRD D10：前端派生不落库，避免与请求逐题分值双真相 |
| 作业总评上限对附件型一并生效 | 会把无题目作业的总评锁死为 0，误伤现网能力（PRD D12 例外） |
| 新增 `ScoreValidation` 公共工具类 | 三个服务的取数上下文（快照 / HomeworkQuestion / LabStep）与文案分支不同，就地校验更直白 |
