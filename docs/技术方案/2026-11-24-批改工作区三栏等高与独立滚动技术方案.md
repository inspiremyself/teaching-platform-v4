- **日期**：2026-11-24
- **状态**：**已定稿（决策写死，可直接编码）**
- **来源**：调研结论「三域下边不对齐，是否搞个外部容器滚动窗」；采用方案 A「外层定高 + 各栏独立内滚」

## 4. 逐文件改动规格

### 4.1 `GradingWorkspace.vue`（TD1）

### 4.2 `workbench.css`（TD3–TD9）

保留 L227–238 原规则不变（作为 `<900px` 自然流基线），将以下规则**追加到 `workbench.css` 文件末尾**；L249–256、L275–280、L325–334 原定义保留，由锁定态规则按选择器优先级覆盖（`.grading-workspace .xxx` 为两级选择器，优先级高于原单类规则，与书写顺序无关）：

```css
@media (min-width: 900px) {
  .grading-workspace .grading-layout {
    flex: 1;
    min-height: 0;
    align-items: stretch;
  }

  .grading-workspace .grading-layout__queue,
  .grading-workspace .grading-layout__detail,
  .grading-workspace .grading-layout__summary {
    min-height: 0;
    overflow-x: hidden;
    overflow-y: auto;
  }

  .grading-workspace .submission-queue,
  .grading-workspace .grading-summary,
  .grading-workspace .summary-side {
    position: static;
    top: auto;
  }

  .grading-workspace .submission-queue__list {
    max-height: none;
    overflow: visible;
  }
}

@media (min-width: 900px) and (max-width: 1279px) {
  .grading-workspace .grading-layout {
    grid-template-rows: minmax(0, 1fr) auto;
  }

  .grading-workspace .grading-layout__summary {
    overflow: visible;
  }
}
```

约束说明：

- `.grading-workspace` 同时是 `.workbench-page`（flex column，gap:16px），`flex:1` 使其网格占满 header 之外的全部高度；`min-height:0` 是 flex 子项允许收缩的必要条件，二者缺一不可。
- `align-items:stretch` 只覆盖锁定态；`<900px` 仍为 `start`，保持现网自然流。
- 三栏 `overflow-y:auto` 放在 grid item 上而不是其内部面板上，滚动条贴栏边缘，内部白卡随内容滚。
- `.summary-side` 的选择器写在全局 `workbench.css` 中，但它同时被 `Results.vue` scoped 定义；为避免加载顺序不确定，TD9 另外要求直接删除 `Results.vue` 中的 sticky 声明，本规则只作为其余 4 页的统一收口。
- 1279px 以下 summary 被移到第二行；若不给 `grid-template-rows`，两行会等比压缩中栏。写死第一行为 `minmax(0,1fr)`、第二行 `auto`，并让 summary 栏 `overflow:visible`，避免右栏出现第二条滚动条。

## 5. 关键行为与边界

| 场景 | 实现口径 |
|---|---|
| 宽度 ≥1280px | header 自适应；下方三栏等高等宽（列宽不变），三栏上下边界齐平，各自内部滚动 |
| 900px ≤ 宽度 ≤ 1279px | 两行网格：第一行 queue/detail 等高内滚；第二行 summary 通栏按内容高度显示、不滚动 |
| 宽度 <900px | locked 规则全部不生效，恢复现网自然文档流 + 页面级滚动，三栏 `align-items:start` |
| 中栏题卡很多 | 只有中栏出现滚动条；左右栏保持可见，不再随页面滚走 |
| 左栏学生很多 | 只有 `.grading-layout__queue` 一条滚动条，列表自带 65vh 内滚被关闭 |
| 右栏内容超长 | 只在 `.grading-layout__summary` 内滚动；窄屏第二行不滚动、按内容撑开 |
| 题卡加载中 / 空列表 | `v-loading` 与空态仍由页面插槽渲染，本方案不改变其内容与时机 |
| 切题 / 草稿保护 / 竞态 | 仍走 Facade `guardBeforeSwitch` 与 `selectionToken`，滚动位置变化不触发任何业务动作 |
| 评分 / 打回 / 发布 / 单题确认 | 请求、确认框、toast 与禁用态全部零改动 |
| 浏览器缩放 / 窗口 resize | 断点切换由 CSS media query 即时完成；不引入 JS 监听、不保存滚动位置 |

## 9. 已否决方案

| 否决项 | 原因 |
|---|---|
| 三栏共用一个外部滚动窗 | 统一滚动容器不改变 grid item 按内容收缩的事实，底边仍不齐；与左栏 65vh 内滚形成嵌套滚动，sticky 依旧失效 |
| 只把 `align-items` 改 `stretch` | 能让底边齐平、sticky 生效，但中栏继续拉长整页，左右栏下半仍空白，未解决「滚动时左右栏离场」 |
| 用 JS 监听滚动同步三栏 `scrollTop` | 引入事件监听与竞态，破坏原生滚动手感，且无法处理内容高度差异 |
| 给每栏设固定 `vh` 高度（如 `calc(100vh - 240px)`） | 硬编码 header 高度，页头操作换行时失效；已有 `--locked` 链路可精确计算剩余高度 |
| 改 `layout/index.vue` 新建锁定模式 | 既有链路已覆盖 5 页所需，重复实现会造成两套口径 |
| 引入虚拟滚动或分页 | 题卡数量在现网规模内可由原生滚动承载，新增依赖超出纯布局需求 |
| 删除 `workbench.css` 原 `align-items:start` | 它是 <900px 自然流的基线，删除会改变窄屏行为 |
