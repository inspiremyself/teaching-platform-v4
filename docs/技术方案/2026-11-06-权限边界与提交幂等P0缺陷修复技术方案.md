## 3. 现状盘点与差距

| 差距 | 现网事实 | 对应决策 |
|---|---|---|
| 查重详情无角色注解 | `detail` 仅 `@GetMapping`；服务层只判断学生与教师两个分支，校管直穿 | TD1–TD3 |
| 教师归属默认放行 | `teacherOwnsTask` 对非 `TEACHER` 返回 `true` | TD3 |
| 改密不处理会话 | `changePassword` 只改 `passwordHash` 并写审计 | TD4 / TD6 |
| 校管只踢一条会话 | `resetPassword` 用 `findFirst...` | TD5 / TD6 |
| 题项变更只看归属 | `createStep/updateStep/deleteStep` 仅 `ownedLab` | TD8 / TD9 |
| 状态可任意回退 | `changeLabStatus` 与 `updateLab` 直接写 `status` | TD10 |
| 详情泄露判分 | `autoScore`、`manualScore`、`isCorrect` 无条件返回 | TD13 |
| 交卷响应泄露判分 | `submitExam` 无条件返回 `autoScore` / `totalScore` | TD14 |
| 交卷无锁 | `findByExamIdAndStudentId` + find-then-check | TD16 |
| 开始考试并发 500 | 无唯一键冲突处理 | TD17 |
| 答案与成绩无唯一约束 | `exam_answer`、`score_record` 仅普通索引 | TD18 / TD19 |
| 试卷题目可重复 | `exam_question` 无唯一约束，`createExam` / `updateExam` 不校验重复 `questionId`；加唯一约束后重复题试卷交卷会冲突 | TD37 |
| 成绩写入分散 | 四处 `scoreRecordRepository.save`，`ScoreRecordWriter` 无人调用 | TD21 / TD22 |
| 作业重交不校验状态 | 只拒绝 `CLOSED` | TD25 |
| 无打回能力 | 无接口、无按钮、无审计常量 | TD26–TD30 / TD33 / TD34 |
| 前端仅凭 `GRADED` 进成绩视图 | `canShowResult` 与入口条件均含非可见性判断 | TD31 / TD32 |

现网核对结论：

1. `CurrentUser` 为 record，含 `sessionKey`，`changePassword(CurrentUser, ...)` 可直接取得当前会话标识。
2. `JwtAuthenticationFilter` 对 `KICKED` 返回 HTTP 401 + `40102`，批量置 `KICKED` 即可让旧 token 立即失效。
3. `audit_log.action` 与 `resource_type` 均为 `VARCHAR(64)`，`AuditAction` / `AuditResourceType` 无作业常量，新增枚举无需 DDL。
4. `ScoreRecordWriter.write(BusinessType, Long, Long, Long, Double, OffsetDateTime)` 已存在且全仓无调用；四处直写点与 PRD 所列完全一致。
5. `LabSubmissionRepository` 已有 `findByLabIdAndStudentIdForUpdate`，无 `countByLabId`；`ExamSubmissionRepository`、`HomeworkSubmissionRepository` 均无 `ForUpdate` 方法。
6. `V1__init_schema.sql` 已有 `uk_exam_submission (exam_id, student_id)`；`exam_answer`、`score_record` 无唯一约束。
7. 当前迁移最高版本为 `V22__question_source_trace.sql`，`V23` 序号可用。
8. `HomeworkAnswerRepository.findByHomeworkSubmissionId` 已存在，打回清空逐题痕迹无需新增查询方法。
9. `exam_answer.id` 与 `score_record.id` 均为自增主键，去重保留 `MAX(id)` 可行。
10. `HomeworkSubmissions.vue` 批改弹窗底部已有 `保存评分` 按钮，打回入口挂载点明确。

## 4. 后端设计

### 4.1 查重详情鉴权（TD1–TD3）

控制器：

```java
@GetMapping("/{id}")
@PreAuthorize("hasAnyRole('TEACHER','STUDENT')")
public ApiResponse<?> detail(@PathVariable Long id) {
    return ApiResponse.ok(plagiarismService.getTaskDetail(SecurityUtils.currentUser(), id));
}
```

服务层：

```java
switch (user.role()) {
    case STUDENT -> {
        if (!Objects.equals(task.getStudentId(), user.id())) {
            throw new BusinessException(40300, "无权限访问该查重记录");
        }
    }
    case TEACHER -> {
        if (!teacherOwnsTask(user, task)) {
            throw new BusinessException(40300, "无权限访问该查重记录");
        }
    }
    default -> throw new BusinessException(40300, "无权限访问该查重记录");
}
```

- `teacherOwnsTask` 第一分支改为 `if (teacher.role() != UserRole.TEACHER) return false;`。
- `list`、`review` 与其他查重接口不变。

仓储新增：


`submitExam` 首行改为使用该查询，锁内完成状态校验、答案删除、评分、写入与状态推进。

`startExam` 结构：

```java
// 方法不再标注 @Transactional；事务模板为字段 transactionTemplate
public Object startExam(CurrentUser currentUser, Long examId) {
    // 1. 考试存在性、发布状态、班级成员、内联题校验
    // 2. 已存在提交按现有状态返回或拒绝
    // 3. 时间窗校验
    OffsetDateTime now = OffsetDateTime.now();
    OffsetDateTime deadlineAt = now.plusMinutes(exam.getDurationMinutes());
    if (exam.getEndAt() != null && deadlineAt.isAfter(exam.getEndAt())) {
        deadlineAt = exam.getEndAt();
    }
    try {
        ExamSubmission created = Objects.requireNonNull(transactionTemplate.execute(status -> {
            ExamSubmission submission = new ExamSubmission();
            submission.setExamId(examId);
            submission.setStudentId(currentUser.id());
            submission.setStartedAt(now);
            submission.setDeadlineAt(deadlineAt);
            submission.setStatus(ExamSubmissionStatus.IN_PROGRESS);
            return examSubmissionRepository.saveAndFlush(submission);
        }));
        return buildStartResult(created, now);
    } catch (DataIntegrityViolationException ex) {
        ExamSubmission existing = examSubmissionRepository
                .findByExamIdAndStudentId(examId, currentUser.id())
                .orElseThrow(() -> new BusinessException(40900, "考试提交创建冲突，请重试"));
        if (existing.getStatus() == ExamSubmissionStatus.IN_PROGRESS) {
            return buildStartResult(existing, now);
        }
        throw new BusinessException(40000, "考试已提交，不能重新开始");
    }
}
```

- 构造函数新增 `PlatformTransactionManager` 参数，并以 `this.transactionTemplate = new TransactionTemplate(transactionManager)` 保存字段；不新增 Bean、不新增类。
- 截止时间沿用现值算法，在方法内直接计算，不新增 `resolveDeadline` 方法。
- 创建步骤必须 `saveAndFlush`，保证唯一键冲突在 `execute` 内抛出。
- 其他异常不在捕获范围。

### 4.6 成绩写入幂等（TD21–TD24）

`ScoreRecordWriter`：

```java
@Transactional
public ScoreRecord write(BusinessType businessType, Long businessId, Long studentId,
                         Long classId, Double score, OffsetDateTime gradedAt) {
    ScoreRecord scoreRecord = scoreRecordRepository
            .findByBusinessTypeAndBusinessIdAndStudentId(businessType, businessId, studentId)
            .orElseGet(ScoreRecord::new);
    scoreRecord.setBusinessType(businessType);
    scoreRecord.setBusinessId(businessId);
    scoreRecord.setStudentId(studentId);
    scoreRecord.setClassId(classId);
    scoreRecord.setScore(score);
    scoreRecord.setGradedAt(gradedAt == null ? OffsetDateTime.now() : gradedAt);
    try {
        return scoreRecordRepository.saveAndFlush(scoreRecord);
    } catch (DataIntegrityViolationException ex) {
        throw new BusinessException(40900, "成绩记录并发冲突，请重试");
    }
}
```

调用点与加锁入口：

| 业务 | 写成绩位置 | 前置锁与取键顺序 |
|---|---|---|
| 考试交卷 | `submitExam` | `findByExamIdAndStudentIdForUpdate(examId, studentId)`，已有键，直接锁 |
| 考试整体批改 | `gradeSubmission` | 先 `findById(submissionId)` 取 `(examId, studentId)`，再 `findByExamIdAndStudentIdForUpdate` 锁内重读 |
| 考试逐题确认 | `confirmAnswer` | 同 `gradeSubmission` |
| 实验提交 | `submitLab` | 已有 `findByLabIdAndStudentIdForUpdate(labId, studentId)` |
| 实验报告批改 | `gradeReport` | 先 `findById(reportId)` 取 `(labId, studentId)`，再 `findByLabIdAndStudentIdForUpdate` 锁内重读 |
| 实验步骤重判 | `saveBlankAcceptedAnswers` 内的 `refreshSubmissionAfterScoring` 循环调用点 | 循环内按每条提交的 `(labId, studentId)` 加锁重读后再重算 |
| 作业整体批改 | `gradeSubmission` | 先 `findById(submissionId)` 取 `(homeworkId, studentId)`，再用新增的 `findByHomeworkIdAndStudentIdForUpdate` 锁内重读 |
| 作业逐题批改 | `gradeAnswer` → `refreshSubmissionGradeState` | 先 `findById(answer) → findById(submission)` 取 `(homeworkId, studentId)`，再锁内重读 |

- 锁内重读得到的对象是唯一写入主体，锁外对象不得再 `save`。
- 锁内重读后必须用锁内对象重跑原方法已有的状态校验：考试 `gradeSubmission` / `confirmAnswer` 仅允许 `SUBMITTED` / `AUTO_SUBMITTED`（`confirmAnswer` 另允许 `GRADED`），作业 `gradeSubmission` 仅允许 `SUBMITTED`；`LabService.gradeReport` 当前无状态校验，维持现状，不新增。
- `ScoreRecordWriter` 是唯一捕获点；调用方不重复捕获，避免同一事务二次包装。
- 删除各服务内私有 `upsertScoreRecord` 直写逻辑；`ExamService` 移除 `scoreRecordRepository` 字段（仅该直写点使用），`LabService` 与 `HomeworkService` 保留该字段仅供打回删除成绩记录使用（`LabService` 现有打回段直接依赖该字段）。
- 实验打回删除成绩记录的现有行为不变。
- `ExamAnswerRepository.deleteByExamSubmissionId` 改为 `@Modifying(flushAutomatically = true)` + `@Query("DELETE FROM ExamAnswer a WHERE a.examSubmissionId = :examSubmissionId")` 批量删除：`ExamAnswer` 主键为 `IDENTITY`，插入会立即执行，派生删除会排队到提交时，配合 `uk_exam_answer_submission_question` 存在“先插入后删除”的冲突风险。

文件：`backend/src/main/resources/db/migration/V23__unique_answer_and_score_record.sql`

```sql
-- 1) exam_answer 去重：保留每个 (exam_submission_id, question_id) 分组中 id 最大的一行
DELETE FROM exam_answer
WHERE id NOT IN (
    SELECT keep_id FROM (
        SELECT MAX(id) AS keep_id
        FROM exam_answer
        GROUP BY exam_submission_id, question_id
    ) keep_rows
);

ALTER TABLE exam_answer
    ADD CONSTRAINT uk_exam_answer_submission_question
    UNIQUE (exam_submission_id, question_id);

-- 2) score_record 去重：保留每个 (business_type, business_id, student_id) 分组中 id 最大的一行
DELETE FROM score_record
WHERE id NOT IN (
    SELECT keep_id FROM (
        SELECT MAX(id) AS keep_id
        FROM score_record
        GROUP BY business_type, business_id, student_id
    ) keep_rows
);

ALTER TABLE score_record
    ADD CONSTRAINT uk_score_record_business_student
    UNIQUE (business_type, business_id, student_id);
```

执行约定：

- 不使用 `IF NOT EXISTS`，依赖 Flyway 只执行一次。
- 派生表别名 `keep_rows` 为 MySQL 必需写法，H2 2.x 同样接受。
- 迁移脚本注释保留“保留 `MAX(id)`”规则，执行后在验收记录登记两张表的删除行数。

## 10. 风险、回滚与运维

| 风险 | 影响 | 应对 |
|---|---|---|
| `V23` 去重误删 | 历史答案或成绩缺失 | 迁移前强制备份；固定保留 `MAX(id)`；执行后登记删除行数 |
| 唯一约束与存量重复冲突 | 迁移失败、启动失败 | 先去重后建约束；H2 与 MySQL 双端预演 |
| 存量试卷含重复题目 | 交卷触发唯一键冲突 | 交卷按 `questionId` 去重且只计一次分；新增/修改试卷拒绝重复题目 |
| 答案删除与插入顺序 | 交卷时唯一键冲突 | `ExamAnswerRepository.deleteByExamSubmissionId` 改 `@Modifying` 批量删除 |
| 批量踢会话范围过大 | 用户被意外登出 | 改密保留当前 `sessionKey`；仅无会话标识时全踢 |
| 实验题项锁定影响日常 | 已发布实验无法改题 | 引导复制副本；复制能力不改 |
| 判分遮蔽影响既有页面 | 学生看不到原本可见信息 | 仅非 `IMMEDIATE` 受影响；前端按 `resultAvailable` 分支 |
| 打回误清除评分 | 教师误操作 | 二次确认；仅 `SUBMITTED` / `GRADED` 可打回；写审计 |
| 悲观锁增加等待 | 交卷响应变慢 | 锁粒度限定为单学生单业务提交行 |

回滚：

- 代码回滚至上一版本。
- `V23` 属破坏性去重，代码回滚不会恢复删除行，必须用迁移前备份恢复数据库。
- 打回为新增能力，代码回滚后已存在的 `SAVED` 记录按现有逻辑可继续提交，无需修数据。

## 11. 已否决方案

| 否决项 | 原因 |
|---|---|
| 新增 `LoginSessionStatus.INVALIDATED` 区分改密踢人 | 需同步前端 `request.ts` 与登录页提示，超出 P0 范围；复用 `KICKED` + `40102` 即可失效 |
| 对 `score_record` 不存在的行加悲观锁 | 数据库对不存在的行无法加锁，阻止不了并发插入；改为锁业务提交行 |
| 在 `submitExam` 事务内捕获唯一键冲突后重读 | 约束冲突会把事务标记为回滚，后续查询不可用 |
| 为 `startExam` 新增独立 Bean 承载创建事务 | 仅一处使用，`TransactionTemplate` 更小；避免新增类与自调用代理问题 |
| 给 `exam_answer` / `score_record` 建幂等业务键列 | 现有字段组合已能唯一标识，新增列需回填与迁移，成本更高 |
| 作业打回删除提交行重建 | 会丢失作答内容与历史关联，违反“保留作答”语义 |
| 校管新增查重查询视图 | 本期安全优先，直接 403；后续按产品需要单列 |
| 为 `exam_question` 增加唯一约束 | 存量重复题目需删除行，会直接改变试卷结构与分值；改为写入校验 + 交卷去重 |
