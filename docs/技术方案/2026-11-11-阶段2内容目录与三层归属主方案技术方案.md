## 3. 数据库迁移 `V31__content_catalog_and_ownership.sql`

**总纪律**：纯结构变更 + 新表，无业务数据回填；`V1`–`V30` 只读冻结；不建 DB 外键（多态列与现网裸列范式）；`owner_scope` / `owner_school_id` / 分域学科两列的取值约束由应用层强制，不加 DB CHECK；只用四个占位符。

**DDL 注释口径（写死）**：SQL 块内用 `-- ` 行注释写死每张表的用途与关键列语义（MySQL / H2 都通用，不改变可执行 schema、不影响 Flyway 解析）。**不引入 MySQL 专有 `COMMENT '...'` 列注释 / 表级 `COMMENT=`，也不写 H2 的 `COMMENT ON`**：一是列内 `COMMENT` 属 MySQL 专有语法，双方言单脚本无法共用；二是 `backend-db-and-config.mdc` §1.4 已把 `SCHEMA.md` 定为表结构与变更说明的单一事实来源，在 DDL 里再写一份元数据注释会形成第二份口径。权威表/列说明仍由 TD15 同步进 `SCHEMA.md`。

### 3.1 九张新表 DDL（写死）

```sql
-- V31 内容目录与三层归属：9 张新表。表/列说明统一用 SQL 行注释承载（MySQL / H2 都通用）；
-- 权威表结构与变更说明见 db/migration/SCHEMA.md（TD15）。不引入 MySQL 专有 COMMENT 子句。
-- 多态列一律不建 DB 外键；owner_scope / 分域学科两列的取值由应用层强制，不加 DB CHECK。

-- textbook：平台级教材目录，同一学科 0..N 条教材；学科是归属列，不是树节点。
-- 不设 status 列：学校是否启用由 school_textbook 逐条唯一承载（D25），不形成第二个启用真相源。
CREATE TABLE textbook (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  global_subject_id BIGINT NOT NULL, -- 指向 subject.id（V30 平台学科字典），非空
  code VARCHAR(64) NOT NULL, -- 同学科内教材编码，与 global_subject_id 组成唯一键
  title VARCHAR(255) NOT NULL,
  created_by BIGINT NULL, -- 平台超管用户 id
```

**布置组与素材枚举（写死）**：`assignment_group_id` 取服务端生成的 **UUID v4 标准字符串（36 位、含连字符）**，标识一次布置，同一次布置写出的多行共享同一个值；**请求体不携带 `assignment_group_id` / `display_order` / `target_type` / `target_id` / `school_id` 等服务端生成字段**，`sectionIds` 是小节选择的唯一真相源（R15 / 评估文档 §5.1）、目标选择另由必填的 `targets` 承载（P19 / TD19）；选节按数组下标从 1 起为每个目标写 `display_order`，整份为每个目标写 1 行 `section_id = NULL` + `display_order = 0`（共 `目标数` 行）；顺序为布置时快照。`courseware_asset.kind` 写死两值 `IMAGE` / `AUDIO`，`file_path` 只存 `data/files/` 下相对路径，`mime` / `size_bytes` 由上传侧写入，**不内联 base64**（R16）。

**布置目标维度（写死，PRD P19 / TD19）**：`target_type` 两值 `CLASS` / `STUDENT`，`target_id` 均非空；`class_id` 始终是租户隔离、鉴权与按班查询的唯一依据，`target_id` 是多态冗余列，**服务端写值保证 `CLASS` 行 `target_id = class_id`、`STUDENT` 行 `target_id = student_user_id` 且 `class_id` 等于 `class_member` 中该生所属班级**；请求体与 DB 都不允许第三态。一次 `assignment_group_id` 支持 1..N 个目标（整班 / 多个班级 / 班内点名 / 两者混合）：**同组所有目标共享同一份有序 `sectionIds` 快照**，选节写 `目标数 × 选中节数` 行、整份写 `目标数` 行；不同目标要不同小节时另发起一次布置（新 `assignment_group_id`）。唯一键纳入 `target_type` / `target_id`，保证同一目标在同组内每个 `display_order` 只有一行；`idx_assignment_target` 承接学生端点名查询，`idx_assignment_school_class` 承接教师端按班与整班目标查询，`idx_assignment_courseware` 承接 D14「有布置引用禁物理删除（`40900`）」的按课件查询（平台课件可被多校布置，该查询不带 `school_id`）。阶段 4 布置端点唯一请求体写死为 `coursewareId` + `sectionIds` + `targets` 三项共存且均必填（另可带 `startAt` / `endAt` 时间窗）：`sectionIds` 是小节选择唯一表达（空数组 = 整份、非空 = 按数组顺序选节），`targets` 是目标选择唯一表达 `[{ classId, studentIds }]`（空 `studentIds` = `CLASS`，非空 = 每个学生一条 `STUDENT`；同一 `classId` 只出现一次），两者不拆端点、不拆成两次操作；**请求体不携带 `assignment_group_id` / `display_order` / `target_type` / `target_id` / `school_id` 等其它布置形态字段**，`school_id` 由 `currentUser.schoolId()` 写入；鉴权与学生端可见集合见 §4.2。本期不实现该端点与目标展开写入动作。
