## 3. 总体链路

```text
点击「下载规范示例」
  → downloadQuestionImportTemplate() → Blob → 题目批量导入模板.json

选择 / 拖拽 .json 文件
  → validateImportFileMeta(name, size)
  → file.text() → stripBom(text)
  → listQuestions() → existingCodes
  → parseImportDocument(text, existingCodes)
      → 顶层 wrapper 校验（fatalError）
      → 逐题类型前置判断 → normalizeImportQuestion
      → validateCodeRules（H1/H3/H2/H4/H6）
      → validateQuestion（AJV 内置 schema）
      → validateBusinessRow（第 3–18 条）
      → 判重 → READY / SKIP / ERROR
      → 批次阻断收口
  → 预览表 / 汇总 chips
  → startImport 串行 createQuestion(payload, { silent: true })
  → 40900 记「编码已被占用」跳过
  → copyFailedItems 输出 wrapper
```

后端接口、鉴权、数据库结构在这条链路中保持原样（TD1 / TD24 / TD25）。

#### 4.1.3 页面规范数据

- `IMPORT_CODE_REQUIREMENTS` 含 `pattern`（`QUESTION_CODE_PATTERN.source`）、`hardRules`（PRD §3.2 六条，H5 标注「判重，非阻断」）、`softRules`、`validExamples`、`invalidExamples`、`duplicateRule`；值均取 PRD §3.4 / §3.2。

#### 4.1.4 `QUESTION_IMPORT_SCHEMA`

```ts
export const QUESTION_IMPORT_SCHEMA = {
  $schema: 'https://json-schema.org/draft/2020-12/schema',
  type: 'array',
  minItems: 1,
  maxItems: QUESTION_IMPORT_MAX_QUESTIONS,
  items: {
    type: 'object',
    additionalProperties: false,
    required: IMPORT_FIELD_DEFINITIONS.filter(f => f.required).map(f => f.name),
    properties: Object.fromEntries(
      IMPORT_FIELD_DEFINITIONS.map(f => [f.name, f.jsonSchema]),
    ),
  },
};
```

`items.properties.code.pattern` 与 `IMPORT_CODE_REQUIREMENTS.pattern` 同为 `QUESTION_CODE_PATTERN.source`；模板里不出现第二份正则（TD7 / TD8）。

#### 4.4.3 文件读取流程（`applyImportFile`，TD20，8 步固定）

```text
1. const metaError = validateImportFileMeta(file.name, file.size)
   非空 → ElMessage.warning(metaError) → clearImportFile() → return
2. parsing.value = true
3. const text = stripBom(await file.text())
4. const items = await listQuestions().catch(() => null)
   if (!items) { clearImportFile(); return }
   const existingCodes = new Set(items.map(item => normalizeImportCode(item.code)))
5. const { result, fatalError: error } = parseImportDocument(text, existingCodes)
6. selectedImportFile.value = file; importFileName.value = file.name
   parseResult.value = result; fatalError.value = error; resetRoundState()
7. catch → clearImportFile() + ElMessage.error(error instanceof Error ? error.message : '导入文件解析失败，请检查文件内容')
8. finally → parsing.value = false; isDragOver.value = false
```

`handleImportFileChange(uploadFile)` 取 `uploadFile.raw`，为空直接 return，否则 `await applyImportFile(raw)`；`handleImportDrop(event)` 取 `event.dataTransfer?.files?.[0]`，为空时 `isDragOver.value = false` 并 return，否则 `await applyImportFile(file)`；`handleImportDragEnter` / `handleImportDragOver` 置 `true`；`handleImportDragLeave` 沿用 `Students.vue:342-349` 的 `currentTarget.contains(relatedTarget)` 判定；`clearImportFile()` 清空 `selectedImportFile` / `importFileName` / `parseResult` / `fatalError` / `isDragOver`，再调用 `resetRoundState()` 统一清 `importResults` / `hasImportRound` / `progress`；不重复赋值。并发文件选择用模块级 `let importFileSeq = 0`：`applyImportFile` 开头取 `const seq = ++importFileSeq`，第 4 步 `listQuestions()` 返回后、写入任何组件状态前检查 `seq !== importFileSeq` 则直接 return（不 `clearImportFile`、不弹提示），保证旧请求不覆盖新文件的预览；`finally` 仍由新请求负责复位 `parsing` / `isDragOver`。第 4 步的 `listQuestions()` 未传 `silent`，失败由 `request.ts` 全局 toast 呈现；`.catch(() => null)` 与空值提前 return 只清文件态，不进入第 7 步外层 catch，避免出现「导入文件解析失败」误导文案；`items` 类型由 `listQuestions(): Promise<QuestionItem[]>` 推断，不写隐式 `any`。

| 旧纯数组脚本失效 | 明确报 `导入文件必须是包含 formatVersion 与 questions 的 JSON 对象，请下载规范示例`（PRD D4） |
