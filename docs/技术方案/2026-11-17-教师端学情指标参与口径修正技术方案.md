## 3. 现网盘点与差距

| 差距 | 现网事实 | 对应决策 |
|---|---|---|

| 考试 / 作业报表只看已有行 | `ExamReportService.getExamResults()` L109–L144、`HomeworkController GET /teacher/homeworks/{id}/submissions` 均只返回提交行；两个 ReportService 的 `ClassMemberRepository` 注入未使用（本期不清理） | TD10–TD15 |

| 前端分析页 | `Analysis.vue` 挂载 `getAnalysis()`，仅 summaryCards / trend / 班级对比 / 业务分布；`api/teacher.ts:36-37` 分析 API 命名 `getAnalysis` / `getTeacherDashboard` | TD16–TD20 |
| 测试基线 | `AnalysisControllerTests.java:121` 硬断言 `summaryCards.length() == 4`；`AnalysisServiceTests` 夹具使用 `-8001` / `1001` / `1003` 等显式 id | TD21 |

现网核对结论：

1. `ActivityStatus` 仅 `DRAFT` / `PUBLISHED` / `CLOSED`；`ExamSubmissionStatus` 仅 `IN_PROGRESS` / `SUBMITTED` / `AUTO_SUBMITTED` / `GRADED`；与 TD1 / TD6 一致。
2. 三类活动实体均有 `classId` 与 `title`：实验为 `Lab.title` 映射列 `experiment_name`，作业 / 考试为 `title`；三类均有 `createdAt`（`Lab` 直写、`Homework` / `Exam` 继承 `BaseEntity` 映射 `created_at`），TD4 / TD5 / TD7 可落地。
3. `LabRepository` / `HomeworkRepository` / `ExamRepository` 现网均有 `findByIdAndSchoolId(Long, Long)`，TD10 无需新增仓储方法。
4. `ClassAccessService.findAssignment()` L47–L55 对本校外班级与未任课均抛 `40300`，TD10 第 ④ 步不再包装异常码。
5. `api/endpoints.ts` 现网只放路径构造器与两个 `fetch` 例外，TD17 只加一个相对路径构造器，不扩展 `fetch` 白名单。

## 4. 后端设计

### 4.1 `AnalysisService` 改动面

- 保留 `getDashboard(CurrentUser)` / `getTeacherOverview(CurrentUser)` 的 public 签名与既有查询。
- 构造器按 TD11 扩展；新增成员固定名单（TD24）：
  - `private static final class ParticipationSnapshot`：私有静态内部类，字段固定为 `businessType` / `businessId` / `businessTitle` / `createdAt` / `Set<Long> studentIds` / `expectedCount` / `participatedCount` / `completedCount`，构造器接收前四项，计数初值 0，不写 getter / setter，字段由 `AnalysisService` 的外层私有方法直接访问。
  - `private List<ParticipationSnapshot> buildParticipationRows(Long teacherId, Long schoolId)`：执行 TD2–TD5 的 UNION ALL 查询，按 `(businessType, businessId)` 分组为 `ParticipationSnapshot`，TD6 累加与去重全部在此方法内完成。
  - `private Map<String, Object> buildDashboard(CurrentUser teacher, List<ParticipationSnapshot> snapshots)`：现网 `getDashboard` 的主体搬迁到此私有重载，`summaryCards` 既有 4 张、`trend`、`recentTasks`、`quickLinks` 及其徽标全部保留现网查询与算法不变；仅第 5 张 `notStartedCount` 卡片改用传入的 `snapshots` 计算，不再发起汇总查询（TD26）。
  - `private boolean isCompleted(String businessType, String submissionStatus)`：TD6 终态判定。
  - `private Map<String, Object> toParticipationActivity(ParticipationSnapshot snapshot)`：生成 D5 的 `activities[]` 单项（8 个字段）。
  - `private Map<String, Object> toParticipationOverviewRow(String businessType, List<ParticipationSnapshot> snapshots)`：生成 D5 的一类行（10 个字段，`activities` 由 `toParticipationActivity` 结果按 TD7 排序）。
  - `private List<Map<String, Object>> queryParticipationStudents(String businessType, Long schoolId, Long teacherId, Long businessId, Map<String, Object> detailContext)`：TD12 单分支查询并按 TD13 组装 `students[]`；行回调把 `cr.name AS class_name` 写入 `detailContext` 的 `className` key（空班时不写入，外层按空串处理）。
  - 不新增其它成员方法；public 新增方法只有 TD10 的 `getTeacherParticipation(...)`。
- 按 TD26：`getDashboard()` 先调 `buildParticipationRows(...)` 再委托 `buildDashboard(...)`；`getTeacherOverview()` 自己调一次 `buildParticipationRows(...)`，再委托同一 `buildDashboard(...)` 后追加 `participationOverview`，**不再调用 public `getDashboard()`，同一请求只执行一次汇总 SQL**。

### 4.2 汇总 SQL（TD2–TD5，唯一形态）

```sql
SELECT 'LAB' AS business_type, e.experiment_id AS business_id, e.experiment_name AS business_title,
       e.class_id, e.created_at, cm.student_user_id, u.username AS student_no, u.display_name AS student_name,
       es.id AS submission_id, es.submit_status AS submission_status
FROM t_experiment e
JOIN class_room cr ON cr.id = e.class_id AND cr.school_id = ?
LEFT JOIN class_member cm ON cm.class_id = e.class_id
LEFT JOIN sys_user u ON u.id = cm.student_user_id
LEFT JOIN experiment_submission es ON es.experiment_id = e.experiment_id AND es.student_id = cm.student_user_id
WHERE e.created_by = ? AND e.school_id = ? AND e.status IN ('PUBLISHED','CLOSED')
UNION ALL
SELECT 'HOMEWORK' AS business_type, h.id AS business_id, h.title AS business_title,
       h.class_id, h.created_at, cm.student_user_id, u.username AS student_no, u.display_name AS student_name,
       hs.id AS submission_id, hs.submit_status AS submission_status
FROM homework h
JOIN class_room cr ON cr.id = h.class_id AND cr.school_id = ?
LEFT JOIN class_member cm ON cm.class_id = h.class_id
LEFT JOIN sys_user u ON u.id = cm.student_user_id
LEFT JOIN homework_submission hs ON hs.homework_id = h.id AND hs.student_id = cm.student_user_id
WHERE h.created_by = ? AND h.school_id = ? AND h.status IN ('PUBLISHED','CLOSED')
UNION ALL
SELECT 'EXAM' AS business_type, ex.id AS business_id, ex.title AS business_title,
       ex.class_id, ex.created_at, cm.student_user_id, u.username AS student_no, u.display_name AS student_name,
       exs.id AS submission_id, exs.status AS submission_status
FROM exam ex
JOIN class_room cr ON cr.id = ex.class_id AND cr.school_id = ?
LEFT JOIN class_member cm ON cm.class_id = ex.class_id
LEFT JOIN sys_user u ON u.id = cm.student_user_id
LEFT JOIN exam_submission exs ON exs.exam_id = ex.id AND exs.student_id = cm.student_user_id
WHERE ex.created_by = ? AND ex.school_id = ? AND ex.status IN ('PUBLISHED','CLOSED')
```

- 参数顺序（9 个）：`schoolId, teacherId, schoolId, schoolId, teacherId, schoolId, schoolId, teacherId, schoolId`。
- H2 mem 与 MySQL 均支持字符串字面量 `UNION ALL` 与 `IN`；不使用 MySQL 专有函数。
- `LEFT JOIN` 放在成员表之后，提交表为空时 `submission_id` 为 `NULL`，由 Java 判未开始。

### 4.3 名单端点响应拼装

- 外层 key 固定顺序：`businessType` / `businessId` / `businessTitle` / `classId` / `className` / `expectedCount` / `participatedCount` / `completedCount` / `notStartedCount` / `participationRate` / `completionRate` / `students`（用 `LinkedHashMap`）。
- `businessTitle` / `classId` / `businessType` 取 TD10 查出的活动实体与入参（不重查）；`className` 取 TD12 SQL 的 `cr.name`。
- `students[]` 的 `submittedAt` 为 `OffsetDateTime`，由 `ApiResponse` 序列化为字符串；`submissionId` 为 `Long`。
- 前端展示的「未开始」文案由 SFC 映射 `participation === 'NOT_STARTED'`，后端只返回枚举字符串，不返回中文状态名。

- `Analysis.vue` 按 TD20 插入组件；`ParticipationPanel` 不接收 `emit`，不依赖 Pinia / router。

## 9. 已否决方案

| 否决项 | 原因 |
|---|---|
| 发布时批量生成三类提交行 | 幽灵数据 + 行数膨胀 + 发布后入班学生无法处理；违反 PRD D1 |
| 汇总按「所带班级」与「创建活动」混算 | 与 `analysis` 现行 activityCount / pendingGradeCount 口径冲突，产生第三种归属 |
| 给考试 / 作业批改队列插入 `submissionId = null` 伪行 | 破坏 `key` / 详情 / 评分入口契约；PRD D7 否决 |
| 在三个 ReportService 直接改返回值承载名单 | 改动 3 个既有端点响应结构，回归面大于新增专用端点 |
| 汇总 SQL 按活动逐条查询（N+1） | 大班级多活动时查询次数不可控；TD2 固定单条 UNION ALL |
| 在 `api/endpoints.ts` 扩展 `fetch` 白名单 | 名单是普通 JSON 请求，走 axios 即可；白名单只保留两个既有例外 |
| 名单 SFC 直接 `import axios` 或自己解包 `res.code` | 违反 `frontend-code-style.mdc` / `frontend-api-contract.mdc` |
| 名单端点由 Controller 手工判断角色字符串 | 违反 `backend-code-style.mdc`；统一方法级 `@PreAuthorize` |
