@Service
public class HomeworkSubmissionClaimService {

    private final HomeworkSubmissionRepository submissionRepository;

    public HomeworkSubmissionClaimService(HomeworkSubmissionRepository submissionRepository) {
        this.submissionRepository = submissionRepository;
    }

    /**
     * 独立事务保证「查找或创建提交行」的唯一键冲突不会污染调用方事务。
     *
     * @return 调用时刻的提交状态；不存在时插入 SAVED 行后返回 SAVED
     */
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public SubmissionStatus claim(Long homeworkId, Long studentId) {
        return submissionRepository.findByHomeworkIdAndStudentId(homeworkId, studentId)
                .map(HomeworkSubmission::getSubmitStatus)
                .orElseGet(() -> {
                    HomeworkSubmission created = new HomeworkSubmission();
                    created.setHomeworkId(homeworkId);
                    created.setStudentId(studentId);
                    created.setSubmitStatus(SubmissionStatus.SAVED);
                    submissionRepository.saveAndFlush(created);
                    return SubmissionStatus.SAVED;
                });
    }
}

## 9. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 作业开始门禁导致提前作答的学生提交失败 | 业务行为变化 | PRD 已确认；文案明确「作业尚未开始」，前端同步只读 |
| 实验时间窗导致历史教师未配置时间前不限制 | 低 | `startAt`/`dueAt` 为空时完全跳过，与现状一致 |
| `REQUIRES_NEW` 边界放大 | 事务与锁复杂度上升 | 严格限定为「提交行首存」；答案、查重、评分仍在外层事务 |
| `REQUIRES_NEW` 残留空 `SAVED` 行 | 数据面出现草稿行 | 可重试复用；不产生重复业务数据；不写 `score_record` |
| 快路径普通读与 claim 之间状态被其他事务改变 | 快照状态与真实状态不一致 | 一律以锁内重读结果为准（TD23 表）；快照只用于区分「顺序重复」与「并发重复」 |
| 题项答案误用 `REQUIRES_NEW` 造成自死锁 | 并发请求锁等待超时 | TD25 写死为「父行 X 锁 + 加锁读」，代码评审必查 |
| `LabRequests` record 补参遗漏 | 编译失败 | `LabServiceTests` 10 处一次性补齐，编译器兜底 |
| `updateLab` 发布校验沿用旧实体 | 漏判新设 `AFTER_DEADLINE` | TD13 固定用请求值；测试覆盖 |
| 复制实验写 `null` 模式 | `.name()` NPE | TD16 固定重置为 `AFTER_TEACHER_CONFIRM` |
| 学科 `40902` 影响既有测试 | 用例变红 | 同步改 `AdminSubjectControllerTests` |
| 守卫 `return false` 造成空白导航 | 用户体验 | 提示由拦截器给出；用户重试即可，不清登录态是更优解 |
| 登录不再二次拉取 user | 若登录响应缺字段会异常 | 后端登录响应已含 `user`/`permissions`（现状事实），不改契约 |

回滚策略：本期无数据库迁移，全部为代码级改动，可按步骤 1–12 独立回退；回退顺序与实施顺序相反。回滚后已产生的 `SAVED` 提交行不影响旧逻辑（旧逻辑同样读取该表）。

## 11. 已否决方案

| 否决方案 | 否决理由 |
|---|---|
| 在 `submitHomework` 内用 `TransactionTemplate` 默认传播级别创建提交行 | 外层已有 `@Transactional`，内层失败会把外层标记 rollback-only；必须 `REQUIRES_NEW` 且封装到独立 Bean |
| 捕获冲突后用普通 `findByHomeworkIdAndStudentId` 重读 | MySQL REPEATABLE READ 下普通 `SELECT` 读旧快照，看不到并发事务已提交的新行；必须加锁读 |
| 每次写入口都无条件先调用 claim（不做存在性快路径） | 实验自动保存为高频路径，每次多开一条 `REQUIRES_NEW` 连接，违反 PRD §10.1「正常路径无额外开销」 |
| 题项答案也用 `REQUIRES_NEW` | 插入子行需要父行共享锁，与外层父行排他锁形成跨连接等待，导致自死锁/超时 |
| 依赖 `homework_answer` 唯一约束兜底 | 该表无唯一约束，并发双写会静默产生重复答案 |
| 并发重复提交一律拒绝 | PRD R6 要求唯一约束冲突按幂等成功处理；且第二次请求已无业务副作用 |
| 用 `assertLabPublishable(lab)` 同时承担时间窗发布校验 | 该方法只读旧实体的题项列表，无法感知本次请求新设的 `AFTER_DEADLINE` 与 `dueAt` |
| 复制实验时把 `AFTER_DEADLINE` 置为 `null` | 列 `nullable=false` 且视图调用 `.name()`，直接 NPE |
| 实验时间窗门禁放在 `accessiblePublishedLab` 内部 | 会同时拦截读接口（详情/列表/报告）与教师批改，违反 PRD 明确的「读不拦截、教师批改不拦截」 |
| 前端统一用 `any` 绕过 `UpdateExamPayload` 类型 | 违反项目契约约束，且掩盖真实的类型不一致 |
| 路由守卫对任何错误都 `logout()` | 把瞬时网络/超时故障放大为登录态丢失，正是 N7 要修的问题 |
| 守卫内再 `ElMessage.error` | `request.ts` 已统一提示，会形成双 toast |
| 登录后再 `fetchUserInfo()` 兜底 | 冗余请求，且登录响应已含完整用户信息 |
