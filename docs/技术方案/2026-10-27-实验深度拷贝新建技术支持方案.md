## 1. 背景与诉求

### 1.1 现状

教师「实验台账」目前只有「新建实验」一个入口（`frontend/src/views/teacher/Labs.vue:12`）。新建弹窗要求教师重新填写实验名称、班级、类型、实验要求、实验内容、实验指导、发布状态、小结要求（`Labs.vue:177-237`）。

实际教学中，同一门课的实验经常需要在不同班级、不同学期复用；教师当前只能靠人工重录，实验内容与题项配置成本高，且容易漏配填空题可接受答案、评分配置等隐性字段。

### 1.2 目标

1. 新建实验时可以选择一个已有实验作为模板，一次性复制其配置与全部题项。
2. 复制出的实验是**独立实验**：拥有新 ID、新编号、独立题项，可单独编辑与发布。
3. 不把源实验的学生作答、成绩等运行数据带入新实验，避免制造假数据。
4. 改动面控制在实验模块内，不引入新表、不做跨模块模板中心。

## 2. 现状与约束

### 2.1 数据关系

| 表 | 实体 | 与实验的关系 |
|---|---|---|
| `t_experiment` | `Lab` | 实验主表，`experiment_id` 主键 |
| `t_experiment_item` | `LabStep` | `experiment_id` 关联主表，题项 |
| `experiment_blank_answer_override` | `ExperimentBlankAnswerOverride` | `experiment_id` + `experiment_item_id` 关联 |
| `experiment_submission` | `LabSubmission` | `experiment_id` + `student_id`，学生提交 |
| `experiment_answer` | `LabStepAnswer` | 关联提交与题项，学生答案 |
| `lab_step_answer_log` | `LabStepAnswerLog` | 答案日志快照 |
| `course_material` | `CourseMaterial` | `material_id` 弱引用实验指导 |

### 2.2 唯一约束

| 表 | 约束 | 对复制的影响 |
|---|---|---|
| `t_experiment_item` | `uk_t_experiment_item_no (experiment_id, experiment_item_no)` | 新实验 ID 不同，原样复制题项序号即可 |
| `experiment_blank_answer_override` | `uk_experiment_blank_override (experiment_id, experiment_item_id, normalized_answer)` | 新实验 ID + 新题项 ID 不同，原样复制即可 |
| `experiment_submission` | `uk_experiment_submission (experiment_id, student_id)` | 不复制，无冲突 |

来源：`backend/src/main/resources/db/migration/V9__experiment_module_redesign.sql:75-95`、`:213-224`。

### 2.3 主键与编号生成

- `Lab` 的 `experiment_id` 由 JPA 层 `@PrePersist` 生成：`ThreadLocalRandom.nextInt(1, 2_000_000_000)`，即 **int 域随机值装入 `Long` 字段**（`Lab.java:81-106`）；上限 20 亿是为兼容 `INT` 列 `experiment_no` 的 `Math.toIntExact(id)` 派生。V16 迁移虽给该列补了 `AUTO_INCREMENT` 作为 H2→MySQL 导入兜底（`V16__restore_mysql_auto_increment.sql:36`），但 JPA 插入总显式携带 ID，复制链路不依赖 DB 自增。
- `LabStep` 的 `id` 由 `@PrePersist` 生成：`nextLong(1, 9_007_199_254_739_992)`（约 2^53，JS 安全整数域，保证前端 number 不丢精度，`LabStep.java:66-91`）。两实体随机范围不同，但机制相同：**留空才生成**。
- `experiment_no` 在 `applyDerivedFields` 中自动取 `experiment_id`（`Lab.java:108-125`）。

结论：复制链路与 `createLab`/`createStep` 共用同一套 `@PrePersist` 生成机制，**不引入第二套 ID 生成逻辑**；复制时**不要**复制源 ID 与源编号，留空即可自动生成；这两项也是复制安全性的关键。

### 2.4 权限现状

- 教师台账只按 `created_by` 过滤：`LabService.listTeacherLabs`（`LabService.java:125-129`）。
- 实验写操作使用 `ownedLab`：`created_by` + **当前仍任教源班级**（`LabService.java:995-1000`）。
- 创建实验时校验目标班级任教关系（`LabService.java:138-148`）。

复制场景必须支持「旧班实验复制到新班」，因此源实验**不能**复用 `ownedLab`，否则教师一旦不再任教旧班就无法复制。

### 2.5 既有约束不一致（本次不修，但必须规避）

| 项 | 现状 |
|---|---|
| 数据库实验名称 | `experiment_name VARCHAR(30) NOT NULL`（`V9:4`、`Lab.java:48`） |
| 前端新建表单 | `maxlength="100"`（`Labs.vue:180`） |

本次复制链路必须按 **30 字**处理标题，否则 31 字以上会直接触发数据库写入失败。既有「空白创建」的 100 字上限问题不在本方案范围内，仅在后续 Phase 处理。

## 3. 复制语义

### 3.1 实验主表字段处理

| 字段 | 数据库列 | 处理 |
|---|---|---|
| `title` | `experiment_name` | 请求值；缺省「源标题（副本）」；≤ 30 字 |
| `description` | `experiment_requirement` | 原样复制 |
| `experimentContent` | `experiment_content` | 原样复制 |
| `experimentType` | `experiment_type` | 原样复制 |
| `instructionType` | `instruction_type` | 原样复制 |
| `scoreVisibilityMode` | `score_visibility_mode` | 原样复制 |
| `summaryRequired` | `summary_required` | 原样复制 |
| `materialId` | `material_id` | 原样复制引用 |
| `classId` | `class_id` | **目标班级** |
| `createdBy` | `created_by` | **当前教师** |
| `status` / `state` | `status` / `state` | 请求值；缺省 `DRAFT`；`state` 由 `setStatus` 派生 |
| `scoreReleased` | `score_released` | **重置 false** |
| `startAt` / `endAt` | `start_at` / `end_at` | **不复制（保持 null）** |
| `id` / `experimentNo` | `experiment_id` / `experiment_no` | **不复制，自动生成** |
| `createdAt` / `updatedAt` | 同名 | 由审计字段自动生成 |

### 3.2 题项字段处理

`t_experiment_item` 的全部业务字段原样复制，仅替换主键与所属实验：

`stepNo`、`title`、`questionType`、`content`、`answerConfigJson`、`scoringConfigJson`、`experimentItemAnswer`、`experimentItemType`、`stepScore`、`state`、`questionId`、`questionSnapshotJson`、`editorLanguage`、`allowPaste`。

> **实现陷阱**：`LabStep` 的 setter 带派生副作用，必须按固定顺序赋值，否则复制结果会被默认值覆盖。详见 §5.3。

### 3.3 填空题可接受答案

`ExperimentBlankAnswerOverride` 全字段复制：

| 字段 | 处理 |
|---|---|
| `experimentId` | 新实验 ID |
| `experimentItemId` | 通过「源题项 ID → 新题项 ID」映射替换 |
| `acceptedAnswer` / `normalizedAnswer` / `blankAnswersJson` | 原样复制 |
| `createdBy` | 当前教师 |

### 3.4 明确不复制的内容

| 对象 | 原因 |
|---|---|
| `experiment_submission` | 复制会造成新实验「已有学生提交」的假数据 |
| `experiment_answer` | 答案必须对应真实学生提交与题项 |
| `lab_step_answer_log` | 日志是学生作答历史，不属于实验模板 |
| `score_record` | 成绩属于学生与源实验，不能迁移 |
| 查重任务 | 依附于源提交，复制无意义 |
| 源实验 ID / 编号 | 新实验必须独立 |
| `start_at` / `end_at` | 新实验需要重新排期 |

### 3.5 实验指导处理

v1 **共享 `material_id`**：

- 新实验的「实验指导」直接指向源 `course_material` 记录，不复制文件。
- 若源 `material_id` 已失效（资料被删除），新实验沿用该 ID；`appendMaterialFields` 会返回空标题/空文件名，台账显示「未上传实验指导」（`LabService.java:1144-1163`）。
- 已知风险：`MaterialService.deleteMaterial` 会同时删除资料记录和物理文件（`MaterialService.java:75-80`），删除源资料会同时影响源实验与副本。该风险与现有「多实验共享同一资料」的行为一致，不在本方案新增处理。

### 5.3 Service 实现（写死顺序）

```java
@Transactional
public Map<String, Object> copyLab(CurrentUser currentUser, Long sourceLabId,
                                   LabRequests.CopyLabRequest request) {
    requireTeacher(currentUser);

    // 1. 源实验：只校验 ownership，允许跨班级复用
    Lab source = labRepository.findByIdAndCreatedBy(sourceLabId, currentUser.id())
            .orElseThrow(() -> new BusinessException(40300, "无权限访问该实验"));

    // 2. 目标班级必须是当前教师任教班级
    classAccessService.assertTeacherAssignedToClass(currentUser, request.classId());

    // 3. 先读取源题项，用于发布门禁与后续复制
    List<LabStep> sourceSteps = labStepRepository.findByLabIdOrderByStepNoAsc(source.getId());
    ActivityStatus targetStatus = parseStatus(request.status());
    if (targetStatus == ActivityStatus.PUBLISHED && sourceSteps.isEmpty()) {
        throw new BusinessException(40000, LAB_PUBLISH_WITHOUT_ITEMS_MESSAGE);
    }

    // 4. 复制主表，重置运行态字段
    Lab copy = new Lab();
    copy.setCreatedBy(currentUser.id());
    copy.setClassId(request.classId());
    copy.setTitle(resolveCopyTitle(source.getTitle(), request.title()));
    copy.setDescription(source.getDescription());
    copy.setExperimentType(source.getExperimentType());
    copy.setInstructionType(source.getInstructionType());
    copy.setExperimentContent(source.getExperimentContent());
    copy.setMaterialId(source.getMaterialId());
    copy.setScoreVisibilityMode(source.getScoreVisibilityMode());
    copy.setSummaryRequired(source.isSummaryRequired());
    copy.setScoreReleased(false);
    copy.setStatus(targetStatus);
    Lab saved = labRepository.save(copy);

    // 5. 复制题项，记录 源 itemId -> 新 itemId
    Map<Long, Long> itemIdMapping = new LinkedHashMap<>();
    for (LabStep sourceStep : sourceSteps) {
        LabStep step = copyStep(sourceStep, saved.getId());
        itemIdMapping.put(sourceStep.getId(), labStepRepository.save(step).getId());
    }

    // 6. 复制填空题可接受答案
    copyBlankOverrides(source.getId(), saved.getId(), itemIdMapping, currentUser.id());

    return toTeacherLabView(saved);
}
```

```java
/**
 * 复制单个题项。
 *
 * <p>{@link LabStep} 的 setter 会顺带派生其它字段：
 * {@code setQuestionType} 会重置 experimentItemType / questionSnapshotJson / editorLanguage，
 * {@code setAnswerConfigJson} 会把 experimentItemAnswer 覆写为 answerConfigJson。
 * 因此必须按「先设 questionType，再覆盖派生字段，最后设 answerConfigJson 与 experimentItemAnswer」的顺序赋值。</p>
 */
private LabStep copyStep(LabStep source, Long targetLabId) {
    LabStep step = new LabStep();
    step.setLabId(targetLabId);
    step.setStepNo(source.getStepNo());
    step.setTitle(source.getTitle());

    step.setQuestionType(source.getQuestionType());
    step.setQuestionSnapshotJson(source.getQuestionSnapshotJson());
    step.setEditorLanguage(source.getEditorLanguage());
    step.setExperimentItemType(source.getExperimentItemType());

    step.setContent(source.getContent());
    step.setAnswerConfigJson(source.getAnswerConfigJson());
    step.setExperimentItemAnswer(source.getExperimentItemAnswer());
    step.setScoringConfigJson(source.getScoringConfigJson());

    step.setStepScore(source.getStepScore());
    step.setState(source.getState());
    step.setQuestionId(source.getQuestionId());
    step.setAllowPaste(source.isAllowPaste());
    return step;
}
```

```java
private void copyBlankOverrides(Long sourceLabId, Long targetLabId,
                                Map<Long, Long> itemIdMapping, Long teacherId) {
    List<ExperimentBlankAnswerOverride> overrides =
            experimentBlankAnswerOverrideRepository.findByExperimentIdOrderByIdAsc(sourceLabId);
    for (ExperimentBlankAnswerOverride source : overrides) {
        Long targetItemId = itemIdMapping.get(source.getExperimentItemId());
        if (targetItemId == null) {
            continue; // 源题项已删除的历史脏数据，跳过
        }
        ExperimentBlankAnswerOverride copy = new ExperimentBlankAnswerOverride();
        copy.setExperimentId(targetLabId);
        copy.setExperimentItemId(targetItemId);
        copy.setAcceptedAnswer(source.getAcceptedAnswer());
        copy.setNormalizedAnswer(source.getNormalizedAnswer());
        copy.setBlankAnswersJson(source.getBlankAnswersJson());
        copy.setCreatedBy(teacherId);
        experimentBlankAnswerOverrideRepository.save(copy);
    }
}
```

```java
private String resolveCopyTitle(String sourceTitle, String requestedTitle) {
    if (requestedTitle != null && !requestedTitle.isBlank()) {
        return requestedTitle.trim();
    }
    String suffix = "（副本）";
    int maxBaseLength = 30 - suffix.length();
    String base = sourceTitle.length() > maxBaseLength
            ? sourceTitle.substring(0, maxBaseLength)
            : sourceTitle;
    return base + suffix;
}
```

### 5.4 Controller 实现

```java
@PostMapping("/teacher/labs/{sourceLabId}/copy")
@PreAuthorize("hasRole('TEACHER')")
public ApiResponse<?> copyLab(@PathVariable Long sourceLabId,
                              @Valid @RequestBody LabRequests.CopyLabRequest request) {
    CurrentUser currentUser = SecurityUtils.currentUser();
    return ApiResponse.ok(labService.copyLab(currentUser, sourceLabId, request));
}
```

### 5.5 事务与一致性

1. `copyLab` 整个方法在单事务内；任何一步失败（题项、填空答案）整体回滚。
2. 主表先保存，拿到新 `experiment_id`，再复制题项与填空答案，保证外键关系正确。
3. `save` 后在同一持久化上下文内查询新题项可见；本方案不使用保存后查询做门禁，发布门禁直接基于 `sourceSteps`，行为更确定。
4. 复制不涉及文件读写，不存在「数据库回滚但文件残留」问题。

```ts
if (createMode.value === 'copy' && !editingId.value) {
  if (!sourceLabId.value) {
    ElMessage.warning('请选择源实验');
    return;
  }
  if (!createForm.classId) {
    ElMessage.warning('请选择目标班级');
    return;
  }
  if (!createForm.title.trim()) {
    ElMessage.warning('请输入新实验名称');
    return;
  }
  if (createForm.status === 'PUBLISHED' && (sourceLab.value?.stepCount ?? 0) === 0) {
    ElMessage.warning('源实验没有题项，不能直接发布');
    return;
  }

  submitting.value = true;
  try {
    const copied = await copyTeacherLab(sourceLabId.value, {
      classId: createForm.classId,
      title: createForm.title.trim(),
      status: createForm.status,
    });
    ElMessage.success(`实验复制成功，共 ${copied.stepCount ?? 0} 个题项`);
    createDialogVisible.value = false;
    await fetchData();
  } finally {
    submitting.value = false;
  }
  return;
}
```

## 10. 风险、边界与后续 Phase

| 项 | 说明 | 归属 |
|---|---|---|
| 实验指导共享 | 删除源资料会同时影响副本；与现有共享行为一致，非新增失败模式；失效仅表现为「未上传实验指导」，不阻塞作答，可重新上传恢复 | 接受 |
| 资料删除引用检查 | `deleteMaterial` 被 `t_experiment.material_id` 引用时拒绝或二次确认；资料域独立改动，触发信号：资料库高频清理或指导变为作答强依赖 | 后续 Phase |
| 实验名称 30 字限制 | 既有前端新建表单仍允许 100 字，属于历史不一致 | 后续 Phase 统一修正 |
| 源实验题库关联 | 复制 `questionId` 引用与 `questionSnapshotJson`，不复制题库记录；题库是教师级共享资源 | 接受 |
| 源实验 0 题项 | 允许复制为草稿；不允许直接发布 | 已处理 |
| 源班级已不再任教 | 允许复制（只校验 `created_by`），便于复用旧班实验 | 已处理 |
| 复制溯源 | 不记录 `copied_from_lab_id`；如后续需要模板体系再补 | 非目标 |
| 台账行内复制 | 后续可复用同一接口与弹窗逻辑 | 后续 Phase |
| 复制实验指导文件 | 需要 `localFileStorageService` 增加按字节写入能力并复制 `course_material` 记录；涉及孤儿文件清理 | 后续 Phase |
| 并发复制 | 每次请求生成独立 ID，无共享状态 | 无风险 |

## 附录 A：已否决方案

| 方案 | 否决原因 |
|---|---|
| 复用 `POST /teacher/labs`，在 `CreateLabRequest` 增加 `sourceLabId` | 创建与复制语义不同；会让 `createLab` 分支膨胀，且复制需要忽略大部分创建字段，契约含混 |
| 复制时允许编辑实验要求、内容、类型 | 前端需要先拉取源实验详情并维护双份表单，交互复杂；复制后可进入「编辑实验」修改，成本更低 |
| 复制学生提交与答案 | 会制造假提交、污染成绩统计，且答案 ID 与提交 ID 强关联 |
| 复制实验指导文件并新建资料记录 | 文件复制、孤儿清理、资料库冗余都需要额外设计；v1 共享引用足够 |
| 共享 `material_id` 但新建一条 `course_material` 记录指向同一文件 | 比共享更危险：删除任一记录会删掉共享文件，导致另一方失效 |
| 直接复制源 `experiment_no` | 编号会重复，失去编号唯一性语义 |
| 用 `ownedLab` 校验源实验 | 教师不再任教旧班时无法复制，违背核心复用场景 |
| 新增复制溯源字段 | 需要 Flyway 迁移与新 UI，本期无明确产品诉求 |
