### 1.2 与 PRD 的边界

- 本方案只展开 PRD 已写死的决策；PRD V1.4 §4.3 第 3 行的「后端改动面」由 TD3 细化为完整新增类清单，属同一决策的实现展开，不新增需求能力。

- **首次生成 / 重新生成口径消歧**：PRD P6 的「产物只写 `courseware` 主表 1 行 `DRAFT` + N 条 `courseware_section` 行」描述的是**首次生成**；PRD P10 / FR-5 的「重新生成须先下架、生成后保持 `DRAFT`」「只更新 `content_json` 与 `heading`、不删除不重建小节行」描述的是**重新生成**，走 `update` 语义、不新增 `courseware` 行。本方案用 `GenerateCoursewareRequest.coursewareId` 是否为空区分两条路径，共用同一 `POST /coursewares/generate` 端点，不新增端点、不产生多余 DRAFT 行。
- 端点子路径、record 字段、SFC 文件名由本方案写死；PRD 不再出现第二份口径。
- 实现时若发现本方案与 PRD 冲突，先按 `feature-dev-workflow.mdc` §2 最小回写 PRD 并同步两文修订记录，禁止在编码阶段自行挑一边。

**`TeacherContentService.list()` 数据来源写死**：先按 §3.3 把 `null` / 空 `filterType` 归一为 `"ALL"` 再构造 `ContentFilterRequest`（现网 `filter` 对 null 抛 `40000`，本方案不改该方法）；`ContentFilterService.filter(currentUser, filterRequest)` 返回 `List<ContentRef>`（实测含 `COURSEWARE` 与 `QUESTION` 两类，`ContentFilterService.java:66-92`）→ 取 `contentType == "COURSEWARE"` 的 `contentId` → `coursewareRepository.findAllById(...)` → 组装 `ContentBrowseItem`；保持 `filter` 返回顺序，不二次排序。

**`update` 步骤写死（TD10 / TD11）**：① `courseware` 不存在 → `40400`；② `status != DRAFT` → `40900`「请先下架再编辑」；③ `ContentSubjectScopeService.validate(currentUser, "PLATFORM", req.globalSubjectId(), null)` + `activeSupport.requireActive(...)`；④ 对 `req.sections()` 每项调 `CoursewareContentJsonSupport.validate(contentJson)`；⑤ 小节全量替换按「删被移除行 → 全部 `sort_order` 置负临时值 `-index-1` → 按目标 `sortOrder` 写回」三步执行，规避 `uk_courseware_section_order`；带 `id` 的既有行只更新 `contentJson` / `heading` / `sortOrder`、不删不重建（`section_id` 稳定）；⑥ 写主表 `title` / `subtitle` / `globalSubjectId`；⑦ `ContentMountService.replaceMounts(currentUser, new ContentRef("COURSEWARE", id, "PLATFORM", null, currentUser.id()), req.mounts())`；⑧ 任一步抛异常整体回滚。

**`saveGenerated` 两态写死**：`req.coursewareId() == null` → 新建 `courseware` 1 行（`ownerScope = "PLATFORM"`、`ownerSchoolId = null`、`schoolSubjectId = null`、`globalSubjectId`、`title`、`subtitle`、`status = "DRAFT"`、`publishedAt = null`、`createdBy = currentUser.id()`）+ N 行 `courseware_section`；`req.coursewareId() != null` → 读该课件，`status != DRAFT` → `40900`「请先下架再重新生成」，按生成结果顺序与既有 `courseware_section`（`findByCoursewareIdOrderBySortOrderAsc`）**逐行按 `id` 更新 `contentJson` / `heading`**，不增删小节行、不改写主表、`status` 保持 `DRAFT`；生成节数与既有节数不等 → `40000`「生成小节数与课件现有小节数不一致」。两条路径都**不写** `content_mount` / `content_share_grant` / `courseware_asset` / `courseware_assignment`。

**`delete` 步骤写死（TD14）**：① `countByCoursewareId(id) > 0` → `40900`「课件已被布置，只能下架」；② `ContentShareGrantService.deleteAllForContent(currentUser, "COURSEWARE", id)`；③ 依次删 `courseware_section` / `courseware_asset` / `content_mount` / `courseware` 行；④ 删除的素材物理文件由 `LocalFileStorageService.delete(filePath)` 在事务提交后处理，删除失败只记日志不影响事务。**下架不检查 `courseware_assignment`**（已布置记录不校验 `status`）。

**`grant` 步骤写死（TD15）**：① `status != PUBLISHED` → `40900`「请先发布再授权」；② `schoolIds` 逐个 `SchoolRepository.existsById(...)`，不存在 → `40400`「学校不存在」；③ 逐个 `ContentShareGrantService.grant(currentUser, ref, schoolId)`；④ 返回最新 `listGrants(id)`。半途重复授权由整体事务回滚保证不产生部分写入。

### 3.7 发布四项门禁的精确判定（TD13）

`publish(Long id)` 为 `@Transactional`，顺序写死：

1. 读 `courseware`；不存在 → `40400`；`status == PUBLISHED` → `40900`「课件已发布」。
2. **门禁① 学科归属**：`globalSubjectId != null`、`ContentSubjectScopeService.validateTextbook(globalSubjectId)` 通过（现网只查 `existsById`）、再由 `activeSupport.requireActive(globalSubjectId)` 要求 `status == ACTIVE`；任一失败 → `40025`「平台学科归属无效」。
3. **门禁② 叶子挂载**：`ContentMountRepository.findByContentTypeAndContentId("COURSEWARE", id)` 中取 `mountType == "TEXTBOOK_SECTION"` 的行；对每行 `mountTargetId` 查 `TextbookSectionRepository.findById(...)`，要求存在且 `existsByParentId(targetId) == false`；合格行数 `>= 1`。零条 → `40000`「发布前至少挂载一个叶子教材小节」。
4. **门禁③ 小节树完整**：`findByCoursewareIdOrderBySortOrderAsc(id)` 行数 `>= 1`、`sortOrder` 从 `1` 起连续且无重复、每行 `heading` 非空白。任一不满足 → `40000`「课件小节树不完整」。
5. **门禁④ 产物完整**：每行 `contentJson` 非空白且 `CoursewareContentJsonSupport.validate(...)` 全部通过（含 1MB 与 schema）；`content_json` 中出现的每个 `image` / `audio` 路径必须能在 `CoursewareAssetRepository.findByCoursewareId(id)` 的 `filePath` 集合中命中。任一不满足 → `40000`「课件产物不完整」。
6. 全通过 → `status = "PUBLISHED"`、`publishedAt = OffsetDateTime.now()`、保存；**不写 `content_share_grant`**。

**`CoursewarePublishGateTests` 四用例造数一一对应**：`publishRejectedWhenNoLeafMount`（② 0 条）、`publishRejectedWhenMountedToNonLeaf`（② 挂到有子行的小节）、`publishRejectedWhenGlobalSubjectInvalid`（① 用 `jdbcTemplate` 把某平台学科 `status` 改为 `DISABLED` 后把课件 `global_subject_id` 指向它，`@AfterEach` 复位为 `ACTIVE`）、`publishRejectedWhenArtifactIncomplete`（④ 某节 `contentJson` 为 `"{}"`）；四例均断言 `code = 40000 / 40025`、HTTP 400、`courseware.status` 仍为 `DRAFT`、`published_at` 仍为 `NULL`。

### 3.8 AI 生成实现（TD8）

**环境变量（写死，只经 Spring `@Value` 占位符读取，不写进任何 `application*.yml`）**：

| 变量 | 代码占位符默认值 | 判定 |
|---|---|---|
| `COURSEWARE_AI_BASE_URL` | 空串 | `isConfigured()` 判空 |
| `COURSEWARE_AI_API_KEY` | 空串 | `isConfigured()` 判空；**空串即「未配置」，不提供任何可用密钥**，与 PRD P3「`api-key` 无默认值」同义 |
| `COURSEWARE_AI_MODEL` | 空串 | `isConfigured()` 判空 |
| `COURSEWARE_AI_TIMEOUT_SECONDS` | `120` | 代码默认 120 秒 |

`CoursewareAiGateway` 用 `@Value("${COURSEWARE_AI_BASE_URL:}")` 等 4 个字段注入；`isConfigured()` 为 false 时 `generate` 直接抛 `BusinessException(40000, "AI 生成服务未配置，请联系管理员")`，不落库。

**请求**：`HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(10)).build()`；`POST ${baseUrl}/chat/completions`，头 `Authorization: Bearer ${apiKey}`、`Content-Type: application/json`；body 为 `{"model": <model>, "temperature": 0.3, "response_format": {"type": "json_object"}, "messages": [{"role":"system","content":<系统提示词>},{"role":"user","content":<用户提示词>}]}`；`HttpRequest.timeout(Duration.ofSeconds(timeoutSeconds))`；系统提示词写死「只输出符合给定 JSON 协议的内容，不输出 Markdown 代码块」；用户提示词由 `title` / `subtitle` / `globalSubjectId` / `textbookSectionId` 对应的教材小节 `heading` 拼接，**`textbookSectionId` 只用于生成上下文、不产生 `content_mount` 行**。

**解析与重试**：`ObjectMapper.readTree(response)` 取 `choices[0].message.content` → 再 `readTree` 得 `{"sections":[{"heading":...,"content":{...}},...]}`；转换为 `List<SectionPayload>`（`sortOrder` 从 1 按数组顺序生成）；对每项 `contentJson` 调 `CoursewareContentJsonSupport.validate(...)`；`sections` 为空或解析抛异常 → 重试 1 次（共 2 次 `complete` 调用）；两次均失败 → `BusinessException(40000, "AI 生成结果解析失败，未写入任何数据")`，不落库。

**首次生成 / 重新生成的唯一入口**：都走 `POST /coursewares/generate`，由 `GenerateCoursewareRequest.coursewareId` 是否为空区分，`PlatformContentService.saveGenerated(...)` 按 §3.6 两态落库。前端「重新生成」按钮在 `status === 'DRAFT'` 时携带当前 `coursewareId` + 全部既有小节 `id` 调用同一端点；服务端在重新生成路径再次以 `status == DRAFT` 拦截「未下架就重新生成」（PRD P10）。AI 网关只产出 `contentJson` 文本，不直接改库；两种方式都不新增 `courseware` 行以外的实体，人工编辑仍走 `PUT /coursewares/{id}`。

### 3.9 `content_json` 协议与 1MB 校验（TD9）

**单节协议（写死，Jackson `JsonNode` 手工校验，不引入 JSON Schema 依赖）**：

```json
{
  "version": 1,
  "paragraphs": [
    {
      "class": "text",
      "sentences": [
        { "text": "正文句子", "narration": "", "image": "", "audio": "" }
      ],
      "exercises": []
    }
  ]
}
```

| 规则 | 判定 |
|---|---|
| 顶层 | `version` 必须为 `1`；`paragraphs` 必须为数组且 `>= 1`；其余顶层字段忽略 |
| `paragraph.class` | 白名单唯一为 `text` / `tip` / `example` / `note`，其它值拒绝 |
| `sentences` | 必须 `>= 1`；每项 `text` 必填非空白字符串；`narration` / `image` / `audio` 可为空串 |
| `image` / `audio` | 非空时必须以 `courseware-assets/` 开头且不含 `base64,` / `data:`；不得内联 base64 |
| `exercises` | 必须为数组且**长度 0**（本期不接评分链路） |
| 字节上限 | `contentJson.getBytes(StandardCharsets.UTF_8).length > 1_048_576` → `BusinessException(40000, "单节正文超过 1MB 上限")`；恰好等于放行 |

`CoursewareContentJsonSupport.validate(String)` 抛 `40000` 时附具体原因；两处调用点为 `CoursewareGenerationService.generate`（写库前）与 `PlatformContentService.update`（逐节写库前）。`CoursewareContentSizeTests` 四断言：`1_048_576` 字节放行、`+1` 字节被拒、AI 生成侧超限重试 1 次后仍不落库、人工保存侧超限后 DB 无新增 / 无改写正文行。

### 3.10 素材上传与读取（TD16）

`uploadAsset(Long coursewareId, MultipartFile file)`：① 课件存在且 `status == DRAFT`，否则 `40400` / `40900`；② 取 `Path.of(file.getOriginalFilename()).getFileName()` 的后缀转小写，必须属于 `.png` / `.jpg` / `.webp` / `.mp3`，否则 `40000`「素材类型不支持」；③ `file.getSize() > 50L * 1024 * 1024` → `40000`「素材超过 50MB」；④ `LocalFileStorageService.store("courseware-assets/" + coursewareId, file)`；⑤ 写 `courseware_asset`：`kind` 由后缀决定（前三者 `IMAGE`、`mp3` 为 `AUDIO`）、`mime = file.getContentType()`、`sizeBytes = file.getSize()`；⑥ 返回 `CoursewareAssetItem`。

`readAsset` 两端点（平台 #22 / 教师 #4）按调用方分流：**教师侧**由 `TeacherContentService` 先 `ContentVisibilityService.assertVisible(...)`；**平台侧**由 `PlatformContentService` 只校验课件存在（类级 `hasRole('PLATFORM_ADMIN')` 已保证身份）。两者都按 `assetId` + `coursewareId` 取 `filePath`，`LocalFileStorageService.read(...)` 返回 `DownloadedAsset`；Controller 按 `MaterialController.download` 形态包装 `ResponseEntity<ByteArrayResource>`（带 `Content-Type` 与 `Content-Disposition: inline`）；**不返回 `Range` / `206`**（阶段 4）。multipart 50MB / 100MB 只是上传配额，与 `content_json` 的 `TEXT` / `LONGTEXT`、`max_allowed_packet`、1MB 单节上限分层，不互相替代。
