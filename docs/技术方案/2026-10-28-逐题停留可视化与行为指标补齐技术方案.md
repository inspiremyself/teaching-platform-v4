# 逐题停留可视化与行为指标补齐技术方案

- **日期**：2026-10-28
- **状态**：已定稿（可直接编码）
- **前置方案**：`2026-10-28-实验作答行为采集与教师展示增强技术方案`（P0 采集链 + P1 展示链已落地）
- **范围**：纯前端增强为主，后端 DTO 层增量暴露两个已有字段；**零迁移、零后端新接口、零后端新表**

## 1. 背景与问题

P0/P1 采集与展示链落地后，后端已完整产出 11 类事件、16 个 metrics 字段，但前端只消费了 6 个展示位，存在三类缺口：

### 1.1 后端有、前端没用好（已聚合未展示）

| 字段 | 位置 | 教师价值 | 现状 |
|---|---|---|---|
| `step_dwell_json`（逐题停留毫秒 Map） | `lab_submission_metrics` | **核心缺口** — 一眼看出哪道题学生只看了 2 秒就跳过去、哪道题花了 20 分钟 | 后端已算好（`LabBehaviorMetricsService.accumulateDwell`），detail 接口已 parse 出 `stepDwellMs: Record<string, number>`（key 为 stepId 字符串），**前端 0 消费** |
| `blur_count`（窗口失焦次数） | `lab_submission_metrics` | 补全注意力信号：切屏=离开浏览器窗口，失焦=在浏览器内但点了别的标签页 | metrics 已有字段，DTO `toBehaviorView` 没暴露，前端 type 也没 |
| `paste_blocked_count`（被禁粘贴尝试次数） | `lab_submission_metrics` | 学生明知道这道题禁止粘贴还试了多少次，是有趣的"试探"信号 | 同上，后端有前端无 |

### 1.2 后端已暴露但前端藏得太深

| 指标 | 现状 | 改进 |
|---|---|---|
| `sessionCount`（会话数） | 只藏在"活跃时长"副标题 `· 会话数 2` | 作为独立小指标卡展示 |

### 1.3 前端展示位"偏科"

[BehaviorSummaryCard.vue](file:///Users/liangzai/CursorProjects/teaching-platform-v4/frontend/src/views/teacher/components/BehaviorSummaryCard.vue) 当前 6 个指标卡：

```
[作答时长] [活跃时长] [保存次数] [粘贴]     [切屏]     [计算时间]
```

→ 调整为 8 个：

```
[作答时长] [活跃时长] [会话数] [保存次数] [粘贴]     [切屏]     [失焦]     [计算时间]
```

同时 `pasteBlockedCount` 作为粘贴卡的副文案补充。

## 2. 决策清单

| # | 决策 | 已否决方案 | 理由 |
|---|---|---|---|
| D1 | **逐题停留用 BehaviorTimelineDrawer 新增 Tab 承载**，不新开独立组件 | 新开 `StepDwellPanel.vue` 独立组件（多一层 import、多一处样式维护） | Tab 切换成本最低；抽屉已承载"行为时间线"，逐题停留同为"行为视图"的一部分 |
| D2 | **前端组件传 step 列表做 stepId → stepNo/title 映射**，不改后端接口 | 后端 behavior detail 接口扩展返回 stepMap（后端 DTO 膨胀；且 behavior detail 接口已有调用方，改动影响面大）；前端自己查 stepRepository 拼 Map（多一次 HTTP 请求） | BehaviorSummaryCard 两个使用点（LabReportDetail / LabReportBatchGrade）上下文均有完整 step 列表，传 prop 零成本；映射逻辑纯前端、零后端侵入 |
| D3 | **后端 DTO `toBehaviorView` 新增暴露 `blurCount` / `pasteBlockedCount`** | 不改后端、前端绕过 metrics 字段直接从事件表算（绕开预聚合，性能退化） | 两个字段已在 metrics 表，DTO 层增量暴露即可，一行代码 |
| D4 | **`LabReportBehavior` type 扩展 blurCount / pasteBlockedCount**；`LabReportBehaviorDetail.metrics` 不变（它已有 stepDwellMs，只是类型写法是内联 intersection） | 新建 `LabReportBehaviorSummary` / `LabReportBehaviorDetailMetrics` 两套 type（重复定义） | detail.metrics 当前写法是 `LabReportBehavior & { stepDwellMs; firstStartedAt; lastEventAt; computedAt }`，已包含 summary 全部字段；扩展 summary type 即同步覆盖 detail |
| D5 | **Step dwell 柱状图用原生 `el-progress` 横条渲染** | 引 ECharts（重依赖，项目现有 import 中无 ECharts）；纯 CSS bar（手动算 width、维护成本高） | el-progress 是项目标配（Element Plus 内置），横条模式 `:percentage="n/max"` 一行渲染，hover tooltip 补充具体时长 |
| D6 | **dwellMs 的 stepId 无匹配 step 时仍展示（显示 stepId 作为兜底）** | 静默隐藏（教师可能以为这道题没停留，实际上是映射丢了） | 防御性兜底：stepNo 未知时显示 `#${stepId}` + dwellMs |
| D7 | **dwellMs < 1000ms 归为"跳过"标记**（红色 dot，dwellMs=0 显示 `-`） | 全部如实显示（0ms 显示 0、50ms 显示 50ms，视觉噪声） | 逐题停留的业务语义是"学生在这道题上花了多少认真时间"；≤1s 的停留大概率是扫一眼就跳过，做视觉标记比精确数值更有教学价值 |
| D8 | **会话数从副标题提升为独立指标卡**；粘贴/切屏/失焦保持单列 | 会话数继续藏在活跃时长副标题 `· 会话数 2`（教师扫视 8 指标卡无法识别"断续作答"学生）；加更多卡（视觉拥挤） | 会话数是"断续作答"的直接信号，与"活跃时长"并列（同一维度下的两种视角）；8 指标卡 4×2 网格平衡最优 |

### 4.2 BehaviorTimelineDrawer.vue — 新增 Tab 切换 + Step Dwell 面板

**Tab 结构**（抽屉顶部）：

```
[行为时间线]  [逐题停留]
```

- 默认选中「行为时间线」（保持现有行为不变）
- 切换到「逐题停留」渲染 Step Dwell 面板

**Step Dwell 面板数据准备**（在 Drawer 内用 computed 组装）：

```typescript
interface StepDwellItem {
  stepId: number;
  stepNo?: number;
  stepTitle?: string;
  dwellMs: number;     // 0 = 未记录停留（兜底）
  skip: boolean;        // dwellMs > 0 且 < 1000ms 判跳过（D7）
}

const stepDwellItems = computed<StepDwellItem[]>(() => {
  const raw = props.stepDwellMs ?? {};  // Record<string, number>
  const briefMap = new Map(props.stepList?.map(s => [String(s.stepId), s]) ?? []);
  return Object.entries(raw)
    .map(([stepIdStr, dwellMs]) => {
      const brief = briefMap.get(stepIdStr);
      return {
        stepId: Number(stepIdStr),
        stepNo: brief?.stepNo,
        stepTitle: brief?.title,
        dwellMs,
        skip: dwellMs > 0 && dwellMs < 1000,
      };
    })
    .sort((a, b) => {
      const aNo = a.stepNo ?? Number.MAX_SAFE_INTEGER;
      const bNo = b.stepNo ?? Number.MAX_SAFE_INTEGER;
      return aNo - bNo || a.stepId - b.stepId;
    });
});

const maxDwellMs = computed(() =>
  stepDwellItems.value.reduce((m, it) => Math.max(m, it.dwellMs), 0)
);
```

**Step Dwell 面板渲染**：

```html
<!-- 逐题停留 Tab 内容 -->
<div v-if="activeTab === 'dwell'" class="step-dwell-panel">
  <p v-if="stepDwellItems.length === 0" class="step-dwell-panel__hint">
    无逐题停留数据（行为事件未采集或 STEP_VIEW 事件缺失）
  </p>
  <div v-else class="step-dwell-list">
    <div
      v-for="item in stepDwellItems"
      :key="item.stepId"
      :class="['step-dwell-row', { 'step-dwell-row--skip': item.skip }]"
    >
      <div class="step-dwell-row__label">
        <strong>题项 {{ item.stepNo ?? `#${item.stepId}` }}</strong>
        <span v-if="item.stepTitle" class="step-dwell-row__title">{{ item.stepTitle }}</span>
        <span v-if="item.skip" class="step-dwell-row__skip-tag">跳过</span>
      </div>
      <el-progress
        :percentage="maxDwellMs > 0 ? Math.round(item.dwellMs / maxDwellMs * 100) : 0"
        :stroke-width="14"
        :format="() => formatStepDwell(item.dwellMs) ?? '—'"
        :status="item.skip ? 'exception' : (item.dwellMs === 0 ? undefined : 'success')"
      />
    </div>
  </div>
</div>
```

### 4.3 behaviorDisplay.ts — 新增 dwell 格式化辅助

```typescript
/** 逐题停留毫秒 → "5min 30s" / "45s" / "—"；0 返回 null 表示跳过 */
export function formatStepDwell(ms: number | null | undefined): string | null {
  if (ms == null || ms <= 0) return null;
  const s = Math.floor(ms / 1000);
  if (s < 60) return `${s}s`;
  const m = Math.floor(s / 60);
  const rs = s % 60;
  return rs === 0 ? `${m}min` : `${m}min ${rs}s`;
}
```
