## 2. 现网基线（2026-11-12 实测，提交 `12aa15e` 后）

### 2.1 锁链路与移除 FK 后的推演

| 步骤 | 现状（有 FK + `saveAndFlush`） | 本方案交付后（无 FK + `save`） |
|---|---|---|
| 1 | `findAllByUsernameAndRole` → `select sys_user`（RR 快照、无锁） | 同左 |
| 2 | `findFirstByUser_IdAndStatusOrderByCreatedAtDesc` → `select user_login_session`（无锁）；命中活跃会话且 `forceLogin=true` 时置 `KICKED`、写 `SESSION_INVALIDATED` 审计（`audit_log` 无外键） | 同左 |
| 3 | `saveAndFlush` → `update sys_user ...` 发出，父行 `X,REC_NOT_GAP` | `save(user)` 为托管实体 `merge`，不产生 SQL；`createActiveSession` 的 IDENTITY `insert user_login_session` 立即发出，**无 FK 校验、不对 `sys_user` 取 S 锁** |
| 4 | `insert user_login_session` → FK 需 S 锁，本事务已持 X 直接满足 | `insert audit_log (LOGIN_SUCCESS)`（`audit_log` 无 FK） |
| 5 | `insert audit_log` → commit | commit flush → `update sys_user ... last_login_at` 申请父行 `X,REC_NOT_GAP`；N 个同账号事务在父行 X 锁上普通串行等待，**无 S 锁持有者、无 S→X 环** |
| 结果 | 10 并发 `10×200`、无新增 1213（`12aa15e` §7 实测） | 同账号并发不再产生 1213；验收以 §7.1 的 10 并发实测为准 |

关键前提（沿用 `12aa15e` 方案 §2.1 第 5 条）：`audit_log` 无外键（`V1:34-43` 建表、`V18` 增强均未加，`AuditLog.user_id` 为普通 `Long`），`http_access_log` 在响应提交后由独立事务写入。因此登录事务内不存在第二处会对 `sys_user` 取 S 锁的 INSERT；§6 非目标第 2 条据此写死禁止新增这类 FK。

## 3. 唯一实现路径

### 3.1 `V32__drop_user_login_session_fk.sql`（新增，全文写死）

```sql
-- 登录会话外键移除：DB 层不再建外键，参照完整性由应用层保证（配套 PRD P3）。
-- 只用 FlywayPlaceholdersConfig 已注入的 ${mysqlOnly}；复用 V29 / V31 的双方言注释块范式。
-- H2 侧执行块内具名 DROP CONSTRAINT；MySQL 侧整块被注释、执行块外 DROP FOREIGN KEY。
-- MySQL 建 FK 时自动生成的 user_id 单列索引保留不删；双侧统一补显式三列索引。
${mysqlOnly}/*
ALTER TABLE user_login_session DROP CONSTRAINT fk_user_login_session_user;
${mysqlOnly}*/
${mysqlOnly}ALTER TABLE user_login_session DROP FOREIGN KEY fk_user_login_session_user;

CREATE INDEX idx_user_login_session_user_status ON user_login_session (user_id, status, created_at);
```

- H2 侧：`${mysqlOnly}` = `--`，第 5 行变行注释 `--/*`、第 7 行变 `--*/`，块内 `DROP CONSTRAINT` 执行；第 8 行被 `--` 注释；第 10 行执行。
- MySQL 侧：`${mysqlOnly}` = 空串，第 5–7 行构成 `/* … */` 注释块，块内 H2 语句不执行；第 8 行 `DROP FOREIGN KEY` 执行；第 10 行执行。
- 不写 `SET FOREIGN_KEY_CHECKS` / `SET REFERENTIAL_INTEGRITY`：删的是约束本身，不是绕过校验删数据。
- 索引列顺序写死为 `(user_id, status, created_at)`：等值命中 `user_id` / `status` 后按 `created_at` 支撑 `OrderByCreatedAtDesc`；不写 `DESC` 以保双库通用，MySQL 8 与 H2 均可反向扫描。

### 3.2 `AuthService.java`（`login` 方法内，按片段原文定位）

由

```java
        user.setLastLoginAt(now);
        // insert user_login_session 经外键对 sys_user 父行取 S 锁；若把 update sys_user 留到 commit flush，
        // 并发登录会互持 S 锁再互等 X 锁，触发 MySQL 1213。先 flush 把父行 X 锁提前到子行 INSERT 之前，
        // 本事务的 FK 校验由已持有的 X 锁直接满足，同账号登录在父行上串行。
        SysUser saved = sysUserRepository.saveAndFlush(user);
        UserLoginSession loginSession = createActiveSession(saved, now);
```

改为

```java
        user.setLastLoginAt(now);
        SysUser saved = sysUserRepository.save(user);
        UserLoginSession loginSession = createActiveSession(saved, now);
```

`SysUser saved` 变量仍供 `createActiveSession` 与 `jwtTokenService.issueToken` 使用，逐字不变；不新增 / 删除 import。**实施防错（写死）**：按上述完整片段逐字替换 `login` 内那一处，禁止在文件内对 `saveAndFlush` 与 `save(user)` 做全局替换——`updateProfile` / `changePassword` 有同形 `save(user)` 语句，零改动。

package com.opencode.teachingplatform.auth;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.test.context.ActiveProfiles;

@SpringBootTest
@ActiveProfiles("test")
class UserLoginSessionSchemaTests {

    @Autowired
    private JdbcTemplate jdbcTemplate;

    @Test
    void sessionTableShouldHaveNoForeignKeyToSysUser() {
        Integer count = jdbcTemplate.queryForObject(
                "SELECT COUNT(*) FROM INFORMATION_SCHEMA.TABLE_CONSTRAINTS "
                        + "WHERE UPPER(TABLE_SCHEMA) = 'PUBLIC' "
                        + "AND UPPER(CONSTRAINT_NAME) = 'FK_USER_LOGIN_SESSION_USER'",
                Integer.class
        );
        assertThat(count).isZero();
    }

    @Test
    void sessionTableShouldHaveUserStatusIndex() {
        Integer count = jdbcTemplate.queryForObject(
                "SELECT COUNT(*) FROM INFORMATION_SCHEMA.INDEXES "
                        + "WHERE UPPER(TABLE_SCHEMA) = 'PUBLIC' "
                        + "AND UPPER(TABLE_NAME) = 'USER_LOGIN_SESSION' "
                        + "AND UPPER(INDEX_NAME) = 'IDX_USER_LOGIN_SESSION_USER_STATUS'",

        );
