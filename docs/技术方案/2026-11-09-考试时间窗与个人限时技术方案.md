### 4.2 时间校验私有方法（TD2–TD5）

```java
private void assertTimeWindowOrder(OffsetDateTime startAt, OffsetDateTime endAt) {
    if (startAt != null && endAt != null && !startAt.isBefore(endAt)) {
        throw new BusinessException(40000, "开始时间必须早于结束时间");
    }
}

private void assertPublishableTimeWindow(OffsetDateTime startAt, OffsetDateTime endAt, OffsetDateTime now) {
    if (endAt == null) {
        throw new BusinessException(40000, "请先设置考试结束时间");
    }
    if (!endAt.isAfter(now)) {
        throw new BusinessException(40000, "结束时间必须晚于当前时间");
    }
    assertTimeWindowOrder(startAt, endAt);
}
```

- 不新增独立类、不新增 Spring Bean。
- `OffsetDateTime.isBefore` / `isAfter` 按时间点比较，兼容不同 offset。
- 时间顺序校验只要求两个值同时非空；`startAt` 单独存在、`endAt` 单独存在均允许。

### 5.2 `useExamDetail` 新增展示计算（TD9 / TD16）

在现有 `remainingSeconds`、`deadlineAt` 之后新增：

```ts
const isTimerUrgent = computed(() => remainingSeconds.value <= 300)

const limitMinutes = computed(() => {
  const startedAt = detail.value?.startedAt
  const deadline = deadlineAt.value
  if (startedAt && deadline) {
    const diff = Math.round((new Date(deadline).getTime() - new Date(startedAt).getTime()) / 60000)
    if (Number.isFinite(diff)) return Math.max(0, diff)
  }
  return detail.value?.durationMinutes ?? 0
})

const windowTruncated = computed(() => {
  const endAt = detail.value?.endAt
  const deadline = deadlineAt.value
  const configured = detail.value?.durationMinutes
  if (!endAt || !deadline || !configured) return false
  const end = new Date(endAt).getTime()
  const deadlineTime = new Date(deadline).getTime()
  if (!Number.isFinite(end) || !Number.isFinite(deadlineTime)) return false
  return Math.abs(end - deadlineTime) <= 1000 && limitMinutes.value < configured
})

const limitText = computed(() => {
  // 仅数据完全缺失时使用兜底文案；四舍五入后可为 0（临近截止进入）
  if (limitMinutes.value <= 0 && !detail.value?.durationMinutes) return '本次限时以服务端为准'
  return `本次限时 ${limitMinutes.value} 分钟${windowTruncated.value ? '（窗口提前结束）' : ''}`
})

const deadlineText = computed(() => (
  deadlineAt.value ? `截止 ${formatDateTime(deadlineAt.value)}` : '截止时间待同步'
))

const isLegacyNoEndAt = computed(() => (
  detail.value?.status === ACTIVITY_STATUS.PUBLISHED && !detail.value?.endAt
```

### 5.3 倒计时单调实现（TD10）

`useExamDetail` 模块级新增：

```ts
let lastRemainingSeconds = 0
```

`startTimer` 改为：

```ts
function startTimer(remaining: number) {
  stopTimer()
  baselineSeconds = Math.max(0, Math.floor(remaining))
  baselineAt = performance.now()
  lastRemainingSeconds = baselineSeconds
  remainingSeconds.value = baselineSeconds

  const update = () => {
    const elapsed = Math.floor((performance.now() - baselineAt) / 1000)
    const next = Math.max(0, baselineSeconds - elapsed)
    remainingSeconds.value = Math.min(lastRemainingSeconds, next)
    lastRemainingSeconds = remainingSeconds.value
    if (remainingSeconds.value <= 0) {
      stopTimer()
      clearDraftTimer()
      if (!autoSubmitTriggered) {
        autoSubmitTriggered = true
        autoSubmit()
      }
    }
  }

  if (baselineSeconds <= 0) {
    remainingSeconds.value = 0
    lastRemainingSeconds = 0
    clearDraftTimer()
    if (!autoSubmitTriggered) {
      autoSubmitTriggered = true
      autoSubmit()
    }
    return
  }

  autoSubmitTriggered = false
  timer = window.setInterval(update, 1000)
  update()
}
```

- `baselineAt` 从 epoch 毫秒改为 `performance.now()`，本机墙钟回拨不影响同一基线内的流逝计算。
- `secondsUntil` 仍用 `Date.now()`，仅作为服务端未返回 `remainingSeconds` 时的初始兜底；后续由详情重拉校正。
- 同一基线内 `Math.min(lastRemainingSeconds, next)` 保证显示单调不增；`startTimer` 重新设置基线时允许服务端校正上调。
- `clearDraftTimer` 为新增私有函数：

```ts

  if (!value) return null

const validateTimeWindow = (
  startAt: string | null | undefined,
  endAt: string | null | undefined,
  durationMinutes: number,
  requireEndAt: boolean,
): boolean => {
  const duration = Number(durationMinutes)
  if (!Number.isInteger(duration) || duration < 1 || duration > 600) {
    ElMessage.warning('考试时长必须为 1–600 分钟的整数')
    return false

    return false

    const end = parseTimeValue(endAt)
    if (start == null || end == null || start >= end) {
      ElMessage.warning('开始时间必须早于结束时间')
      return false
    }
  }
  return true
}
```

## 9. 边界与异常

| 场景 | 预期 |
|---|---|
| 倒计时归零后网络断开 | 前端仍触发 `autoSubmit()`；失败进入既有失败条与 6 次重试，不依赖详情重拉 |
| 页面隐藏后重新可见，本地已归零 | 先置 `autoSubmitTriggered` 并交卷，再 `loadExam` 校正；`loadExam` 失败不重复弹错 |
| 页面隐藏后重新可见，本地未归零 | 本地先减，随后服务端 `remainingSeconds` 重置基线；同一基线内不增加 |
| 本机时间回拨 | `performance.now()` 不受影响；显示值不回增；交卷仍以服务端为准 |
| `startedAt` 缺失（历史提交） | 本次限时回退 `durationMinutes`；不显示“窗口提前结束” |
| 进入时距截止不足 30 秒（四舍五入为 0） | 实际限时 `N = 0`，展示“本次限时 0 分钟（窗口提前结束）”；不阻断交卷 |
| `deadlineAt` 缺失但 `remainingSeconds` 存在 | 时钟显示“截止时间待同步”；倒计时按服务端基线递减 |
| `endAt` 为空的历史考试 | 详情显示“时间待定”或“开始 - 未设置”；追加历史无统一截止提示 |
| 窗口截断 `deadlineAt == endAt` | 限时显示实际分钟数 + “（窗口提前结束）”；误差 ≤1 秒 |
| 教师保存 DRAFT 时 `endAt` 为空 | 允许；前端不拦截，后端只校验顺序 |
| 教师发布时 `endAt` 为空/已过 | 前端本地拦截空值；已过交后端返回文案；均不发起发布请求（已过场景请求会到后端） |
| `updateExam` 非 `DRAFT` | 40000「只有草稿状态的考试可以修改」；时间校验不执行 |
| `CLOSED` + `IN_PROGRESS` 调 `start` | 40000「考试未发布，不能开始」；详情接口仍返回进行中提交，可继续作答 |
| 全客观题截止后交卷 | 直接 `GRADED`；前端按 `submissionStatus` 展示结果 |
| 含主观题截止后交卷 | `AUTO_SUBMITTED`；等待教师批改 |
| 到期瞬间有排队草稿防抖 | 清除定时器，不发送请求；自动交卷使用内存答案与已落库草稿 |
| 到期前已发出的草稿请求 | 允许完成；服务端宽限期内正常接收，不追回 |

## 13. 已否决方案（附录）

| 方案 | 否决原因 |
|---|---|
| 新建 `ExamTimeWindowValidator` 独立类 | 只有两个私有校验方法，新增类会增加无谓抽象与注入面 |
| 在 Service 重复校验 `durationMinutes` 范围 | DTO 已是唯一入口，重复校验会造成文案双源；Controller 测试覆盖足够 |
| 允许 `CLOSED` 下 `start` 继续作答 | 现有状态机明确 `start` 仅 `PUBLISHED`；继续作答走详情接口，改状态机会扩大范围 |
| 已发布考试开放 `endAt` 编辑 | 现网 `updateExam` 仅 `DRAFT`；开放会牵动已开始提交的快照语义与权限，超出本期 |
| 修改 `deadlineAt` 快照以支持教师提前收卷 | 与 PRD 非目标冲突，且需新增终止/重算流程 |
| 前端新增 `limitMinutes` 接口字段 | `startedAt`、`deadlineAt` 已足够推导，新增字段会扩散契约 |
| 倒计时继续用 `Date.now()` 并只做 UI 钳制 | 墙钟回拨仍会影响基线；`performance.now()` 是单一路径 |
| 可见时只重拉详情 | 离线/重拉失败时不会触发到期交卷；必须先本地校准 |
| 到期后继续允许草稿保存 | 与“到期锁定作答”语义冲突；服务端宽限期只是兜底 |
