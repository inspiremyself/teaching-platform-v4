# HTTP 访问日志统一落库（基础能力）技术方案

**创建日期**：2026-09-15  
**状态**：已定稿（决策写死，可直接编码）  
**范围**：在 Spring Boot 后端为 **`/api/v1/**` 全量 HTTP 请求**建立统一访问日志管道，异步写入 MySQL/H2（Flyway 新表），与现有业务 `audit_log` 并存、职责分离  
**非目标（本期）**：请求/响应 Body 落库、管理端查询 UI、日志检索 API、自动归档/分区、接入 ELK/Loki、用 AOP 替代 Filter 作为主采集点、将现有 `audit_log` 手写点改为自动推导

## 1. 背景与调研结论

### 1.1 诉求

需要「统一 HTTP 访问日志 / 全接口落库」作为架构基础能力，补齐现网只有**零散业务审计**（`audit_log` + 手写 `auditLogService.log`）的缺口，便于安全审计、排障与后续运营分析。

### 1.2 现网结论

| 能力 | 现状 | 缺口 |
|------|------|------|
| 业务审计 | 表 `audit_log` + `AuditLogService`；登录、校管、题库等**部分**写操作 | 非全接口；无 HTTP 维度（耗时、状态码、IP） |
| 登录会话 | `user_login_session` | 会话生命周期，非访问轨迹 |
| HTTP 采集 | 无统一 Filter/Interceptor | 无全链路访问表 |
| 异步写日志 | 仓库内 **无** `@EnableAsync` | 需新建线程池，避免同步写库拖慢接口 |
| 安全链 | `JwtAuthenticationFilter` → `UsernamePasswordAuthenticationFilter` | 访问日志 Filter **挂 JWT 之前**，外层 `finally` 读 `CurrentUser` |

### 1.3 方案一句话

**在 JWT 之前（外层）增加 `HttpAccessLogFilter`，对 `/api/v1` 请求计时并异步写入 `http_access_log`，响应带 `X-Trace-Id`；业务语义审计仍走 `audit_log`。**

## 2. 目标与非目标

### 2.1 本期目标（Phase 1 — 基础能力）

- 任意 `/api/v1/**` 请求（除 `OPTIONS`、开关关闭）在完成后产生 **一条** 访问记录。
- 记录可关联用户（已登录）或匿名（未带有效 Token / 登录前）。
- 写库 **不阻塞** 业务线程（异步 + 失败隔离）。
- 可通过 SQL 验证：`SELECT * FROM http_access_log ORDER BY id DESC LIMIT 20;`

### 2.2 非目标（归属后续 Phase）

| Phase | 内容 |
|-------|------|
| Phase 2 | 校管只读 API：`GET /api/v1/admin/access-logs` 分页检索（`SCHOOL_ADMIN` + `school_id` 范围） |
| Phase 3 | 保留策略（定时清理 N 天前数据）、表分区或冷存储 |
| Phase 3 | 可选：从 `HandlerMapping` 解析 `controller#method`  enrich 字段（仍由 Filter 触发，**不**引入 AOP） |

## 3. 架构设计

### 3.1 分层职责

```text
HTTP Request
  → HttpAccessLogFilter              （外层：计时、trace_id、响应头；finally 提交写库）
  → JwtAuthenticationFilter          （鉴权，填充 SecurityContext / 401 短路仍回到外层 finally）
  → DispatcherServlet → Controller
  → HttpAccessLogAsyncWriter         （@Async 持久化）
  → http_access_log (MySQL/H2)

并行不变：
  业务 Service → AuditLogService → audit_log   （语义事件，手写调用）
```

### 3.2 为何 Filter 而非 AOP

| 维度 | Filter（选定） | Controller AOP（否决，见附录 A） |
|------|----------------|----------------------------------|
| JWT 层 401 | ✅ 可记录（访问日志 Filter **包裹** JWT，`return` 不写下游仍执行外层 `finally`） | ❌ 通常无切面 |
| 覆盖边界 | 与 `/api/v1` 前缀规则一致 | 仅 `@RestController` 方法 |
| 耗时 | 整请求 wall time | 仅方法体内 |
| 与现网一致 | 已有 `OncePerRequestFilter` 模式 | 新增横切，与 Filter 重复 |

**结论**：全接口 HTTP 访问日志以 **Filter 为唯一采集点**；AOP 不纳入本期实现。

### 3.3 Filter 行为（写死）

类：`com.opencode.teachingplatform.common.accesslog.HttpAccessLogFilter`

1. 若 `app.http-access-log.enabled == false` → `filterChain.doFilter` 直接返回。
2. 若 `OPTIONS` → 直接 `doFilter`，不写库、不写 `X-Trace-Id`。
3. 若 URI 不以 `/api/v1` 开头 → 直接 `doFilter`，不写库、不写 `X-Trace-Id`。
4. 否则：`traceId = UUID.randomUUID()`；`startedAt = System.nanoTime()`；响应头 `X-Trace-Id`。
5. `try { filterChain.doFilter(...) } finally {` 组装 `HttpAccessLogRecord`：`status = response.getStatus()`，`durationMs = (nanoTime - startedAt) / 1_000_000`，用户字段来自 `SecurityContextHolder` 的 `CurrentUser`（`instanceof` 判断）。
6. 调用 `HttpAccessLogService.submit(record)`（同步入队异步任务，不在 Filter 内 `save`）。

**注册**：`SecurityConfig.securityFilterChain` 对 `UsernamePasswordAuthenticationFilter` **连续** `addFilterBefore`（Spring Security 6 不得以未注册 order 的 `JwtAuthenticationFilter` 为锚点）：

1. `.addFilterBefore(httpAccessLogFilter, UsernamePasswordAuthenticationFilter.class)`
2. `.addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class)`

请求顺序为 **HttpAccessLog → Jwt → …**（先注册访问日志、后注册 JWT，后者插入更靠近 `UsernamePasswordAuthenticationFilter`）。

**Bean 注册**：`HttpAccessLogFilter` **不用** `@Component`；由 `AccessLogAsyncConfig` 的 `@Bean` 提供，仅挂入 Security 链，避免 Servlet 容器重复注册。

**`user_role` 映射**：`CurrentUser.role().name()` 写入列 `user_role`；无 `CurrentUser` 时三列用户字段均为 NULL。

### 3.4 异步写库（写死）

- `HttpAccessLogService.submit`：校验 `enabled`（双重保险），调用 `HttpAccessLogAsyncWriter.writeAsync(record)`。
- `HttpAccessLogAsyncWriter.writeAsync`：`@Async("httpAccessLogExecutor")`，`@Transactional` 内 `repository.save(entity)`。
- 异常：`catch` 后 `log.error("http access log persist failed, traceId={}", ...)`，**不抛出**。

## 4. 数据模型

### 4.1 表 `http_access_log`（V17）

```sql
CREATE TABLE http_access_log (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  trace_id VARCHAR(36) NOT NULL,
  user_id BIGINT NULL,
  school_id BIGINT NULL,
  user_role VARCHAR(32) NULL,
  http_method VARCHAR(16) NOT NULL,
  request_path VARCHAR(512) NOT NULL,
  query_string VARCHAR(1024) NULL,
  status_code INT NOT NULL,
  duration_ms INT NOT NULL,
  client_ip VARCHAR(64) NULL,
  user_agent VARCHAR(512) NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_http_access_log_created_at (created_at),
  INDEX idx_http_access_log_user_id (user_id),
  INDEX idx_http_access_log_trace_id (trace_id)
);
```

说明：

- **`updated_at`**：与现网 `BaseEntity` 惯例一致，本期写入后不再更新。
- **不存** `session_key`、JWT、Body。
- 登录成功会在 **`audit_log`** 有 `LOGIN_SUCCESS`，同时 **`http_access_log`** 有对应 POST 行（`user_id` 仍为 NULL，因 Token 在响应体返回后才由客户端持有）——**接受这种双轨**，不在本期合并。

### 4.2 实体与仓库

- `HttpAccessLog` extends `BaseEntity`（`@Table(name = "http_access_log")`）。
- `HttpAccessLogRepository extends JpaRepository<HttpAccessLog, Long>`，无自定义查询（本期）。

### 4.3 配置项

```yaml
app:
  http-access-log:
    enabled: true
```

绑定类：**仅** `AppHttpAccessLogProperties`（`@ConfigurationProperties(prefix = "app.http-access-log")`），在 **`AccessLogAsyncConfig`** 上 `@EnableConfigurationProperties(AppHttpAccessLogProperties.class)` 注册；与 `app.jwt-secret` 等同属 `application.yml` 的 `app:` 节点，**不**引入聚合 `AppProperties` 类。

## 附录 A：已否决方案

| 方案 | 否决原因 |
|------|----------|
| Controller `@Around` AOP 全接口 | 漏 Filter 层失败、非 Controller 入口；与 Filter 重复 |
| 写入现有 `audit_log` | 语义与体量不匹配；`action` 无法表达每次 GET |
| 同步 Filter 内 `repository.save` | 增加接口延迟，与「基础能力不拖累业务」冲突 |
| 记录 Request/Response Body | 含密码、答题内容、multipart 二进制；合规与存储成本高 |
| ContentCachingRequestWrapper 全量包装 | 内存与 multipart 风险；本期无 Body 需求 |
