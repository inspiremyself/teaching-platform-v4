## 1. 背景与诉求

### 1.1 业务背景

校管端第一期在 `class_teacher` 上用 **`subject_name` 自由文本** 标注学科教师任课科目。该模式存在：

- 命名不一致（同校多种写法）
- 班级指派需手打，无校标下拉
- 无法集中维护、停用学科

本期在学校层引入 **学科字典表**，班级指派改为 FK；与真实教务「先维护科目库、再指派」一致。

### 1.2 与第一期关系

| 项 | 第一期（V13） | 本期（V14） |
|----|--------------|-------------|
| 学科存储 | `class_teacher.subject_name VARCHAR(64)` | `class_teacher.subject_id → school_subject` |
| 校管维护 | 班级表单内手输 | 独立「学科管理」+ 班级下拉 |
| 教学鉴权 | `class_teacher` 教师归属 | **不变** |

---

## 2. 目标与非目标

### 2.1 目标

1. 校管可维护本校学科（名称、编码、启停）。
2. 班级创建/编辑时，学科教师从 **ACTIVE 学科字典** 下拉选择。
3. 同班允许多名教师绑定 **同一 `subject_id`**（如两名「数据库原理」教师）。
4. V14 迁移现有 `subject_name` 数据至字典并回填 FK。
5. API/前端 **一次性切换** 为 `subjectId`，不保留 `subjectName` 请求兼容。

### 2.2 非目标

- 作业/实验/考试/题库表增加 `subject_id`。
- 课表、课时、走班排课。
- 平台级跨校标准学科码表。
- 学科物理删除、批量导入导出。
- 院系/年级/专业维度。

## 3. 数据模型

### 3.1 ER（本期增量）

```text
school (1)
  │
  ├──1:N── school_subject          ← 新增
  │         school_id
  │         name / code / status
  │         UNIQUE(school_id, code)
  │
  └──1:N── class_room
            │
            └──1:N── class_teacher
                      role ∈ { HEAD, SUBJECT }
                      subject_id → school_subject.id（SUBJECT 必填；HEAD 为 NULL）
                      UNIQUE(class_id, teacher_user_id)
                      （不设 UNIQUE(class_id, subject_id) — 同班同科多师允许）
```

### 3.2 新表 `school_subject`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT PK | 自增 |
| `school_id` | BIGINT NOT NULL | → `school.id` |
| `name` | VARCHAR(128) NOT NULL | 展示名，trim 后 1～128 |
| `code` | VARCHAR(64) NOT NULL | 学科编码，trim 后转 **大写** 存储，1～64 |
| `status` | VARCHAR(16) NOT NULL | `ACTIVE` / `DISABLED` |
| `created_at` / `updated_at` | TIMESTAMP | 审计字段 |

约束：

- **`UNIQUE(school_id, code)`**
- **不设** `UNIQUE(school_id, name)`（允许同名不同 code，由校管自行规范）

Java：

- `com.opencode.teachingplatform.school.entity.SchoolSubject`
- `com.opencode.teachingplatform.school.repository.SchoolSubjectRepository`
- 枚举 `SubjectStatus { ACTIVE, DISABLED }`（放 `common/enums`）

### 3.3 变更 `class_teacher`

| 变更 | 说明 |
|------|------|
| 新增 `subject_id BIGINT NULL` | `role=SUBJECT` 时 NOT NULL（Service 校验）；`role=HEAD` 时必须 NULL |
| **删除 `subject_name`** | V14 迁移完成后 DROP 列 |

`ClassTeacher` 实体：`subjectName` 字段删除，新增 `subjectId`。

### 3.4 角色与学科字段语义

| role | subject_id | 说明 |
|------|------------|------|
| `HEAD` | `NULL` | 班主任不绑学科 |
| `SUBJECT` | 必填 FK | 必须指向本校 `school_subject`；**允许多行相同 `subject_id`** |

### 3.5 Flyway `V14__school_subject_dictionary.sql`（写死顺序）

1. `CREATE TABLE school_subject (...)` + `UNIQUE(school_id, code)`  

2. **灌字典 — 固定映射**（按 `school_id` + trim 后 `subject_name` 去重，仅 `role='SUBJECT'`）：

   | 原 `subject_name` | `code` |
   |-------------------|--------|
   | 软件体系结构 | `SE-ARCH` |
   | 数据库原理 | `DB-PRINCIPLE` |
   | 未标注学科 | `UNSPECIFIED` |

   ```sql
   INSERT INTO school_subject (school_id, name, code, status, created_at, updated_at)
   SELECT DISTINCT cr.school_id, TRIM(ct.subject_name),
          CASE TRIM(ct.subject_name)
            WHEN '软件体系结构' THEN 'SE-ARCH'
            WHEN '数据库原理'   THEN 'DB-PRINCIPLE'
            WHEN '未标注学科'   THEN 'UNSPECIFIED'
          END,
          'ACTIVE', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP
   FROM class_teacher ct
   JOIN class_room cr ON cr.id = ct.class_id
   WHERE ct.role = 'SUBJECT'
     AND ct.subject_name IS NOT NULL
     AND TRIM(ct.subject_name) <> ''
     AND TRIM(ct.subject_name) IN ('软件体系结构', '数据库原理', '未标注学科');
   ```

3. **灌字典 — 其余 legacy 名称**（未命中步骤 2 固定映射者）：

   ```sql
   INSERT INTO school_subject (school_id, name, code, status, created_at, updated_at)
   SELECT school_id, name,
          CONCAT('LEGACY-', LPAD(CAST(rn AS CHAR(3)), 3, '0')),
          'ACTIVE', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP
   FROM (
     SELECT cr.school_id AS school_id,
            TRIM(ct.subject_name) AS name,
            ROW_NUMBER() OVER (PARTITION BY cr.school_id ORDER BY TRIM(ct.subject_name)) AS rn
     FROM class_teacher ct
     JOIN class_room cr ON cr.id = ct.class_id
     WHERE ct.role = 'SUBJECT'
       AND ct.subject_name IS NOT NULL
       AND TRIM(ct.subject_name) <> ''
       AND TRIM(ct.subject_name) NOT IN ('软件体系结构', '数据库原理', '未标注学科')
   ) legacy_names;
   ```

   `CONCAT` + `LPAD` + `ROW_NUMBER()` 在 H2（路径 B）与 MySQL 8（路径 A）均可用；**禁止**应用层补码。

4. `ALTER TABLE class_teacher ADD COLUMN subject_id BIGINT NULL`  

5. **回填 FK**（按 `school_id` + trim 后 `subject_name` = `school_subject.name` 匹配）：

   ```sql
   UPDATE class_teacher ct
   SET subject_id = (
     SELECT ss.id FROM school_subject ss
     INNER JOIN class_room cr ON cr.id = ct.class_id
     WHERE ss.school_id = cr.school_id
       AND ss.name = TRIM(ct.subject_name)
   )
   WHERE ct.role = 'SUBJECT' AND ct.subject_name IS NOT NULL;
   ```

   步骤 2～3 保证同一 `school_id` 下每个 distinct `name` 仅一条字典行，标量子查询结果唯一，**无需** `LIMIT` / `FETCH FIRST`。

6. **兜底**：凡 `role='SUBJECT'` 且 `subject_id IS NULL` 的行，统一设为 **`code='UNSPECIFIED'`** 且同 `school_id` 的字典 id。  

7. `ALTER TABLE class_teacher DROP COLUMN subject_name`  

8. H2 / MySQL：索引/约束名冲突时显式 `DROP` 再建。

**不修改** `V13__school_organization_phase1.sql` 与 `V2__seed_data.sql`。

## 4. 鉴权与数据范围

### 4.1 权限矩阵（增量）

| 能力 | SCHOOL_ADMIN | TEACHER | STUDENT |
|------|:------------:|:-------:|:-------:|
| 学科 CRUD / 启停 | ✅ 本校 | — | — |
| 学科只读列表（ACTIVE） | ✅ 本校 | — | — |
| 班级指派选学科 | ✅ 下拉用 ACTIVE 字典 | — | — |
| 教学业务 | — | ✅ 不变（`class_teacher` 教师归属） | ✅ 不变 |

### 4.2 数据范围（写死）

`AdminSubjectService` 所有入口：

```java
Long schoolId = currentUser.schoolId();
// 读写均限定 school_id = schoolId
```

`AdminClassService.validateTeachers(schoolId, classId, teachers)` 校验 `subjectId` 时：

- 学科必须 `school_id == schoolId`（与班级同校）
- 学科不存在或跨校 → **40025**
- **`createClass`（`classId == null`）**：每个 SUBJECT 的 `subjectId` 对应学科必须 **`ACTIVE`**，否则 **40026**
- **`updateClass`（`classId != null`）**：对每个 `teachers[]` 项，查 `findByClassIdAndTeacherUserId(classId, teacherUserId)`：
  - 若存在且 **`existing.subjectId.equals(request.subjectId)`** 且学科为 **`DISABLED`** → **允许**（保留历史指派）
  - 其余情况（新教师、换科、新选 DISABLED 学科）→ 学科必须 **`ACTIVE`**，否则 **40026**

## 5. API 契约

前缀：`/api/v1/admin/subjects`；鉴权：`@PreAuthorize("hasRole('SCHOOL_ADMIN')")`。

### 5.1 列表

`GET /api/v1/admin/subjects?status=ACTIVE|DISABLED`（`status` 可选；缺省返回全部）

**响应项**：

```json
{
  "id": 1,
  "name": "软件体系结构",
  "code": "SE-ARCH",
  "status": "ACTIVE",
  "assignmentCount": 2
}
```

`assignmentCount`：`class_teacher` 中 `subject_id = id` 的行数（只读统计，便于校管判断影响面）。

### 5.2 创建

`POST /api/v1/admin/subjects`

```json
{ "name": "操作系统", "code": "OS" }
```

- `name` trim 后 1～128 字符，否则 **40000**「学科名称长度必须在1到128个字符之间」
- `code` trim 后转大写；须匹配 **`^[A-Z0-9-]{1,64}$`**，否则 **40000**「学科编码格式不合法」
- `(school_id, code)` 冲突 → **`40901`**「学科编码已存在」
- 默认 `status=ACTIVE`

### 5.3 更新

`PUT /api/v1/admin/subjects/{id}`

```json
{ "name": "操作系统原理", "code": "OS-PRINCIPLE" }
```

- 只能改 **本校** 学科；不存在 → **`40400`**
- `name` / `code` 校验规则与 **§5.2 创建** 相同
- `code` 变更仍受 `(school_id, code)` 唯一约束

### 5.4 启停

`POST /api/v1/admin/subjects/{id}/status`

```json
{ "status": "DISABLED" }
```

- 停用后已有 `class_teacher` **保留**；新班级指派选不到（前端只拉 ACTIVE）
- 审计：`SUBJECT_STATUS`

### 5.5 班级 API 契约变更（breaking）

**`AdminRequests.ClassTeacherItem`**：

```java
public record ClassTeacherItem(
    @NotNull Long teacherUserId,
    @NotNull ClassTeacherRole role,
    Long subjectId   // role=SUBJECT 时必填；HEAD 必须为 null
) {}
```

**删除** `subjectName` 字段；请求体带 `subjectName` **不读取、不兼容**。

**响应 `teachers[]` 项**：

```json
{
  "teacherUserId": 2,
  "teacherName": "李老师",
  "role": "SUBJECT",
  "subjectId": 2,
  "subjectName": "数据库原理"
}
```

**教师只读 `GET /api/v1/classes` → `myAssignment`**：

```json
{
  "role": "SUBJECT",
  "subjectId": 1,
  "subjectName": "软件体系结构"
}
```

### 5.6 校验与错误码

| code | 场景 | message |
|------|------|---------|
| 40023 | `SUBJECT` 缺/空 `subjectId` | 学科教师必须选择学科 |
| 40025 | `subjectId` 不存在或非本校 | 学科不存在 |
| 40026 | 新指派使用了 `DISABLED` 学科 | 学科已停用，不能指派 |
| 40901 | `(school_id, code)` 冲突 | 学科编码已存在 |

其余组织域错误码（40020/40022/40024 等）不变。

## 11. 已否决方案（附录）

| 方案 | 否决原因 |
|------|----------|
| 保留 `subject_name` 冗余列 | 双源字段；本期以 `subject_id` 为唯一真相 |
| 请求体同时接受 `subjectName` + `subjectId` | 用户要求一次性 breaking change |
| `UNIQUE(school_id, name)` | 用户指定唯一键为 `(school_id, code)` |
| `UNIQUE(class_id, subject_id)` | 禁止同班同科多师，与已定决策冲突 |
| 软字典（前端 suggest + 后端仍存字符串） | 无法强制校标；长期技术债 |
| 学科硬删除 | 与教师/学生组织域策略不一致 |
| 教学任务绑 `subject_id` | 超出本期范围 |
