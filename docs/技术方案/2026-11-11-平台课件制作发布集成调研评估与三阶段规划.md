## 1. 结论摘要

**可行，但不能「把三个项目拷进来」。** 三个对标项目各自只提供一层能力，且全部是 Python + MongoDB + 静态 HTML 体系；目标平台是 Spring Boot 3.3 + MySQL + Vue3 单后端，且总纲 V7.1 已把内容模型写死。正确的集成形态是：**借鉴协议与状态机，重写实现**。

| 结论 | 说明 |
|---|---|
| 能力来源 | AI 生成看 `AIXUE`；发布/授权/按小节布置看 `JLZK`；`RENDER` 只提供静态 CSS/JS 资产与 DOM 契约，**不是可嵌入的渲染器** |
| 集成路径（唯一结论） | 单一 Java 后端 + MySQL，结构化 JSON 为唯一内容真相源，Vue3 组件渲染，**不引入 Python 服务、不引入静态 HTML 产物、不引入 `sid` 票据、不引入 MongoDB** |
| 存储与容量 | **不引入 MongoDB**；现网 `*_json` 列均为 `TEXT`（MySQL 64KB），课件正文按小节分行天然分片；`V31` 建 `content_json TEXT`，MySQL 侧用现有 `${mysqlOnly}` 占位符升级为 `LONGTEXT`，H2 侧保留 `TEXT`/CLOB；服务端单节正文上限 1MB |
| 目录口径 | 「学科 → 教材 → 叶子小节」，不建 `course` 实体；学科是**归属列**不是树节点，教材→叶子小节是目录树，课件经 `content_mount` 挂到叶子小节 |
| 布置形态 | 选节布置 = **任意不连续子集 + 教师自定义呈现顺序**（`assignment_group_id` / `display_order` 布置时快照）；整份布置 = 按课件原 `courseware_section.sort_order` 展开全部小节，不支持打乱 |
| 最大障碍 | 不是技术，是**口径冲突**：用户最终业务形态与已定稿总纲 V7.1 在「谁制作」「发布态」「任务闭环」「挂载与写入端点」等处不一致；C1–C6 已于 2026-11-11 全部确认（§4.2 / §9），但**总纲 V7.2 未修订前不得逐期立项**，否则阶段 3/4 无法按现网口径验收 |
| 分期 | P1 目录与内容基座（**即总纲阶段 2 主方案的落地期；该主方案当前尚未产出**）→ P2 平台制作·发布·授权（对齐阶段 3 平台侧）→ P3 按小节布置与学生学习（对齐阶段 4 课件侧） |

## 2. 对标项目调研结论

### 2.1 `AIXUE`：AI 生成课件（可借鉴「协议与流水线」）

- **两段解耦链路**：阶段 A「AI 只生成课件 JSON（不产 HTML）→ 落 MongoDB」；阶段 B「JSON → 整页静态 HTML（模板字符串拼接，与 LLM 无关）→ `generated_pages/` → 发布副本 `htmlPublish/`」。证据：`AIXUE/课件生成/课件生成实现逻辑与产物资源分析.md:9-24`。
- **课件 JSON 协议**：`{title, subtitle, sections[{heading, paragraphs[{html, title, sentences[{text, narration, image, audio}], exercises[]}]}]}`；强制约束：真实内容禁占位、每句独立 `narration`、图片只在句子级、LaTeX 用 `\(...\)`、只输出一个 `json` 围栏代码块。证据：`AIXUE/课件生成SKILL规范.md:23-67,198-243`、`AIXUE/deploy/shared/deepagent_courseware.py:23-80`。
- **AI 调用**：DeepSeek（OpenAI 兼容协议经 LangChain `ChatOpenAI`），`temperature=0.0`，system = `COURSEWARE_SCHEMA` + `COURSEWARE_SYSTEM_PROMPT` + Skills 文本。证据：`AIXUE/deploy/shared/config.py:79-104`、`AIXUE/deploy/shared/deepagent_courseware.py:384-423`。**设计稿的多轮 DeepAgent 已旁路，实际是单次 LLM 补全 + JSON 解析失败重试**（`docs/DeepAgent课件生成方案.md` 与源码不一致，不可照搬设计稿）。
- **生成 ≠ 发布**：`未发布 / 待发布 / 已发布` 三态；生成页面后 `db_set_page_url` 强制回退未发布并清空 `publish_target`；发布须先生成；发布 body 为 `{school_ids}`，`publish_target = {type:'all', class_ids:[], school_ids:[...]}`；重新生成必须重新发布。证据：`AIXUE/deploy/teacher/routes_course.py:711-810`、`AIXUE/deploy/shared/models.py:730-766,800-829,944-946`、`AIXUE/docs/coursework_management/课程管理模块设计与接口文档.md:12-22`。
- **目录与小节**：新主流为 `qb_folders(parent_id)` 自关联树 + `courseware.qb_folder_id` 挂**叶子 folder**；生成时 `sub_index` 可产出单子节独立页，页内目录 `data-page` → `showPage()` 跳转，句子级 `data-audio` 局部播放，教师/管理端 `unlock=1` 解锁全部目录。证据：`AIXUE/docs/课程管理_题目录入_MongoDB数据模型分析.md:43-92`、`AIXUE/分页改造方案.md:7-36,102-107`、`AIXUE/deploy/subjects/general.py:1066-1081`。
- **任务表**：`tasks` 含 `school_id / class_id / teacher_id / subject_id / grade_key / chapter_index / sub_index / type(1课件学习…) / status / start_at / end_at`，按「章 + 节」定位课件学习任务。证据：`AIXUE/docs/database/nankai_sys_test_数据库表结构全记录.md:851-869`。
- **不可直接迁移**：Python TPL 渲染内核、按学科分库 Mongo（9 个物理库）、`/pages` `/htmlPublish` 多前缀静态挂载与 nginx `sub_filter` 改写、静态页无鉴权靠 `session.js` 注入 token、原生单页编辑器、uni-app `web-view`、TTS 双厂商。

### 2.2 `JLZK`：发布授权与按小节布置（可借鉴「状态机与任务模型」）

- **两套体系必须区分**：设计态（`docs/architecture.md`、`database/mysql/01_schema.sql`、`database/mongodb/collections.md`，部分接口标 `⏳` 未实现、写成 React）与运行态（FastAPI + MySQL + 按学科分库 Mongo + Vue3/uni-app）。**运行态为实现依据**；设计态的 `coursewares` 元数据仅作字段命名参考，不作为已实现接口依据。

  6. 顺序由 `assignment_group_id`（服务端生成，标识「一次布置」，同次布置的多行共享）+ `display_order`（组内次序）承载，**两列随 `V31` 一次建成**；一次布置 POST 携带**有序 `sectionIds` 数组**，服务端按数组下标从 1 起写 `display_order`，**请求体不携带顺序值**（唯一真相源为数组顺序）；整份布置 `display_order=0`。学生端按 `assignment_group_id` 分组、组内按 `display_order` 升序渲染；顺序是**布置时快照**，课件小节排序变更 / 下架 / 重新生成 / 挂载变更均不改写。**`sectionIds` 是唯一选择表达**：空数组 = 整份布置（1 行 `section_id=NULL` + `display_order=0`），非空数组 = 选节布置（按数组顺序），两种形态互斥，**布置请求体只认 `sectionIds`，缺失该字段或携带其它布置形态字段一律拒绝且不落库**；非空数组元素须互不相同、属于该课件且该课件对教师可见（D21），校验失败整次布置不落库。
- **对后续文档的约束**：P3 PRD / 技术方案把「学习任务-知识讲解课件」写成业务称谓 + 菜单项，FR 只覆盖浏览、布置、阅读；验收不含成绩、提交、完成度，并含「无编辑 / 撤销端点」负向断言与「任意子集 / 乱序呈现」正向断言；总纲 V7.2 同步登记 D14 的 `courseware_assignment` 两列。

#### 4.3.1 一句话端到端链路

平台超管在 `/admin/platform-content`「平台内容」**按学科与教材定位**（仅作为 AI 生成上下文，此时尚未产生挂载行）→ 显式触发 AI 生成 JSON（产物只落 `DRAFT`，**不自动发布、不自动授权**）→ 人工核对 / 结构化编辑正文并**挂到 ≥1 个叶子小节**（草稿态允许 0 行挂载，C5）→ 通过四项发布前校验后点「发布」（`DRAFT → PUBLISHED`）→ **另一次操作**按学校集合点「授权」（写 `content_share_grant`）→ 被授权学校的教师 `t9001` 在 `/teacher/content`「教学内容」只读浏览、按课件内小节预览 → 选班级与时间窗、**勾选任意几个课件小节并可拖拽调整其顺序**后点「布置」（写 `courseware_assignment`，含 `assignment_group_id` / `display_order`）→ 该班学生 `20260001` 在 `/student/content`「学习内容」看到「学习任务-知识讲解课件」，并按教师指定顺序阅读。

#### 4.3.4 「学习任务-知识讲解课件」是什么、不是什么

- **是**：教师端 `/teacher/content` 的一个布置动作 + 学生端 `/student/content` 的一个阅读列表项的**业务称谓**，物理上就是 `courseware_assignment` 行 + 按选中 `courseware_section` 渲染的正文。
- **不是**：第四套任务闭环、新的学生任务主表、作业 / 考试 / 实验的新题型、需要作答与判分的学习活动、新的前端壳层。
- **按小节布置的白话（两条业务能力）**：
  - **只选某几个**：教师从课件小节列表勾选**任意不连续子集**（例：课件有 1–6 节，只勾 2、5、6 节），学生端**只**看到勾选的小节；选 N 节就写 N 行布置记录。
  - **打乱顺序**：教师在布置弹层里拖拽 / 上移下移调整所选小节次序（例：5 → 2 → 6），学生端按教师指定次序呈现，**不按课件原 `sort_order`**；次序存 `display_order`，是布置时快照。
  - **整份布置**：不勾选小节，学生端按课件原 `courseware_section.sort_order` 看到全部小节；**整份布置不支持打乱顺序**。
  - 学生端按 `assignment_group_id` 分组、组内按 `display_order` 升序渲染，按 `section_id` 读 `courseware_section.content_json`，不查 `content_mount`、不切静态页。
- **本期边界**：布置记录只新增与按班读取，不提供编辑 / 撤销 / 删除端点；下架课件不取消已布置（R11），误布置本期无单条收回入口（§6.4 非目标，后续如需撤销须独立立项）。

#### 4.3.5 五个动作的白话时序

| 动作 | 白话与数据变化 |
|---|---|
| 发布 | 四项校验通过后 `DRAFT → PUBLISHED`；**不写授权表**，所以发布完可以没有任何学校能用 |
| 授权 | 发布之后**另一次操作**，按学校集合增删 `content_share_grant` 行；可多次增删；取消授权只删授权行 |
| 下架 | `PUBLISHED → DRAFT` 置回、不新增第三态；只禁止**新浏览 / 新布置**，已布置记录继续可读 |
| 重新生成 | 先下架 → 重跑 AI 生成 / 人工编辑 → 保持 `DRAFT` → 重新发布；**只更新 `courseware_section.content_json` 与 `heading`，不删除 / 不重建小节行**（`section_id` 稳定）；已布置记录不改写，`display_order` 与分组不变，重新发布后学生按原顺序读到新正文 |
| 删除 | 有 `courseware_assignment` 引用时**禁止物理删除**（`40900` / HTTP 409），只可下架；无引用时删正文行、素材行与挂载行，并同事务清该课件全部授权行（D20） |

> **已布置记录为什么不校验 `status`（R11）**：课件不存正文快照、不建版本表。若学生端要求「必须是 `PUBLISHED` 才可读」，下架后就没有可读副本；因此学生端按 `courseware_id / section_id` 读 `courseware_section.content_json` **当前值**，与 `status`、授权状态、挂载状态解耦。三处同口径可用性判定只作用于「新浏览 / 新布置」。

## 5. 集成架构（唯一结论）

**单一 Java 后端 + MySQL，结构化 JSON 为唯一内容真相源，Vue3 组件渲染；不引入 Python 服务、不引入静态 HTML 产物、不引入 `sid` 票据。**

| 层 | 唯一结论 |
|---|---|
| 内容存储 | **正文唯一真相源为 `courseware_section.content_json`**（按小节分行，沿用 `AIXUE` 的 `paragraphs → sentences{text,narration,image,audio}` 协议）；`courseware` 只存 `title/subtitle/status/归属/发布信息`，**不设 `content_json` 列**，避免双源；富文本只放行白名单 class，图片/音频只存相对路径并指向 `courseware_asset` 行；MySQL 为唯一真相源 |
| 存储与容量 | **本期不引入 MongoDB**（§5.2）：正文只按小节整段读写、筛选走学科 / 教材 / 小节 / 授权等关系列，用不上文档库查询；发布门禁、删内容清 grant、一次布置多行写入都依赖单库事务。**现网 `TEXT` 在 MySQL 下仅 64KB**，故 `V31` 建 `content_json TEXT NOT NULL`，MySQL 侧用现有 `${mysqlOnly}` 占位符追加 `ALTER TABLE courseware_section MODIFY COLUMN content_json LONGTEXT NOT NULL;`（`LONGTEXT` 上限 4GB，实际受 `max_allowed_packet` 约束），H2 侧该行被 `--` 注释、保留 `TEXT`/CLOB；**只用四个双方言占位符、不新增占位符 / profile**。按小节分行是天然分片，图片 / 音频只存 `courseware_asset` 相对路径、不内联 base64；**服务端单节正文上限 1MB**，AI 生成与人工编辑保存都校验，超限失败不落库（R16 / R17） |
| AI 生成 | `CoursewareGenerationService` 用 JDK 21 `java.net.http.HttpClient` 调 OpenAI 兼容接口（**不新增第三方 SDK**）；配置 `app.courseware.ai.base-url/api-key/model/timeout-seconds=120`，`api-key` 走环境变量、prod 必填；**AI 只产 JSON**，服务端 schema 校验、解析失败最多重试 1 次、失败不落库；生成请求同步，不引入任务队列。**由平台超管在 `/admin/platform-content` 显式点「AI 生成」触发**，产物只落 `DRAFT` 草稿，**不自动发布、不自动授权**，必须经人工核对 / 结构化编辑 + 叶子挂载 + 发布前校验后才可发布（白话时序见 §4.3） |
| 渲染 | `courseware_section` 即业务小节，天然支持「列小节 / 选小节 / 只渲染选中页」，无需 `sub_index` 切片与 `showPage(n)`；本期只复用 `RENDER` 的 CSS 视觉规范与 **MathJax 3**（`static/vendor/mathjax/es5/tex-chtml.js`），翻页、目录、句子音频、公式排版用 Vue3 组件重写；**pdf.js 本期不引入**（留作后续文档类资料预览） |

### 5.1 数据模型映射（P1 一次建成，P2/P3 不再建表）

```text
subject (V30 已有)
  └─ textbook(global_subject_id → subject.id)                  平台级教材目录，一科 0..N
       └─ textbook_section(parent_id, sort_order)                叶子 = 无子行，不加 is_leaf
            └─ content_mount(content_type=COURSEWARE,
                             mount_type=TEXTBOOK_SECTION,
                             mount_target_id=叶子小节.id)
                 └─ courseware(owner_scope=PLATFORM,
                               owner_school_id NULL,
                               global_subject_id, school_subject_id NULL,
                               status, published_at)              不存正文
                      ├─ courseware_section(heading, sort_order,
                      │                     content_json)          TEXT/LONGTEXT，单节 ≤1MB
                      ├─ courseware_asset(kind, file_path, mime, size)  图片 / 音频
                      ├─ content_share_grant(content_type, content_id,
                      │                      school_id, granted_by)  发布后按学校集合授权
                      └─ courseware_assignment(school_id, courseware_id,
                                              section_id NULL=整份,
                                              assignment_group_id,        一次布置分组
                                              display_order,              组内次序，整份=0
                                              class_id, 时间窗, created_by,
                                              created_at)                 BaseEntity 审计列
```

`school_textbook`（学校启用教材）、`content_mount`、`content_share_grant`、`courseware_asset` 与 D20/D23/D24/D25 的约束（多态列不建外键、`owner_school_id` 不加 DB CHECK、挂载全量替换、跨归属 `40400`、学科无效 `40025`）一并落地；`courseware_assignment.school_id` 按 1B 范式非空并按校过滤。**`assignment_group_id` 与 `display_order` 均非空、随 `V31` 一次建成**；DB 唯一键 `(assignment_group_id, display_order)`；服务端按有序 `sectionIds` 数组下标生成 `display_order`（请求体不携带 `assignment_group_id` / `display_order` / 其它布置形态字段，唯一真相源为数组顺序），并校验同组 `section_id` 不重复、数组元素属于该课件**且该课件对教师可见（D21）**，不单独判定小节可见性，失败整次布置不落库；顺序为布置时快照，课件小节排序变更 / 重新生成均不改写。**`courseware_assignment` 继承 `BaseEntity`，`created_at` / `updated_at` 由 `common/model/BaseEntity.java` 审计列提供**，学生端组间按 `created_at` 倒序即以此列为依据。

**`content_json` 列类型与容量（写死，R16 / R17）**：`V31` 先 `CREATE TABLE courseware_section (... content_json TEXT NOT NULL ...)`（双方言通用），紧接一行 `${mysqlOnly}ALTER TABLE courseware_section MODIFY COLUMN content_json LONGTEXT NOT NULL;` —— MySQL 侧展开为有效 DDL（`LONGTEXT` 上限 4GB，实际受 `max_allowed_packet` 约束），H2 侧变成 `--` 注释并保留 `TEXT`/CLOB。**MySQL `MODIFY COLUMN` 会重写整列定义，`NOT NULL` 必须显式带在 ALTER 上**，否则列被改回可空、与实体 `nullable = false` 冲突。现网 `V1` / `V6` / `V9` 的 `*_json` 都是 `TEXT`，本方案只对课件正文扩容、不改动历史表。四个占位符的值由 `common/config/FlywayPlaceholdersConfig.java:29-55` 按 `DataSource` 产品名注入（`mysqlOnly`：MySQL `""` / H2 `--`），按 `backend-db-and-config.mdc` §2.3 **不新增第五个占位符、不新增 profile、不在 `application*.yml` 声明占位符**。**实体侧写死 `private String contentJson;` + `@Column(name = "content_json", nullable = false, columnDefinition = "TEXT")`**（沿用现网 `LabStepAnswer.java:24` 等 `TEXT` 惯例，不把 MySQL 专有 `LONGTEXT` 写进 JPA 元数据）；P1 在 MySQL（`ddl-auto=validate`）与 H2（路径 B 文件库 / UT mem，`none` + Flyway）双库实测用于**验证这一已写死结论**，若校验不通过须按流程先修订本方案，不在编码阶段自行改注解。服务端对 `content_json` 设单节 **1MB = 1,048,576 字节上限（按 UTF-8 字节数计，恰好等于放行、超出即拒绝）**：AI 生成走既有「schema 校验失败最多重试 1 次、失败不落库」，人工编辑保存同样校验；`LONGTEXT` 的 4GB 只是 DB 容量，真实可用还受 `max_allowed_packet` 与 JSON 请求体限制约束，二者与 `spring.servlet.multipart` 的 50MB/100MB 上传配额不是同一层配置。按小节分行是天然分片，图片 / 音频只存 `courseware_asset` 相对路径、不内联 base64。
