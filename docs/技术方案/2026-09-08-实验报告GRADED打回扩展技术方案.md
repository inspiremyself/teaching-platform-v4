## 1. 背景与诉求

### 1.1 问题场景

教师在 `LabReports.vue` 批改队列中遇到如下记录：

- 提交状态显示 **已批改**（`GRADED`）
- 当前总分 **0**（或任意已评分数）
- 提交时间与批改时间相同（**自动评完**时常见）

教师希望将该报告打回，让学生修改作答后重新提交。父方案仅支持 `SUBMITTED` 打回，此场景无「打回」按钮，接口亦返回 400。

### 1.2 根因

`submitLab` → `refreshSubmissionAfterScoring`：当**全部**实验步骤均有作答记录且均有 `score`（含 0 分）时，同一事务内状态升为 `GRADED` 并 `upsertScoreRecord`；教师刷新 `LabReports` 队列时通常直接看到「已批改」，而非停留在「已提交」。

### 1.3 设计结论（一句话）

扩展 `returnReport`：在 `SUBMITTED` 与 `GRADED` 两种起始状态下，统一打回至 `SAVED`；`GRADED` 打回时额外删除 `score_record`，其余数据清理与父方案一致。

---

## 2. 目标与非目标

### 2.1 目标

1. 教师可对批改队列中 **`SUBMITTED` 或 `GRADED`** 的单条报告执行打回。
2. `GRADED` 打回后，学生端恢复可编辑；`GET /api/v1/analysis/my-scores` 中该实验条目消失；`GET /api/v1/analysis/my-score-overview` 的 `avgScore`、`completedItems` 回落，且 `groupedScores` 中 `LAB` 项的 `scoreCount` 减 1、`avgScore` 重算，直至再次提交并评完写入 `score_record`。
3. `SUBMITTED` 打回行为与父方案已交付实现保持一致（回归不变）。
4. 打回后教师队列该行变为「已保存」，优先级标签由「已完成」/「优先批改」变为「草稿跟进」。

### 2.2 非目标

- 不区分「自动评完」与「教师手工评完」的 `GRADED`（方案 A：全部 `GRADED` 可打回）。
- 不支持批量打回、详情页/总览页新增打回入口。
- 不记录打回原因、不向学生推送通知。
- 不改造 `refreshSubmissionAfterScoring` 的自动升 `GRADED` 逻辑。

## 3. 状态与数据变更

### 3.1 状态流转（扩展后）

```text
                         submitLab
SAVED ─────────────────────────────► SUBMITTED ──gradeReport / allScored──► GRADED
  ▲                                       │                                    │
  │                                       │                                    │
  └──────────── returnReport ◄────────────┴────────────────────────────────────┘
              （起始状态 SUBMITTED 或 GRADED，目标状态均为 SAVED）
```

### 3.2 `experiment_submission`（`LabSubmission`）字段变更

| 字段 | 打回前（`SUBMITTED`） | 打回前（`GRADED`） | 打回后（`SAVED`） |
|------|----------------------|-------------------|-------------------|
| `submit_status` | `SUBMITTED` | `GRADED` | `SAVED` |
| `submitted_at` | 有值 | 有值 | `null` |
| `graded_at` | `null` | 有值 | `null` |
| `total_score` | 可能有分 | 有分（含 0） | `0` |
| `teacher_comment` | 通常空 | 可能有评语 | `''` |
| `summary_text` | 保留 | 保留 | **不变** |
| `summary_attachment_path` | 保留 | 保留 | **不变** |

### 3.3 `experiment_answer`（`LabStepAnswer`）

与父方案 §3.3 **完全相同**：清空全部评分相关字段，保留作答内容与 `score_source = "TEACHER"`。

> **教师手工评过的分**：`GRADED` 打回时与自动评分字段一并清空，不保留单步人工分（与父方案对 `confirmStepScore` 残留的处理一致）。

### 3.4 `score_record`

| 打回前状态 | 处理 |
|------------|------|
| `SUBMITTED` | **不触及**（通常无记录） |
| `GRADED` | **删除** `findByBusinessTypeAndBusinessIdAndStudentId(LAB, labId, studentId)` 命中行；`Optional` 为空则 no-op |

删除时机：在 `labStepAnswerRepository.saveAll(answers)` 之后、`submission.setSubmittedAt(null)` 之前执行（与 §5.1 代码顺序一致）。

再次 `submitLab` 且升 `GRADED` 时，现有 `upsertScoreRecord` 会重新创建或覆盖记录。

### 3.5 实验状态前置条件

与父方案 §3.4 **完全相同**（仅 `PUBLISHED` 允许打回）。

### 3.6 不打回的数据

与父方案 §3.5 **完全相同**（`experiment_answer_log`、磁盘答题图保留）。

## 4. API 设计

### 4.1 打回实验报告

**`POST /api/v1/teacher/lab-reports/{id}/return`**

- **角色**：`TEACHER`
- **路径参数**：`id` = `LabSubmission.id`
- **请求体**：无
- **成功响应** `200`：与父方案相同

```json
{
  "code": 0,
  "message": "OK",
  "data": {
    "submissionId": 3001,
    "status": "SAVED",
    "labId": 1001,
    "studentId": 2
  },
  "timestamp": "2026-09-08T10:00:00+08:00"
}
```

### 4.2 错误码

| 场景 | HTTP | code | message |
|------|------|------|---------|
| 报告不存在 | 404 | 40400 | 实验报告不存在 |
| 实验非当前教师创建 | 403 | 40300 | 无权限访问该实验 |
| 班级非当前教师 | 403 | 40300 | 无权限访问该班级 |
| 状态为 `SAVED` | 400 | 40000 | 仅已提交或已批改的报告可打回 |
| 重复打回（已为 `SAVED`） | 400 | 40000 | 仅已提交或已批改的报告可打回 |
| 实验已关闭 | 400 | 40000 | 实验已关闭，不能打回 |
| 实验未发布（`DRAFT`） | 400 | 40000 | 实验未发布，不能打回 |

> `SUBMITTED` 与 `GRADED` 均允许打回；`SAVED` 与重复打回命中同一 400 文案，不单独区分。

### 4.3 权限

与父方案 §4.3 **完全相同**（`ownedLab` 双校验）。

## 5. 后端实现要点

### 5.1 修改 `LabService.returnReport`

同步更新方法 JavaDoc：说明起始状态为 `SUBMITTED` 或 `GRADED`；`GRADED` 时删除 `score_record`。

将状态校验由：

```java
if (submission.getSubmitStatus() != SubmissionStatus.SUBMITTED) {
    throw new BusinessException(40000, "仅已提交且未批改完成的报告可打回");
}
```

改为：

```java
SubmissionStatus status = submission.getSubmitStatus();
if (status != SubmissionStatus.SUBMITTED && status != SubmissionStatus.GRADED) {
    throw new BusinessException(40000, "仅已提交或已批改的报告可打回");
}
boolean wasGraded = status == SubmissionStatus.GRADED;
```

在清空答案评分字段的 `saveAll` 之后、`submission.setSubmittedAt(null)` 之前，若 `wasGraded`：

```java
if (wasGraded) {
    scoreRecordRepository
        .findByBusinessTypeAndBusinessIdAndStudentId(
            BusinessType.LAB, lab.getId(), submission.getStudentId())
        .ifPresent(scoreRecordRepository::delete);
}
```

完整执行顺序（与现网 `returnReport` 对齐，仅插入 `wasGraded` 分支）：

1. 权限与实验状态校验（不变）
2. 状态校验 → 得到 `wasGraded`
3. 清空全部 `LabStepAnswer` 评分字段 → `saveAll`
4. **`wasGraded` 时删除 `ScoreRecord`**
5. `submission.setSubmittedAt(null)`、`setTeacherComment("")`
6. `refreshSavedSubmissionAfterScoring(submission)`
7. 返回 Map（不变）

### 5.2 Controller

**无改动**（复用现有 `POST .../return`）。

### 5.3 DTO

**无新增**。

  status === 'GRADED'

    : '打回后学生可修改作答并重新提交，是否继续？';

// handleReturn 内：
await ElMessageBox.confirm(returnConfirmMessage(row.submitStatus), '打回确认', { type: 'warning' });
