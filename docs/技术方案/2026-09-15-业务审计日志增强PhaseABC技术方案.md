# 业务审计日志（`audit_log`）增强 — Phase A / B / C 技术方案

**创建日期**：2026-09-15  
**状态**：已定稿（决策写死，可直接编码）  
**范围**：在现网 `audit_log` + `AuditLogService` 基础上，分三期交付 **覆盖补全（A）**、**可关联与模型（B）**、**校管消费与保留（C）**；与 `http_access_log` **职责分离、并存**  
**非目标（全文）**：教学域（实验/作业/考试/资料/查重）批量接入 audit、平台超管跨校审计、`audit_log` 异步写库、Body 落库、ELK/Loki、教师端操作日志 UI、`GET /api/v1/admin/access-logs`（归属 HTTP 访问日志方案 Phase 2，本方案不实现）

## 1. 背景

现网仅有零散手写审计（校管组织、登录、题库部分写操作），存在 **漏写**、**无 `school_id` 校管范围查询**、**无法与 HTTP `X-Trace-Id` 关联**、**无校管 UI/API** 等问题。HTTP 访问日志 Phase 1 已（或并行）补齐「全接口轨迹」，本方案补齐 **业务审计链路的 A/B/C**，与 [HTTP 访问日志统一落库基础能力技术方案](./2026-09-15-HTTP访问日志统一落库基础能力技术方案.md) 互补。

---

## 2. 架构

```text
HTTP Request
  → HttpAccessLogFilter          （set RequestTraceContext；写 http_access_log）
  → JwtAuthenticationFilter → Controller → Service
       → AuditLogService.log*     （读 RequestTraceContext；同步写 audit_log）

Phase C:
  SCHOOL_ADMIN → GET /api/v1/admin/audit-logs → AdminAuditLogQueryService（school 范围）
  AuditLogRetentionJob           （按 retention-days 清理 audit_log）
```

**不**将 GET 列表、批改、学生作答写入 `audit_log`（非目标）。

## 3. Phase A — 覆盖补全与枚举契约

### 3.1 枚举（唯一 action / resource 来源）

包路径：**`com.opencode.teachingplatform.common.audit`**

**`AuditAction`**（持久化值为 `enum.name()`）须包含现网全部 action 及本期新增：

| 分类 | 枚举常量 |
|------|----------|
| 认证 | `LOGIN_SUCCESS`, `LOGIN_FAILURE`, `LOGOUT`, `SESSION_INVALIDATED`, `PROFILE_UPDATED`, `PASSWORD_CHANGED`, `PASSWORD_CHANGE_FAILED` |
| 组织 | `SCHOOL_UPDATE`, `TEACHER_CREATE`, `TEACHER_UPDATE`, `TEACHER_STATUS`, `CLASS_CREATE`, `CLASS_UPDATE`, `CLASS_DELETE`, `STUDENT_CREATE`, `STUDENT_UPDATE`, `STUDENT_STATUS`, `STUDENT_IMPORT`, `SUBJECT_CREATE`, `SUBJECT_UPDATE`, `SUBJECT_STATUS` |
| 题库 | `QUESTION_CREATE`, `QUESTION_UPDATE`, `QUESTION_DELETE` |

**`AuditResourceType`**：`USER`, `SCHOOL`, `TEACHER`, `CLASS`, `STUDENT`, `SUBJECT`, `QUESTION`。

### 3.2 调用点变更（写死）

| 类 / 方法 | 动作 |
|-----------|------|
| `AuthService.login` | 成功：**`logSecurity`** → `LOGIN_SUCCESS`，`userId/schoolId` = `saved`，`actorRole` = `saved.getRole().name()`，`resourceType` = `USER`，`resourceId` = `saved.getId()`，detail **`role`, `forceLogin`** |
| `AuthService.login` | 失败：**每次** `throw` 前 **`logSecurity(LOGIN_FAILURE)`**，`resourceType` = **`USER`**，`resourceId` = 已匹配用户 id 或 **NULL**（见 §3.3），detail **`username`（trim）、`role`（请求体）**，**禁止** password |
| `AuthService.login` → `handleExistingActiveSession` | `forceLogin=true` 且旧 session 置 **`KICKED`** 并 `save` 后：**`logSecurity(SESSION_INVALIDATED)`**，`userId` = `existingSession.getUser().getId()`，`schoolId` 取自该用户，`actorRole` = 该用户 **`role.name()`**，`resourceType` = `USER`，`resourceId` = 同上 |
| `AuthService.logout` / `updateProfile` / `changePassword`（成功） | **`log(CurrentUser, …)`** → 分别 `LOGOUT` / `PROFILE_UPDATED` / `PASSWORD_CHANGED`，`resourceType` = `USER` |
| `AuthService.changePassword` | 旧密码错：**`log(CurrentUser, PASSWORD_CHANGE_FAILED, …)`** 后 `throw` |
| `QuestionService.delete` | 删除前：`QUESTION_DELETE`，`resourceId` = 题目 id，detail **`code`** |
| `AdminStudentService.updateStudent` | 保存后：`STUDENT_UPDATE`，detail **`displayName`, `classId`** |
| `AdminStudentService.changeStatus` | 保存后：`STUDENT_STATUS`，detail **`status`** |
| `AdminClassService.updateClass` | 替换 teachers 后：`CLASS_UPDATE`，detail **`name`, `status`, `teacherCount`** |
| 其余已有 `auditLogService.log` | 改为 enum + `CurrentUser` 重载，action/resource 与上表一致 |

**`logSecurity(SecurityAuditEvent event)`**（**`record`**，字段写死）：`AuditAction action`、`Long userId`（可空）、`Long schoolId`（可空）、**`String actorRole`（可空）**、`AuditResourceType resourceType`、`Long resourceId`（可空）、`Map<String,Object> detail`；用于无 **`CurrentUser`** 场景；**`LOGIN_SUCCESS`/`SESSION_INVALIDATED` 必须传 `actorRole`**；**`LOGIN_FAILURE` 不传 `actorRole`**；仍填充 trace/ip（Phase B 起）。

### 3.3 LOGIN_FAILURE 与 `user_id`

| 失败原因 | `user_id` | `school_id` |
|----------|-----------|-------------|
| 用户名+角色不存在 | **NULL** | **NULL** |
| 用户存在但非 ACTIVE 或密码错误 | **该用户 id** | **该用户 school_id** |

## 4. Phase B — 数据模型与 trace 关联

### 4.1 V18 迁移（写死）

```sql
ALTER TABLE audit_log MODIFY COLUMN user_id BIGINT NULL;

ALTER TABLE audit_log ADD COLUMN school_id BIGINT NULL;
ALTER TABLE audit_log ADD COLUMN actor_role VARCHAR(32) NULL;
ALTER TABLE audit_log ADD COLUMN trace_id VARCHAR(36) NULL;
ALTER TABLE audit_log ADD COLUMN client_ip VARCHAR(64) NULL;

UPDATE audit_log
SET school_id = (SELECT u.school_id FROM sys_user u WHERE u.id = audit_log.user_id),
    actor_role = (SELECT u.role FROM sys_user u WHERE u.id = audit_log.user_id)
WHERE user_id IS NOT NULL;

CREATE INDEX idx_audit_log_school_created ON audit_log (school_id, created_at);
CREATE INDEX idx_audit_log_action_created ON audit_log (action, created_at);
CREATE INDEX idx_audit_log_trace_id ON audit_log (trace_id);
```

实体 **`AuditLog`** 同步新增字段；`user_id` 映射为 **nullable**。V18 **不使用** `AFTER` 子句（与现网迁移一致，兼容 H2 UT）；历史回填用 **相关子查询 `UPDATE`**（语义同 `JOIN sys_user`，H2 `MODE=MySQL` UT 与 MySQL 双兼容），**禁止**单条 `ALTER` 多列 `ADD`（H2 UT 不支持）。

### 4.2 `RequestTraceContext`

- 类路径：**`com.opencode.teachingplatform.common.trace.RequestTraceContext`**
- API：`set(String traceId, String clientIp)`、`getTraceId()`、`getClientIp()`、`clear()`
- **仅** `HttpAccessLogFilter` 在 `enabled=true` 且 URI 以 `/api/v1` 开头且非 OPTIONS 的分支内使用（与 access log 覆盖规则一致）

### 4.3 `HttpAccessLogFilter` 改动

在现有 `traceId = UUID…` 之后、 `try { doFilter }` 之前调用 **`RequestTraceContext.set(traceId, resolveClientIp(request))`**；在 `finally` 中 **`httpAccessLogService.submit` 之后** 调用 **`RequestTraceContext.clear()`**。

### 4.4 `AuditLogService` 行为

- **`log(CurrentUser actor, AuditAction action, AuditResourceType resourceType, Long resourceId, Map<String, Object> detail)`**  
  写入：`user_id=actor.id()`, `school_id=actor.schoolId()`, `actor_role=actor.role().name()`, action/resource 枚举名，trace/ip 来自 context。
- **`logSecurity(SecurityAuditEvent event)`**  
  写入 event 中 `userId`/`schoolId`/`actorRole`（均可空，规则见 §3.2 record 说明）；登录失败 **不写** `actorRole`。
- JSON 失败：**不抛**；`detail_json = null` + error log。

**否决**：audit 异步写库（与「审计与业务同事务」冲突，见附录）。

## 8. 验收标准

### Phase A

1. 校管更新学生 / 启停 / 班级更新 / 删题后，SQL 可查对应 **action** 行。
2. 故意错误登录产生 **`LOGIN_FAILURE`**；`forceLogin` 踢下线产生 **`SESSION_INVALIDATED`**。

### Phase B

1. 任意 `/api/v1` 写操作 audit 行 **`trace_id`** 与同请求 **`X-Trace-Id`** 一致（抽样 2 个接口）。
2. 历史行 V18 回填后 **`school_id`** 与 `sys_user` 一致。

### Phase C

1. 校管登录 → **操作日志** 页可见分页列表，筛 action 生效。
2. **`AuditLogRetentionJob` 单元/集成测试**：插入 `created_at` 为 **31 天前** 的行，`retention-days=30`，调用 `purgeExpired()` 后该行消失、7 天前行仍在。
3. `cd backend && ./mvnw test` 中本方案新增/修改测试类全绿；`cd frontend && npm run build` 通过。
