- **日期**：2026-10-28
- **状态**：已定稿（决策写死，可直接编码）
- **范围**：学生端实验作答行为采集（后端事件表 + 接收接口 + 前端采集器）+ 行为指标聚合与风险标记 + 教师端批改队列 / 报告详情 / 提交总览三处展示增强
- **性质**：**新增 2 张独立表（V19/V20），不修改任何现有业务表结构**；AI 自动判分（P2）不在本方案范围，但本方案产出的展示位与数据链路是 P2 的承载基础
- **前置共识**（2026-10-28 调研结论）：行为数据走"审计日志式"独立采集、字段可扩展（payload JSON）、不落业务表；LLM 供应商已定 DeepSeek（P2 用）；判分架构沿用现有策略模式（`ScoringEngine` + `QuestionScoringStrategy`）

## 1. 背景与问题

为期末综合评分与反作弊建设数据基础，当前存在两个缺口：

1. **无作答过程数据**：`experiment_submission` 只有 `submittedAt`，没有"开始作答时间"，算不出作答时长；无粘贴、切屏、逐题停留等行为数据。
2. **教师端无行为展示位**：批改队列（`LabReports.vue`）只有提交状态/总分/时间，教师无法识别"3 分钟交卷""大段粘贴"等异常作答。

**现状资产盘点（可复用，不重造）**：

| 资产 | 位置 | 复用方式 |
|---|---|---|
| 答案快照日志 | `lab_step_answer_log`（V10），每次保存答案追加 `(answerId, content, fillTime)` | **保存次数/保存时间线直接复用，不上报重复事件**；最早 `fillTime` 是"开始作答时间"的候选源 |
| 自动保存 | `LabSteps.vue` 已有 1200ms 防抖静默保存 + 切题保存 + 提交前保存 | 采集器挂载点现成 |
| 审计字段范式 | `audit_log`（`user_id/school_id/actor_role/action/detail_json/trace_id/client_ip`，V18 增强） | 新事件表沿用同样的审计维度列，但**不复用该表**（见 D1） |
| 分页/筛选先例 | `listTeacherReports` 已用 Specification + 内存命中集混合策略（见批改队列分页方案 D2） | riskLevel 筛选沿用同构模式 |
| 批量行映射 | `toReportListViews(List)`（分页/queue 共用唯一实现） | 扩展字段只改这一处 |
| 双方言迁移 | `${alterModifyColumn}` 占位符机制（V18 在用） | V19/V20 沿用 |

**为什么不能只靠 `lab_step_answer_log`**：它只在"内容变化触发保存"时产生，覆盖不了进入页面、粘贴未改内容、切屏、停留时长这类无保存行为；且快照 content 是大文本，不适合当行为事件表用。

## 3. 决策清单

| # | 决策 | 已否决方案（原因） | 选择理由 |
|---|---|---|---|
| D1 | **新建独立 `behavior_event` 表**，不复用 `audit_log`。列：`id/event_uuid/biz_type/event_type/occurred_at/received_at/student_id/lab_id/submission_id/step_id/payload_json/school_id/client_ip/trace_id`；可扩展字段一律进 `payload_json` | 复用 `audit_log`（面向管理操作、手动逐条写入、`action` 枚举收口、`resource_id` 单值无法同时定位 step；高频行为事件会污染管理审计查询） | 用户既定方向"审计日志式、字段可扩展、不用业务表"；高频批量写与管理审计低频单写是两种负载；payload JSON 承载扩展字段 |
| D2 | **答案保存不产生行为事件**：保存次数/保存时间线从 `lab_step_answer_log` 聚合 | 前端上报 SAVE 事件（与 V10 日志双写，口径必然漂移） | 单一事实源；指标装配时两源合并 |
| D3 | 事件目录 P0 写死 11 类：`LAB_ENTER / LAB_LEAVE / STEP_VIEW / PASTE / VISIBILITY / WINDOW_BLUR / WINDOW_FOCUS / HEARTBEAT / SUBMIT_CLICK / SUBMIT_BLOCKED / SAVE_FAILED`（见 §4.2） | 只采集进入+提交（时长口径靠首尾事件，中间离开/挂机等噪声无法剔除）；逐键击采集（量噪比极低） | 覆盖"时长/粘贴/专注度/提交流程"四大指标族；HEARTBEAT 是活跃时长的主数据源 |
| D4 | **批量上报 + 幂等**：`POST /student/labs/{labId}/behavior-events`，body 为事件数组，每批 ≤100 条、单条 payload ≤4KB；`event_uuid` 全表唯一，重复 uuid 丢弃并计入 `dropped` | 逐条实时上报（请求数爆炸）；仅内存队列不去重（重试产生重复） | 前端缓冲批量发送 + 失败重试必须配幂等键 |
| D5 | 事件归属键 = **`(biz_type, lab_id, student_id)`**，`submission_id` 仅冗余可空 | 以 `submission_id` 为归属键（`LAB_ENTER` 时 submission 可能尚未创建，关联丢失） | `lab_step_answer_log` 路径证明首次保存才创建 submission；归属键必须在首次保存前就成立 |
| D6 | 时钟口径：`occurred_at` 为客户端时间；服务端容差 ±10min，超差以 `received_at` 替代并在 payload 追加 `clockAdjusted:true`；时长计算对负差截断为 0 | 服务端收到时间当发生时间（批量缓冲导致全部偏移） | 学生机时钟不可信但多数准确；容差+兜底即可 |
| D7 | **指标预聚合表 `lab_submission_metrics`**（`submission_id` 主键），指标+风险标记落库，不每次现算；`event_watermark` 记录已计入的最大事件 id | 列表页逐行现算（N 次事件表聚合 = 新型 N+1）；Redis 缓存（重启丢、无审计性） | 列表页每页 100 行需要批量读；落库结果可被 P3/P4 直接复用 |
| D8 | 指标计算触发时机写死 2 个：① `submitLab` 成功后同步全量算一次（外层写事务内，REQUIRED）；② 教师列表/详情读取时**懒算**：当前页 metrics 缺失或 `event_watermark` 落后的行，按 `(labId, studentId)` 批量重算。**懒算写库必须经 `LabBehaviorMetricsService.refreshStaleMetrics(...)`（`@Transactional(propagation = REQUIRES_NEW)`）**：`listTeacherReports`/`listTeacherReportQueue`/`getSubmissionOverview` 均为 `@Transactional(readOnly = true)`，在其中直接写 metrics 会静默失败；且重算结果**直接以内存对象返回装配，不在外层 readOnly 事务里重查库**（MySQL RR 快照下重查读不到内层新提交） | 定时任务全量刷（无需求且引入调度复杂度）；事件写入时实时增量维护（写入路径变重，规则变更无法回放）；去掉 readOnly（改变现有查询事务语义，影响面大） | 提交时是唯一必然事件；懒算覆盖 SAVED 行与迟到事件；REQUIRES_NEW + 内存返回同时解决只读事务写入与可重复读快照两个坑 |
| D9 | 风险规则 P1 只做 **3 条规则 + 标记展示**，阈值全局配置（`application.yml` 的 `lab.behavior.risk.*`），不合成处分、不自动扣分：`DURATION_TOO_SHORT`（总时长 < 题项数×45s）、`PASTE_HEAVY`（粘贴字符 >500 且粘贴/终稿字符 >0.3）、`FOCUS_LOSS`（切屏 ≥5 次或隐藏时长占比 >50%）；无事件行打 `NO_BEHAVIOR_DATA`（不提升等级）；riskScore=权重和（40/30/20），LOW<30 / MEDIUM 30-59 / HIGH ≥60 | 机器学习异常检测（无数据基础，P0 正是为了积累数据）；硬编码阈值（不同实验强度差异大，必须可配） | 规则透明可解释，教师复核制，与"不自动处分"原则一致 |
| D10 | `riskLevel` 筛选下沉后端：教师域内先查 metrics 得命中 submissionId 集合，作为 Specification 的 `id IN` 谓词；`NONE` 语义写死 = **metrics 缺失 或 `risk_flags_json` 含 `NO_BEHAVIOR_DATA`**（懒算会为无事件行建 metrics，"无 metrics 行"随时间消失，NONE 不能只按缺失判定） | metrics 表 JOIN Specification（跨表 join 在双言下可读性差）；前端过滤（分页后失效，分页方案 D8 已否决过） | 与 keyword 筛选的"内存命中集"策略同构 |
| D11 | 行为详情接口独立：`GET /teacher/lab-reports/{submissionId}/behavior` 返回 metrics 全量 + 时间线（按 `occurred_at,id` 升序，截断 500 条 + `timelineTotal`） | 塞进报告详情响应（契约膨胀，Detail 页多数打开不看时间线） | 按需加载；独立接口便于 P3 复用 |
| D12 | 前端采集器独立模块 `utils/behaviorCollector.ts`：启动绑定 labId，队列缓冲，**5s 或满 20 条**批量发送；正常发送走 `request.ts`（统一鉴权/拦截）；`beforeunload`/`visibilitychange→hidden` 兜底用 **`fetch(url, {method:'POST', keepalive:true, headers: 带鉴权})`**，**不使用 `navigator.sendBeacon`**（sendBeacon 无法带自定义 Authorization 头，会造出无鉴权写入通道）；失败指数退避重试 ≤3 次（同一 uuid） | 各组件自行 fetch（重复代码、无缓冲）；WebSocket（无实时性需求）；sendBeacon（无鉴权头） | 单一采集器；keepalive fetch 在页面卸载场景与 sendBeacon 等效且鉴权完整 |
| D13 | 埋点挂载：只在 `LabSteps.vue` 作答会话内激活（进入启动/离开销毁）；PASTE 在编辑器**外层容器** `@paste` 捕获（读 `clipboardData` 文本长度），不改动 `TextAnswerEditor`/`CodeAnswerEditor` 内部；**`blocked` 不由前端判定——前端只报 `pastedLength/fieldKind`，服务端 ingest 时按 `step.allowPaste` 回填 `blocked` 进 `payload_json`**（客户端不可信，且前端无需消费 allowPaste）；`allowPaste=false` 的题本期**不硬拦截**，仅记录 | 改编辑器组件内部（侵入共用组件，影响作业/考试场景）；前端判定 blocked（客户端数据不可信）；本期硬拦截粘贴（产品策略变更，超出 P0 范围） | 采集与作答组件解耦；先采数后定管控策略 |
| D14 | 展示列写死：批改队列新增「作答时长 / 活跃时长 / 保存次数 / 粘贴(次数·字符) / 切屏(次数·时长) / 风险」6 列 + riskLevel 筛选；SAVED 行时长后缀 `*` 表示"截至最近事件"口径；无数据行显示 `-` 且风险列灰显"无数据" | 只加风险一列（指标不可解释，教师无法复核）；全部塞详情页（队列页失去筛查价值） | 队列页承担"快速筛查"，详情页承担"复核取证" |
| D15 | 提交总览页（`getTeacherLabSubmissionOverview` 数据源）每学生加「时长/粘贴/风险」3 列，metrics 批量装配与批改队列共用同一私有方法 | Overview 页不改（班级维度的异常分布看不到）；Overview 用独立装配逻辑（口径漂移） | 共用装配方法是防漂移的唯一手段 |
| D16 | 权限：学生端 `requireStudent` + `accessiblePublishedLab`；实验已 CLOSED 后**拒收**新事件（返回 `dropped` 计数）；教师端 `requireTeacher` + submission 归属实验必须 `createdBy = currentUser` | 提交后拒收（LAB_LEAVE/心跳尾部数据丢失）；任何教师可读（越权） | 沿用现有权限口径；拒收时机与作答锁定一致 |
| D17 | 三个鲁棒性补充（2026-10-28 场景质询补入）：① metrics 增加 **`session_count`**（`LAB_ENTER` 计数，断续作答会话数），活跃时长列展示格式 `60min · 2次`；② **浏览器直接关闭时 Vue `onBeforeUnmount` 不执行**，`LAB_LEAVE{reason:"unload"}` 与末段不满 60s 的尾部心跳由采集器 `beforeunload` 钩子内部补发（不依赖组件生命周期）；③ `uploadAnswerImage` 保存答案后**追加 `appendAnswerSnapshot`**，快照口径统一为"每次服务端确认的答案变更"，图片上传场景不再少计保存次数 | 依赖组件 onBeforeUnmount 发 LAB_LEAVE（直接关浏览器时丢失）；图片上传不写快照（"先答题后统一传图"场景保存次数失真）；会话数不加列（断续作答这一常见正向信号在队列页不可见） | 直接关浏览器与统一传图均为真实高频场景，采集完整性优先 |

## 4. 数据库迁移

> 双方言：沿用 V18 的占位符机制；两张新表 DDL 均使用 MySQL/H2 兼容语法（`AUTO_INCREMENT`+`TIMESTAMP`+`TEXT`，与 V10 已验证的写法同构），**不需要占位符分支**。

### 4.1 `V19__behavior_event.sql`（新增）

```sql
CREATE TABLE behavior_event (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  event_uuid VARCHAR(36) NOT NULL,
  biz_type VARCHAR(16) NOT NULL DEFAULT 'LAB',
  event_type VARCHAR(32) NOT NULL,
  occurred_at TIMESTAMP NOT NULL,
  received_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  student_id BIGINT NOT NULL,
  lab_id BIGINT NOT NULL,
  submission_id BIGINT NULL,
  step_id BIGINT NULL,
  payload_json TEXT NULL,
  school_id BIGINT NULL,
  client_ip VARCHAR(64) NULL,
  trace_id VARCHAR(36) NULL,
  CONSTRAINT uk_behavior_event_uuid UNIQUE (event_uuid)
);
CREATE INDEX idx_behavior_event_biz_lab_student ON behavior_event (biz_type, lab_id, student_id, id);
CREATE INDEX idx_behavior_event_submission ON behavior_event (submission_id);
CREATE INDEX idx_behavior_event_type_time ON behavior_event (event_type, occurred_at);
```

- 无外键：行为事件允许在 submission 创建前到达，且采集链路不能因业务行删除而级联丢数据。
- 容量估算：核心索引 `(biz_type, lab_id, student_id, id)` 支撑指标聚合按归属键顺序扫描。

### 4.2 事件目录（`event_type` 枚举 + payload 契约，写死）

| event_type | 触发时机 | payload 字段 |
|---|---|---|
| `LAB_ENTER` | 作答页 mounted | `{routeFrom?}` |
| `LAB_LEAVE` | 路由离开（组件 `onBeforeUnmount`）/ 浏览器直接关闭（采集器 `beforeunload` 钩子，不经组件生命周期，D17） | `{reason: "route"\|"unload"\|"submitted", lastStepId?, dwellMs?}` |
| `STEP_VIEW` | 当前题项切换 | `{stepId, fromStepId?, dwellMs?}`（dwellMs=上一题停留） |
| `PASTE` | 编辑器容器 paste | `{stepId, fieldKind:"TEXT"\|"CODE", pastedLength}`（`blocked` 由服务端按 `step.allowPaste` 回填，前端不传，D13） |
| `VISIBILITY` | visibilitychange | `{state:"hidden"\|"visible", hiddenMs?}`（visible 时带回本次隐藏时长） |
| `WINDOW_BLUR` | window blur | `{}` |
| `WINDOW_FOCUS` | window focus | `{blurMs}` |
| `HEARTBEAT` | 每 60s（页面可见时） | `{activeMs}`（自上次心跳的活跃毫秒数） |
| `SUBMIT_CLICK` | 点击提交按钮 | `{}` |
| `SUBMIT_BLOCKED` | 前端校验拦截提交 | `{reason:"no-saved-answer"\|"summary-required"\|"autosave-failed"}` |
| `SAVE_FAILED` | 保存接口失败 | `{stepId, silent}` |

> 事件类型枚举落后端 `BehaviorEventType`（String 存储，非法值该条丢弃计入 dropped，不整批失败）。

## 5. 接口定义

### 5.1 `POST /api/v1/student/labs/{labId}/behavior-events`（新增）

学生批量上报行为事件。`@PreAuthorize("hasRole('STUDENT')")`。

**Request**：

```json
{
  "events": [
    { "eventUuid": "3f6c...", "eventType": "STEP_VIEW", "occurredAt": "2026-10-28T10:01:02+08:00", "stepId": 123, "payload": {"fromStepId": 122, "dwellMs": 45000} }
  ]
}
```

**校验**（逐条执行，失败条目计入 dropped，**不整批 400**）：

| 规则 | 不满足时 |
|---|---|
| `events` 空 → `BusinessException(40000,"事件列表不能为空")`；长度 > `max-batch-size` → 整批 40000 | 整批失败 |
| `eventUuid` 非空 ≤36 字符、`eventType` 合法、`occurredAt` 可解析、payload JSON ≤ `max-payload-bytes` | 该条 dropped |
| `occurredAt` 与服务器时间偏差 > 容差 | 以 `received_at` 替代 + payload 追加 `clockAdjusted:true`，**仍接收** |
| uuid 已存在 | 该条 dropped（幂等） |

**业务校验**：`requireStudent` + `accessiblePublishedLab`；实验 `CLOSED` → 整批返回 `200 {accepted:0, dropped:n, closed:true}`（不抛异常，让前端停止上报）；`stepId` 非空时校验属于该实验，不属于则该条 dropped。

**Response**：`{"accepted": 18, "dropped": 2}`。写库时回填 `submission_id`（若该生该实验已存在 submission）、`school_id/client_ip/trace_id`（从 CurrentUser + 请求上下文取，与 AuditLogService 同源）。

### 5.2 `GET /api/v1/teacher/lab-reports`（扩展，契约不破坏）

- Query 新增 `riskLevel`（`LOW/MEDIUM/HIGH/NONE`，非法值按空结果处理，与 status 语义对齐；`NONE` = metrics 缺失或 flags 含 `NO_BEHAVIOR_DATA`，见 D10）。
- 行字段新增（追加，不改已有字段）：

```json
{ "behavior": { "totalDurationMs": 3720000, "activeDurationMs": 3400000, "durationOpen": false, "saveCount": 14, "pasteCount": 2, "pastedChars": 320, "hiddenCount": 1, "hiddenMs": 60000, "sessionCount": 2, "riskLevel": "LOW", "riskFlags": [] } }
```

`behavior` 在懒算后恒有值；`null` 仅作防御性兜底（如 metrics 写入失败），前端统一按 `riskFlags` 含 `NO_BEHAVIOR_DATA` 判定并灰显"无数据"tag，不依赖 `behavior === null`。`durationOpen:true` 表示 SAVED 行"截至最近事件"口径。`GET /teacher/lab-reports/queue` 行结构**同步扩展**（D15 同一装配方法）。

### 5.3 `GET /api/v1/teacher/lab-reports/{submissionId}/behavior`（新增）

教师查看单份报告的行为详情。`@PreAuthorize("hasRole('TEACHER')")` + ownedLab 校验。

```json
{
  "metrics": { "...": "§5.2 behavior 全字段 + stepDwellMs: {\"123\": 45000}, firstStartedAt, lastEventAt, computedAt" },
  "timeline": [ { "eventType": "PASTE", "occurredAt": "...", "stepId": 123, "payload": {"pastedLength": 300} } ],
  "timelineTotal": 132
}
```

`timeline` 按 `(occurred_at, id)` 升序、上限 500 条；`metrics: null` 时 `timeline` 仍返回（可能只有未聚合的迟到事件，先触发一次懒算再读）。

### 5.4 提交总览接口扩展

`GET /teacher/labs/{labId}/submission-overview`（现有）每学生行追加 `behavior` 摘要（同 §5.2 结构，可 null），由 D15 共用装配方法批量填充。

**`BehaviorIngestService.ingest(currentUser, labId, batch)`**：

```text
1. requireStudent；lab = accessiblePublishedLab(labId)
2. lab.status == CLOSED → return {accepted:0, dropped:events.size(), closed:true}
3. events 为空 → 40000；size > maxBatchSize → 40000
4. submission = labSubmissionRepository.findByLabIdAndStudentId(labId, user.id)  // 可空，回填用
5. 逐条校验（§5.1 表）→ 构造 BehaviorEvent：
   - uuid/类型/时间容差/payload 字节上限按 §5.1；stepId 非空时校验属于该实验
   - PASTE 条目：服务端回填 `payload.blocked = !step.allowPaste`（D13，客户端不传 blocked）
   - receivedAt 由代码显式 `OffsetDateTime.now()`（DB DEFAULT 仅为兜底）
   - schoolId 取 currentUser.schoolId()；traceId/clientIp 取 `RequestTraceContext.getTraceId()/getClientIp()`（与 AuditLogService 同源）
   - submission_id 回填（submission 存在时）
6. 去重：findByEventUuidIn(uuids) 过滤已存在；剩余 saveAll
   （并发极端下兜底 catch DataIntegrityViolationException → 该条按 dropped 计，不抛出）
7. return {accepted, dropped}
```

**`LabBehaviorMetricsService`**：

```text
computeForSubmission(submission)：
1. events = behaviorEventRepository.findByBizTypeAndLabIdAndStudentIdOrderByIdAsc("LAB", labId, studentId)
2. answerLogs = 该 submission 全部 answer 的 lab_step_answer_log（经 answerIds 批量一次查）
3. firstStartedAt = min(LAB_ENTER.occurred_at, answerLogs 最早 fillTime)   // 均为空 → null
4. lastEventAt = max(事件 occurred_at, answerLogs 最后 fillTime)
5. totalDurationMs = submission.submittedAt != null ? submittedAt - firstStartedAt : lastEventAt - firstStartedAt
   （负值截断 0；firstStartedAt null → totalDurationMs null）
6. activeDurationMs = Σ HEARTBEAT.activeMs（无心跳行 → null，前端显示 -）
7. save_count = answerLogs.size（含图片上传触发的快照，D17③）
8. paste_count / pasted_chars / paste_blocked_count = PASTE 事件聚合
9. visibility_hidden_count / hidden_ms = VISIBILITY 聚合（hidden 计数 + visible 带回的 hiddenMs 求和）
10. blur_count = WINDOW_BLUR 计数；session_count = LAB_ENTER 计数（D17①）
11. step_dwell_json：STEP_VIEW.dwellMs 按 fromStepId 累计 + LAB_LEAVE.dwellMs 按 lastStepId 累计（Map<Long,Long> → JSON）
12. 风险规则（阈值读 lab.behavior.risk.*）：
    events.isEmpty() → flags=[NO_BEHAVIOR_DATA], score=0, level=LOW
    DURATION_TOO_SHORT：totalDurationMs 非空且 < stepCount×perStepMinMs → +40
    PASTE_HEAVY：pastedChars > 阈值 且 pastedChars/ΣanswerText.length > 阈值 → +30
    FOCUS_LOSS：hiddenCount ≥ 阈值 或 (totalDurationMs>0 且 hiddenMs/total > 阈值) → +20
13. event_watermark = max(event.id)；computed_at = now；saveOrUpdate（按 submission_id 主键）
```

**懒算入口**：`ensureMetricsFresh(List<LabSubmission> rows)`（`LabService` 私有，供列表/queue/overview/behavior 详情四处调用）：

```text
1. ids = rows.map(id)；existing = metricsRepository.findAllById(ids) → Map<submissionId, Metrics>
2. stale = rows 中缺失 metrics，或 metrics.event_watermark < 该(lab,student)最新事件 id
   （最新事件 id 批量查：按 (lab,student) 对去重后 findMaxIdByBizTypeAndLabIdAndStudentIdIn → 自定义 @Query group by）
3. stale 非空 → fresh = labBehaviorMetricsService.refreshStaleMetrics(staleRows)
   // @Transactional(propagation = REQUIRES_NEW)，内部逐个 computeForSubmission 并落库，
   // 返回 Map<submissionId, Metrics>（内存对象，不在外层 readOnly 事务重查，D8）
4. 合并 existing + fresh 返回 Map<submissionId, Metrics>
```

> `computeForSubmission` 本身保持 REQUIRED：submitLab 联动时在外层写事务内；`refreshStaleMetrics` 是唯一从 readOnly 上下文进入的写路径。

**`submitLab` 联动**：`LabService.submitLab` 提交成功事务内追加调用 `labBehaviorMetricsService.computeForSubmission(submission)`（注入新依赖；构造器注入追加字段，测试构造同步更新）。注意：提交瞬间前端缓冲中的尾部事件（LAB_LEAVE、最后一次心跳）可能尚未到达，本次计算以已到事件为准，**迟到事件由教师首读的懒算兜底重算**（D8 时机②）。

**`uploadAnswerImage` 改造**（D17③）：`LabService.uploadAnswerImage` 在 `saveAnswerForStep` 成功后追加 `appendAnswerSnapshot(answer)`，与 `saveAnswer` 保持同一快照口径（"每次服务端确认的答案变更"）。这是对既有行为的**口径修正**，不改变接口契约与返回结构。

**`listTeacherReports` 改造点**（最小侵入）：§5.2 行扩展挂进 `toReportListViews`：方法内先 `ensureMetricsFresh(rows)` 再逐行组装 `behavior` 节点；riskLevel 筛选按 D10 在 Specification 组装前解析命中集（`NONE` → 教师域内 submissionIds 减去"metrics 存在且 flags 不含 NO_BEHAVIOR_DATA"的 id 集）。

### 6.2 前端

**`utils/behaviorCollector.ts`**（新建，唯一采集器）：

```text
start({labId, getContext}) / stop() / track(eventType, payload?) / setStep(stepId)
- 内部队列；5s 定时 + 满 20 条立即发送；正常发送走 `request.ts`（统一鉴权/拦截）；卸载/切后台兜底用 `fetch(url, {method:'POST', keepalive:true, headers:{Authorization: ...}})`，**不用 sendBeacon**（D12）
```

## 7. 指标口径矩阵（单一事实源）

| 指标 | 数据源 | 口径 |
|---|---|---|
| 开始作答时间 | `LAB_ENTER` 最早 occurred_at ∪ `lab_step_answer_log` 最早 fillTime，取 min | 学生机时钟异常时由保存时间兜底 |
| 总作答时长 | `submittedAt − firstStartedAt`；SAVED 行 `lastEventAt − firstStartedAt` 且 `durationOpen=true` | 负值截断 0；无源头 → null |
| 活跃时长 | Σ `HEARTBEAT.activeMs` | 无心跳（旧数据/短会话）→ null 显示 `-`；**上限估计**（多设备并发可见时可能重复计，方向为高估，见 §10） |
| 保存次数 | `lab_step_answer_log` 行数（该 submission 全部 answer） | D2 单一事实源；`uploadAnswerImage` 同步追加快照（D17③），口径 = **每次服务端确认的答案变更**（含"先答题后统一传图"） |
| 会话数 | `LAB_ENTER` 事件计数 | D17①；断续作答（做一半退出、隔几天继续）识别 |
| 粘贴次数/字符 | `PASTE` 事件计数 / Σ pastedLength | 含 blocked 尝试，blocked 另计 |
| 切屏次数/时长 | `VISIBILITY hidden` 计数 / Σ hiddenMs | WINDOW_BLUR 单独计数不并入 |
| 逐题停留 | `STEP_VIEW.dwellMs`（按 fromStepId）+ `LAB_LEAVE.dwellMs` | 存储 `step_dwell_json` |
| 风险标记 | D9 三条规则 | 仅标记，不处分 |

| A11 | 直接关浏览器 | 作答 5 分钟后直接关闭标签页（不经路由离开），教师端可见 `LAB_LEAVE{reason:"unload"}` 与尾部心跳，活跃时长包含最后一段 |
| A12 | 断续作答 | 做 30 分钟退出、隔天再做 30 分钟提交：活跃时长 ≈60min 且显示 `· 2次`，风险不标记"时长过短" |
| A13 | 统一传图 | 先答文字再统一传图提交：保存次数包含图片上传触发的快照 |

## 10. 兼容性与风险

| 风险 | 评估 | 缓解 |
|---|---|---|
| 心跳量：60s×2h×50 人×12 实验 ≈ 7.2 万行/学期/班 | 低：单行 <300B，学期量级百万行内，索引覆盖聚合路径 | 采集范围仅 LAB；后续可按需调大间隔配置 |
| 学生机时钟不准导致时长失真 | 中：已用"保存时间兜底 + 容差替代 + 负值截断"三层防护 | D6 口径写死，时长类指标仅作风险参考不处分 |
| 懒算在列表请求内同步执行拖慢首屏 | 低：单页 ≤100 行、事件按归属键索引扫描；仅首算慢，之后 watermark 短路 | stats 与分页本就两请求；可接受 |
| 粘贴采集依赖容器级事件，富文本/代码编辑器内部若 stopPropagation 会漏 | 低：现编辑器均为 textarea/简单封装，冒泡可达 | A1 验收覆盖两种编辑器 |
| 页面卸载时批量请求丢失 | 中：beforeunload 场景普通 fetch 可能被取消 | 兜底用 `fetch(..., {keepalive:true})` 带完整 Authorization 头（与 sendBeacon 等效且鉴权完整）；**不引入 sendBeacon**（无法带自定义头，会造成无鉴权写入通道），D12 |
| 隐私边界 | 仅采集作答页行为，无键击内容（PASTE 只记长度不记内容） | 事件目录写死，评审兜底 |
| 多设备/多标签并发作答 | 低概率：两台设备同时 visible 时心跳重复计，活跃时长**虚高**（方向为高估而非低估，不用于处分）；同浏览器多标签页已由"仅 visible 累计"挡住 | §7 口径注明"活跃时长为上限估计"；P3 风险合成时以方向安全的方式使用 |
| 行为事件可被伪造/时钟可被篡改 | 固有局限：任何客户端埋点都防君子不防小人；时钟改大只会让"时长过短"不触发（方向安全）；activeDuration 由心跳增量累计、不依赖 occurred_at 差值，抗时钟回拨 | 教师复核制兜底（D9 只标记不处分）；P3 可叠加服务端信号（保存间隔、查重）交叉验证 |
| 未来新增删除实验/提交功能 | 现网无删除入口（已核对无 `deleteLab`/`deleteSubmission`），V20 FK 当前无阻塞 | 未来实现删除链路时须先处理 `lab_submission_metrics` FK（级联或先删 metrics），在此登记 |
