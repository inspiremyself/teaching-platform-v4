## 3. 后端改动

### 3.1 `AdminSubjectController` 注解矩阵（写死）

移除类级 `@PreAuthorize("hasRole('SCHOOL_ADMIN')")`；类级 `@Validated` 保留；6 个 `@RequestMapping` 方法各写一条方法级注解，不遗漏、不合并：

| 方法 | HTTP | 方法级 `@PreAuthorize` |
|---|---|---|
| `list` | `GET /api/v1/admin/subjects` | `hasAnyRole('SCHOOL_ADMIN','TEACHER')` |
| `create` | `POST /api/v1/admin/subjects` | `hasRole('SCHOOL_ADMIN')` |
| `update` | `PUT /api/v1/admin/subjects/{id}` | `hasRole('SCHOOL_ADMIN')` |
| `changeStatus` | `POST /api/v1/admin/subjects/{id}/status` | `hasRole('SCHOOL_ADMIN')` |
| `listPlatform` | `GET /api/v1/admin/subjects/platform` | `hasRole('SCHOOL_ADMIN')` |
| `enablePlatform` | `POST /api/v1/admin/subjects/platform/{platformSubjectId}/enable` | `hasRole('SCHOOL_ADMIN')` |

类级注解移除后，`ControllerAuthorizationTests#everyEndpointIsCoveredByMethodOrClassLevelPreAuthorize` 会逐方法检查方法级注解；上表 6 行使 `AdminSubjectController` 通过此断言，其它 controller 的覆盖结论不因本方案变化（§6）。构造器、字段、方法体、`SecurityUtils.currentUser()` 取参方式全部零改动，按 `backend-code-style.mdc` §3。

### 3.2 数据范围与错误码

- `AdminSubjectService` / `SchoolSubjectRepository` / `school_subject` 表 / `AdminSubject` 视图字段零改动；教师读到的仍只是 `currentUser.schoolId()` 下 `status = ACTIVE` 的行，跨校数据不返回。
- 不新增错误码、不改 `GlobalExceptionHandler`、不改 `SILENT_CODES` / `AUTH_FAILURE_CODES`；越权仍由框架返回 `40300`「Access Denied」，前端全局 toast 语义不变。
- `status` 参数解析沿用现网 `parseStatus`；非法值行为零改动，本方案不定义新参数、不新增默认值。

## 4. 前端改动

### 4.1 三个 composable（实验 / 作业 / 考试）

| 文件 | 唯一改动 |
|---|---|
| `frontend/src/composables/useLabs.ts` | `onMounted` 改为 `await Promise.allSettled([fetchClasses(), fetchSubjects()])`，其后仍 `resetCreateForm()` → `await fetchData()` |
| `frontend/src/composables/useHomeworks.ts` | `onMounted` 改为 `await Promise.allSettled([fetchClasses(), fetchSubjects()])`，其后仍 `resetForm()` → `await fetchHomeworks()` |
| `frontend/src/composables/useExamList.ts` | `onMounted` 改为 `await Promise.allSettled([fetchClasses(), fetchQuestions(), fetchSubjects()])`，其后仍 `resetForm()` → `await fetchExams()` |

`Promise.allSettled` 吞掉初始化子请求的 rejection（错误提示仍由 `request.ts` 拦截器统一给出），但**不吞掉主列表请求**：`fetchData()` / `fetchHomeworks()` / `fetchExams()` 照常执行。学科、班级、题库池任一失败时对应 `ref` 保持初始值，页面显示空下拉 / 空列表而不是整页空白。

### 4.2 两个 SFC（资料 / 题库）

| 文件 | 唯一改动 |
|---|---|
| `frontend/src/views/teacher/Materials.vue` | `onMounted` 中 `void fetchSubjects();` 改为 `void fetchSubjects().catch(() => { subjectOptions.value = []; });`，`void fetchData();` 不变 |
| `frontend/src/views/teacher/Questions.vue` | `onMounted` 中 `void fetchSubjects();` 改为 `void fetchSubjects().catch(() => { subjectOptions.value = []; });`，`resetForm()` 与 `void fetchData();` 不变 |

`.catch` 只把学科下拉置空，消除未处理的 Promise rejection，不新增 toast、不改变 `subjectId` 初值 `0`。

### 4.3 不变项（写死）

`api/admin.ts#listSubjects` 的 URL 与返回泛型、`types/admin.ts#AdminSubject`、5 处 `fetchSubjects` 内部实现、6 处文案、编辑态 `subjectId = 0` 省略提交、`contracts.spec.ts`、`request.ts`、校管端 `Subjects.vue` / `Classes.vue` 全部零改动；不新增页面 / 路由 / 菜单 / 组件 / composable / store。
