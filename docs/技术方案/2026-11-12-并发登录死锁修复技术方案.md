## 2. 根因与现网基线（2026-11-12 实测）

### 2.1 调用链与 SQL 顺序

`POST /api/v1/auth/login` 由 `SecurityConfig` 的 `permitAll` 放行（无 token 时 `JwtAuthenticationFilter` 不过滤），`AuthController#login` 直接调 `AuthService#login`；该方法标注 `@Transactional`（默认 `REQUIRED`、无隔离级别定制）。事务内实际顺序：

1. `findAllByUsernameAndRole` → `select sys_user ...`（一致性读，建立 RR 快照，不加锁）；`schoolRepository.findByCode` / `findById` 亦为无锁读。
2. `findFirstByUser_IdAndStatusOrderByCreatedAtDesc` → `select user_login_session ...`（无锁快照读）；命中活跃会话且 `forceLogin=true` 时 `handleExistingActiveSession` 把托管实体置为 `KICKED` 并写 `SESSION_INVALIDATED` 审计（`audit_log` 无外键）。
3. `user.setLastLoginAt(now)` + `sysUserRepository.save(user)`：托管实体 `merge` 不产生 SQL，脏检查得到的全列 `update sys_user` 被**延迟到 commit flush**。
4. `createActiveSession` → `userLoginSessionRepository.save(new session)`：`BaseEntity` 为 `GenerationType.IDENTITY`，`insert user_login_session` 先于 commit flush 发出；`V11` 的 `fk_user_login_session_user` 指向 `sys_user(id)`。
5. `auditLogService.logSecurity(LOGIN_SUCCESS)` → `insert audit_log`：`V1:34-43` 建表无外键、`V18:1-15` 增强未加外键、`AuditLog.java:12-13` 的 `user_id` 为普通 `Long`（无 `@ManyToOne`）。这是 D3 成立的关键前提：审计 INSERT 早于 `saveAndFlush` 发生，若该表带指向 `sys_user` 的外键就会重新制造 S→X 环。
6. commit flush → `update sys_user set ... last_login_at=... where id=1`，同时 flush 第 2 步的 `update user_login_session ... status='KICKED'`。
7. `HttpAccessLogFilter` 在响应提交后用 `@Async` + 独立事务写 `http_access_log`（无外键、异常被吞），不参与登录事务。

### 2.2 死锁直接证据（本机 `SHOW ENGINE INNODB STATUS`）

| 编号 | 实测命令 / 位置 | 结论 |
|---|---|---|
| E1 | `mysql -h127.0.0.1 -uroot -p12345678 -N -e "SHOW ENGINE INNODB STATUS\G"` 的 `LATEST DETECTED DEADLOCK` | 时间 `2026-11-12 11:23:54`；事务 `427961` / `427962` 均在执行 `update sys_user set ... last_login_at='2026-11-12 03:23:54...' ... where id=1`；两者均 **HOLDS** `sys_user` `PRIMARY` 的 `S locks rec but not gap`（heap no 2 = id 1），均 **WAITING** 同一记录的 `lock_mode X locks rec but not gap`；`WE ROLL BACK TRANSACTION (2)`。即「互持 S 锁、互等 X 锁」的锁升级环 |
| E2 | 回滚事务内 `insert into user_login_session (...) values (1, ..., 'ACTIVE', ...)` 后查 `performance_schema.data_locks` | 输出 `sys_user / PRIMARY / RECORD / S,REC_NOT_GAP / GRANTED / 1` 与 `sys_user / NULL / TABLE / IS`、`user_login_session / NULL / TABLE / IX`。**父行 S 锁来源唯一确定为会话表外键校验** |
| E3 | 回滚事务内 `update user_login_session set user_id=1, status='ACTIVE', updated_at=now() where id=1139` | 只出现 `user_login_session / PRIMARY / X,REC_NOT_GAP`；父行无 S 锁。证明「全列 UPDATE 显式写回未变化的 `user_id`」不会额外给 `sys_user` 加 S 锁，`saveAndFlush` 同批 flush 该更新不破坏 D3 |
| E4 | 两个回滚事务并发执行「先 `update sys_user ... where id=1`，再 `insert user_login_session(...)`」 | 两个 mysql 客户端均退出码 0、无 1213；父行 X 锁先于子行 INSERT 时退化为串行等待 |
| E5 | 仓库文档 | `docs/技术方案/2026-11-12-frp-dev演示链路首屏性能优化技术方案.md` **V1.7**（§2「V1.6 实测」行、§5「并发压测」行、§7 非目标第 3 条、§10「实现阶段 V1.5」行）、`docs/运维文档/2026-11-12-frp-dev演示链路性能配置.md`（§4 V4 第 4 步、§5「遗留缺陷」与「验收结论」行）：同账号 10 并发 `forceLogin:true` → MySQL 1213、`4×500`；改为 10 个不同 ACTIVE 账号后 `7×200 + 3×400`、无 5xx、639 ms。以上按章节 + 锚文本定位，不写行号 |

## 3. 修复方案（唯一实现路径）

### 3.1 生产代码唯一改动

文件：`backend/src/main/java/com/opencode/teachingplatform/auth/service/AuthService.java`，`login` 方法内从 `OffsetDateTime now = OffsetDateTime.now();` 到 `UserLoginSession loginSession = createActiveSession(saved, now);` 的片段由

```java
        OffsetDateTime now = OffsetDateTime.now();
        userLoginSessionRepository.findFirstByUser_IdAndStatusOrderByCreatedAtDesc(user.getId(), LoginSessionStatus.ACTIVE)
                .ifPresent(existingSession -> handleExistingActiveSession(existingSession, request.forceLogin(), now));

        user.setLastLoginAt(now);
        SysUser saved = sysUserRepository.save(user);
        UserLoginSession loginSession = createActiveSession(saved, now);
```

改为（只替换 `save` 一行并插入注释，其余逐字不变）：

```java
        OffsetDateTime now = OffsetDateTime.now();
        userLoginSessionRepository.findFirstByUser_IdAndStatusOrderByCreatedAtDesc(user.getId(), LoginSessionStatus.ACTIVE)
                .ifPresent(existingSession -> handleExistingActiveSession(existingSession, request.forceLogin(), now));

        user.setLastLoginAt(now);
        // insert user_login_session 经外键对 sys_user 父行取 S 锁；若把 update sys_user 留到 commit flush，
        // 并发登录会互持 S 锁再互等 X 锁，触发 MySQL 1213。先 flush 把父行 X 锁提前到子行 INSERT 之前，
        // 本事务的 FK 校验由已持有的 X 锁直接满足，同账号登录在父行上串行。
        SysUser saved = sysUserRepository.saveAndFlush(user);
        UserLoginSession loginSession = createActiveSession(saved, now);
```

`saveAndFlush` 是 `JpaRepository` 现成方法，`main/java` 已有 14 处同类用法（如 `AdminSubjectService` / `PlatformSchoolService` / `HomeworkSubmissionClaimService`），不新增依赖、不新增 import。该 flush 会同时刷出 `handleExistingActiveSession` 弄脏的 `update user_login_session ... status='KICKED'`；E3 已实测该更新不给父行加 S 锁。`forceLogin=false` 且命中活跃会话时，`handleExistingActiveSession` 在 `saveAndFlush` 之前抛 `40901` 并回滚，不产生父行 UPDATE。

实施防错（写死）：同一 `AuthService.java` 的 `updateProfile` 方法内另有一处同形的 `SysUser saved = sysUserRepository.save(user);`（本轮现网实测），本方案对该方法零改动；必须按上面的完整片段逐字替换 `login` 方法内那一处，**禁止**在文件内全局替换 `save(user)`，否则会连带改变 `updateProfile` 并与 §4 写死的三处 `save` stub 口径冲突。

### 3.2 锁顺序推演（D3 的验收口径）

| 步骤 | 改动前 SQL / 锁 | 改动后 SQL / 锁 |
|---|---|---|
| 1 | `select sys_user ...`（RR 快照，无锁） | 同左 |
| 2 | `select user_login_session ...`、托管会话置 `KICKED`、写 `SESSION_INVALIDATED` 审计（无外键） | 同左 |
| 3 | `insert user_login_session` → 父行 `S,REC_NOT_GAP` | `update sys_user ...` → 父行 `X,REC_NOT_GAP`（其它同账号事务在此排队） |
| 4 | `insert audit_log (LOGIN_SUCCESS)` | `insert user_login_session` → FK 需 S 锁，本事务已持 X，不再产生跨事务 S 锁环 |
| 5 | commit flush：`update sys_user ...` 申请 `X,REC_NOT_GAP` → 与其余事务的 S 锁成环 → 1213 | `insert audit_log (LOGIN_SUCCESS)` → commit，无遗留 UPDATE |
| 结果 | 死锁 victim 回滚 → 全局兜底 500 | 同账号 10 请求在父行 X 锁上串行，全部提交成功 |

### 3.3 不变项（写死）

`LoginRequest`、`AuthController`、`SecurityConfig`、`JwtAuthenticationFilter`、`JwtTokenService`、`SysUser` / `UserLoginSession` 实体、`SysUserRepository` / `UserLoginSessionRepository`、`AuditLogService`、`HttpAccessLogFilter`、`GlobalExceptionHandler`、`request.ts`、三套前端壳层与登录页、`db/migration/` 全部零改动；`SysUser saved` 变量仍供 `createActiveSession` 与 `issueToken` 使用；响应 `Map.of("token", ..., "user", ..., "permissions", ...)` 逐字不变。

### 7.1 C / D 项写死的并发命令

```bash
cd /Users/liangzai/CursorProjects/teaching-platform-v4
OUT="$(mktemp -d)"; trap 'rm -rf "$OUT"' EXIT
printf '%s' '{"username":"t9001","password":"123456","role":"TEACHER","forceLogin":true}' > "$OUT/payload.json"
mysql -h127.0.0.1 -uroot -p12345678 -N teaching_platform \
  -e "select coalesce(max(id),0) from audit_log" > "$OUT/auditmax.before"
wc -l < data/logs/backend.log | tr -d ' ' > "$OUT/loglines.txt"
mysql -h127.0.0.1 -uroot -p12345678 -N -e "SHOW ENGINE INNODB STATUS\G" \
  | grep -A2 'LATEST DETECTED DEADLOCK' | tail -1 > "$OUT/deadlock.before"
mysql -h127.0.0.1 -uroot -p12345678 -N teaching_platform \
  -e "select last_login_at from sys_user where id=1" > "$OUT/lastlogin.before"
seq 1 10 | xargs -P 10 -I{} curl -sS --max-time 12 -o "$OUT/{}.json" -w '%{http_code}\n' \
  -X POST http://127.0.0.1:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' --data-binary "@$OUT/payload.json" > "$OUT/codes.txt"
sort "$OUT/codes.txt" | uniq -c
grep -L '"code":0' "$OUT"/[0-9]*.json
mysql -h127.0.0.1 -uroot -p12345678 -N -e "SHOW ENGINE INNODB STATUS\G" \
  | grep -A2 'LATEST DETECTED DEADLOCK' | tail -1 > "$OUT/deadlock.after"
diff "$OUT/deadlock.before" "$OUT/deadlock.after"
mysql -h127.0.0.1 -uroot -p12345678 -N teaching_platform \
  -e "select last_login_at from sys_user where id=1" > "$OUT/lastlogin.after"
paste "$OUT/lastlogin.before" "$OUT/lastlogin.after"
mysql -h127.0.0.1 -uroot -p12345678 -N teaching_platform \
  -e "select count(*) from audit_log where user_id=1 and action='LOGIN_SUCCESS' and id > $(cat "$OUT/auditmax.before")"
tail -n +$(( $(cat "$OUT/loglines.txt") + 1 )) data/logs/backend.log \
  | grep -E '1213|DeadlockLoserDataAccessException|SQLState 40001' || true
```

判据：`10 200`；`grep -L '"code":0'` 无输出；`diff` 无输出；`paste` 输出的两列中后者大于前者；`count(*)` 为 10；末行 `grep -E ... \|\| true` 无输出；`curl` 无 `--max-time 12` 超时。审计计数用 `audit_log.id` 自增水位线而非 `created_at` 时间窗：实测 `@@session.time_zone = SYSTEM`、`NOW() = 12:31:55` 而 `UTC_TIMESTAMP() = 04:31:55`、`audit_log.created_at` 显示为 `04:30:42`，CLI 与 JDBC 的 TIMESTAMP 转换尺度不同，时间字符串比较跨环境不可靠。`-p12345678` 取自 `scripts/path-b/backend.sh` 的 `DB_PASS` 默认值；`mktemp -d` 产物由 `trap` 在命令结束时清理。

## 9. 风险与回滚

| 风险 | 影响 | 缓解 / 判据 |
|---|---|---|
| 同账号登录改为父行 X 锁串行 | 并发远超 10、且某长事务持有 `sys_user` X 锁时，可能触发 `innodb_lock_wait_timeout=50` 后仍返回 500 | 临界区只含 1 次会话 INSERT + 2 次审计 INSERT + commit；验收 C 以 `codes.txt` 全为 `200`、无 `--max-time 12` 超时为判据；超限并发 / 长事务治理属 §8 非目标 |
| Hikari 默认 10 连接被 10 个等锁请求占满 | `HttpAccessLogAsyncWriter` 的异步写库短暂排队 | X 锁从 `saveAndFlush` 持有到 commit；验收 C 以 §7.1 末行 `grep -E ... \|\| true` 无输出、`codes.txt` 无 `000` 且 10 个响应均含 `code:0` 为判据；不调整线程池（§8） |
| `saveAndFlush` 会一并 flush 托管会话的 `KICKED` 全列 UPDATE | 有人担心该 UPDATE 又给父行加 S 锁 | E3 已实测全列写回未变化的 `user_id` 不给 `sys_user` 加 S 锁；`40901` 分支在 flush 之前抛出并回滚（§3.1） |
| Mockito 严格 stub | 2 处 `save` stub 未同步改成 `saveAndFlush` 会触发 `UnnecessaryStubbingException`，3 处 `save` stub 被误改会让 `updateProfile` / `changePassword` 用例失败 | §4 逐行写死 5 处 stub 的去留；`./mvnw test` 兜底（验收 A） |

回滚（唯一顺序）：回退 `AuthService.java` 的 `saveAndFlush` 一行与 3 行注释 → 回退 `AuthServiceTests.java` 的 2 处 stub、新增用例与 2 条 import → 移除 §5 两处文档引用 → 删除本文。无迁移、无 schema 变更，回滚不影响已有的 `sys_user` / `user_login_session` / `audit_log` 数据。
