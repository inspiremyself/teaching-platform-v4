# 实验报告单条打回技术方案

**创建日期**：2026-09-07  
**状态**：已定稿（决策写死，可直接编码）  
**范围**：实验（Lab）域——教师对**单条** `SUBMITTED` 实验报告打回至 `SAVED`，学生保留作答内容并重新编辑/提交  
**非目标**：`GRADED` 打回、批量打回、学生自助撤回、打回原因采集与展示、打回历史表、新增 `RETURNED` 枚举状态、清理 `experiment_answer_log`

## 1. 背景与诉求

### 1.1 业务诉求

教师在实验报告批改队列中，发现某学生「已提交」的报告存在明显问题（漏题、截图错误、小结未按要求填写等），希望将该学生的单条提交**打回到可编辑状态**，让学生修改后重新提交，而不影响同实验其他学生。

### 1.2 现状结论

| 能力 | 现状 |
|------|------|
| 提交状态机 | `SAVED → SUBMITTED → GRADED`，单向推进 |
| 学生编辑锁 | `SUBMITTED`/`GRADED` 时 `ensureEditableSubmission` 抛 400 |
| 学生端只读 | `LabSteps.vue`：`readonly = ['SUBMITTED','GRADED'].includes(status)` |
| 提交后自动评分 | `submitLab` → `applyScoringResult` → `refreshSubmissionAfterScoring`；若全部子题已答且均有 `score`，状态升为 **`GRADED`** |
| 教师逐步确认分 | `confirmStepScore` 可在 `SUBMITTED` 下写入单步 `score`；若随后全题均有分则可能升为 **`GRADED`**（不可打回） |
| 教师打回 | **无** API、无 UI |
| 作业/考试打回 | **无**可复用实现 |

### 1.3 设计结论（一句话）

新增教师单条打回 API：在权限与状态校验通过后，将 `LabSubmission` 从 `SUBMITTED` 回退为 `SAVED`，**保留全部作答内容**，清除提交时间与提交时产生的自动评分痕迹，使学生端现有保存/提交流程无需改动即可生效。

## 2. 目标与非目标

### 2.1 目标

1. 教师可对批改队列中**单条** `SUBMITTED` 报告执行打回。
2. 打回后该学生在对应实验下恢复「已保存草稿」语义：可继续 `saveAnswer`、上传图片、修改小结、再次 `submit`（实验须为 `PUBLISHED`）。
3. 打回不改变其他学生的提交状态与评分数据。
4. 打回后教师队列统计（待批改数等）正确反映：该条从 `SUBMITTED` 移出，状态显示为「已保存」。

### 2.2 非目标

- 不支持 `GRADED` 打回（含提交后全客观题自动评完直接升为 `GRADED` 的记录）。
- 不支持批量打回、按实验一键打回全班。
- 不支持学生端「撤回提交」。
- 不记录打回历史、不展示打回原因、不向学生推送通知。
- 不清空作答内容、不删除已上传答题图文件、不清理 `experiment_answer_log`。
- 不改造作业/考试域提交状态机。

## 3. 状态与数据变更

### 3.1 状态流转

```text
                    submitLab
SAVED ──────────────────────────► SUBMITTED
  ▲                                    │
  │         returnReport (本期)        │ gradeReport
  │                                    │ 或 allScored 自动升 GRADED
  └────────────────────────────────────┼──────────────────► GRADED
                                       │                        ▲
                                       │                        │
                                       └── (本期不可打回) ───────┘
```

### 3.2 `experiment_submission`（`LabSubmission`）字段变更

| 字段 | 打回前（`SUBMITTED`） | 打回后（`SAVED`） |
|------|----------------------|-------------------|
| `submit_status` | `SUBMITTED` | `SAVED` |
| `submitted_at` | 有值 | `null` |
| `graded_at` | `null` | `null` |
| `total_score` | 可能有汇总分 | `0` |
| `teacher_comment` | 通常空 | `''` |
| `summary_text` | 保留 | **不变** |
| `summary_attachment_path` | 保留 | **不变** |
| `plagiarism_rate` | 保留 | **不变** |

### 3.3 `experiment_answer`（`LabStepAnswer`）字段变更

对属于该 `submissionId` 的**全部**答案行（`labStepAnswerRepository.findByLabSubmissionId`）：

| 字段 | 打回后 |
|------|--------|
| `answer_text` | **不变** |
| `answer_json`（含多图 path） | **不变** |
| `answer_file_path` | **不变** |
| `question_snapshot_json` | **不变** |
| `editor_language` | **不变** |
| `auto_score` | `null` |
| `suggested_score` | `null` |
| `score` | `null` |
| `score_source` | **`"TEACHER"`**（`NOT NULL`，禁止写 `null`） |
| `auto_judge_detail` | `null` |
| `teacher_comment` | `''` |
| `accepted_auto_score` | `false` |

> **再次提交**：`submitLab` 会逐步 `labScoringSupport.score` 并 `applyScoringResult`，自动评分重新计算。  
> **再次保存**：学生 `saveAnswer` 在 `score == null` 时会写入 `score = 0D`（现有逻辑），与草稿态一致。  
> **教师已逐步确认的分**：若报告仍为 `SUBMITTED` 且教师曾调用 `confirmStepScore`，打回时与自动评分字段一并清空（§3.3），不保留单步人工分。

### 3.4 实验状态前置条件

学生侧 `saveAnswer` / `uploadAnswerImage` / `submitLab` 要求实验非 `DRAFT`（`accessiblePublishedLab`）且非 `CLOSED`。打回须与之一致：

| 实验 `status` | 打回 | 说明 |
|---------------|------|------|
| `PUBLISHED` | **允许** | 打回后学生可立即保存并再次提交 |
| `CLOSED` | **拒绝** | 错误：「实验已关闭，不能打回」；教师须先改回 `PUBLISHED` |
| `DRAFT` | **拒绝** | 错误：「实验未发布，不能打回」；学生端 `accessiblePublishedLab` 亦不可访问 |

**已关闭实验的典型操作顺序**：`CLOSED` → 教师改状态为 `PUBLISHED` → 打回 → 学生修改 → 再次提交。

### 3.5 不打回的数据

| 数据 | 处理 |
|------|------|
| `experiment_answer_log` | **保留**（历史快照，仅追加不写回） |
| 磁盘答题图 `lab-answers/...` | **保留** |
| `score_record`（成绩汇总表） | **不触及**（`SUBMITTED` 无记录） |

## 4. API 设计

### 4.1 打回实验报告

**`POST /api/v1/teacher/lab-reports/{id}/return`**

- **角色**：`TEACHER`
- **路径参数**：`id` = `LabSubmission.id`（与 `gradeReport`、`getTeacherLabReportDetail` 一致，称 reportId）
- **请求体**：无
- **成功响应** `200`：

```json
{
  "code": 0,
  "message": "OK",
  "data": {
    "submissionId": 3001,
    "status": "SAVED",
    "labId": 1001,
    "studentId": 2
  },
  "timestamp": "2026-09-07T16:00:00+08:00"
}
```

### 4.2 错误码

| 场景 | HTTP | code | message（与现网 `BusinessException` 一致） |
|------|------|------|---------------------------------------------|
| 报告不存在 | 404 | 40400 | 实验报告不存在 |
| 实验非当前教师创建 | 403 | 40300 | 无权限访问该实验 |
| 班级非当前教师 | 403 | 40300 | 无权限访问该班级 |
| 状态非 `SUBMITTED` | 400 | 40000 | 仅已提交且未批改完成的报告可打回 |
| 实验已关闭 | 400 | 40000 | 实验已关闭，不能打回 |
| 实验未发布（`DRAFT`） | 400 | 40000 | 实验未发布，不能打回 |
| 重复打回（已为 `SAVED`） | 400 | 40000 | 仅已提交且未批改完成的报告可打回 |

> `GRADED` 与 `SAVED` 均命中同一 400 文案，不单独区分。

### 4.3 权限

与 `LabService.gradeReport` / `ownedLab` 完全对齐：

1. `requireTeacher(currentUser)`
2. `labSubmissionRepository.findById(reportId)`
3. `labRepository.findByIdAndCreatedBy(labId, currentUser.id())` — 实验须为当前教师创建
4. `classRoomRepository.findByIdAndTeacherUserId(lab.getClassId(), currentUser.id())` — 班级须归属当前教师

## 5. 后端实现要点

### 5.1 新增方法

`LabService.returnReport(CurrentUser currentUser, Long reportId)`

```java
@Transactional
public Map<String, Object> returnReport(CurrentUser currentUser, Long reportId) {
    requireTeacher(currentUser);
    LabSubmission submission = labSubmissionRepository.findById(reportId)
        .orElseThrow(() -> new BusinessException(40400, "实验报告不存在"));
    Lab lab = ownedLab(currentUser, submission.getLabId());
    if (lab.getStatus() == ActivityStatus.CLOSED) {
        throw new BusinessException(40000, "实验已关闭，不能打回");
    }
    if (lab.getStatus() == ActivityStatus.DRAFT) {
        throw new BusinessException(40000, "实验未发布，不能打回");
    }
    if (submission.getSubmitStatus() != SubmissionStatus.SUBMITTED) {
        throw new BusinessException(40000, "仅已提交且未批改完成的报告可打回");
    }

    List<LabStepAnswer> answers = labStepAnswerRepository.findByLabSubmissionId(submission.getId());
    for (LabStepAnswer answer : answers) {
        answer.setAutoScore(null);
        answer.setSuggestedScore(null);
        answer.setScore(null);
        answer.setScoreSource("TEACHER");
        answer.setAutoJudgeDetail(null);
        answer.setTeacherComment("");
        answer.setAcceptedAutoScore(false);
    }
    if (!answers.isEmpty()) {
        labStepAnswerRepository.saveAll(answers);
    }

    submission.setSubmitStatus(SubmissionStatus.SAVED);
    submission.setSubmittedAt(null);
    submission.setGradedAt(null);
    submission.setTotalScore(0D);
    submission.setTeacherComment("");
    labSubmissionRepository.save(submission);

    return Map.of(
        "submissionId", submission.getId(),
        "status", submission.getSubmitStatus().name(),
        "labId", lab.getId(),
        "studentId", submission.getStudentId()
    );
}
```

### 5.2 Controller

`LabController` 新增（置于 `gradeReport` 同级）：

```java
@PostMapping("/teacher/lab-reports/{id}/return")
@PreAuthorize("hasRole('TEACHER')")
public ApiResponse<?> returnReport(@PathVariable Long id) {
    CurrentUser currentUser = SecurityUtils.currentUser();
    return ApiResponse.ok(labService.returnReport(currentUser, id));
}
```

### 5.3 DTO

本期**不新增** `LabRequests` 类型（无请求体）。

## 6. 前端实现要点

### 6.1 类型（`frontend/src/types/lab.ts`）

```typescript
export interface ReturnLabReportResult {
  submissionId: number;
  status: LabReportStatus;
  labId: number;
  studentId: number;
}
```

### 6.2 API（`frontend/src/api/labs.ts`）

```typescript
export const returnTeacherLabReport = (reportId: number | string) =>
  request.post<ReturnLabReportResult>(`/teacher/lab-reports/${reportId}/return`);
```

### 6.3 教师页（唯一入口：`LabReports.vue`）

补充 import 与状态：

```typescript
import { ElMessage, ElMessageBox } from 'element-plus';
import { listTeacherLabReports, listTeacherLabs, returnTeacherLabReport } from '@/api/labs';

const returningId = ref<number | null>(null);
```

在 `report-row__actions` 区域，**仅**对 `row.submitStatus === 'SUBMITTED'` 的行增加：

```html
<el-button type="warning" plain :loading="returningId === row.id" @click="handleReturn(row)">
  打回
</el-button>
```

交互：

1. `ElMessageBox.confirm`：文案「打回后学生可修改作答并重新提交，是否继续？」
2. 确认后调用 `returnTeacherLabReport(row.id)`；请求进行中 `returningId = row.id` 防重复点击
3. 成功：`ElMessage.success('已打回，学生可重新编辑提交')`，`fetchData()` 刷新列表
4. 失败：沿用 `request.ts` 统一错误提示（含实验已关闭、未发布、状态不符）

`handleReturn` 实现要点：确认框 `catch` 静默取消；`returningId` 在 `finally` 中置 `null`；`row.id` 即 `LabSubmission.id`（`toReportListView` 的 `id` 字段）。

**不在** `LabReportDetail.vue`、`LabReportBatchGrade.vue`、`LabSubmissionOverview.vue` 增加打回入口。

打回成功后，该行 `submitStatus` 变为 `SAVED`，教师列表标签显示「已保存」（与现有 `statusLabel` 一致），优先级降为「草稿跟进」。

### 6.4 学生端

**零改动**。打回后 `getStudentLabDetail` / 步骤页返回 `submissionStatus: 'SAVED'`：

- `readonly` 为 `false`
- 可保存、可提交
- 状态标签显示「已保存草稿」（`LabSteps.vue` 现有文案）

## 9. 已否决方案

| 方案 | 否决原因 |
|------|----------|
| 新增 `RETURNED` 枚举状态 | 与「回到上一状态 SAVED」重复，扩大前后端改动面 |
| 打回时清空作答内容 | 业务确认保留全部作答（决策 #3） |
| 打回原因 + 学生端展示 | 本期非目标；YAGNI |
| `lab_submission_return_log` 历史表 | 本期非目标；后续若有审计需求再单开 |
| 多入口（详情页/总览页）打回 | 入口分散，本期写死批改队列唯一入口 |
| `GRADED` 可打回 | 本期范围外，避免 `ScoreRecord` 回滚复杂度 |
| `score_source` 置 `null` | 违反 `experiment_answer.score_source NOT NULL` 约束 |
| 实验 `CLOSED` / `DRAFT` 仍允许打回 | 打回后学生无法访问或保存，造成无效状态；须 `PUBLISHED` |
| 清理 `experiment_answer_log` | 日志为追加审计，打回不应抹除历史 |
