### 4.1 `ExamService.submitExam` 自动结案

改造后顺序（仅列变化点）：

```java

        .orElseThrow(() -> new BusinessException(40400, "考试不存在"));

    submission.setStatus(ExamSubmissionStatus.AUTO_SUBMITTED);
} else {
    submission.setStatus(ExamSubmissionStatus.SUBMITTED);
}

// ... 第 6 步逐题评分，hasManualGrading 在遇到主观题时置 true（不变）

// 7. 分数与时间落库；无主观题时在同一事务内直接结案

submission.setManualScore(0.0);
submission.setTotalScore(autoScore);
submission.setSubmittedAt(now);

    submission.setStatus(ExamSubmissionStatus.GRADED);
}

// 8. 成绩记录：先结案，再按现有可见性判定
```

- 不改变 `canStudentSeeScore`、`upsertScoreRecord`、`ExamSubmissionStatus` 枚举。

### 5.2 答案格式化（`Results.vue` 本地实现）

替换现有 `formatDisplayAnswer`，新增两个内部函数：

```ts
/** 判断题真值集合，与 PRD FR-3 约定保持一致（大小写经 toUpperCase 归一） */
const JUDGE_TRUE_VALUES = new Set(['TRUE'])
const JUDGE_FALSE_VALUES = new Set(['FALSE'])

/** 判断是否为普通对象（排除数组与 null） */
const isPlainRecord = (value: unknown): value is Record<string, unknown> =>
  typeof value === 'object' && value !== null && !Array.isArray(value)

/**
 * 将任意答案节点压平成可读文本。
 * 数组按“，”连接；对象优先取 answer/text/value/answerText/selectedKey/code。
 */
const toScalarText = (value: unknown): string => {
  if (value === null || value === undefined) return ''
  if (typeof value === 'string') return value.trim()
  if (typeof value === 'number' || typeof value === 'boolean') return String(value)
  if (Array.isArray(value)) {
    return value.map(toScalarText).filter(Boolean).join('，')
  }
  if (isPlainRecord(value)) {
    for (const key of ['answer', 'text', 'value', 'answerText', 'selectedKey', 'code']) {
      const text = toScalarText(value[key])
      if (text) return text
    }
  }
  return ''
}

/**
 * 按 kind 解析学生答案；无 kind 时按标准答案字段兜底。
 * 返回空字符串表示无可读内容，由调用方统一转“未作答”。
 */
const formatAnswerNode = (node: unknown): string => {
  if (node === null || node === undefined) return ''
  if (!isPlainRecord(node)) return toScalarText(node)

  const kind = typeof node.kind === 'string' ? node.kind : ''
  if (kind === 'single') return toScalarText(node.selectedKey)
  if (kind === 'multiple') return toScalarText(node.selectedKeys)
  if (kind === 'judge') {
    const raw = String(node.value ?? '').trim().toUpperCase()
    if (JUDGE_TRUE_VALUES.has(raw)) return '正确'
    if (JUDGE_FALSE_VALUES.has(raw)) return '错误'
    return toScalarText(node.value)
  }
  if (kind === 'fill') return toScalarText(node.blanks)
  if (kind === 'code') return toScalarText(node.code)
  if (kind === 'text') return toScalarText(node.text ?? node.answer ?? node.answerText)

  // 标准答案形态（PRD FR-3 规则 5）：按顺序取第一个非空字段；
  // 该字段无法压平为标量时，原样输出该字段的 JSON 字符串，继续向后兜底
  for (const key of ['correctAnswer', 'correct', 'answer', 'answers', 'blanks', 'selectedKey', 'selectedKeys']) {
    const field = node[key]
    if (field === undefined || field === null) continue
    if (Array.isArray(field) && field.length === 0) continue
    if (typeof field === 'string' && !field.trim()) continue
    const text = toScalarText(field)
    if (text) return text
    const rawField = JSON.stringify(field)
    if (rawField && rawField !== '{}') return rawField
  }
  // 无任何可读字段时原样输出对象 JSON，禁止 [object Object]
  const rawNode = JSON.stringify(node)
  return rawNode && rawNode !== '{}' ? rawNode : ''
}

/** 批改页答案展示：空值与不可读内容统一显示“未作答” */
const formatDisplayAnswer = (value: string | null): string => {
  if (!value || !value.trim()) return '未作答'
  try {
    return formatAnswerNode(JSON.parse(value)) || '未作答'
  } catch {
    return value
  }
}
```

验收样例（与 PRD FR-3 一致）：

| 输入 | 输出 |
|---|---|
| `{"kind":"single","selectedKey":"B"}` | `B` |
| `{"kind":"multiple","selectedKeys":["A","C"]}` | `A，C` |
| `{"kind":"judge","value":"TRUE"}` | `正确` |
| `{"kind":"judge","value":"B"}` | `B`（非 TRUE/FALSE 原样输出） |
| `{"kind":"fill","blanks":[{"answer":"pwd"},{"answer":"ls"}]}` | `pwd，ls` |
| `{"kind":"code","code":"ls -l"}` | `ls -l` |
| `{"kind":"text","text":"答案"}` | `答案` |
| `["A"]` | `A` |
| `{"correctAnswer":"B"}` | `B` |
| `{"correctAnswer":["A","C"]}` | `A，C` |
| `{"foo":{"bar":1}}` | `{"foo":{"bar":1}}`（无可读字段时输出整个对象 JSON） |
| `null` / `""` | `未作答` |
| 非 JSON 字符串 `B` | `B` |

现状两个逐题按钮均带 `:disabled="detail?.status === 'GRADED'"`（[Results.vue](file:///Users/liangzai/CursorProjects/teaching-platform-v4/frontend/src/views/teacher/exams/Results.vue#L165-L170)）。TD1 上线后纯客观卷交卷即为 `GRADED`，该禁用会让 PRD D11 要求的“保持可用”失效。

```vue
<button class="action-panel__secondary" type="button" :disabled="!detail" @click="confirmAnswer(answer.questionId, true)">
  采纳推荐分
</button>
<button class="action-panel__secondary" type="button" :disabled="!detail" @click="confirmAnswer(answer.questionId, false)">
  按当前分确认
</button>
```

- 只移除 `detail?.status === 'GRADED'`，保留 `!detail` 兜底；不按 `suggestedScore` 是否存在新增禁用条件。
- 无推荐分时点击“采纳推荐分”由后端返回 `40000 当前题目没有可采纳的推荐分`，沿用现有错误提示链路。
- 在 `GRADED` 提交上确认会触发 `recomputeSubmissionAfterTeacherConfirmation`，其 `allConfirmed=true` 时无条件写 `score_record`；这是显式教师动作，与 §4.2 口径一致，不视为可见性缺陷。
- `confirmAnswer` 后端与 `ExamAnswerDetail` 类型均不改。

## 8. 测试计划

### 8.1 后端 `ExamServiceTests`

新增仅客观题夹具（不复用 `createPublishedExamForStudent`，后者含 `SHORT` 主观题）：

- 夹具工厂 `createObjectiveOnlyExam(ScoreVisibilityMode mode)`：只挂 1 道 `SINGLE` 题，`status=PUBLISHED`，`scoreVisibilityMode` 显式传参；验证 `AFTER_TEACHER_CONFIRM` 时传 `null`。
- 超时提交构造：`startExam` 只按 `now + durationMinutes` 生成 `deadline_at`，不校验考试 `endAt`，因此超时用例必须先 `startExam`，再 `jdbcTemplate.update("UPDATE exam_submission SET deadline_at = ? WHERE id = ?", OffsetDateTime.now().minusMinutes(1), submissionId)`，最后调用 `submitExam`。
- 历史卡单构造：交卷（新逻辑下已 `GRADED`）后用 `jdbcTemplate.update("UPDATE exam_submission SET status = 'SUBMITTED' WHERE id = ?", submissionId)` 回写状态，模拟 TD1 上线前的存量数据；不修改 `exam_answer` 分数。
- `AUTO_SUBMITTED` + 未评分主观题构造：在含主观题夹具上按上述“超时提交构造”交卷，得到 `AUTO_SUBMITTED`，不对主观题调用 `confirmAnswer` / `grade`。
- `score_record` 断言一律按 `business_type='EXAM' AND business_id=<本次 examId>` 过滤，避免种子数据干扰。

## 10. 风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 纯客观题交卷即可见成绩 | `AFTER_TEACHER_CONFIRM` 不再产生等待 | PRD D3 已确认；需要延迟发布时后续开放 `MANUAL_RELEASE` |
| `MANUAL_RELEASE` 结案后仍无 `score_record` | `releaseScores` 只置 `scoreReleased=true`，不回填 `score_record`；基于 `score_record` 的分析口径会缺该条记录 | PRD §7.1.2 已确认本期不补写；发布链路补写留待后续需求 |
| 移除 `@NotEmpty` 后请求可传 `null` | 若 Service 未做空值处理会 NPE | TD5 强制 `null → List.of()` |
| `AUTO_SUBMITTED` 部分批改后降级 | 队列“超时提交”变“待评分” | 现网重算行为，本期明确保留 |
| 既有用例依赖 `SUBMITTED` | 全客观题夹具断言可能失败 | 新夹具独立命名；现有含主观题用例不改 |
| 答案格式继续演进 | 新 `kind` 可能无展示 | TD11 集中收敛，新增题型时扩展 `formatAnswerNode` |

回滚方式：代码级回滚本次提交即可；无数据库变更，无需数据回滚。
