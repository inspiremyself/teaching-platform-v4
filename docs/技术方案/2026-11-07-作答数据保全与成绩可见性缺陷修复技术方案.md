## 2. 已定决策清单

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| TD1 | 实验答案 DTO 校验 | `SaveStepAnswerRequest.answerText` 去掉 `@NotBlank`，保留 `String` 类型；`LabService.saveAnswer` 不改校验顺序：`answerText == null` 归一为 `""`，图片题型按 payload 校验图片，非图片题型携带图片抛 `40000 当前题型不支持图片作答`；文字与图片都为空时按清空写入 |
| TD2 | 草稿接口形态 | `PUT /api/v1/exams/{id}/draft`，`@PreAuthorize("hasRole('STUDENT')")`；请求体直接复用 `ExamRequests.SubmitExamRequest`，不新增 DTO |
| TD3 | 草稿校验顺序与错误码 | ①考试不存在 → `40400 考试不存在`；②非本班学生 → `40300 无权限保存草稿`；③提交行不存在 → `40400 未找到考试提交记录`；④状态非 `IN_PROGRESS` → `40000 考试已提交，无法保存草稿`；⑤`deadlineAt != null && now > deadlineAt + 120s` → `40000 考试已结束，无法保存草稿`；⑥`questionId` 不在该考试题目集合 → `40000 题目不属于该考试`。`deadlineAt == null` 不做时间限制。请求体复用 `SubmitExamRequest`，该 DTO **不含** `questionType`；前端多传的 `questionType` 由 Jackson 忽略，后端题型一律取自 `ExamQuestion` 快照 |
| TD4 | 草稿并发控制 | `saveDraft` 用 `findByExamIdAndStudentIdForUpdate` 获取提交行悲观写锁，与 `submitExam` 串行；同请求内按 `questionId` 去重，后出现的条目覆盖前面的条目 |

| TD6 | 草稿响应 | `{ submissionId, savedAt, savedCount }`；`savedAt` 为 `OffsetDateTime.now()`，由 Jackson 序列化为 ISO-8601；`savedCount` 为去重后写入题数；`answers` 为 `null` 或空数组时返回 `savedCount=0` 且 200 |
| TD7 | `IN_PROGRESS` 详情读取 | `getExamDetail` 在 `IN_PROGRESS` 时为每题附加 `studentAnswer`（草稿 `answer_json`），不附加 `isCorrect`、`earnedScore`、`teacherComment`、`answerJson`、`analysisText`；返回 `resultAvailable=false`、`gradingInProgress=false`；**保留**现有 `deadlineAt` 与 `remainingSeconds` 输出，不改变倒计时恢复逻辑 |
| TD8 | 教师详情字段 | 仅 `TEACHER` 分支在结果 Map 顶层新增 `scoreReleased = exam.isScoreReleased()`；学生分支不返回该字段 |
| TD9 | 交卷草稿兜底 | `submitExam` 在 `deleteByExamSubmissionId` **之前**读取 `findByExamSubmissionId` 构建 `questionId -> answerJson`；逐题取答案时，payload 的 `answers` 中存在该 `questionId`（含空值）使用 payload，否则使用草稿；草稿解码为 `SubmitAnswerItem` 后走原有 `AnswerPayloadNormalizer` + `gradingAdapter.grade` 流程 |
| TD10 | 草稿 JSON → 交卷条目解码 | 新增私有方法 `resolveDraftAnswerItem(questionId, questionType, draftJson)`，只返回 `SubmitAnswerItem` 的四个内容字段（`selectedOptions`、`answerText`、`answerJson` 回填 `draftJson`、`attachmentPath=null`）：`null/空白` → 全空；JSON 数组 → `selectedOptions=数组元素`、`answerText=逗号拼接`；对象 `kind=single` → `selectedOptions=[selectedKey]`、`answerText=selectedKey`；`kind=multiple` → `selectedOptions=selectedKeys`、`answerText=逗号拼接`；`kind=judge` → `selectedOptions=[value]`、`answerText=value`；`kind=fill` → `selectedOptions=[]`、`answerText=按 index 升序拼接 blanks[].answer（保留空串）`；`kind=code` → `selectedOptions=[]`、`answerText=code`；其余 `kind` → `selectedOptions=[]`、`answerText=text`。**实现方式固定**：在 `ExamService` 内新增两个私有方法 `readStringArray(JsonNode node, String field)`（读数组字段并转 `List<String>`）与 `joinBlankAnswers(JsonNode node)`（遍历 `blanks` 读 `answer` 拼接）；`multiple` 分支只调用 `readStringArray(node, "selectedKeys")`，`judge` 分支只调用 `jsonText(node, "value")`，不复用同一方法。`joinBlankAnswers` **必须与前端 `buildCompatibilityAnswerText` 的空位语义一致**：按 `index` 升序排序、跳过 `index <= 0` 的项、逐项 `answer.trim()` 后**保留空串**用 `,` 拼接（不得过滤空答案，否则空位会错位） |

```java
private ExamRequests.SubmitAnswerItem resolveDraftAnswerItem(Long questionId, String questionType, String draftJson) {
    if (draftJson == null || draftJson.isBlank()) {
        return new ExamRequests.SubmitAnswerItem(questionId, List.of(), null, null, null);
    }
    JsonNode node = readJsonNode(draftJson);
    if (node == null) {
        return new ExamRequests.SubmitAnswerItem(questionId, List.of(), draftJson, draftJson, null);
    }
    if (node.isArray()) {
        List<String> options = new ArrayList<>();
        node.forEach(item -> options.add(item.asText()));
        return new ExamRequests.SubmitAnswerItem(questionId, options, String.join(",", options),
                writeJson(options), null);
    }
    String kind = jsonText(node, "kind");
    if (kind == null) {
        return new ExamRequests.SubmitAnswerItem(questionId, List.of(), null, draftJson, null);
    }
    return switch (kind) {
        case "single" -> {
            String key = jsonText(node, "selectedKey");
            yield new ExamRequests.SubmitAnswerItem(questionId,
                    key == null ? List.of() : List.of(key), key, draftJson, null);
        }
        case "multiple" -> {
            List<String> options = readStringArray(node, "selectedKeys");
            yield new ExamRequests.SubmitAnswerItem(questionId, options,
                    String.join(",", options), draftJson, null);
        }
        case "judge" -> {
            String value = jsonText(node, "value");
            yield new ExamRequests.SubmitAnswerItem(questionId,
                    value == null ? List.of() : List.of(value), value, draftJson, null);
        }
        case "fill" -> {
            String text = joinBlankAnswers(node);
            yield new ExamRequests.SubmitAnswerItem(questionId, List.of(), text, draftJson, null);
        }
        case "code" -> {
            String code = jsonText(node, "code");
            yield new ExamRequests.SubmitAnswerItem(questionId, List.of(), code, draftJson, null);
        }
        default -> {
            String text = jsonText(node, "text");
            yield new ExamRequests.SubmitAnswerItem(questionId, List.of(), text, draftJson, null);
        }
    };
}
```

- 新增私有方法 `List<String> readStringArray(JsonNode node, String field)`：仅被 `multiple` 分支调用，读 `node.get(field)`，非数组返回 `List.of()`，数组元素 `asText()` 后过滤空串。
- 新增私有方法 `String joinBlankAnswers(JsonNode node)`：仅被 `fill` 分支调用，取 `node.get("blanks")` 后按 `index` 升序排序、跳过 `index <= 0` 的项，逐项 `answer.trim()` 后**保留空串**用 `,` 拼接（与前端 `buildCompatibilityAnswerText` 一致，不得过滤空答案）；无 `blanks` 返回 `null`。
- `judge` 分支只调用现有 `jsonText(node, "value")`，不复用 `readStringArray`，避免把单值当数组读取。
- 未识别 `kind`、`kind` 为空、JSON 非对象非数组时，按 TD10 返回全空或原文，不做题型猜测。
- 草稿值为 `null` 且 payload 缺失时，得到全空条目，按「未作答」评分，行为与历史空白题一致。

```java
    ExamSubmission locked = examSubmissionRepository
            .findByExamIdAndStudentIdForUpdate(examId, candidate.getStudentId())
            .orElse(null);
    if (locked == null || locked.getStatus() != ExamSubmissionStatus.GRADED) {
        continue;
    }
    Double lockedScore = locked.getTotalScore();
    scoreRecordWriter.write(BusinessType.EXAM, exam.getId(), locked.getStudentId(),
            exam.getClassId(), lockedScore == null ? 0D : lockedScore, now);
}
return Map.of("released", true, "scoreVisibilityMode", exam.getScoreVisibilityMode().name());
```

- 补写只针对 `GRADED`，阅卷中提交不造记录。
- `ScoreRecordWriter` 已实现「先查后写」，重复调用只更新同一行；并发唯一冲突仍是 `40900`，本期不改。

## 11. 风险与回滚

| 风险 | 处置 |
|---|---|
| 历史 `exam_answer` 存在重复行导致草稿 upsert 触发唯一约束 | 上线前确认 V23 已执行；草稿与交卷共用提交行悲观锁，正常不会并发写入同一题；若存量重复行导致 `DataIntegrityViolationException`，由 `GlobalExceptionHandler` 的通用兜底返回 500，需先清理存量重复行 |
| 草稿保存频率高带来写入压力 | 1500ms 防抖 + 串行队列；单次仅按题 upsert，不触发评分与快照查询 |
| 收紧可见性导致学生暂时看不到分数 | 产品侧同步说明；成绩在 `GRADED` 且模式允许后自然可见 |
| 发布补写与批改并发 | 逐条提交行悲观锁，与批改串行 |
| `LAB` / `HOMEWORK` 成绩列表回归 | resolver 仅对 `EXAM` 追加 `GRADED` 条件；以 `HomeworkServiceTests` / `AnalysisServiceTests` 回归 |
| 回滚 | 代码级回滚即可；无迁移、无数据结构变更、无历史数据写入 |

| 发布补写依赖唯一冲突异常兜底 | `ScoreRecordWriter` 会把冲突转 `40900`，与幂等补写目标冲突；改为先查后写 |
| 在 `submitExam` 先删答案再读草稿 | 删除后草稿不可恢复，改为先读后删 |
| 前端用 `beforeunload` 发起草稿异步保存 | 浏览器不保证请求发出，改为 `visibilitychange=hidden` flush |
| 在 `StudentScoreVisibilityResolver` 统一对所有业务类型追加 `GRADED` | 会改变 `LAB` / `HOMEWORK` 现有可见性，本期只约束 `EXAM` |
| 新建公共答案格式化 / 解码工具文件 | 改动面小，按现有文件内私有方法实现，避免新增抽象 |
