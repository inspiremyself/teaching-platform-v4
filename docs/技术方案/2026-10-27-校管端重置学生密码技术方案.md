# 校管端「重置学生密码」技术方案

**创建日期**：2026-10-27  
**状态**：已定稿（决策写死，可直接编码）  
**范围**：学校管理台学生管理列表新增「重置密码」操作；新增校管重置学生密码接口；操作日志可见  
**非目标**：教师端修改学生密码；强制首登改密闭环；密码加密方案重构（NoOp 现状不动）；批量重置；新增登录会话状态枚举、修改 Filter 40102 文案

## 1. 背景与诉求

### 1.1 现状

学校管理台「学生管理」（`frontend/src/views/admin/Students.vue`）支持新增、编辑（仅姓名 + 班级）、停用/启用、Excel 导入。学生密码只能在**新增/导入时设置一次**（`AdminRequests.CreateStudentRequest.password`），后续无任何修改入口：

- `PUT /api/v1/admin/students/{id}` 的 `UpdateStudentRequest` 只有 `displayName + classId`（`AdminRequests.java:101-105`）。
- 唯一改密接口 `POST /api/v1/auth/change-password`（`AuthController.java:44-48`）只能学生本人凭旧密码修改。

学生遗忘密码时，校管只能删除重建账号，班级成员关系与历史数据都会受影响。

### 1.2 目标

1. 校管在学生列表对单个学生执行「重置密码」，输入新密码即刻生效。
2. 操作进入审计日志，操作日志页可筛选追踪。
3. 改动面收敛在 admin 域，不引入新表、不触碰密码加密现状。

## 3. 重置语义与安全边界

### 3.1 字段处理

| 字段 | 处理 |
|---|---|
| `password_hash` | 更新为 `{noop} + 新密码（trim 后）` |
| `must_change_password` | 显式置 `false` |
| 登录会话 | 该学生当前 `ACTIVE` 会话置 `KICKED` + `invalidated_at=now`；无 ACTIVE 会话则跳过 |
| 其余字段（姓名、班级、状态等） | **一律不动** |

### 3.2 安全边界（写死）

1. **密码不进审计**：`detail` 仅 `Map.of("username", ..., "displayName", ...)`；任何分支（含异常路径）不得打印或落库新密码。
2. **密码不进日志**：Service 与 Controller 不新增任何包含密码的 log 语句。
3. **响应不回显密码**：成功响应仅 `{ "reset": true }`，不返回学生视图（避免响应体携带敏感字段的误判空间，也与 `AuthService.changePassword` 的 `{"changed": true}` 风格对齐）。
4. **trim 后校验与落库一致**：以 trim 后的值做长度校验并存库，杜绝「校验用原值、存库用 trim 值」的口径分裂。

### 3.3 明确不做的内容

| 对象 | 原因 |
|---|---|
| 新增 `LoginSessionStatus` 枚举值 / 修改 Filter 40102 文案 | 「账号已在其他设备登录」文案对被重置密码场景不够精确，但改文案涉及登录冲突链路口径，属独立议题 |
| `must_change_password = true` 强制首登改密 | 决策 #1 已定为直设密码；前端无强制改密跳转流程，启用会造成功能断裂 |
| 教师端重置本班学生密码 | 角色边界变更需独立设计，本期仅校管 |
| 批量重置 | 无产品诉求 |
| 密码加密方案（BCrypt 等） | 独立安全重构议题，改动面覆盖登录、导入、改密全链路 |

## 4. 接口设计

### 4.1 路由

```text
POST /api/v1/admin/students/{id}/password
Content-Type: application/json
```

角色：`SCHOOL_ADMIN`（继承控制器级 `@PreAuthorize`）。

### 4.2 请求 DTO

在 `AdminRequests` 中新增：

```java
public record ResetStudentPasswordRequest(
        @NotBlank(message = "新密码不能为空")
        @Size(min = 6, max = 32, message = "密码长度必须在6到32个字符之间")
        String password
) {
}
```

> 说明：`@Size` 作用于 trim 前的原值；Service 内 trim 后再复核一次长度，防止「空格填充绕过最小长度」（如 `"  1234  "`）。详见 §5.2。

### 4.3 请求示例

```json
{
  "password": "newpass123"
}
```

### 4.4 响应

```json
{
  "code": 0,
  "message": "ok",
  "data": { "reset": true },
  "timestamp": "2026-10-27T18:00:00+08:00"
}
```

### 4.5 错误码

| 场景 | HTTP | code | message |
|---|---|---|---|
| 学生不存在 / 跨校 / 非学生角色 / 无班级归属 | 404 | 40400 | 学生不存在 |
| 非 `SCHOOL_ADMIN` 角色调用 | 403 | 40300 | （安全框架统一） |
| `password` 为空 | 400 | 40000 | 新密码不能为空 |
| 长度不在 6~32 | 400 | 40000 | 密码长度必须在6到32个字符之间 |
| trim 后长度不足 6 | 400 | 40000 | 密码长度必须在6到32个字符之间 |

> 404 而非 403：沿用 `requireStudent` 既有行为（`AdminStudentService.java:169-175`），不暴露学生是否存在于其他学校。

### 5.2 Service 实现

```java
/**
 * 校管重置学生密码。
 *
 * <p>语义：直接覆盖 password_hash，即刻生效；不启用强制首登改密；
 * 同时将该学生当前 ACTIVE 登录会话置为 KICKED，使旧登录态失效。
 * 安全约束：新密码任何分支均不写入审计、日志与响应体。</p>
 */
@Transactional
public Map<String, Object> resetPassword(CurrentUser currentUser, Long studentId,
                                         ResetStudentPasswordRequest request) {
    SysUser student = requireStudent(currentUser, studentId);
    String newPassword = request.password().trim();
    if (newPassword.length() < 6 || newPassword.length() > 32) {
        throw new BusinessException(40000, "密码长度必须在6到32个字符之间");
    }
    student.setPasswordHash("{noop}" + newPassword);
    student.setMustChangePassword(false);
    sysUserRepository.save(student);

    OffsetDateTime now = OffsetDateTime.now();
    userLoginSessionRepository
            .findFirstByUser_IdAndStatusOrderByCreatedAtDesc(studentId, LoginSessionStatus.ACTIVE)
            .ifPresent(session -> {
                session.setStatus(LoginSessionStatus.KICKED);
                session.setInvalidatedAt(now);
                userLoginSessionRepository.save(session);
            });

    auditLogService.log(currentUser, AuditAction.STUDENT_PASSWORD_RESET, AuditResourceType.STUDENT, studentId, Map.of(
            "username", student.getUsername(),
            "displayName", student.getDisplayName()
    ));
    return Map.of("reset", true);
}
```

### 5.3 Controller 实现

```java
@PostMapping("/{id}/password")
public ApiResponse<?> resetPassword(@PathVariable Long id, @Valid @RequestBody ResetStudentPasswordRequest request) {
    CurrentUser currentUser = SecurityUtils.currentUser();
    return ApiResponse.ok(adminStudentService.resetPassword(currentUser, id, request));
}
```

### 5.4 事务与一致性

学生行更新 + 会话置 `KICKED` + 审计写入同一 `@Transactional`；无文件操作，无一致性强边界。审计失败则整体回滚（含会话状态），与 admin 域现有写操作行为一致。

4. 提交中 `submitting` 防重复点击；失败由 `request.ts` 统一报错，弹窗保持打开。

### 7.3 手工验收

1. 校管登录 → 学生管理 → 某学生行点击「重置密码」，输入两次一致新密码，二次确认后提示成功。
2. 退出后用该学生账号 + 新密码可登录；旧密码登录失败。
3. 学生在线时被重置密码，其旧页面下一次请求返回 40102 并被前端踢回登录页（`request.ts` 401 处理）。
4. 停用状态学生同样可重置，重置后启用可正常登录。
5. 两次密码不一致、长度 <6 时前端拦截不发请求。
6. 操作日志页出现 `STUDENT_PASSWORD_RESET` 记录，详情 JSON 中无任何密码明文。

## 8. 验收标准

1. 校管可在学生列表对任意本校学生重置密码，操作列入口与「编辑/停用」并列。
2. 新密码即刻生效，旧密码失效；学生旧登录会话被置 `KICKED`，旧 token 请求返回 40102。
3. 跨校学生、非校管角色调用均被拒绝。
4. 密码 6~32 位校验前后端一致（trim 口径统一）。
5. 审计日志记录操作人、学生 username/displayName，不含密码明文；操作日志页可筛选该动作。
6. `must_change_password` 保持 `false`，登录流程无变化。
7. `cd backend && ./mvnw test` 通过，含新增用例。
8. `cd frontend && npm run build` 通过。
9. 无数据库迁移，`ddl-auto=validate` 启动通过。

## 10. 风险、边界与后续 Phase

| 项 | 说明 | 归属 |
|---|---|---|
| 明文密码存储 | NoOp 现状下校管理论上可经数据库直接看到密码；本功能不改变该风险等级 | 接受（独立安全议题） |
| 被踢学生看到「账号已在其他设备登录」 | 复用 `KICKED` 状态与 40102 文案，对被重置场景不够精确；改文案涉及登录冲突链路口径 | 接受（后续可独立优化文案） |
