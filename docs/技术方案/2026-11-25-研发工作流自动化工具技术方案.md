### 3.2 `.cursor/skills/feature-delivery-pipeline/SKILL.md`（TD2–TD5）

**frontmatter**：只含 `name` 与 `description`，取值按 TD2 写死。

**第 1 节 规范来源与复用规则**，写死四条：
1. 流程规范唯一来源为 `.cursor/rules/feature-dev-workflow.mdc`；自查唯一执行入口为 `.cursor/skills/self-review-and-fix/SKILL.md`；本技能不复制其条款。
2. invoke 任一技能 = 先 Read 该 SKILL.md 全文，再按对应模式执行。
3. 每阶段开始与结束用 `todo_write` 标记状态；未达硬门槛禁止推进下一阶段。
4. 语义判断（方案/实现是否收敛）只由自查技能判定，脚本只提供确定性动作与退出码；禁止为推进阶段放宽 K 门槛、备份门禁或验收标准。

**第 2 节 Stage 0–6 状态机表**（TD4，逐格写死）：

| Stage | 名称 | 进入条件 | 动作 | 硬门槛（未满足禁止推进） | 失败去向 |
|---|---|---|---|---|---|
| 0 | 输入判定 | 用户给出需求描述或指定入口 | 判定三态：缺 PRD → 提示用户补充需求，不臆造 PRD；有 PRD 缺方案 → 起草进 Stage 1；有已定稿方案且无实现 diff → Stage 2；已有实现 diff → Stage 3 | 判定结果已写入 `todo_write` | 判定歧义时停下问用户 |
| 1 | 方案收敛 | 需要起草或修订技术方案 | 按 `tech-spec-decisive.mdc` 写 `docs/技术方案/YYYY-MM-DD-<主题>.md` → invoke `self-review-and-fix` 方案模式 | 技能判定收敛且方案文首为「已定稿」 | 未收敛继续开轮，禁止进 Stage 2 |
| 2 | 编码 | Stage 1 收敛 | 严格按方案文件清单编码；按 `code-conventions.mdc` §2 路由读对应细则；遇 Flyway / 清库 / 覆盖库先过备份门禁 | 只改方案列出文件；备份门禁已过（如涉及） | 范围外需求停下问用户 |
| 3 | 实现收敛 | 编码完成 | invoke `self-review-and-fix` 实现模式 | 技能判定收敛 | 未收敛继续开轮，禁止进 Stage 4 |
| 4 | 门禁 | Stage 3 收敛 | `bash scripts/dev/gate.sh`（无参数，按 `git status --porcelain` 判侧；仅端到端验证需强制单侧时用显式参数） | 退出码 0 且 stdout 含 `[PASS]` | FAIL → 回 Stage 3，问题点重新计数 |
| 5 | 环境验收 | Stage 4 PASS | `bash scripts/dev/env-up.sh` | 退出码 0 且 stdout 含 `[PASS]` | `[ENV]` → 暂停并提示用户处理，用户处理后从 Stage 5 重试；`[CODE]` → 回 Stage 3 重新计数 |
| 6 | 交付 | Stage 5 PASS | `bash scripts/dev/delivery.sh --prepare --spec <方案路径>` → 对输出验收清单逐条标注「需浏览器人工验收」或「本次已自动验证」→ 展示报告 | 报告已展示 | 缺 `--spec` 退出非 0 → 补参数重跑 |

**第 3 节 硬门槛与失败回退**：把表中三条回退规则展开写死——① 门禁 FAIL 与 Stage 5 `[CODE]` FAIL 回 Stage 3 且问题点重新计数；② Stage 5 `[ENV]` FAIL 暂停提示用户（如停掉占用进程），不回 Stage 3、不重新计实现问题点；③ 全流程不执行 `git push`、不 `kill` 进程、不改端口配置。

**第 4 节 脚本调用契约**：写死三个脚本的路径、参数、输出前缀（`[PASS]` / `[FAIL]` / `[SKIP]` / `[ALREADY_RUNNING]`）与退出码解读规则（只读退出码，禁止把命令输出当「已通过」证据）；写死「禁止现场拼 lint/test/build/启动命令，一律走脚本」。

**第 5 节 交付边界**：Stage 6 展示报告后流程结束；commit message 建议遵循「写为什么」；提交与推送由用户自行执行（现网用户级 `permissions.deny` 已禁 `git push`）。

### 3.3 `scripts/dev/gate.sh`（TD6）

**参数解析**：用 `case "$1" in` 逐参数解析 `--frontend` / `--backend` / `--all` / `--help`（参数仅 4 个，不引入 `getopts`）；多于一个模式参数时打印 usage 并退出 2。

**模式判定**：
- 无参数（默认）：`git status --porcelain -- frontend` 非空 → frontend 侧跑；`git status --porcelain -- backend` 非空 → backend 侧跑（porcelain 含 untracked，天然覆盖新文件）；无改动侧打印 `[SKIP] frontend 无改动` / `[SKIP] backend 无改动`。
- 显式 `--frontend` / `--backend` / `--all`：强制跑指定侧，不做跳过判定、无 `[SKIP]` 输出。

**命令序列**（对齐 `feature-dev-workflow.mdc` §3）：
- frontend 侧：`cd frontend && npm run lint` → `npm test` → `npm run build`，三命令顺序执行。
- backend 侧：`cd backend && ./mvnw test`。

**执行与汇总**：
- 每个子命令执行前打印 `[GATE] <侧> <命令名> 开始`；结束后打印 `[GATE] <侧> <命令名> OK` 或 `[GATE] <侧> <命令名> FAIL(退出码 N)`（N 为该命令真实退出码，经 `cmd || rc=$?` 捕获）；任一命令非 0 即停止本侧后续命令；`--all` 或自动判侧双侧执行时任一侧失败后**不再执行另一侧**。
- 全部结束后：任一失败 → 输出 `[FAIL] gate: <首个失败命令> 退出码 N`，退出 1；无失败 → 输出 `[PASS] gate`，退出 0（两侧均 `[SKIP]` 时同样 `[PASS]` 退出 0）。
- **超时落地**：不实现单命令强制超时（macOS 无 `timeout`，引入 coreutils 属新增依赖）；「失败原因写入 stdout」由上述 `FAIL(退出码 N)` 与 `[FAIL]` 汇总行承担；若调用方（技能/用户）侧会话超时，由调用方按 FAIL 处理。
- 幂等：只执行读与构建类命令，不写仓库文件；重复执行不产生副作用。

### 3.4 `scripts/dev/env-up.sh`（TD7）

**可覆盖环境变量**（对齐既有脚本约定）：`BACKEND_PORT=${BACKEND_PORT:-8080}`、`FRONTEND_PORT=${FRONTEND_PORT:-5173}`；调用子脚本时透传 `SERVER_PORT=$BACKEND_PORT`、`VITE_API_TARGET=http://localhost:${BACKEND_PORT}`。

**步骤（顺序写死）**：
1. **后端端口检测**：`lsof -nP -iTCP:${BACKEND_PORT} -sTCP:LISTEN` 有输出 → 后端已在监听，记 `BACKEND_ALREADY=1`，跳过启动；无输出 → `nohup bash scripts/path-b/backend.sh >/tmp/teaching-platform-dev-backend.log 2>&1 &`，stdout 打印 `backend started pid=<PID>`，轮询 `lsof` 每 3 秒一次，上限 180 秒；超时未监听 → 输出 `[FAIL] [ENV] 后端 ${BACKEND_PORT} 端口未就绪（占用方: $(lsof -nP -tiTCP:${BACKEND_PORT} -sTCP:LISTEN | head -n1)，为空时输出「占用方: 无」），日志 /tmp/teaching-platform-dev-backend.log`，退出 1。
2. **后端归属预检（仅在端口已有监听时执行）**：`resp=$(curl -s -w '\n%{http_code}' -X POST http://localhost:${BACKEND_PORT}/api/v1/auth/login -H 'Content-Type: application/json' -d '{}')`，取末行为 HTTP 状态、其余为响应体——状态 `400` 且响应体含 `"code":40000`（本平台统一响应的参数校验指纹，2026-11-25 现网实测）→ 判定为本平台后端，继续步骤 3；其余任何结果（`000` / `404` / `200` / `501` / 其他状态或响应体）→ 判定端口被非本平台进程占用，输出 `[FAIL] [ENV] 端口 ${BACKEND_PORT} 被非本平台进程占用（占用方 PID: $(lsof -nP -tiTCP:${BACKEND_PORT} -sTCP:LISTEN | head -n1)）`，退出 1。新拉起的后端跳过本预检，直接由步骤 3 的 healthcheck 验证。
3. **后端健康验证**：`bash scripts/common/healthcheck-login.sh`（默认教师账号，脚本内置 `FORCE_LOGIN=true`）；非 0 → 输出 `[FAIL] [CODE] healthcheck 登录失败（HTTP/业务码见上）`，退出 1。
4. **前端端口检测**：`lsof` 同法探 `${FRONTEND_PORT}`；已在监听 → 记 `FRONTEND_ALREADY=1`；未监听 → `nohup bash scripts/path-b/frontend.sh >/tmp/teaching-platform-dev-frontend.log 2>&1 &`，stdout 打印 `frontend started pid=<PID>`，轮询 `curl -sf -o /dev/null http://localhost:${FRONTEND_PORT}/` 每 3 秒一次，上限 60 秒；超时 → `[FAIL] [ENV] 前端端口未就绪…`，退出 1。
5. **前端 HTTP 探活**：`curl -s -o /dev/null -w '%{http_code}' http://localhost:${FRONTEND_PORT}/` 非 200 → `[FAIL] [ENV] 前端 HTTP 非 200`，退出 1。

**汇总输出**：两服务均就绪 → `[PASS] env-up（backend: started|already, frontend: started|already）`，退出 0；两服务均已就绪时额外输出 `[ALREADY_RUNNING]`。全程不 `kill` 任何进程、不改端口配置、不使用 mock 服务。

### 3.5 `scripts/dev/delivery.sh`（TD8/TD9）

**用法**：`./scripts/dev/delivery.sh --prepare --spec docs/技术方案/<文件>.md`。用 `case "$1" in` 逐参数解析（与 gate.sh 同法）；`--prepare` 必为首个参数；`--spec` 必传，缺失或文件不存在时打印 usage 并退出 2。除 `--prepare` 外不实现任何子命令。

**输出三节（纯 stdout，不写文件）**：
1. `## Commit message 建议`：按 `git status --porcelain` 改动路径输出模板——frontend 独改 → `type(frontend): `，backend 独改 → `type(backend): `，双改 → `type(fullstack): `；`type` 由技能按方案语义填（feat/fix/refactor/docs）；模板行下附两行占位「<为什么>」与「- <要点 1>」。
2. `## Diff 摘要`：`git diff --stat` 原文 + `git status --porcelain` 中 untracked 文件清单。
3. `## 验收清单`：awk 提取 `--spec` 文件中首个匹配 `^#{1,3} .*验收标准` 的标题行至下一个顶格 `^## ` 标题（不含）之间的内容，逐行转为 `- [ ] <原文>`；未匹配到该节 → 报错「spec 中未找到验收标准节」退出 2。

**约束**：不执行 `git add` / `commit` / `push` / `config` 等任何 git 写操作（`git diff` / `status` 只读）；脚本源码不出现 `--push` / `--commit` / `--add` 字符串。

## 7. 风险与回滚

| 风险 | 控制 |
|---|---|
| 端口被非本平台进程占用被误判为「已在运行」 | healthcheck / HTTP 200 归属验证兜底；失败归 `[ENV]`/`[CODE]` 并打印占用方 PID 与日志路径 |

| 脚本误操作进程或数据 | 三脚本均为只读/构建/探活类；不 kill、不写 git、不写仓库文件 |
| 回滚 | 纯新增资产：删除 5 个新增文件、还原 `docs/运维文档/README.md` 追加的 1 行索引即可；无数据库与迁移回滚；无 Hook 配置可删 |
