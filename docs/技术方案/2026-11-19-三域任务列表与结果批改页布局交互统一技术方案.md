## 3. 架构设计（模式落地）

### 3.1 分层与依赖方向

```text
页面薄壳（List.vue / Homeworks.vue / Labs.vue，零改动）
   │ provide/inject 既有 InjectionKey
   ▼
域 composable（useExamList / useHomeworks / useLabs）─ 保留表单与提交
   │ 委派
   ▼
Facade: workbench/useWorkbench.ts
   │                     │                    │
   ▼                     ▼                    ▼
taskAdapters.ts   submissionAdapters.ts  taskActionStrategies.ts
   │                     │
   └──────────► workbench/types.ts ◄────────────┘
                     ▲
                     │ 页面只引用类型
既有共享层（不改）：scoreDisplay.ts / scoringStrategies.ts / gradingDraft.ts
```

- 模板 SFC 与共享 UI 位于同目录，样式由 `workbench.css` 统一 import。
- Facade 不 import `api/`；取数函数以回调注入。页面 / composable 仍通过既有 `@/api` 模块取数，遵守 `frontend-api-contract.mdc`。
- 域差异只存在于 Adapter 映射表与 Strategy 操作表；模板与 Facade 内不允许出现 `if (domain === 'LAB')` 业务分支（回调注入不算域分支）。

### 3.3 Adapter：`taskAdapters.ts` 逐字段映射

唯一导出 `taskAdapterOf(domain: WorkbenchDomain): TaskAdapter`。

```ts
export interface TaskRowVM {
  id: number
  title: string
  status: string
  statusLabel: string
  className: string
  startAt: string | null
  endAt: string | null
  submissionCount: number | null
  itemCount: number | null
  description: string
  raw: any
}
export interface TaskFilterSnapshot {
  classId: number | null
  status: string
  deadlineBucket: 'ALL' | 'UPCOMING' | 'OVERDUE' | 'UNDATED'
}
export interface TaskAdapter {
  adapt(raw: any): TaskRowVM
  filtersOf(raw: any): TaskFilterSnapshot
}
```

| `TaskRowVM` 字段 | EXAM `ExamListItem` | HOMEWORK `HomeworkListItem` | LAB `LabItem` |
|---|---|---|---|
| `id` | `id` | `id` | `id` |
| `title` | `title` | `title` | `title` |
| `status` | `status` | `status` | `status` |
| `statusLabel` | `DRAFT`→草稿、`PUBLISHED`→已发布、`CLOSED`→已关闭、其余→未知 | 同左 | 同左 |
| `className` | `className ?? '未分配班级'` | `className ?? '未分配班级'` | `className ?? '未分配班级'` |
| `startAt` | `startAt ?? null` | `startAt ?? null` | `startAt ?? null` |
| `endAt` | `endAt ?? null` | `dueAt ?? null` | `dueAt ?? null` |
| `submissionCount` | `submissionCount ?? 0` | `submissionCount ?? 0` | `null`（接口无此字段） |
| `itemCount` | `questionCount ?? null` | `null`（接口无此字段） | `stepCount ?? null` |
| `description` | `description ?? ''` | `description ?? ''` | `description ?? ''` |
| `raw` | 原始对象 | 原始对象 | 原始对象 |

`filtersOf`：三域统一返回 `{ classId: row.classId ?? null, status: row.status, deadlineBucket: bucketOf(row.endAt ?? dueAt) }`；`bucketOf` 按 TD9。`adapt(null)` 返回 `{ id:0, title:'', status:'', statusLabel:'未知', className:'未分配班级', startAt:null, endAt:null, submissionCount:null, itemCount:null, description:'', raw:null }`，不抛异常。`raw` 仅供 `actionsOf` 注入的 handler 读取原始行，模板禁止绑定 `row.raw` 的任何字段；ESLint 基线已关闭 `no-explicit-any`，此处 `any` 不新增例外。

### 3.4 Adapter：`submissionAdapters.ts` 逐字段映射

唯一导出 `submissionAdapterOf(domain: WorkbenchDomain): SubmissionAdapter`。

```ts
export interface QueueItemVM {
  id: number | string
  studentName: string
  status: string
  statusLabel: string
  objectiveScore: number | null
  manualScore: number | null
  totalScore: number | null
```

| `QueueItemVM` 字段 | EXAM `ExamSubmissionListItem` | HOMEWORK `HomeworkSubmissionItem` | LAB `LabReportItem` |
|---|---|---|---|
| `id` | `submissionId` | `id` | `id` |
| `studentName` | `studentName` | `studentName` | `studentName ?? studentUsername ?? '未知学生'` |
| `status` | `status`（IN_PROGRESS / SUBMITTED / AUTO_SUBMITTED / GRADED） | `submitStatus`（SAVED / SUBMITTED / GRADED） | `submitStatus ?? 'SAVED'` |

| `totalScore` | `totalScore ?? null` | `totalScore ?? null` | `totalScore ?? null` |
| `draftFlag` | 由 Facade 注入 | 同左 | 同左 |

`backfillQueueScores` 只改匹配 id 的一项，`objectiveScore = summary.autoScore`、`manualScore = summary.manualScore`，其余字段原样保留；不匹配返回原数组。`adapt(null)` 返回全空项（`id:''`、状态「未知」、三段 `null`、`draftFlag:false`）。

### 3.5 Strategy：`taskActionStrategies.ts`

唯一导出 `taskActionStrategyOf(domain: WorkbenchDomain, status: string): TaskActionStrategy`。

```ts
export interface TaskActionVM {
  key: 'steps' | 'viewResult' | 'edit' | 'publish' | 'close'
  label: string
  tone: 'ghost' | 'success' | 'warning' | 'primary'
  handler: (row: TaskRowVM) => void
}
export interface TaskActionStrategy {
  actions: TaskActionVM[]
  primaryKey: 'viewResult'
}
```

`handler` 由调用方注入，策略表只固定 `key` / `label` / `tone`。标签写死：`steps`=步骤配置、`viewResult`=查看结果、`edit`=编辑、`publish`=发布、`close`=关闭。色调写死：`viewResult`=primary，`edit` / `steps`=ghost，`publish`=success，`close`=warning。

| 域 / 状态 | 操作数组（顺序固定，最多 4 个） |
|---|---|
| EXAM / DRAFT | `[viewResult, edit, publish]` |
| EXAM / PUBLISHED | `[viewResult, close]` |
| EXAM / CLOSED | `[viewResult]` |
| HOMEWORK / DRAFT | `[viewResult, edit, publish]` |
| HOMEWORK / PUBLISHED | `[viewResult, edit, close]` |
| HOMEWORK / CLOSED | `[viewResult, edit]` |
| LAB / DRAFT | `[steps, viewResult, edit, publish]` |
| LAB / PUBLISHED | `[steps, viewResult, edit, close]` |
| LAB / CLOSED | `[steps, viewResult, edit, publish]`（实验允许重新发布） |

- 未知状态统一按 `[viewResult]` 返回，不抛异常。
- 状态切换的前置校验仍由注入的 `publish` / `close` handler 执行（考试 `validateTimeWindow`、实验 `stepCount > 0`、作业班级锁定），策略不复制校验。
- 实验 `CLOSED` 的 `publish` 标签与 `DRAFT` 相同，目标状态由注入 handler 写死为 `PUBLISHED`。

### 3.6 Facade：`useWorkbench.ts`

```ts
export function useWorkbenchList<T>(options: {
  domain: WorkbenchDomain
  fetchRows: () => Promise<T[]>
  handlers: {
    viewResult(row: TaskRowVM): void
    edit(row: TaskRowVM): void
    publish(row: TaskRowVM): void | Promise<void>
    close(row: TaskRowVM): void | Promise<void>
    steps(row: TaskRowVM): void
  }
}): {
  rows: Ref<TaskRowVM[]>
  filteredRows: ComputedRef<TaskRowVM[]>
  filters: { keyword: Ref<string>; status: Ref<string>; classId: Ref<number | null>; deadlineBucket: Ref<DeadlineBucket> }
  classOptions: ComputedRef<{ id: number; label: string }[]>
  meta: ComputedRef<WorkbenchMeta>
  actionsOf(row: TaskRowVM): TaskActionVM[]
  refresh(): Promise<void>
}

export interface DraftPort<TDetail, TDraft> {
  create(detail: TDetail): TDraft
  setScore(draft: TDraft, key: string, score: number | null): void
  setComment(draft: TDraft, key: string, comment: string): void
  hasChanges(draft: TDraft): boolean
  commit(draft: TDraft): void
  forSummary(draft: TDraft): Pick<GradingDraftState, 'scores' | 'marked'>
}

export function createSharedDraftPort<TDetail>(
  itemsOf: (detail: TDetail) => DraftItem[],
): DraftPort<TDetail, GradingDraftState>

export function useGradingWorkspace<TDetail, TDraft>(options: {
  domain: WorkbenchDomain
  loadQueue: () => Promise<unknown[]>
  loadDetail: (id: number | string) => Promise<TDetail>
  scoreLinesOf: (detail: TDetail) => ScoreLineItem[]
  draftPort: DraftPort<TDetail, TDraft>
  statusOf: (detail: TDetail) => string | null | undefined
  isReadOnly: (status: string | null | undefined) => boolean
  handlers: {
    saveGrade(detail: TDetail, draft: TDraft): Promise<void>
    saveAnswerGrade?(detail: TDetail, key: string): Promise<void>
    returnSubmission?(detail: TDetail): Promise<void>
    releaseScores?(): Promise<void>
  }
}): {
  queue: Ref<QueueItemVM[]>
  filteredQueue: ComputedRef<QueueItemVM[]>
  keyword: Ref<string>
  statusFilter: Ref<string>
  selectedId: Ref<number | string | null>
  detail: Ref<TDetail | null>
  draft: Ref<TDraft | null>
  summary: ComputedRef<ScoringSummary>
  readOnly: ComputedRef<boolean>
  setScore(key: string, score: number | null): void
  setComment(key: string, comment: string): void
  selectSubmission(id: number | string): Promise<boolean>
  guardBeforeSwitch(action: () => void | Promise<void>): Promise<boolean>
  save(): Promise<void>
  saveAnswer(key: string): Promise<void>
  returnSubmission(): Promise<void>
  releaseScores(): Promise<void>
  refresh(): Promise<void>
}
```

行为约束：

1. `classOptions` 由 `rows` 按 `classId` 去重生成，不再额外请求班级接口；三域列表接口仍在 composable 里并行加载班级供编辑表单使用。
2. `filters` 为本地筛选，`keyword` 匹配标题 / 描述 / 班级名（均 `trim().toLowerCase()`），其余按 TD9 与状态 / 班级相等比较。
3. `meta` 六项按 TD10 / TD11 计算，`当前任务提示` 文案固定为 `当前筛选 x / y`。
4. `selectSubmission` 先执行 `guardBeforeSwitch`，通过后 `++selectionToken`，再 `loadDetail`；返回时 token 不等则丢弃结果。成功后用 `scoreLinesOf` 重建逐题行，用 `draftPort.create` 重建草稿，`summary` 用 `draftPort.forSummary(draft)` 调 `buildScoringSummary`，并调用 `backfillQueueScores`。
5. `draftFlag` 只对当前选中项注入：Facade 维护 `dirtyIds` 集合；`setScore` / `setComment` 调用 `draftPort` 后按 `draftPort.hasChanges` 加入或移除当前 id，再重建队列视图；其他项恒 `false`。
6. `save()` 调注入的 `saveGrade(detail, draft)`，成功后 `draftPort.commit(draft)`、`dirtyIds` 删除当前 id、刷新队列与详情，停留当前项；失败保留草稿。确认弹窗由注入 handler 负责，文案按 11-19 PRD D10。
7. `useGradingWorkspace` 不调用 `ElMessage` / `ElMessageBox` 以外的 UI，不创建路由跳转；所有业务动作由注入回调承担。
8. `readOnly` 固定由 `isReadOnly(statusOf(detail.value))` 计算；考试传详情 `status`，作业与实验传详情 `submitStatus`。
9. `saveAnswer(key)` / `returnSubmission()` / `releaseScores()` 分别委派注入的同名 handler；考试不注入后两者时调用直接返回，不产生动作。考试与作业必须为 `steps` 注入空函数，因它们的策略表不产生该动作。
10. `refresh()` 先重载队列并 `++selectionToken`，再以当前 `selectedId` 重载详情；`selectedId` 为 `null` 时自动选中第一条队列项。左队列条目点击走 `selectSubmission(id)`；实验批量页「上一个 / 下一个学生、班级」仍执行现网 `router.push`，页面路由 `watch` 先把 `selectedId` 改为新路由 id，再调用 `refresh()`，不改为原地切换。
11. 作业与实验注入 `createSharedDraftPort(itemsOf)`，页面提供从当前详情生成 `DraftItem[]` 的函数（作业取 `questions`，实验取 `answers || items`）；Port 内部只调用既有 `createGradingDraft` / `setDraftScore` / `setDraftComment` / `hasDraftChanges` / `commitDraft`，`forSummary` 返回原 draft 的 `scores` 与 `marked`。
12. 考试在 `Results.vue` 内注入 `examDraftPort`，对接现网 `GradingSnapshot`：`create` = `createGradingState`，`setScore` = `setQuestionScore`（key 用 `Number(key)`），`setComment` 写 `snapshot.gradeMap[Number(key)].teacherComment`，`hasChanges` = `hasUnsavedChanges`，`commit` 为空函数（保存后由 `refresh()` 重建快照），`forSummary` 把 `gradeMap` 转 `scores`、把 `markedQuestionIds` 转 `marked`。`examGradingState.ts` 零改动，`buildGradePayload(snapshot)` 仍在保存 handler 内调用。

## 5. 交互时序与状态约束

1. **列表筛选**：用户输入 → Facade 更新 `filters` → `filteredRows` 重算 → 统计 chip 同步；不触发网络请求。
2. **查看结果**：操作列点击 → 注入的 `viewResult` handler 执行现网 `router.push`，路由不改名。
3. **切换答卷**：点击队列条目 → `selectSubmission` → `guardBeforeSwitch`（有草稿弹确认）→ token 自增 → `loadDetail` → 生成 `scoreLines` / `draft` / `summary` → 回填当前队列项 → 渲染中栏与右栏。取消切换时保持当前详情不变。
4. **保存**：逐题保存走域注入 handler，不弹整卷确认；整卷保存由 handler 弹现网确认文案，成功后 `draftPort.commit(draft)` 并刷新，停留当前项。
5. **打回**：不经过 `guardBeforeSwitch`，直接调用域 handler 的独立确认；成功后清空草稿并刷新队列。
6. **发布成绩**：考试与作业从结果页 `headerActions` 发起，调用现网 API；实验无此按钮。
7. **只读态**：`isReadOnly` 复用 `isReadOnlySubmission(domain, status)`；禁用态控件灰化，`GRADED` / `SAVED` / `IN_PROGRESS` 不可评分，继承 11-19 PRD D4。
8. **守卫单一入口**：考试 `confirmDiscardDraft`、作业 `guardDraft`、实验评分台与批量页 `guardDraft` 保留函数名称，内部一律委派 Facade `guardBeforeSwitch`；页面不得再自行弹同一确认框，避免双重确认。打回确认不经过该入口。
