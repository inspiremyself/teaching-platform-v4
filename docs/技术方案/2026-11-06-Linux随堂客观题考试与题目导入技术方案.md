## 5. 后端改造

### 5.1 DTO：`ExamRequests`

文件：`backend/src/main/java/com/opencode/teachingplatform/exam/dto/ExamRequests.java`

`ExamQuestionItem` 收敛为 4 个字段：

```java
public record ExamQuestionItem(
        Long questionId,
        String sourceType,
        @NotNull Integer sortOrder,
        @NotNull Double questionScore
) {
    public ExamQuestionItem(Long questionId, Integer sortOrder, Double questionScore) {
        this(questionId, "BANK", sortOrder, questionScore);
    }

    public String resolvedSourceType() {
        return sourceType == null || sourceType.isBlank() ? "BANK" : sourceType;
    }

    @AssertTrue(message = "考试题目必须来自题库")
    public boolean isValidConfig() {
        return questionId != null && "BANK".equalsIgnoreCase(resolvedSourceType());
    }
}
```

要点：

- 移除 `@NotNull` 标注在 `questionId` 上，避免 `MethodArgumentNotValidException` 先抛「must not be null」，保证文案统一为「考试题目必须来自题库」。
- 删除 `questionType` / `stem` / `optionsJson` / `answerJson` / `scoringConfigJson` 五个字段。
- 保留 3 参构造，既有测试与服务调用可继续编译。
- **`questions` 字段必须补 `@Valid`**（`CreateExamRequest` / `UpdateExamRequest` 各一处，`ExamRequests` 顶部新增 `import jakarta.validation.Valid;`）：现网 `@RequestBody` 已有 `@Valid`，但 record 内的 `List<ExamQuestionItem>` 没有级联注解，`ExamQuestionItem` 上的 `@AssertTrue` 目前实际不执行。补 `@Valid` 后三层阻断才与 TD8 一致。
- `CreateExamRequest` 与 `UpdateExamRequest` 末尾各追加 `Boolean shuffleQuestions`：

```java
public record CreateExamRequest(
        @NotBlank String title,
        String description,
        @NotNull Long classId,
        OffsetDateTime startAt,
        OffsetDateTime endAt,
        @NotNull Integer durationMinutes,
        @NotBlank String status,
        ScoreVisibilityMode scoreVisibilityMode,
        @Valid List<ExamQuestionItem> questions,
        Boolean shuffleQuestions
) {}

public record UpdateExamRequest(
        @NotBlank String title,

        OffsetDateTime startAt,

```

- PRD §15.3 的 curl 示例仍携带 `sourceType: "BANK"`，该字段保留；调用方即使误传已删除的 `questionType` / `stem`，也会被 Spring Boot 默认的 `FAIL_ON_UNKNOWN_PROPERTIES=false` 忽略。

```ts
import type { ImportParseResult, ImportPreviewRow } from '@/types/question-import'

export function normalizeImportCode(code: string): string {
  return code.trim().toUpperCase()
}

export function parseImportJson(
  text: string,
  existingCodes: Set<string>,
): { result: ImportParseResult | null; fatalError: string }
```

`parseImportJson` 执行顺序：

1. `text.trim()` 为空 → `fatalError = '请粘贴题目 JSON'`。
2. `JSON.parse` 失败 → `fatalError = 'JSON 解析失败：' + 原始错误信息`（浏览器错误信息包含位置）。
3. 根节点不是数组 → `fatalError = '根节点必须是数组'`。
4. 数组长度为 0 → `fatalError = '至少需要一道题目'`。
5. 逐行执行单题校验，产出 `ERROR` / 候选通过行。

单题阻断性校验（任一条不通过即 `ERROR`，记录第一条失败原因）：

| 序号 | 校验 | 失败文案 |
|---|---|---|
| 1 | 元素是对象 | `第 N 行：题目必须是对象` |
| 2 | `code` 为字符串且 `trim()` 后非空 | `code 不能为空` |
| 3 | 规范化后长度 ≤ 64 | `code 长度不能超过 64 个字符` |
| 4 | `stem` 为字符串且 `trim()` 后非空 | `stem 不能为空` |
| 5 | `type` ∈ `SINGLE` / `MULTI` / `JUDGE` | `type 必须为 SINGLE / MULTI / JUDGE` |
| 6 | `difficulty` 缺省补 `EASY`；出现时必须 ∈ `EASY` / `MEDIUM` / `HARD` | `difficulty 必须为 EASY / MEDIUM / HARD` |
| 7 | `score` 缺省补 `2`；出现时必须为大于 0 的整数 | `score 必须为正整数` |
| 8 | `options` 缺省：`JUDGE` 补 `T/F`；`SINGLE` / `MULTI` 报错 | `选择题必须提供 options` |
| 9 | `options` 为数组且长度 ≥ 2 | `options 至少 2 个` |
| 10 | 每个 `key` 与 `content` 为字符串，`key` 去空格转大写后非空，`content` `trim()` 后非空 | `options.content 不能为空` |
| 11 | `key` 不重复 | `options.key 重复：X` |
| 12 | `JUDGE` 的 key 集合恰为 `{T, F}` | `判断题 options 的 key 必须为 T / F` |
| 13 | `answer` 为数组且非空 | `answer 不能为空` |
| 14 | `JUDGE` 答案每项必须 ∈ `{T, F}`（先于通用 key 归属校验，保证 `true` / `false` 得到判断题专属文案） | `判断题答案必须为 T / F` |
| 15 | `answer` 每项去空格转大写后存在于 options key 中 | `答案 key 不在选项中：X` |
| 16 | `SINGLE` 答案恰好 1 个 | `单选题答案必须恰好 1 个` |
| 17 | `MULTI` 答案至少 1 个（已被第 13 条覆盖，保留显式分支） | `多选题答案至少 1 个` |
| 18 | `analysis` 缺省补空字符串；出现时必须为字符串 | `analysis 必须为字符串` |

候选通过行再判重（顺序固定）：

1. `normalizeImportCode(code)` 已在本份 JSON 更早的 `READY` 行出现 → `SKIP`，`message = '跳过：JSON 内重复编码'`。
2. `existingCodes.has(normalizeImportCode(code))` → `SKIP`，`message = '跳过：题库已存在该编码'`。
3. 均未命中 → `READY`。

- 已判 `SKIP` 的行不占用后续重复判定（因为它本身不导入）。
- `READY` 行的 `draft` 使用规范化后的 `code`、`options[].key`、`answer[]`。

#### 6.6.1 洗牌工具

```ts
function fnv1a32(input: string): number {
  let hash = 0x811c9dc5
  for (let i = 0; i < input.length; i += 1) {
    hash ^= input.charCodeAt(i)
    hash = Math.imul(hash, 0x01000193)
  }
  return hash >>> 0
}

function mulberry32(seed: number): () => number {
  let state = seed >>> 0
  return () => {
    state = (state + 0x6d2b79f5) >>> 0
    let t = state
    t = Math.imul(t ^ (t >>> 15), t | 1)
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61)
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296
  }
}

export function shuffleExamQuestions<T extends { sortOrder?: number | null }>(
  questions: T[],
  seedKey: string,
): T[] {
  if (questions.length <= 1) return [...questions]
  const ordered = [...questions].sort((a, b) => (a.sortOrder ?? 0) - (b.sortOrder ?? 0))
  const random = mulberry32(fnv1a32(seedKey))
  for (let i = ordered.length - 1; i > 0; i -= 1) {
    const j = Math.floor(random() * (i + 1))
    ;[ordered[i], ordered[j]] = [ordered[j], ordered[i]]
  }
  return ordered
}
```

- 只用 `Math.imul`、`>>> 0`、`Math.floor`，跨浏览器结果一致。
- 先按 `sortOrder` 排序再洗牌，重复调用结果不变（幂等）。
- 题库题 `sortOrder` 必定存在；缺省按 0 处理不改变组卷内相对顺序。

## 8. 关键算法与伪代码

### 8.1 学生题目顺序

```text
输入：questions（组卷顺序）、studentId、examId、shuffleQuestions
若 shuffleQuestions !== true → 直接返回 questions
seed = fnv1a32(`${studentId}:${examId}`)
rand = mulberry32(seed)
ordered = questions 按 sortOrder 升序
for i from ordered.length - 1 down to 1:
    j = floor(rand() * (i + 1))
    swap(ordered[i], ordered[j])
返回 ordered
```

- 题号 = 洗牌后数组下标 + 1。
- 提交与评分按 `questionId` 关联，不受顺序影响。

### 8.2 导入流水线

```text
文本 → trim 为空？→ fatal「请粘贴题目 JSON」
     → JSON.parse 失败 → fatal「JSON 解析失败：<原始信息>」
     → 非数组 → fatal「根节点必须是数组」
     → 空数组 → fatal「至少需要一道题目」
     → 逐行阻断校验（§6.3.2 表）
     → 通过行判 JSON 内重复 → SKIP
     → 通过行判教师题库重复 → SKIP
     → READY
     → 汇总：readyCount / skipCount / errorCount
     → errorCount > 0 或 readyCount === 0 → 禁止提交
     → 按行顺序串行 POST /questions（silent）
     → 40900 → SKIPPED；其他错误 → FAILED；成功 → SUCCESS
     → 至少 1 条 SUCCESS → emit('imported')
```

### 8.3 判断题兼容判定

```text
options = JSON.parse(optionsJson) 失败 → 不兼容
options 非数组 → 不兼容
keys = options.map(o => String(o.key).trim().toUpperCase())
keys 长度 !== 2 或 不包含 T 或 不包含 F → 不兼容
answer = JSON.parse(answerJson) 失败 → 不兼容
answer 非数组或为空 → 不兼容
answer 存在非 T/F 项 → 不兼容
否则兼容
```

## 11. 验收标准

### 11.1 导入

- [ ] 题库页存在「批量导入」入口，且为唯一入口。
- [ ] 合法 JSON 完整预览；非法 JSON、缺字段、答案越界均被阻止。
- [ ] 重复编码（含仅大小写不同）被判为跳过并在结果中列出。
- [ ] 待导入数量为 0 或存在错误时不能提交。
- [ ] 导入进行中无法重复提交或关闭弹窗。
- [ ] 导入成功的题目出现在题库列表，编码、题型、题干、答案、解析正确。
- [ ] 判断题导入后学生作答判分正确。

### 11.2 建卷

- [ ] 「题目乱序」开关存在，默认关闭，编辑回显正确。
- [ ] 未选择任何题目时点击保存被拦截并提示「请至少选择一道题目」。
- [ ] 新建考试成绩可见性默认「交卷后立即可见」，下拉只有两项。

- [ ] 含内联题的试卷无法保存或发布，提示「请先将题目保存到题库后再组卷」。
- [ ] 主观题 + `IMMEDIATE` 保存前出现警告，且可继续保存。

### 11.3 学生考试

- [ ] 未开启乱序时所有学生顺序一致。
- [ ] 开启乱序时 20 题、10 名学生至少出现两种顺序。

- [ ] 纯客观题 + `IMMEDIATE` 交卷后立即显示总分。

- [ ] 教师端成绩与学生端（可见时）一致。
- [ ] 乱序考试评分结果与不开启乱序一致。

## 13. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 洗牌算法被后续修改 | 历史场次题序与讲评资料不一致 | 种子公式与算法冻结；变更须新增 `shuffle_version` |
| 洗牌仅前端 | 接口仍返回原始顺序 | 正常界面不暴露原始顺序；风险可接受 |
| 导入无事务 | 网络中断导致部分成功 | 结果区列出失败项，可重复导入（重复项自动跳过） |
| 导入逐条请求 | 50 题产生 50 次 HTTP | 题目数量级为百级，串行可接受；进度条保证可感知 |
| 学生解析逐题查库 | 单场百题产生百次 PK 查询 | 与现网教师分支一致，规模可控 |
| 存量小写编码在 H2 下判重大小写敏感 | 手工新增 `LINUX-001` 可能与存量 `linux-001` 并存（MySQL 默认 CI 排序规则会拦截） | 不追溯存量；导入预检按规范化集合判重，覆盖主路径；H2 仅用于本地联调 |
| 历史内联题只读 | 教师需删除后重新选题 | 提示明确；不迁移历史数据 |
| 发布预检多一次请求 | 发布耗时略增 | 仅 DRAFT→PUBLISHED 触发，收益大于成本 |
| 前端类型收敛影响其他页面 | 编译期暴露 `AFTER_SUBMIT` / `HIDDEN` 使用点 | `npm run build` 兜底；仅改 `exam.ts`，`homework.ts` / `lab.ts` 不动 |

## 14. 已否决方案

| 否决方案 | 原因 |
|---|---|
| 后端洗牌并落库学生题序 | 需新增字段与学生维度快照，超出本期范围；PRD D4 指定前端确定性洗牌 |
| 新增 `POST /questions/batch` 批量导入接口 | PRD 指定复用单题接口；新增接口需重复实现校验与审计，收益低 |
| 导入支持 Excel / CSV | PRD §4.2 明确不在本期范围 |
| 服务端强制校验判断题 `T`/`F` | 会阻断种子题 id=2 与既有考试用例，且 PRD 只要求组卷时前端拦截 |
| 导入使用 Promise.all 并发提交 | 破坏「逐行进度 + 409 跳过 + 失败继续」的确定性语义 |
| 历史内联题迁移为题库题 | 内联题无稳定身份，自动迁移语义不可控；PRD D22 明确不迁移 |
| 保留 `ExamQuestionItem` 内联字段仅做运行时忽略 | 会让 `sourceType=INLINE` 静默通过，无法落实文案统一的 40000 |
| 修改 `submitExam` 响应隐藏非可见成绩 | PRD D18 明确沿用现网，仅前端不展示 |
| 为学生详情抽象批量解析查询 | 单场百题规模不值得引入批量映射；与教师分支保持一致更易维护 |
| 在 `QuestionConfigList` 增加「不支持题目」徽标 | 该组件被作业页复用，改共享组件会放大回归面；考试页独立只读区更安全 |
| 沿用 `existsByCodeAndIdNotAndCreatedBy`（按教师判重） | 该否决项的前提「`question_bank.code` 全局唯一」已由 `V29` 解除；本期按 `existsBySchoolIdAndCreatedByAndCodeAndIdNot(schoolId, createdBy, code, id)` 归属维度判重；PRD §12.5 测试提示按本方案 §6 改写 |
