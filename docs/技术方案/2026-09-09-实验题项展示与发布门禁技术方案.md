# 实验题项展示与发布门禁技术方案

**创建日期**：2026-09-09  
**状态**：已定稿（决策写死，可直接编码）  
**范围**：教师端实验台账列表的题项数量展示修正；实验发布时「至少 1 个题项」后端门禁  
**非目标**：固定题项数量上限/下限（除 0 题不可发布）、列表展示「x/y 题项已完善」、题项完善度后端校验、学生端改动、Flyway 迁移

## 1. 背景与诉求

### 1.1 问题

教师实验台账「步骤规模」列展示 `4 步` + 副文案 `4/5 步已配置`。调研结论：

- 分母 `5` 为 `Labs.vue` 前端写死，**无产品规则、无后端字段、与种子数据（1～3 题项）不一致**。
- 「已配置」实际只统计题项**条数**，未校验题干/答案是否完善，与 `LabSteps.vue` 内 `isStepConfigured` 语义不符。
- 后端 `changeLabStatus` 当前允许 **0 题项** 直接发布，学生端进入空实验。

### 1.2 目标

1. 列表展示说真话：题项数量自由，不设「满 5 题才算完成」。
2. 发布前保证实验至少有一个题项，避免空实验上线。
3. 改动面小：纯文案 + 发布校验，不引入题项完善度后端镜像。

## 4. 发布门禁（后端）

### 4.1 私有方法

在 `LabService` 新增：

```java
private void assertLabPublishable(Lab lab) {
    List<LabStep> steps = labStepRepository.findByLabIdOrderByStepNoAsc(lab.getId());
    if (steps.isEmpty()) {
        throw new BusinessException(40000, "实验尚未配置题项，无法发布");
    }
}
```

### 4.2 调用点

| 方法 | 条件 |
|------|------|
| `changeLabStatus` | `parseStatus(request.status()) == ActivityStatus.PUBLISHED` → `assertLabPublishable(lab)` → `save` |
| `createLab` | `parseStatus(request.status()) == ActivityStatus.PUBLISHED` → **直接** `throw new BusinessException(40000, …)`（不 `save`） |
| `updateLab` | `applyLab` 后、若请求 `status` 为 `PUBLISHED` → `assertLabPublishable(lab)` → `save` |

**`createLab` 补充说明（写死）**：教师通过「新建实验」弹窗直接选「已发布」时，**不落库**即 400；前端 `request.ts` 展示 `message`。教师应先存草稿再进题项配置，最后点「发布实验」。

### 4.3 权限

与现有实验写操作一致：`requireTeacher` + `ownedLab` / `created_by`；**不新增**鉴权点。

## 7. 测试计划

| 用例名 | 断言 |
|--------|------|
| `changeLabStatusToPublishedWithoutItemsShouldFail` | 种子无题项实验 → `changeLabStatus(PUBLISHED)` → `BusinessException` message 含 `尚未配置题项` |
| `changeLabStatusToPublishedWithItemsShouldSucceed` | 种子含 ≥1 题项 → 发布成功 |
| `createLabAsPublishedWithoutItemsShouldFail` | `createLab` 请求 `status=PUBLISHED` → 400 |
| `updateLabToPublishedWithoutItemsShouldFail` | `DRAFT` 无题项实验 → `updateLab` 设 `PUBLISHED` → 400 |
| `closeOrDraftLabWithoutItemsShouldSucceed` | 无题项实验 → `CLOSED`/`DRAFT` 状态变更不受阻 |

### 7.1 现有测试连带（必改）

| 用例 | 原因 | 修改 |
|------|------|------|
| `teacherCanUpdateOwnedLab` | 当前 `DRAFT` 无题项实验 `updateLab` 设 `PUBLISHED` 会成功 | **写死**：`seedStep(labId, …)` 后再 `updateLab(..., "PUBLISHED", …)`；断言仍为发布成功 |

其余 `seedLab(..., PUBLISHED, …)` 经 JDBC 直插、不经 `changeLabStatus`/`updateLab` 发布路径的用例 **不改**。

## 8. 验收标准

1. 教师台账：4 题项实验仅显示 **「4 个题项」**，**无** `/5` 或「步已配置」字样。
2. 0 题项实验显示 **「0 个题项」** + 副文案 **「请先配置题项」**。
3. 0 题项实验点「发布实验」：前端 warning，不发起请求（或请求被拒且提示一致）。
4. 含 ≥1 题项实验可正常发布；发布后学生端可见对应题项数。
5. `cd backend && ./mvnw test` 通过，含新增用例。
6. `cd frontend && npm run build` 通过。

## 附录 A：已否决方案

| 方案 | 否决原因 |
|------|----------|
| 将分母 `5` 改为 `4` 或可配置「目标题项数」 | 仍是无业务依据的假进度，且需新字段 |
| 仅改前端、后端仍允许 0 题发布 | API 可绕过，学生仍会看到空实验 |
| 列表拉全量题项在前端算完善度 | N+1 请求或列表接口膨胀，本期过度设计 |
| 发布必须全部题项「已完善」 | 规则复杂、需后端镜像 `validateLabStepDraft`；教师可先发布再迭代，本期不做 |
