## 3. 架构设计（模式落地）

### 3.1 分层与依赖方向

```text
页面（Results / HomeworkSubmissions / LabReportDetail / LabReportBatchGrade）
   │ 只 import
   ▼
Facade: scoreDisplay.ts ──────► scoringStrategies.ts（Strategy + Adapter）
   │                                   │
   │                                   ▼
   └──────────────────────► gradingDraft.ts（Factory + State 快照）
```

- 依赖方向单向向下；策略模块不 import 页面，草稿模块不 import 策略模块；Facade 同时 re-export 二者供页面使用。
- 考试专属 `examGradingState.ts` 位于页面目录，作为兼容 Adapter 保留旧 API，内部只调用共享层。

### 3.2 Strategy + Adapter：`scoringStrategies.ts`

唯一导出形态：

```ts
export type ScoringDomain = 'EXAM' | 'HOMEWORK' | 'LAB'
export type ScoreLineKind = 'AUTO' | 'MANUAL' | 'REFERENCE'

export interface ScoreLineItem {
  key: string
  kind: ScoreLineKind
  questionType: string | null
  score: number | null
  autoScore: number | null
  suggestedScore: number | null
  scoreSource: string | null
  judgeDetail: string | null
  maxScore: number | null
  teacherComment: string
}

export interface ScoringDomainStrategy {
  adapt(raw: any): ScoreLineItem
  isReadOnly(status: string | null | undefined): boolean
  noManualText: string
}

export const scoringStrategyOf = (domain: ScoringDomain): ScoringDomainStrategy
```

三域策略行为写死：

| 域 | `adapt` 的 `kind` 判定 | `key` | `maxScore` | `isReadOnly` | `noManualText` |
|---|---|---|---|---|---|
| EXAM | `isCorrect === null` → MANUAL；否则 AUTO | `String(questionId)` | `questionScore` | `GRADED` / `IN_PROGRESS` | 本卷无主观题，系统已完成判分 |
| HOMEWORK | `scoreSource === 'TEACHER'` → MANUAL；`AUTO` / `AUTO_ACCEPTED` → AUTO；`SUGGESTED` / `RECOMMENDED` → REFERENCE | `String(answer.id ?? question.id)` | `question.score` | `SAVED` / `GRADED` | 本卷无主观题，系统已完成判分 |
| LAB | 同 HOMEWORK，`SUGGESTED` 也归 REFERENCE | `String(answerId ?? id ?? stepId)` | `maxScore ?? stepScore` | `SAVED` / `GRADED` | 本卷无需人工评分，系统已完成判分 |

实现约束：

- `adapt(null)` 不抛异常，返回全空行（`kind: 'REFERENCE'`）。
- 未传 `scoreSource` 但 `score` 有值且 `isCorrect === null` 时，EXAM 仍判 MANUAL；HOMEWORK / LAB 判 REFERENCE。
- `judgeDetail` 原样存入 `ScoreLineItem`，**只在 Facade 的 `formatJudgeDetail` 出口转中文**；策略层不翻译。

### 3.3 Template Method：`buildScoringSummary`

```ts
export interface ScoringSummary {
  autoScore: number
  manualScore: number
  totalScore: number
  completed: number
  total: number
  percent: number
  hasManual: boolean
  noManualText: string
}

export function buildScoringSummary(
  domain: ScoringDomain,
  items: readonly ScoreLineItem[],
  draft: Pick<GradingDraftState, 'scores' | 'marked'>,
): ScoringSummary
```

固定算法（不随域变化）：

1. `autoScore` = 所有 `kind === 'AUTO'` 的 `score ?? autoScore ?? 0` 之和。
2. `manualScore` = 所有 `kind === 'MANUAL'` 且 `draft.marked.includes(key)` 的 `draft.scores[key] ?? 0` 之和。
3. `totalScore = autoScore + manualScore`。
4. `manualItems = items.filter(kind === 'MANUAL')`；`total = manualItems.length`；`completed = manualItems.filter(marked).length`。
5. `percent = total === 0 ? 0 : Math.round(completed / total * 100)`；`hasManual = total > 0`。
6. `noManualText = scoringStrategyOf(domain).noManualText`。

### 3.4 Factory + State：`gradingDraft.ts`

```ts
export interface GradeItem { score: number | null; teacherComment: string }
export interface DraftItem extends GradeItem { key: string }
export interface GradingDraftState {
  scores: Record<string, number | null>
  comments: Record<string, string>
  marked: string[]
  baselineMarked: string[]
  initialComments: Record<string, string>
}

export function createGradingDraft(
  items: readonly DraftItem[],
  options?: { markAll?: boolean },
): GradingDraftState
export function setDraftScore(state: GradingDraftState, key: string, score: number | null): void
export function setDraftComment(state: GradingDraftState, key: string, comment: string): void
export function hasDraftChanges(state: GradingDraftState): boolean
export function commitDraft(state: GradingDraftState): void
```

约束：

- `createGradingDraft` 保存 `score ?? null`，**禁止把 `null` 收敛成 0**；`initialComments` 保存打开时的评语快照。
- `options.markAll === true` 时，把所有 `score !== null` 的题 key 同时写入 `marked` 与 `baselineMarked`（用于 `GRADED` / 已结案答卷，继承 11-18 PRD D8 的「已落库分数视为已评分」）；否则两者均为空数组。
- `setDraftScore(key, 0)` 计入 `marked`；`setDraftScore(key, null)` 从 `marked` 移除。
- `hasDraftChanges` = `marked` 与 `baselineMarked` 的集合不同，或任一 `comments[key] !== initialComments[key]`；只读态不会误报草稿。
- `commitDraft` 把当前 `comments` 写回 `initialComments`、把 `marked` 写回 `baselineMarked`；仅用于「确认放弃草稿 / 关闭弹窗」，保存成功后按新详情重建草稿（见下）。

**保存成功后的顺序写死**：刷新详情 → 用新详情重建 `ScoreLineItem[]` → `createGradingDraft(items, { markAll: isReadOnlySubmission(domain, newStatus) })` → 渲染新状态。不得只对旧草稿调 `commitDraft`，否则人工分会因标记清空而归零。

### 3.5 Facade：`scoreDisplay.ts` 升级

保留既有 5 个导出（`scoreSourceLabel`、`scoreSourceTagType`、`displaySuggestedScore`、`resolvedInitialScore`、`maxScoreOf`）行为不变，其中 `resolvedInitialScore` 仅作向后兼容，**三域草稿初始化不得调用它**；新增：

```ts
export type ScoreSourceLike = 'AUTO' | 'AUTO_ACCEPTED' | 'SUGGESTED' | 'RECOMMENDED' | 'TEACHER' | string | null | undefined
export function formatJudgeDetail(raw: string | null | undefined): string
export function questionTypeLabel(type: string | null | undefined): string
export { buildScoringSummary, scoringStrategyOf, createGradingDraft, setDraftScore, setDraftComment, hasDraftChanges, commitDraft }
export type { ScoringDomain, ScoreLineItem, ScoringSummary, GradingDraftState, DraftItem }
```

`formatJudgeDetail` 用**有序前缀匹配**（先长后短），避免 `blank 1: matched` 被 `matched` 泛化规则吃掉；匹配不到统一返回「系统自动判定」。题型映射按 TD8 写死有序表，不做 includes 模糊匹配。

## 5. 文案映射（实现者照抄）

| 原始串 | 中文 |
|---|---|
| `single choice matched` | 答案匹配，系统自动给分 |
| `single choice mismatch` | 答案不匹配，系统判定 0 分 |
| `true/false matched` | 判断正确，系统自动给分 |
| `true/false mismatch` | 判断错误，系统判定 0 分 |
| `multiple choice mode=…` 开头 | 多选题按当前规则自动判定 |
| `blank N: matched` / `mismatch` | 第 N 空匹配 / 第 N 空不匹配，多段顿号连接 |
| `matched=[…]; length=` 开头 | 系统按命中关键词与作答长度生成参考分 |
| `scoring engine unavailable` / `missing rule config` / `unsupported question type` | 自动判题暂不可用，请人工评分 |
| null / 空串 / 未知 | 系统自动判定 |
