# 全站字号统一规格与可读性门禁技术方案

- **日期**：2026-11-27
- **状态**：**已定稿（决策写死，可直接编码）**
- **输入**：用户复测反馈「还是有许多影响可读性的，某些地方文字还是很小。全面梳理，统一规格和标准规范，应用到所有页面」+ 2026-11-27 用户确认「标准档」
- **性质**：纯前端展示层治理。后端、DB、API、路由、权限、`package.json`、Vite / Vitest 配置一律不改
- **覆盖口径**：本方案覆盖 `2026-11-24-全站前端设计体系与基础组件规格统一技术方案.md` 的 TD4 字号阶梯、`2026-11-27-全站字号与组件尺寸可读性提升技术方案.md` 的 TD1 / TD6 / TD9 / A2 / A3、`2026-11-27-学生端重点区域字号覆盖补齐技术方案.md` 的 TD3 / TD9 / A2–A5，以及对应 PRD D7 / D28 的旧字号数值；四份旧文档只在「修订记录」表末追加覆盖指针，正文不改

## 1. 背景与问题（可验证）

两轮局部提档后，全站清点仍存在三类可读性缺口：

| # | 现象 | 现网实测 | 影响 |
|---|---|---|---|
| P1 | token 下沿仍偏小 | `--font-size-xs=12px` 实用 85 处、`sm=14px` 实用 241 处，合计 326 处分布在 46 个文件 | 辅助与次要文字普遍停在 12/14px |
| P2 | 门禁盲区硬编码 | `components/question-config/**`、`components/typed-editor/**`、`components/lab/**` 共 9 个文件、44 处 11/12/13/14/15/16/20px 文本字号，不在 `designTokens.spec.ts` #8/#9 扫描范围 | 这些页面文字完全不随 token 放大 |
| P3 | 控件高度未随字号 | `--control-height-sm/md/lg = 32/36/40px`，而 sm 字将升到 16px、base 升到 18px | small 控件与表格行可能拥挤 |
| P4 | 定点提档不可持续 | 前两轮共改 10 个代码文件，无法覆盖 46 个 xs/sm 实用文件 | 用户复测仍见小字 |

不做项初稿：不改业务、不改布局结构、不改颜色与断点的门禁口径、不引入新依赖、不放宽基线。

## 2. 已定决策清单

| 编号 | 决策点 | 唯一结论 |
|---|---|---|
| TD1 | 统一字号阶梯 | `tokens.css` 11 档写死为 `xs 14 / sm 16 / base 18 / md 20 / lg 22 / xl 26 / 2xl 30 / 3xl 34 / 4xl 42 / 5xl 50 / 6xl 58`（px），档位名与顺序不变 |
| TD2 | 语义下限 | 辅助文字 ≥14px（xs）、次要说明 ≥16px（sm）、正文 ≥18px（base）、条目标题 ≥20px（md）、卡片标题 ≥22px（lg）、区块标题 ≥26px（xl）、页面主标题 ≥34px（3xl） |
| TD3 | 门禁同步 | `designTokens.spec.ts` 的 `FONT_SIZE_LADDER` 注释与常量改为 TD1 的 11 个值，并把 `FONT_SIZE_WHITELIST` 上方注释改为「新阶梯不含 24，白名单保留供图标豁免」；`FONT_SIZE_WHITELIST` 仍保留 24；其余 14 条断言与 `designTokenBaseline.json` 不改 |
| TD4 | 控件高度 | `tokens.css` 的 `--control-height-sm/md/lg` 改为 `34px / 38px / 44px`；EP `--el-component-size*` 继续引用这三个 token；不新增控制高度档位 |
| TD5 | 盲区硬编码清零 | 9 个 `components/**` 文件中的 44 处文本 `font-size: Npx` 全部按 TD6 映射改为 `var(--font-size-*)`；图标块的 18/24px 不在本次范围 |
| TD6 | px→token 固定映射 | `11px→var(--font-size-xs)`、`12px→var(--font-size-sm)`、`13px→var(--font-size-sm)`、`14px→var(--font-size-sm)`、`15px→var(--font-size-base)`、`16px→var(--font-size-base)`、`20px→var(--font-size-lg)`；逐文件按数值批量替换，不改其它声明。唯一排除：`QuestionEditorDialog.vue:522` 的 `.question-editor-dialog__meta-chip .material-symbols-outlined` 16px 与 `FillBlankEditor.vue:212` 的 `.question-dialog__blank-remove .material-symbols-outlined` 18px 是图标字号，不参与替换 |
| TD7 | 文件范围 | 只改 §3 表格列出的 16 个文件：2 个源码基线文件、9 个盲区组件、4 份旧文档指针、本方案；不新增文件、不新增依赖 |
| TD8 | 验收口径 | 门禁 15 条全绿；9 个盲区组件内文本 px 字号计数为 0；教师表格 / 题库弹窗 / 三栏批改台 / 校管 CRUD 四类密集区无文字截断、重叠、横向滚动 |
| TD9 | 文档回写 | 四份旧文档各自「修订记录」表末追加一行覆盖指针；插入文本见 §3.2 |
| TD10 | 验收分期 | 单阶段交付，不存在 Phase 2；A1–A7 全部对应本次单阶段实现 |

## 7. 已否决方案

| 否决项 | 原因 |
|---|---|
| 保留档值、把 326 处 xs/sm 逐个改为 base/md | 46 文件散弹改动、无门禁兜底、漏掉 44 处硬编码，层级被压平 |
| 只清 44 处硬编码、不动阶梯 | 不能解决 xs/sm 普遍 12/14px 的问题，用户仍会看到小字 |
| 用 `zoom` / `transform: scale` 放大 | 破坏固定定位与滚动容器 |
| 在 views 新增 px 字号字面量 | 触发门禁 #8/#9，违反单一来源 |
| 采用增强档（16/18/20/22/24/28/32/36/44/52/60） | 可读性更高但密集区溢出风险显著，用户已选标准档 |
