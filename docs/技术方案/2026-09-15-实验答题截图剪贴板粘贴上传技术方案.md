## 1. 背景与诉求

### 1.1 业务诉求

学生在 Windows 下常用 **Win+Shift+S**、截图工具或 **微信/QQ 截图** 将画面复制到剪贴板，期望在实验作答区 **Ctrl+V** 直接插入答题截图，而无需先存盘再点「添加图片」。

### 1.2 现状结论

| 能力 | 现状 |
|------|------|
| 选文件上传 | `TextAnswerEditor` 隐藏 `<input type="file">` + `handleFileChange` → `compressLabAnswerImage` → `uploadStudentLabAnswerImage` |
| 剪贴板粘贴 | **无** `paste` / `clipboardData` 处理 |
| 上传 API 与鉴权 | 已在《2026-09-04》定稿；粘贴产生的 `File` 与选文件等价 |
| 开通多图的业务页 | 仅 `LabSteps.vue` 传 `enable-images` |
| 作业/考试 `TextAnswerEditor` | 未传 `enable-images`，行为保持不变 |

### 1.3 设计结论（一句话）

在 `TextAnswerEditor` 根容器监听 `paste`，从剪贴板提取 `image/*` 为 `File` 后复用现有 `processImageFile` 上传链路；**不改后端**。

## 2. 目标与非目标

### 2.1 目标

1. 学生实验作答页（`SAVED` 编辑态）：焦点在文字框或作答区内时，**Ctrl+V / ⌘+V** 可粘贴剪贴板截图并出现在缩略图列表。
2. 粘贴路径与选文件路径在压缩、上传、草稿 `images[]` 更新、缩略图 blob 预览上**行为一致**。
3. 纯文本粘贴不受影响（剪贴板无 `image/*` item 时）。
4. 提示文案明确支持快捷键粘贴。

### 2.2 非目标

- 不改造 `LabAnswerImageGallery`、教师端、预览 composable。
- 不为 `HomeworkDetail.vue` / `exams/Detail.vue` 开通 `enable-images` 或粘贴。
- 不在 `document` / `window` 上注册全局 `paste` 监听。
- 不解析 `text/html` 内嵌 `<img src="...">`（仅 `clipboardData.items` 的 `image/*`）。
- 不保证 iOS Safari / 微信内置浏览器粘贴图片（列为环境限制，本期不专项开发）。
- 不新增 E2E / Vitest 用例。

## 3. 前端方案（唯一路径）

### 3.1 重构：`processImageFile`

在 `TextAnswerEditor.vue` `<script setup>` 内新增异步函数 `processImageFile(file: File): Promise<void>`，逻辑从现网 `handleFileChange` **原样迁移**：

1. 校验 `props.labId`、`props.stepId`（缺失则 `ElMessage.error('缺少实验题项信息，无法上传图片')` 并 return）。
2. 若 `currentImages.length >= 5`，`ElMessage.warning('单题最多上传 5 张图片')` 并 return。
3. 设置 `uploading = true`，清空 `compressionHint`（多张粘贴时的循环策略见 §3.3）。
4. `compressLabAnswerImage(file)` → `uploadStudentLabAnswerImage` → `toLabAnswerImageMeta` → 更新 `localPreviewUrls` → `emitDraft`。
5. 压缩成功时设置 `compressionHint` 与现网一致。
6. `catch` 中 `ElMessage.error(...)`；`finally` 中 `uploading = false`。

`handleFileChange` 在取到 `input.files[0]` 后仅调用 `await processImageFile(file)`。

### 3.2 新增：`handlePaste`

绑定：`div.text-answer-editor` 增加 `@paste="handlePaste"`。

```text
handlePaste(event: ClipboardEvent):
  if !supportsImages || disabled → return

  const items = event.clipboardData?.items
  if !items?.length → return

  let sawAnyImageItem = false
  const imageFiles: File[] = []
  for each item in items:
    if item.type.startsWith('image/'):
      sawAnyImageItem = true
      const file = item.getAsFile()
      if !file → continue
      mime = file.type（小写 trim）|| item.type（小写 trim）
      if mime not in {image/png, image/jpeg, image/jpg, image/webp} → continue
      push normalizePastedFileName(file, mime)

  if !sawAnyImageItem → return   // 无 image/*，不 preventDefault（纯文本粘贴）

  event.preventDefault()

  if imageFiles.length === 0 → ElMessage.error('仅支持 png、jpeg、webp 图片'); return

  if uploading → ElMessage.warning('正在上传图片，请稍候'); return

  for each file in imageFiles:
    if currentImages.length >= 5 → ElMessage.warning('单题最多上传 5 张图片'); break
    await processImageFile(file)
```

`normalizePastedFileName(file: File, mime: string): File`：`name = file.name` 非空且含 `.` 则沿用，否则 `paste-{Date.now()}.{ext}`（`ext` 按 §0#12 MIME→后缀映射）；**始终** `return new File([file], name, { type: mime, lastModified: file.lastModified })`。

### 3.3 `uploading` 与连续粘贴

`processImageFile` 每次调用在 `finally` 置 `uploading = false`。一次粘贴多张时，**循环内逐张 await**，每张独立走完整 `uploading` 升降（按钮会短暂 loading，与连续点选多次文件一致）。

### 3.4 与 Element Plus `el-input` 的交互

`el-input` textarea 的 `paste` 事件会冒泡至 `div.text-answer-editor`。不在 textarea 上单独绑监听，避免双份逻辑。

### 3.5 模板改动

仅两处：

1. 根 `div` 增加 `@paste="handlePaste"`。
2. `.text-answer-editor__upload-tip` 文案追加 §0#18 片段。

## 9. 附录：已否决方案

| 否决项 | 原因 |
|--------|------|
| 新建 `useLabAnswerImagePaste.ts` | 逻辑仅一处使用，抽文件增加扩散面 |
| `document.addEventListener('paste', ...)` | 易误伤页内其他输入框，范围不可控 |
| 剪贴板含图+文时同时粘贴文字 | 截图场景几乎无 text；并行易导致 textarea 与上传顺序混乱 |
| 粘贴走新 API 或 base64 JSON 上传 | 与现网 multipart 重复，后端需改契约 |
| 为作业/考试同步开通粘贴 | 未开 `enable-images`，超出本期范围 |
| 解析 HTML clipboard 内嵌图 | 复杂度高、来源不可控，Windows 截图不走该路径 |
| 粘贴时队列合并为单次 `uploading` | 与连续选文件 UX 不一致，实现收益小 |
