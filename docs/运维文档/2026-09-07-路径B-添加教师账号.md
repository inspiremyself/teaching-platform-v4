# 路径 B：添加教师账号

**创建日期**：2026-09-07  
**适用场景**：本地联调（H2 文件库）需要临时/额外教师账号时。  
**配套脚本**：`scripts/common/create-teacher.sh`、`scripts/common/healthcheck-login.sh`

### 示例用法

后端已用路径 B 启动后，在仓库根目录执行：

```bash
./scripts/common/create-teacher.sh \
  --username teacher-260806 \
  --password 123456 \
  --display-name '王老师-leon'
```

用户名已存在、只想验证能否登录：

```bash
./scripts/common/create-teacher.sh \
  --username teacher-260806 \
  --password 123456 \
  --display-name '王老师-leon' \
  --force
```

---

## 1. 前置条件

| 条件 | 说明 |
|------|------|
| 路径 B 后端已启动 | `./scripts/path-b/backend.sh`（`test` profile，占用 `data/h2/`） |
| 端口可达 | 默认 `http://localhost:8080`；换端口时同步设环境变量 |
| 工具 | `curl`、`python3` |

不要在后端未启动时直连 H2 文件库：文件锁由运行中的 JVM 独占，脚本走同进程的 `/h2-console`。

---

## 2. 行为说明

1. 登录 H2 Console，连接与后端相同的文件库（默认 `${仓库根}/data/h2/teaching_platform`）。
2. 查询 `sys_user`：用户名已存在则失败；加 `--force` 则跳过插入。
3. 插入教师行：`role=TEACHER`，`status=ACTIVE`，`password_hash={noop}<明文>`。
4. 调用 `POST /api/v1/auth/login`（`role=TEACHER`，`forceLogin=true`）做探活。

登录页使用**明文密码**即可；库内 `{noop}` 前缀与种子账号、`AuthService` 去前缀比对一致。

演示教师 `t9001` 禁止用本脚本改写；探活请用：

```bash
./scripts/common/healthcheck-login.sh
```

---

## 3. 环境变量（可选）

| 变量 | 默认 | 说明 |
|------|------|------|
| `API_BASE` | `http://localhost:8080/api/v1` | 登录探活地址 |
| `H2_CONSOLE` | `http://localhost:8080/h2-console` | H2 Console 根路径 |
| `H2_FILE` | `<仓库根>/data/h2/teaching_platform` | 与 `path-b/backend.sh` 注入的文件路径一致（无 `.mv.db` 后缀） |

后端换端口示例：

```bash
API_BASE=http://127.0.0.1:18080/api/v1 \
H2_CONSOLE=http://127.0.0.1:18080/h2-console \
./scripts/common/create-teacher.sh \
  --username teacher-demo \
  --password 123456 \
  --display-name '演示教师B'
```

---

## 4. 成功判据

- 脚本退出码 `0`
- 控制台出现 `Update count: 1`（新插入时）或 `--force` 跳过插入提示
- 登录探活 HTTP `200` 且业务 `code=0`，响应含 token

前端：打开 http://localhost:5173/ ，选教师身份，用脚本里的用户名/明文密码登录。

---

## 5. 范围与反例

- **仅路径 B**（本地 H2 文件库）。路径 A（Docker MySQL）不在本文范围。
- 不要手写明文 `password_hash='123456'`（缺 `{noop}` 会导致登录失败）。
- 不要在后端运行时另开 H2 Shell 抢文件锁。
- 清空本地库仍是：停后端后删 `data/h2/`，下次启动 Flyway 重灌；本脚本写入的账号也会一并消失。
