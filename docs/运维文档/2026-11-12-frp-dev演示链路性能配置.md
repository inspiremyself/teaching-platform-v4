# frp + Vite dev 演示链路性能配置

```text
配套脚本：scripts/path-b/dev.sh、scripts/common/healthcheck-login.sh
示例用法：
  ./scripts/path-b/dev.sh up
  ./scripts/path-b/dev.sh status
  ./scripts/common/healthcheck-login.sh
  ./scripts/path-b/dev.sh down
```

技术方案：`docs/技术方案/2026-11-12-frp-dev演示链路首屏性能优化技术方案.md`（V1.7 已定稿，验证阶段最小回写）。本文只说明唯一运行入口与验收入口，配置项、决策与回滚以方案为准。

## 1. 链路现状

- 本机 `frpc -c frpc.toml`，配置位于 `~/frp/frp_0.69.1_darwin_amd64/frpc.toml`；`type = http` → `127.0.0.1:5173`，`customDomains = ["150.158.135.137"]`，`[proxies.transport] useCompression = true` 已启用。
- 公网访问入口：`http://150.158.135.137:9080`（frps 的 vhost HTTP 端口 9080）。**80 端口是云主机 nginx 默认站**，返回「没有找到站点」且 `/login` 为 404，不是本链路入口。
- 前端仍是 Vite dev server（5173），后端 Spring Boot（8080），`/api` 由 Vite 代理转发。
- frp 压缩只在 frpc↔frps 隧道段生效，frps→浏览器仍为原始字节；不要以浏览器 transferred 下降判断压缩生效。

## 2. 单轨启动

路径 B 唯一入口为 `scripts/path-b/dev.sh`：`up` / `down` / `status` / `logs` 全部走该脚本，`up` 末尾自动调用 `scripts/common/healthcheck-login.sh`。启动、停止、查看状态与日志不再按访问来源区分，也不注入额外运行期变量。

后端使用 `application*.yml` 现网默认值：HTTP 访问日志开启、`local` profile 为 `DEBUG`、`X-Trace-Id` 与审计 trace 正常写入；前端 HMR / `/@vite/client` 保持可用。每次重启后先在本机访问一次 `/login` 完成 `warmup` 预热，再放开给外部用户。

## 3. 字体与首屏

- `frontend/src/assets/global.css` 不再 `@import` Google Fonts；3 个字体自托管在 `frontend/public/fonts/`：`inter-latin-variable.woff2`、`dm-sans-latin-variable.woff2`、`material-symbols-outlined-subset.woff2`（按源码图标名生成的 `text=` 子集）。
- `.material-symbols-outlined` 类定义由 `global.css` 本地提供，图标通过 ligature 渲染。
- `frontend/vite.config.ts` 的 `server.warmup.clientFiles` 在启动时预热 4 个首屏模块；每次重启后先在本机访问一次 `/login` 完成预热，再放开给外部用户。
- 改动图标或新增图标名时，需另开技术方案更新 `32f1474` 中已落地的 `text=` 清单并重新生成子集，否则新图标会显示英文文本。

## 4. 验收步骤

按技术方案 §6 的单轨 V1–V6 执行：

1. V1：`frontend/` 下 `npm run build`、`npm run lint`；核对唯一入口 `scripts/path-b/dev.sh` 存在、旧演示入口文件已不存在；`text=` 清单、`vite.config.ts` / `global.css` / 3 个字体相对 `32f1474` 零改动。
2. V2：`./frpc verify -c frpc.toml` 退出码 0，`shasum -a 256 frpc.toml` 与 S1 基线一致（配置零改动）。
3. V3：本机 `/login` 预热完成后，公网以唯一 query 强制新文档：FCP ≤ 3 s 且不高于 S1 基线；Network 中 `fonts.googleapis.com` / `fonts.gstatic.com` 请求数为 0，3 个字体均为同源 `/fonts/*` 且总量 ≤ 400 KB；登录页与侧栏图标按 computed `font-family` 含 `Material Symbols Outlined` 且宽度 < 50 px 判定，不要求统一 24 px。
4. V4：`/usr/sbin/ab -c 10 -n 100 http://150.158.135.137:9080/login` 与技术方案 §5 写死的 10 个不同 ACTIVE 账号并发登录均无 axios 10 s 超时、无 5xx（登录 4xx 业务码不计失败）；`scripts/common/healthcheck-login.sh` 通过。同一账号 10 并发会触发既有死锁，不作为本验收模型。
5. V5：单轨语义：后端进程不含 V1.6 演示期注入的环境变量；`http_access_log` 计数增加、`data/logs/backend.log` 含 `DEBUG` 级别的 `c.o.t.` 应用日志行（Spring Boot 缩写包名）、`X-Trace-Id` 响应头存在、`/@vite/client` 200 且 HMR 可用；`audit_log` 新写入行 `trace_id` / `client_ip` 非 NULL；`behavior_event` 按技术方案 §5 / §6 等价判据核对（本地 `lab` / `lab_submission` 为 0 时不手工造数据）。
6. V6：文档单轨：本页文首示例只含 `dev.sh`；本页文首 / 正文说明 / 本验收节 / 回滚节 / README 索引行不含旧演示入口名、旧变量名与双轨表述；§5 历史实测表按表头标注保留旧字符串；`docs/运维文档/README.md` 索引行脚本列为 `scripts/path-b/dev.sh`；`dev.sh down` 后 5173 / 8080 释放；本页已在 `docs/运维文档/README.md` 索引中。

> FCP 与图标测量口径见技术方案 §6：S4 本机 `/login` 预热完成后，以 `agent-browser open <PUB>/login?v=<唯一值>` 强制新文档，连续稳定值判定；重启后第一次冷模块加载不计入；侧栏图标按 computed `font-family` 与宽度判定，不要求统一 24 px。
