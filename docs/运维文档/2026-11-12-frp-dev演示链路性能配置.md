# frp + Vite dev 演示链路性能配置

```text
配套脚本：scripts/path-b/dev-public.sh、scripts/path-b/dev.sh、scripts/common/healthcheck-login.sh
示例用法：
  ./scripts/path-b/dev-public.sh up
  ./scripts/path-b/dev-public.sh status
  ./scripts/common/healthcheck-login.sh
  ./scripts/path-b/dev-public.sh down
```

技术方案：`docs/技术方案/2026-11-12-frp-dev演示链路首屏性能优化技术方案.md`（V1.4 已定稿）。本文只说明运行方式与验收入口，配置项、决策与回滚以方案为准。

## 1. 链路现状

- 本机 `frpc -c frpc.toml`，配置位于 `~/frp/frp_0.69.1_darwin_amd64/frpc.toml`；`type = http` → `127.0.0.1:5173`，`customDomains = ["150.158.135.137"]`，`[proxies.transport] useCompression = true` 已启用。
- 公网访问入口：`http://150.158.135.137:9080`（frps 的 vhost HTTP 端口 9080）。**80 端口是云主机 nginx 默认站**，返回「没有找到站点」且 `/login` 为 404，不是本链路入口。
- 前端仍是 Vite dev server（5173），后端 Spring Boot（8080），`/api` 由 Vite 代理转发。
- frp 压缩只在 frpc↔frps 隧道段生效，frps→浏览器仍为原始字节；不要以浏览器 transferred 下降判断压缩生效。

## 2. 演示模式启动

`scripts/path-b/dev-public.sh` 是唯一的对外演示启动入口，转调 `scripts/path-b/dev.sh`，并在启动前注入：

| 变量 | 值 | 作用 |
|---|---|---|
| `SERVER_COMPRESSION_ENABLED` | `true` | 后端 API JSON 开启 gzip |
| `APP_HTTP_ACCESS_LOG_ENABLED` | `false` | 关闭「每个请求一条访问日志 INSERT」 |
| `SPRING_DATASOURCE_HIKARI_MAXIMUM_POOL_SIZE` | `20` | 连接池 10 → 20 |
| `SERVER_TOMCAT_THREADS_MAX` | `80` | 避免 200 线程争抢少量连接 |
| `LOGGING_LEVEL_COM_OPENCODE_TEACHINGPLATFORM` | `INFO` | 关掉 `local` profile 的 DEBUG 应用日志 |

**已定降级**：关闭访问日志后 `HttpAccessLogFilter` 不再设置 `RequestTraceContext`，`audit_log` 与 `lab_behavior_event` 的 `trace_id` / `client_ip` 写入 NULL（两列允许 NULL，不会报错），`X-Trace-Id` 响应头消失，校管审计日志 Trace 列显示为空。这是演示期接受的行为；日常开发用 `scripts/path-b/dev.sh` 启动即恢复。

启动、停止、查看状态与日志分别用 `dev-public.sh up` / `down` / `status` / `logs backend`，探活用 `scripts/common/healthcheck-login.sh`。日常开发不要带 `dev-public.sh`，直接 `scripts/path-b/dev.sh up`。

## 3. 字体与首屏

- `frontend/src/assets/global.css` 不再 `@import` Google Fonts；3 个字体自托管在 `frontend/public/fonts/`：`inter-latin-variable.woff2`、`dm-sans-latin-variable.woff2`、`material-symbols-outlined-subset.woff2`（按源码图标名生成的 `text=` 子集）。
- `.material-symbols-outlined` 类定义由 `global.css` 本地提供，图标通过 ligature 渲染。
- `frontend/vite.config.ts` 的 `server.warmup.clientFiles` 在启动时预热 4 个首屏模块；每次重启后先在本机访问一次 `/login` 完成预热，再放开给外部用户。
- 改动图标或新增图标名时，需同步更新方案 §3.1 写死的清单并重新生成子集，否则新图标会显示英文文本。

## 4. 验收步骤

按技术方案 §6 的 V1–V6 执行：

1. V1：`frontend/` 下 `npm run build`、`npm run lint`；`bash -n scripts/path-b/dev-public.sh`；核对 `text=` 参数与方案 §3.1 清单一致、`vite.config.ts` diff 仅新增 `warmup`。
2. V2：`./frpc verify -c frpc.toml` 退出码 0，`shasum -a 256 frpc.toml` 与实施前基线一致（配置零改动）。
3. V3：公网首次打开 `/login`，Network 中 `fonts.googleapis.com` / `fonts.gstatic.com` 请求数为 0，3 个字体均为同源 `/fonts/*` 且总量 ≤ 400 KB，登录页与侧栏图标渲染为图标而非文字。
4. V4：公网单用户 FCP ≤ 3 s 且不高于实施前基线；`/usr/sbin/ab -c 10 -n 100 http://150.158.135.137:9080/login` 与技术方案 §5 写死的 10 个不同 ACTIVE 账号并发登录均无 axios 10 s 超时、无 5xx（登录 4xx 业务码不计失败）；`scripts/common/healthcheck-login.sh` 通过。同一账号 10 并发会触发既有死锁，不作为本验收模型。
5. V5：先 `dev-public.sh down` 再 `dev.sh up`，核对访问日志仍写库、DEBUG 日志未变、HMR 可用；`git status --short` 相对实施前快照比较。
6. V6：`dev-public.sh up` 输出 5 行注入变量；`data/logs/backend.log` 无 `com.opencode.teachingplatform` DEBUG 行；`dev-public.sh down` 后 5173 / 8080 释放；本页已在 `docs/运维文档/README.md` 索引中。
