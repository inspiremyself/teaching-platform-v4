# 路径 C：本地 MySQL 联调与 H2 迁移

**创建日期**：2026-09-09  
**适用场景**：本机已安装 MySQL（如 MySQL Workbench / Homebrew），希望用**真实 MySQL** 联调；或将路径 B H2 文件库中的**表结构 + 业务数据**迁入 MySQL。  
**配套脚本**：`scripts/path-c/backend.sh`、`scripts/path-c/frontend.sh`、`scripts/common/migrate-h2-to-mysql.sh`、`scripts/common/healthcheck-login.sh`

### 示例用法

```bash
# 1. 将 H2 整库迁入 MySQL（须先停路径 B/C 后端）
./scripts/common/migrate-h2-to-mysql.sh

# 2. 路径 C 联调（两个终端，backend 同 path-b/backend.sh）
./scripts/path-b/backend.sh
./scripts/path-c/frontend.sh

./scripts/common/healthcheck-login.sh
```

---

## 1. 与路径 A / B 的区别

| 路径 | 数据库 | 典型场景 |
|------|--------|----------|
| **A** | Docker MySQL（密码默认 `123456`） | 整站演示、Compose 一键起 |
| **B** | H2 文件库（`backend-h2.sh`） | 无 MySQL 时的可选联调 |
| **C** | 本机 MySQL（同 `path-b/backend.sh`） | MySQL Workbench、H2 迁出 |

- 路径 A/B/C **不要并行占用** `8080`、`5173`。
- 路径 C 与路径 A 可共用同一 MySQL 实例，但**库名**默认均为 `teaching_platform`；同时跑两套后端会争用同一库，一般只启其一。
- 上传文件仍在仓库根 `data/files/`，**不随数据库迁移**；迁库后实验图/资料附件仍依赖该目录。

## 2. 前置条件

| 依赖 | 要求 |
|------|------|
| JDK | 21 |
| Maven | 3.x（`backend/mvnw` 调用系统 `mvn`） |
| MySQL | 8.x，监听 `3306`（或自设 `DB_PORT`） |
| 客户端 | `mysql` CLI、`python3`（迁移脚本用） |
| Node.js | 前端 Vite（与路径 B 相同） |

本机 MySQL 示例（请按实际修改密码）：

```bash
mysql -h127.0.0.1 -uroot -p -e "CREATE DATABASE IF NOT EXISTS teaching_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

路径 C 脚本默认：`DB_USER=root`、`DB_PASS=12345678`（与 `application.yml` 默认 `123456` 不同，因本机安装常见自设密码）。可通过环境变量覆盖。

## 3. H2 → MySQL 整库迁移

将路径 B 当前 H2 文件库（**结构 + 数据**，含校管导入、脚本建账号等本地业务数据）导入 MySQL。

**注意**

1. **先停后端**（占用 H2 文件锁或 8080 端口会导致失败或不一致）。
2. 脚本会**自动备份** MySQL、H2 与 `data/files/`（`backup-local-data.sh --h2 --with-files`），再 **DROP 并重建** MySQL 库。
3. 迁移产物落在 `data/backups/`（gitignore）：`h2_to_mysql_dump.sql`、`teaching_platform_mysql.sql`。

```bash
# 默认：127.0.0.1:3306 / root / DB_PASS=12345678 / teaching_platform
./scripts/common/migrate-h2-to-mysql.sh

# 自定义
DB_PASS=你的密码 MYSQL_HOST=127.0.0.1 LABEL=milestone-xaust ./scripts/common/migrate-h2-to-mysql.sh
```

| 环境变量 | 默认 | 说明 |
|----------|------|------|
| `DB_PASS` | `12345678` | MySQL 密码 |
| `MYSQL_HOST` | `127.0.0.1` | 主机 |
| `MYSQL_PORT` | `3306` | 端口 |
| `MYSQL_USER` | `root` | 用户 |
| `DB_NAME` | `teaching_platform` | 库名 |
| `H2_FILE` | `<仓库根>/data/h2/teaching_platform` | H2 文件路径（无 `.mv.db` 后缀） |
| `LABEL` | `before-mysql-migrate` | 备份目录后缀 |

实现说明：H2 `SCRIPT` 导出 → `scripts/common/h2-dump-to-mysql.py` 转为 MySQL 8 语法 → `mysql` 导入。Flyway 历史表一并迁入，后端启动时不会重复跑迁移。

## 4. 启动路径 C

**终端 1 — 后端**

```bash
./scripts/path-b/backend.sh
# 或 ./scripts/path-c/backend.sh（相同）
```

**终端 2 — 前端**

```bash
./scripts/path-c/frontend.sh
```

等价手工命令：

```bash
cd backend && \
  SPRING_PROFILES_ACTIVE=local \
  DB_HOST=127.0.0.1 DB_PORT=3306 \
  DB_NAME=teaching_platform DB_USER=root DB_PASS=12345678 \
  FILE_STORAGE_ROOT="$(pwd)/../data/files" \
  ./mvnw spring-boot:run
```

换端口示例：

```bash
SERVER_PORT=18080 ./scripts/path-c/backend.sh
VITE_API_TARGET=http://127.0.0.1:18080 ./scripts/path-c/frontend.sh
```

## 5. MySQL Workbench

- **Connection**：`localhost:3306`，用户 `root`，密码与 `DB_PASS` 一致。
- **Schema**：`teaching_platform`（迁移完成后可见全部业务表）。
- 修改数据后，路径 B 的 H2 **不会自动同步**；若要以 MySQL 为准反向同步，需自行导出/导入，本仓库仅提供 H2 → MySQL 方向脚本。

## 7. 常见问题

1. **后端启动报 `Schema-validation: missing table`**  
   MySQL 库为空或仅部分表：先执行 `migrate-h2-to-mysql.sh`，或空库下首次启动由 Flyway 建表（仅种子数据，无 H2 本地业务数据）。

2. **`Database may be already in use`（迁移时）**  
   路径 B 后端仍在跑：停 `./scripts/path-b/backend.sh` 后再迁移。

3. **登录 500 / 连不上库**  
   检查 MySQL 是否启动、`DB_PASS` 是否与 Workbench 一致；勿在未设 `DB_PASS` 时裸跑 `./mvnw spring-boot:run`（会沿用 yml 默认 `123456`）。

4. **与路径 A 密码不一致**  
   Compose 内 MySQL root 密码为 `123456`；路径 C 脚本默认 `12345678` 面向本机安装，按环境设置 `DB_PASS` 即可。
