## 1. 配置键与环境变量（唯一口径）

配置键声明在 `backend/src/main/resources/application.yml` 的 `app.courseware.ai` 子块（当前 `:40-46`），**值全部由环境变量经 `${ENV:default}` 占位符注入**，仓库内不提供任何可用密钥：

| 配置键 | 环境变量 | 默认值 | 说明 |
|--------|----------|--------|------|
| `app.courseware.ai.base-url` | `COURSEWARE_AI_BASE_URL` | 空串 | OpenAI 兼容网关地址，如 `https://<网关地址>/v1`；网关拼接 `/chat/completions` |
| `app.courseware.ai.api-key` | `COURSEWARE_AI_API_KEY` | 空串 | `Bearer` 密钥；**不写入仓库、不写入任何 `application*.yml` 的字面量** |
| `app.courseware.ai.model` | `COURSEWARE_AI_MODEL` | 空串 | 模型名，需支持 `response_format=json_object` |
| `app.courseware.ai.timeout-seconds` | `COURSEWARE_AI_TIMEOUT_SECONDS` | `120` | 单次请求超时秒数；`<= 0` 时后端兜底为 `120` |

要点：

- 三个 profile 文件（`application-local.yml` / `application-test.yml` / `application-prod.yml`）与 `src/test/resources/application-test.yml` **都不覆盖**这四键；`local` / `test` / `prod` / UT 共用主配置的同一份声明。
- 只要 `base-url` / `api-key` / `model` 任一为空串，网关判定为「未配置」：应用**正常启动**，「AI 生成」入口返回 `40000`「AI 生成服务未配置，请联系管理员」且**不落库**；不会因缺少变量导致启动失败。
- 评估文档 V2.4 §5.2 的「prod 必填」是**部署侧要求**（运维必须注入），运行时语义以上一条为准；后端没有启动期强校验。
- 配置键同样可被任意 Spring 属性源覆盖，例如 `--app.courseware.ai.model=<模型名>`；运维侧统一用环境变量。

## 2. 按启动路径注入

### 2.1 路径 B（默认，本机 MySQL / `local` profile）

`scripts/path-b/backend.sh` 默认 MySQL、`DB_PASS=12345678`；`dev.sh` 是它的后台编排入口，环境变量会透传给后端进程。

```bash
# 前台两终端方式：在 backend.sh 前注入即可
env COURSEWARE_AI_BASE_URL='https://<网关地址>/v1' \
    COURSEWARE_AI_API_KEY='<密钥>' \
    COURSEWARE_AI_MODEL='<模型名>' \
    COURSEWARE_AI_TIMEOUT_SECONDS=120 \
    ./scripts/path-b/backend.sh
# 另一个终端
./scripts/path-b/frontend.sh
```

- 改动配置后**必须重启后端**：先 `./scripts/path-b/dev.sh down` 停掉已有实例，再 `up`；`dev.sh` 检测到 `8080` / `5173` 已有监听会**跳过启动**，此时新注入的环境变量不会生效。前台 `backend.sh` / `frontend.sh` 方式同样须先确认端口空闲。只改环境变量不重启不生效。
- 端口默认后端 `8080`、前端 `5173`，勿并行占用；换端口用 `SERVER_PORT` / `FRONTEND_PORT` / `VITE_API_TARGET`（见 `dev.sh` 头部注释）。
- 前端 Vite 5.4.21 需 Node ≥ 20.12，Node 18 会报 `crypto.hash is not a function` 导致 SFC 预转换 500；换版本方法见 `2026-09-11-nvm多项目Node版本与IDE配合.md`。

### 2.2 路径 C

`scripts/path-c/backend.sh` 转调 `scripts/path-b/backend.sh`，注入方式与 §2.1 完全相同。

### 2.3 路径 B 的 H2 第二形态

`scripts/path-b/backend-h2.sh` 用 `test` profile + `data/h2/` 文件库，配置键共用主配置；注入方式同 §2.1，换端口避免与 8080 并行：

```bash
SERVER_PORT=18080 ./scripts/path-b/backend-h2.sh
```

测试的 H2 mem 库由 `cd backend && ./mvnw test` 覆盖，**不要**把 `src/test/resources/application-test.yml` 改成文件库。

### 2.4 路径 A（Docker Compose 整站）

`docker-compose.yml` 的 `backend.environment` 当前只声明了 `SPRING_PROFILES_ACTIVE` / `DB_*` / `JWT_SECRET` / `FILE_STORAGE_ROOT` / `SERVER_PORT`，**未注入这 4 个 AI 变量**；本期未改 Compose 文件，也未新增脚本入口。因此整站演示环境下「AI 生成」处于未配置态（返回 `40000`），其余功能不受影响。如需启用，须由运维另立变更在 Compose 的 `backend.environment` 追加 4 项后重建容器，本文不提供未验证的编排片段。

## 3. 注入是否生效的判定

### 3.1 取平台超管 token（curl 登录示例须含 `role`）

```bash
TOKEN=$(curl -sS -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"platform9001","password":"123456","role":"PLATFORM_ADMIN","forceLogin":true}' \
  | python3 -c 'import sys,json; print(json.load(sys.stdin)["data"]["token"])')
```

也可直接复用探活脚本：`env USERNAME=platform9001 ROLE=PLATFORM_ADMIN FORCE_LOGIN=true ./scripts/common/healthcheck-login.sh`（默认 `forceLogin=true`，避免撞上「已在其他设备登录」）。

### 3.2 查可用的生成上下文 id

AI 生成请求需要 `globalSubjectId`（`ACTIVE` 平台学科）与 `textbookSectionId`（叶子教材小节）。先查端点再替换，不要写死跨环境的 id：

```bash
BASE=http://localhost:8080/api/v1/admin/platform-content
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/subjects"
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/textbooks"
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/textbooks/{textbookId}/sections"   # 取 leaf 小节 id
```

把端点返回的 `ACTIVE` 学科 id 与 `leaf=true` 小节 id 存入 `SUBJECT_ID` / `SECTION_ID` 后执行 §3.3；不同库、不同环境的值不同，一律以端点返回为准。本文档不把 id 当作跨环境固定结论，§3.3 给出的本机示例值只用于可复制执行，换库必须替换。

### 3.3 调生成端点看错误文案

```bash
# 两个值来自 §3.2 端点返回；下面是本机 E2E 造数的示例值，换库必须替换
SUBJECT_ID=5
SECTION_ID=1
PAYLOAD=$(printf '{"globalSubjectId":%s,"textbookSectionId":%s,"title":"运维验收","subtitle":""}' \
  "$SUBJECT_ID" "$SECTION_ID")
curl -sS -X POST "$BASE/coursewares/generate" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d "$PAYLOAD"
```

| 返回 | 判定 |
|------|------|
| `code=40000`「AI 生成服务未配置，请联系管理员」 | 4 个变量未注入或注入不完整，配置未生效 |
| `code=40000`「AI 生成请求失败」 | **注入已生效**（网关已尝试连接但不可达/密钥错/超时）；本地无真实网关时用它判定链路 |
| `code=0` 且返回课件详情 | 真实网关可用，生成成功 |

两种失败返回都应满足 `courseware` / `courseware_section` 无新增行（不落库）；可用 `curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/coursewares"` 前后对比。

## 4. 故障排查

| 现象 | 原因 | 处置 |
|------|------|------|
| 「AI 生成服务未配置，请联系管理员」 | `base-url` / `api-key` / `model` 有空串；或改了变量没重启 | 按 §2 注入，`dev.sh down` → `up`，再按 §3.3 复测 |
| 「AI 生成请求失败」 | 网关地址不可达、密钥错误、请求超时 | 核对 `COURSEWARE_AI_BASE_URL` / `API_KEY` / `TIMEOUT_SECONDS`，查网关侧日志；本地指向 `http://127.0.0.1:1/v1` 时该文案属预期 |
| 「AI 生成服务返回异常状态」 | 网关返回非 2xx | 查网关配额 / 鉴权 / 模型名 |
| 生成结果解析失败（最多重试 1 次） | 模型未返回合法 `json_object` 内容 | 换支持 `response_format=json_object` 的模型；失败不落库 |
| 生成端点 403 / 404 | token 角色不对或路径写错 | 用 `PLATFORM_ADMIN` 平台超管 token；教师端应访问 `/api/v1/teacher/content/**` |
| 改了 `application.yml` 仍不生效 | 后端未重启，或改到了 profile 文件 | 只在主 `application.yml` 声明；重启后端 |
| 前端 5173 白屏 / `.vue` 预转换 500 | Node 18 与 Vite 5 不兼容 | 切到 Node ≥ 20.12（见 §2.1） |
| 端口被占用 | 路径 A/B/C 并行 | 先 `./scripts/path-b/dev.sh down` 停掉多余实例，再按 §2.1 用默认端口重启（换端口参数见 `dev.sh` 头部注释，本文不作为默认处置） |
