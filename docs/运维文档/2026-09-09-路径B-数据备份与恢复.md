# 路径 B：数据备份与恢复

**创建日期**：2026-09-09  
**适用场景**：本地 H2 文件库联调；防止清库、Flyway 重建、重构测试导致账号与导入数据丢失。  
**配套脚本**：`scripts/common/backup-path-b-data.sh`、`scripts/common/restore-path-b-data.sh`  
**Agent 技能**：`.cursor/skills/path-b-data-backup/SKILL.md`

### 示例用法

```bash
# 清库或跑破坏性迁移前
./scripts/common/backup-path-b-data.sh --label before-migration --with-files

# 查看已有备份
./scripts/common/backup-path-b-data.sh --list

# 恢复最近一次备份（须先停后端）
./scripts/common/restore-path-b-data.sh --latest --with-files
```

---

## 1. 备份什么

| 目录 | 说明 |
|------|------|
| `data/h2/` | H2 文件库（`teaching_platform.mv.db` 等），含全部业务数据 |
| `data/files/` | 上传根（课程资料、实验答题图）；需加 `--with-files` |

备份输出：`data/backups/<YYYY-MM-DD_HHMMSS>[_label]/`，含 `manifest.json`（时间、label、是否含 files、可选 git commit）。

---

## 2. 前置条件

| 条件 | 说明 |
|------|------|
| 推荐停后端 | H2 文件锁由 JVM 独占；运行中备份默认拒绝 |
| 应急 | 加 `--force` 可在后端运行时复制（可能不一致，不推荐） |
| 恢复 | **必须**停 `./scripts/path-b/backend.sh`，否则脚本拒绝 |

---

## 3. 常见场景

### 3.1 重构 / 迁移前

```bash
./scripts/common/backup-path-b-data.sh --label before-v14 --with-files
```

### 3.2 误删 `data/h2/`

1. `./scripts/common/backup-path-b-data.sh --list`
2. `./scripts/common/restore-path-b-data.sh --latest`
3. 重启后端并 `./scripts/common/healthcheck-login.sh`

### 3.3 仅丢自定义教师账号、库仍在

不必整库恢复；用校管端新建或 `create-teacher.sh`（见 [2026-09-07-路径B-添加教师账号.md](./2026-09-07-路径B-添加教师账号.md)）。

---

## 4. 环境变量（可选）

| 变量 | 默认 | 说明 |
|------|------|------|
| `SERVER_PORT` | `8080` | 检测后端是否占用 |
| `H2_DIR` | `<仓库根>/data/h2` | H2 目录 |
| `FILES_DIR` | `<仓库根>/data/files` | 上传目录 |
| `BACKUP_ROOT` | `<仓库根>/data/backups` | 备份根目录 |

---

## 5. 成功判据

**备份**

- 退出码 `0`
- 控制台打印 `完成: data/backups/...`
- 目录内存在 `h2/*.mv.db` 与 `manifest.json`

**恢复**

- 退出码 `0`
- 重启后端后 `healthcheck-login.sh` 通过
- 自定义账号可登录（若备份中含该数据）

---

## 6. 范围与反例

- **仅路径 B**（H2 文件库）。Docker MySQL（路径 A）不在本文范围。
- `data/` 已在 `.gitignore`；备份不会进 git，勿指望 clone 仓库带回本地数据。
- 删 `data/h2/` 后 Flyway 只会重灌**演示种子**（`t9001`、`20260001` 等），手动导入/脚本创建的账号**不会**自动回来。
- 不要在后端运行时执行恢复。
