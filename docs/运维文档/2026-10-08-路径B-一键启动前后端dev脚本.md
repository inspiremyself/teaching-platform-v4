# 路径 B：一键启动前后端（dev.sh）

**创建日期**：2026-10-08  
**适用场景**：单终端**一键后台启动**前后端联调环境（默认本机 MySQL / `local` profile），并自动完成就绪探活；同样支持一键停止。  
**配套脚本**：`scripts/path-b/dev.sh`（内部复用 `backend.sh` / `backend-h2.sh` / `frontend.sh` / `healthcheck-login.sh`）

### 快速用法

```bash
./scripts/path-b/dev.sh up        # 后台启动前端 + 后端（默认 MySQL），并登录探活
./scripts/path-b/dev.sh status    # 查看运行状态与日志尾部
./scripts/path-b/dev.sh logs backend    # 跟踪后端日志（Ctrl+C 退出，不影响服务）
./scripts/path-b/dev.sh logs frontend   # 跟踪前端日志
./scripts/path-b/dev.sh down      # 停止前后端
```

---

## 1. 与现有启动方式的关系

| 方式 | 进程形态 | 适用场景 |
|------|----------|----------|
| `backend.sh` / `frontend.sh` | **前台**，占两个终端 | 需要实时盯着日志开发 |
| `dev.sh up` | **后台** nohup，日志落盘 | 单终端联调、快速起停 |
| 路径 A `up.sh` | Docker Compose 三容器 | 整站演示 |

- `dev.sh` 不替代原子脚本，只是编排：后端仍调用 `backend.sh`（或 `DB=h2` 时 `backend-h2.sh`），前端仍调用 `frontend.sh`，探活调用 `healthcheck-login.sh`。
- 前后端端口与路径 A/B/C 规则一致：默认 `8080` / `5173`，勿并行占用。

## 2. 启动流程（`up`）

1. **端口去重**：若 `SERVER_PORT` / `FRONTEND_PORT` 已有监听进程，跳过对应服务，不重复启动。
2. **后台启动**：`nohup` 拉起子脚本，日志与 pid 落在 `data/logs/`：
   - `data/logs/backend.log`、`data/logs/backend.pid`
   - `data/logs/frontend.log`、`data/logs/frontend.pid`
3. **就绪等待**：轮询后端 `GET /api/v1/auth/me`（任何 HTTP 响应即视为就绪，默认无 token 返回 403 属预期）与前端首页，超时分别为 180s / 60s。
4. **登录探活**：复用 `healthcheck-login.sh`（默认教师 `t9001/123456`）。探活失败只告警不回滚，需人工看日志。

## 3. 环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `DB` | （空 = MySQL） | `DB=h2` 时后端改用 H2 文件库（`backend-h2.sh`） |
| `SERVER_PORT` | `8080` | 后端端口 |
| `FRONTEND_PORT` | `5173` | 前端端口 |
| `VITE_API_TARGET` | 自动推导 | 未显式设置且 `SERVER_PORT≠8080` 时自动设为 `http://localhost:${SERVER_PORT}` |
| `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASS` | `127.0.0.1:3306/root/12345678` | 透传给 `backend.sh` |
| `SKIP_PROBE` | `false` | `true` 时 `up` 后跳过登录探活 |
| `BACKEND_WAIT_SEC` / `FRONTEND_WAIT_SEC` | `180` / `60` | 就绪等待超时 |

示例：

```bash
# 无 MySQL，用 H2 文件库
DB=h2 ./scripts/path-b/dev.sh up

# 换端口并行起一套
SERVER_PORT=18080 FRONTEND_PORT=18081 ./scripts/path-b/dev.sh up

# 只起服务不做登录探活（如演示账号已被改密）
SKIP_PROBE=true ./scripts/path-b/dev.sh up
```

## 4. 停止与排查

- `down` 按**端口**定位监听进程（`lsof`），先 `kill` 温和终止，15s 未退则 `kill -9`；与 pid 文件无关，手工 `nohup` 起的同端口服务同样能停。
- 排查顺序：`dev.sh status` → `dev.sh logs backend|frontend` → 若是数据库问题参考《2026-09-09-路径C-本地MySQL联调与H2迁移.md》。
- `data/logs/` 已被 gitignore（随 `data/` 整体忽略），可放心堆积；需要清理时直接删除即可（不影响运行中进程，仅失去历史日志）。

## 5. 常见问题

| 现象 | 处理 |
|------|------|
| `up` 提示端口已被占用 | 之前起过服务：`dev.sh status` 确认，直接用或 `dev.sh down` 后重启 |
| 后端等待超时 | `logs backend` 看 Flyway / MySQL 连接错误；确认 `DB_PASS` 与本机一致 |
| 前端代理 404 | 确认 `VITE_API_TARGET` 与后端实际端口一致 |
| H2 文件锁冲突 | 上一个后端未完全退出：`dev.sh down` 后重试，或 `lsof -nP -iTCP:8080` 手工确认 |
