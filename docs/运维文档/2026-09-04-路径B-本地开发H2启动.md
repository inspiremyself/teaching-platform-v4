# 路径 B：本地开发（H2 / test profile）

**创建日期**：2026-09-04  
**适用场景**：日常前后端联调、调试、演示链路验证；**无需本机 MySQL**。  
**配套脚本**：`scripts/path-b/backend.sh`、`scripts/path-b/frontend.sh`、`scripts/common/healthcheck-login.sh`

### 示例用法

在仓库根目录执行（路径 B 需两个终端）：

```bash
# 路径 B（两个终端）
./scripts/path-b/backend.sh
./scripts/path-b/frontend.sh
```

后端就绪后可探活：

```bash
./scripts/common/healthcheck-login.sh
```

## 1. 前置条件

| 依赖 | 要求 | 说明 |
|------|------|------|
| JDK | 21 | `pom.xml` 指定 `java.version=21` |
| Maven | 3.x | 仓库内 `backend/mvnw` 为调用系统 `mvn` 的薄壳，仍需本机有 `mvn` |
| Node.js / npm | 建议 Node 18+ | 前端 Vite 开发服务器 |
| 端口空闲 | 默认 `8080`、`5173` | 可按下文换端口 |

检查命令：

```bash
java -version
mvn -v
node -v && npm -v
```

---

## 2. 运行模型

| 进程 | 命令入口 | 默认地址 | 数据 |
|------|----------|----------|------|
| 后端 | `SPRING_PROFILES_ACTIVE=test` | http://localhost:8080 | H2 **文件库**（仓库根 `data/h2/`）+ Flyway |
| 前端 | `npm run dev` | http://localhost:5173 | Vite 将 `/api` 代理到后端 |

说明：

- 默认 Spring profile 是 `local`（连 MySQL）。路径 B **必须**显式使用 `test`，否则本机无 MySQL 时后端起不来，前端登录易表现为 500。
- **数据目录统一在仓库根 `data/`**（不再使用 `backend/data/`）：
  - H2：`data/h2/teaching_platform.*`
  - 上传根：`data/files/`
    - `materials/` — 课程资料（既有）
    - `lab-answers/{yyyy-MM-dd}/` — 实验答题图（本期）
- `scripts/path-b/backend.sh` 注入绝对路径：`H2_FILE`、`FILE_STORAGE_ROOT`。裸跑时 yml 默认相对 `backend/` 的 `../data/...`，同样指向仓库根。
- **重启后业务数据与上传文件保留**；首次启动或清空目录后会 Flyway 灌种。
- 单元测试仍用 `src/test/resources` 的内存 H2，与路径 B 文件库隔离。
- 前端 `src/utils/request.ts` 使用相对路径 `/api/v1`，开发态走 Vite 代理，一般**不必**复制 `frontend/.env.example`。
- 代理目标默认 `http://localhost:8080`，可用环境变量 `VITE_API_TARGET` 覆盖。
- 根 `.gitignore` 已忽略 `data/`，不会进仓库。

## 3. 启动步骤

在仓库根目录开两个终端（或两个后台任务）。

**终端 1 — 后端**

```bash
./scripts/path-b/backend.sh
```

**终端 2 — 前端**

```bash
./scripts/path-b/frontend.sh
```

前端脚本会在缺少 `node_modules` 时自动执行 `npm install`，再启动 Vite。

访问：http://localhost:5173/


## 6. 换端口（可选）

后端占用冲突时：

```bash
SERVER_PORT=18080 ./scripts/path-b/backend.sh
```

前端指向新后端，并可选换前端端口：

```bash
VITE_API_TARGET=http://127.0.0.1:18080 ./scripts/path-b/frontend.sh -- --port 18081
```

脚本会把额外参数传给 `npm run dev`。

---

## 7. 停止与重置数据

在对应终端按 `Ctrl+C` 结束进程即可。文件库与上传默认保留。

若要清空路径 B 本地库并重新灌种：

```bash
# 先停后端，再删除文件库目录
rm -rf data/h2
./scripts/path-b/backend.sh
```

仅清空实验答题图（保留资料等其它上传）：

```bash
rm -rf data/files/lab-answers
```

## 8. 常见问题

1. **登录报「角色不能为空」**  
   请求体缺少 `role`。页面登录会带角色；用 curl 时需显式传 `TEACHER` 或 `STUDENT`。

2. **后端默认连 MySQL 失败**  
   确认环境变量 / 脚本使用的是 `SPRING_PROFILES_ACTIVE=test`，不要裸跑 `./mvnw spring-boot:run`。

3. **前端依赖未安装**  
   使用 `./scripts/path-b/frontend.sh`，或手动 `cd frontend && npm install`。

4. **`mvnw` 报找不到 mvn**  
   安装 Maven 并保证 `mvn` 在 `PATH` 中（当前 wrapper 会转调系统 Maven）。

5. **与路径 A 冲突**  
   路径 A 也会占用 `8080/5173`。不要并行占用同一端口；先停一侧再启另一侧。

6. **想清空演示/联调数据**  
   停后端后执行 `rm -rf data/h2`，再启动即可重新灌种。

7. **旧数据还在 `backend/data/`**  
   布局已迁到仓库根 `data/`。若需保留旧库，可自行把 `backend/data/h2` 挪到 `data/h2` 后再启动；否则直接用新目录即可（空目录会重新灌种）。

## 9. 相关配置位置

| 文件 | 作用 |
|------|------|
| `backend/src/main/resources/application-test.yml` | 路径 B：H2 **文件库**、Flyway、H2 Console（`H2_FILE`） |
| `backend/src/test/resources/application-test.yml` | 单元测试：H2 **mem**（勿改成文件库） |
| `backend/src/main/resources/application.yml` | `app.file-storage-root`（`FILE_STORAGE_ROOT`） |
| `scripts/path-b/backend.sh` | 注入仓库根 `data/` 绝对路径并启动 |
| `data/h2/` | 路径 B 本地 H2（gitignore，可删重置） |
| `data/files/` | 路径 B 上传根（含 `lab-answers/{yyyy-MM-dd}/`） |
| `frontend/vite.config.ts` | 开发服务器与 `/api` 代理（`VITE_API_TARGET`） |
| `frontend/.env.example` | 可选；生产/容器场景的 `VITE_API_BASE_URL` 示例 |
| `backend/AGENTS.md` / `frontend/AGENTS.md` | 启动约定与联调注意点 |
