## 示例用法

```bash
# 门禁：默认按 git 改动侧跑 lint/test/build（仓库根目录执行）
./scripts/dev/gate.sh
./scripts/dev/gate.sh --all

# 环境验收：端口检查 → 未就绪则启动 → healthcheck
./scripts/dev/env-up.sh

# 交付报告：生成 commit message 建议 + diff 摘要 + 验收清单（纯 stdout）
./scripts/dev/delivery.sh --prepare --spec docs/技术方案/2026-11-25-研发工作流自动化工具技术方案.md
```

## 1. 用法与参数

### 1.1 `scripts/dev/gate.sh`

| 参数 | 行为 |
|---|---|
| （无参数） | 按 `git status --porcelain` 判定 frontend / backend 改动侧，只跑有改动侧；无改动侧输出 `[SKIP]` |
| `--frontend` | 强制跑前端侧 `npm run lint` → `npm test` → `npm run build`，无 `[SKIP]` |
| `--backend` | 强制跑后端侧 `./mvnw test`，无 `[SKIP]` |
| `--all` | 强制两侧全跑，无 `[SKIP]` |
| `--help` | 打印 usage |

- 三种模式参数互斥，多于一个时打印 usage 并退出 2。
- 输出前缀：`[GATE]`（逐命令进度）、`[PASS]` / `[FAIL]` / `[SKIP]`（汇总）。
- 任一子命令非 0 即停止本侧后续命令，汇总行写明首个失败命令与退出码。

### 1.2 `scripts/dev/env-up.sh`

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `BACKEND_PORT` | `8080` | 后端端口，透传为 `SERVER_PORT` |
| `FRONTEND_PORT` | `5173` | 前端端口 |

固定顺序：后端端口检测（未监听则 `nohup` 启动 `scripts/path-b/backend.sh`，日志 `/tmp/teaching-platform-dev-backend.log`）→ 归属预检（端口已有监听时 POST 空 body 至 `/api/v1/auth/login`，HTTP 400 且响应体含 `"code":40000` 判为本平台，其余判为非本平台占用）→ `scripts/common/healthcheck-login.sh` → 前端端口检测（未监听则启动 `scripts/path-b/frontend.sh`，日志 `/tmp/teaching-platform-dev-frontend.log`）→ 前端 HTTP 探活。

- 幂等：服务已在运行则跳过启动、报告 `ALREADY_RUNNING`，不重复拉起。
- **不 kill 任何进程**；端口被非本平台进程占用时报告占用方 PID 并退出 1，由用户自行处理。

### 1.3 `scripts/dev/delivery.sh`

| 参数 | 行为 |
|---|---|
| `--prepare` | 唯一子命令；输出三节报告：commit message 建议、`git diff --stat` 摘要、验收清单 |
| `--spec <路径>` | 必传；指向含「验收标准」节的技术方案文件，awk 提取该节逐条转为 `- [ ]` 清单 |

- 纯 stdout、不写文件、零 git 写操作；脚本无 `--push` / `--commit` / `--add`。
- 验收清单的「需浏览器人工验收」/「本次已自动验证」状态标注由编排技能（Stage 6）完成，脚本只输出条目。

## 2. 退出码

| 脚本 | 退出码 | 含义 |
|---|---|---|
| `gate.sh` | 0 | 全部通过（含两侧均 `[SKIP]`） |
| `gate.sh` | 1 | 任一子命令失败 |
| `gate.sh` | 2 | 参数错误（多模式互斥等） |
| `env-up.sh` | 0 | 两服务就绪（`[PASS]`，均 already 时附加 `[ALREADY_RUNNING]`） |
| `env-up.sh` | 1 | 失败；`[FAIL]` 必带 `[ENV]`（端口占用/未就绪）或 `[CODE]`（healthcheck 登录失败）之一 |
| `delivery.sh` | 0 | 报告已输出 |
| `delivery.sh` | 2 | 参数缺失 / `--spec` 文件不存在 / 未找到验收标准节 |

## 3. 自检命令清单

```bash
# T2 的 7 词表含「或 / 推荐」，两词因 frontmatter 触发词列举合法命中且正文常见，grep 全量误报，
# 不入命令清单，须按技术方案 §4 T2 断言逐处人工核对。

# T3 脚本语法
bash -n scripts/dev/gate.sh scripts/dev/env-up.sh scripts/dev/delivery.sh

# T4 gate 判侧（干净工作区预期 2×[SKIP]+[PASS]，退出 0）
./scripts/dev/gate.sh

# T5 gate 强制（前端有改动时无 [SKIP]）
./scripts/dev/gate.sh --frontend

# T7 gate 参数互斥（预期 usage，退出 2）
./scripts/dev/gate.sh --frontend --backend

# T8 env 就绪（服务运行中：[PASS]，均 already 时含 [ALREADY_RUNNING]，退出 0）
./scripts/dev/env-up.sh

# T11 delivery 输出（三节报告；执行前后 git status 无变化）
./scripts/dev/delivery.sh --prepare --spec docs/技术方案/2026-11-25-研发工作流自动化工具技术方案.md

# T12 delivery 参数（预期 usage，退出 2）
./scripts/dev/delivery.sh --prepare

# T13 守卫零新增
git diff --stat
```

T6（gate 失败场景：临时语法错误）、T9（`python3 -m http.server 8080` 占位验证 `[ENV]`）、T10（`USERNAME=nouser PASSWORD=x` 验证 `[CODE]`）为有副作用/需占用端口的用例，操作步骤见技术方案 §4，验证后须还原现场。
