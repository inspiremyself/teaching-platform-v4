# 自查并修正

对**技术方案文档**或**代码实现**做多轮自查 → 修复 → 再自查，直到**本轮新发现问题点收敛**（≤2，最好为 0）。收敛标准与 `feature-dev-workflow.mdc` 一致。

## 工作流嵌入点（`feature-dev-workflow.mdc` 何时 invoke 本技能）

| 工作流章节 | 模式 | 未收敛前禁止 |
|------------|------|--------------|
| §1.1 方案写完 | **方案模式**（§2） | §2 编码、标「已定稿」 |
| §2.1 编码写完 | **实现模式**（§3） | §3 验证、声称可验收 |
| §3 验证失败 | **实现模式**（§3） | 口头宣称已修好（问题点重新计数） |

用户口头触发（`/self-review-and-fix`、`自查并修正` 等）：先 §0 判定模式，再执行对应章节。

---

## 0. 判定模式（必须先做）

根据**上一轮对话主任务**（不是用户最新一句里的单个词）选一条路径：

| 模式 | 触发信号（满足任一） |
|------|----------------------|
| **方案模式** | `feature-dev-workflow` §1.1 方案写完；上一轮在起草/修订 `docs/技术方案/*.md`；用户说「自查方案」「审阅方案」「方案定稿前检查」；尚无对应实现 diff |
| **实现模式** | `feature-dev-workflow` §2.1 编码写完或 §3 验证失败；上一轮在改前后端/测试代码；用户说「对照技术方案自查实现」「实现自查」；git diff 或对话中已有方案对照编码 |

**无法判定时**：若存在未收敛方案且用户未开写码 → 方案模式；若已有实现改动且存在已定稿方案 → 实现模式；仍不清则向用户确认一句。

**不要**在同一轮里混做方案+实现大改；实现模式发现方案缺口时，先最小回写方案再改码。

---

## 1. 收敛规则（两模式通用）

每轮只统计**本轮新发现**的问题点（上轮已修的不重复计）。轮次 N 从目标方案 **§修订记录** 已有行数 +1 推算，或实现模式从对话上下文续编。

| 本轮新发现问题点 K | 动作 |
|-------------------|------|
| K = 0 | ✅ 收敛，结束 |
| K ≤ 2，且均为非阻塞项且已修复/记入修订记录 | ✅ 收敛，结束 |
| K > 2 | ❌ 修复全部后**必须**再 invoke 本技能开下一轮 |
| 需用户拍板 | ❌ 写入方案「待确认」，停下，不算收敛 |

**非阻塞项**：措辞、修订记录、示例微调。**阻塞项**：API/状态机/鉴权/入口/验收不可测/决策清单缺口/与现网矛盾/测试计划无法覆盖 schema 或契约变更。

每轮结束前**必须**用下方模板向用户汇报；方案模式同步写入 §修订记录（含轮次、K、处理、结论）。

## 2. 方案模式

**必读**：`tech-spec-decisive.mdc`、目标方案全文、`feature-dev-workflow.mdc` §1.1。

### 2.1 每轮动作（按序执行，不可跳步）

1. **决策清单逐行**：入口、API、鉴权、边界、验收、非目标 — 每行能在正文找到唯一展开，且与 §测试计划 / §验收标准 / §实施顺序 可互指。
2. **现网对照**（§2.2）：验证方案「现状/迁移/删除」假设与仓库一致；发现矛盾优先改方案。
3. **五透镜扫漏**（§2.3）：专抓「写得像定了、实现仍会猜」的缺口。
4. **歧义词搜索**（§2.4）：全文扫未写死的实现路径。
5. 列出**本轮新发现问题点**（编号，阻塞项标注）。
6. **当场修文档**；开放项写进「待确认」或「非目标」；同步 §修订记录。
7. 按 §1 判定收敛；已收敛则文首状态为 **已定稿（决策写死，可直接编码）**（若尚未定稿）。

### 2.2 现网对照（方案模式必做）

用 **codegraph**（架构/调用链/符号定义）或 **grep**（精确符号、迁移文件名）核对，至少覆盖方案中**会被删改**的项：

| 对照项 | 做法 |
|--------|------|
| Flyway 序号 | `Glob **/db/migration/V*.sql`：新迁移版本 = 当前最大 +1 |
| 待删 API / 路由 / 字段 | grep 方案中的路径、字段名、Repository 方法在前后端与测试中的引用 |
| 鉴权与数据范围 | 读相关 Service/Filter；核对方案写的校验点是否覆盖 **create 与 update**、私有方法（如 `ownedXxx`） |
| 种子与演示账号 | 对照 `V*__seed*.sql`、README、`healthcheck-login.sh`；新增账号是否需同步文档 |
| 前端壳层 | 区分 `authStore.homePath` 与 `router/index.ts` 内 **`redirectToRoleHome`** 等**同名不同文件**的入口 |

**汇报**：收敛轮可在模板下附 3～5 条「现网核对结论」（方案假设与仓库一致/已修正）。

### 2.3 五透镜扫漏（方案模式高频漏项）

每轮至少快速过一遍；命中则计为问题点：

| 透镜 | 问什么 | 典型漏项（本仓库已出现过） |
|------|--------|---------------------------|
| **兄弟操作** | 只写了 `create` 鉴权，**`update` 改关联 id**（如 `classId`）是否同样校验？ | `ExamService.createExam` 写了、`updateExam` 漏写 |
| **权限列表** | `permissions` / 角色矩阵是否**完整枚举**，而非「在现网基础上去掉 X」？ | `TEACHER` 未写死删除 `CLASS_WRITE` 后的全量列表 |
| **测试连带** | schema/契约/Filter/删除类 变更后，**哪些现有测试类**必须删/迁/改 SQL？ | 漏 `StudentServiceTests`、`ClassServiceTests`、`JwtAuthenticationFilterTests`；`HomeworkServiceTests`/`LabServiceTests` 仍 `INSERT teacher_user_id` |
| **横表对齐** | 决策清单 #N ↔ §测试计划 ↔ §验收 ↔ §实施顺序 ↔ README/运维 是否同一口径？ | 演示账号进了种子却未进 README；测试只写 Controller 未写 ServiceTests |
| **破坏性契约** | record/DTO/JWT claim 变更后，**测试构造与便捷 API** 是否写死？ | `CurrentUser` 增 `schoolId` 未写便捷构造默认值；「可删或留空壳」类二选一 |

### 2.4 歧义词搜索

在目标方案中 grep：`或` / `二选一` / `可选方案` / `推荐` / `待定` / `亦可` / `可挂在` / `可不写` / `可删或` / `视情况`。

**不计入问题**（勿误报）：

- 枚举**取值**说明（如 `HEAD` 或 `SUBJECT`）
- 业务**行为描述**（如「看见或批改」）
- §修订记录 中对历史问题的复述

**计入问题**：任何涉及「做不做 / 用哪种实现 / 挂哪个入口 / 删还是留」的表述未给唯一结论。

### 2.5 方案轮次输出模板

```text
方案自查第 N 轮
- 新发现问题点：K 个
  1. …（阻塞/非阻塞）
  2. …
- 已修复：…
- 现网核对：（可选，收敛轮建议写）…
- 结论：未收敛（K>2，继续下一轮）/ 已收敛（K≤2 或 K=0）
```

## 3. 实现模式

**必读**：对应已定稿方案（决策清单 + 测试计划 + 验收标准）、`feature-dev-workflow.mdc` §2.1、相关文件 **git diff**。

### 3.1 每轮动作

1. **决策清单逐行勾选**（不是扫一眼）；未落地项计为问题点。
2. **对照 git diff** 扫高频漏项（下表）。
3. **测试连带**：方案 §测试计划 列出的用例/类名是否在 diff 中都有对应；`mvnw test` / `npm run build` 未跑不声称收敛，但可在收敛后提示 §3 验证。
4. 列出**本轮新发现问题点**（编号）。
5. **修复本轮全部**（方案缺口 → 先最小回写方案；bug → 最小 diff）。
6. 按 §1 判定；收敛后提示进入 `feature-dev-workflow.mdc` §3，除非用户已要求在本轮内跑验证。

### 3.2 实现模式 diff 高频漏项

| 类别 | 自查点 |
|------|--------|
| 契约 | `/api/v1`、响应解包、枚举/状态与后端一致 |
| 鉴权兄弟操作 | create **与** update/私有 `ownedXxx` 是否都改用同一 `*AccessService` |
| 前端交互 | 方案写死的 props/事件、只读/编辑态、双根模板、`homePath` **与** `redirectToRoleHome` |
| 异步与竞态 | 切题/切路由：关弹层、scope 快照、`generation`/`session` 丢过期请求 |
| 资源生命周期 | blob/预览：先 `closePreview` 再 revoke |
| 边界 | 加载失败、空列表、卸载中途回调 |
| 测试 | 方案 §测试计划 用例名/断言、错误文案、删类后旧测试是否清除、迁移后测试 SQL 字段 |
| 范围外 | 未开通能力语义不变 |
| 文档 | 方案要求更新的 README/运维示例是否在 diff 中 |

### 3.3 实现轮次输出模板

```text
实现自查第 N 轮
- 对照方案：<方案文件名>
- 新发现问题点：K 个
  1. …
  2. …
- 已修复：…
- 结论：未收敛 / 已收敛
```

## 4. 反例

- ❌ 只自查一轮就宣称收敛
- ❌ K>2 仍说「差不多了」
- ❌ 不列问题点编号，只口头说「没问题」
- ❌ 实现模式发现方案错误却直接改代码不改方案
- ❌ 把上轮已修问题重复计入本轮 K
- ❌ 未 Read 本 SKILL、仅凭 `feature-dev-workflow.mdc` 摘要执行自查
- ❌ 只做歧义词 grep、不做现网对照与五透镜
- ❌ 方案只写 Controller 测试迁移，漏 ServiceTests / FilterTests / 集成 SQL
- ❌ 鉴权只补 `create` 路径，漏 `update` 改关联 id 或 `ownedXxx` 私有方法
- ❌ permissions 写「去掉 X」却不给改后的完整列表
