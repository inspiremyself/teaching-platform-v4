# 视觉一致性审计（字号 / 尺寸类）

## 何时加载

- 用户给出截图或体验描述，例如「文字还是小」「某些元素没覆盖到」。
- 用户说「全面梳理」「统一规格和标准」「应用到所有页面」。
- 交付后再次反馈同类视觉问题，需要判断是定点残留还是全局标准缺失。

---

## 1. 全站覆盖审计清单

审计产物必须写入方案背景节，不能只写「截图看起来小」。

| 审计项 | 做法 | 产出 |
|---|---|---|
| token 档位引用 | `grep -RhoE 'var\(--font-size-[a-z0-9]+\)' frontend/src \| sort \| uniq -c`，再按 `views/teacher`、`views/student`、`views/admin`、`components/**`、`layout/**` 分组统计 | 各档位总数与分布文件数 |
| 文本 px 字面量 | `grep -RniE 'font-size:[[:space:]]*[0-9.]+px' frontend/src`，逐条标注是图标块还是文本 | 文本硬编码清单 + 图标例外清单 |
| 门禁盲区 | 读 `frontend/src/assets/__tests__/designTokens.spec.ts` 的 `styleScopeFiles` / 白名单 / `designTokenBaseline.json`，把硬编码所在文件标记为「扫描内」或「盲区」 | 盲区文件清单 |
| rem / em / zoom / scale | `grep -RniE 'font-size:[[:space:]]*[0-9.]+(rem\|em)\|zoom:\|transform:[[:space:]]*scale' frontend/src` | 非 token 字号来源清单 |
| Element Plus | 查 `--el-font-size-*` / `--el-component-size*` 映射，以及 `size="small"` / `size="large"` 控件 | EP 字号与高度来源清单 |
| 壳层与全局 | 查 `layout/**`、`assets/global.css`、`assets/layout.css`、`workbench.css` 的固定高度 / 宽度 / 字号 | 全局联动点清单 |

## 2. 定点修改与全局标准的决策规则

按以下顺序判定，结论写死在方案 §0 / §1：

1. 用户说「所有页面 / 统一规格 / 全面梳理 / 应用到所有页面」→ **必须走全局标准**，禁止只按截图红框定点改。
2. 同类低档引用 ≥50 处，或跨 ≥10 个文件 → **走全局标准**（调 token 阶梯或统一语义规格），定点修改仅用于全局落地后的残留修正。
3. 门禁盲区文本硬编码 ≥10 处 → 全局方案必须包含「px → token 映射清零」；只改 token 值不算全局方案。
4. 仅单个组件、无全局诉求、引用数很少 → 可定点，但方案必须写明「不做全局」的理由与非目标。
5. 交付后用户再次反馈同类问题 → 先回到审计表核对是否漏了盲区或只改了局部，禁止重复逐点补丁。

---

## 3. 全局标准方案必须写死的项目

- 新阶梯的全部数值，以及语义下限（辅助 / 次要 / 正文 / 条目 / 卡片标题 / 区块标题 / 页面主标题）。
- 控件高度与 EP 变量映射。
- `designTokens.spec.ts` 的 `FONT_SIZE_LADDER` 常量、注释、白名单注释同步要求；`designTokenBaseline.json` 不重写。
- 盲区硬编码的 px → token 固定映射表，逐值写死；图标例外必须点名到文件与选择器。
- 旧方案 / PRD 的覆盖指针，写死落点与文本。
- 验收口径：最小字号、门禁全绿、盲区文本 px 计数为 0、密集区无截断 / 重叠 / 横向滚动。

---

## 4. 方向确认模板

用 `ask_followup_question`，选项必须带具体数值与验收口径，禁止问「要不要改」这类无信息量问题。

示例结构：

```text
问题：已清点到 <低档引用数> 处 / <文件数> 个文件，另有 <盲区硬编码数> 处文本硬编码。
推荐：<新阶梯全部数值>，辅助 ≥N / 次要 ≥N / 正文 ≥N，门禁全绿，盲区文本 px 清零。
选项：
1. 标准档（推荐）：<全部数值 + 验收口径>
2. 增强档：<全部数值 + 更高验收口径 + 溢出风险>
3. 只清盲区硬编码：不动阶梯，说明为何不推荐
4. 先只改某页面：说明适用范围与后续计划
```

用户已明确说「直接推进」时可跳过确认，但方案必须记录该授权来源。

---

## 5. 实现自查扫漏

- 盲区组件内 `font-size:\s*\d+px` 应只剩方案点名的图标例外；门禁扫描范围内不得新增 px 字号字面量。
- EP 组件类变量覆盖必须写在组件类选择器上（如 `.el-tag { --el-tag-font-size: ... }`），不能只写 `:root`，否则会被组件类本地变量遮蔽。
- 禁止顺手修改未写入方案的 `line-height` / `letter-spacing` / `font-weight` 等属性；发现需要时先回写方案。
- token 定义与门禁常量 / 注释必须逐档一致；`FONT_SIZE_WHITELIST` 在新阶梯不含 24 时仍保留 24 供图标豁免，并同步注释。
- 新增测试若用 `matchAll`，正则必须带 `g` 标志；若用 `splitRules` 解析 CSS，选择器字符串可能带前置 CSS 注释，需先去注释再精确匹配。

---

## 6. 验证与人工验收

- 自动验证只走 `scripts/dev/gate.sh` 与 `scripts/dev/env-up.sh`，禁止现场拼 lint / test / build / 启动命令。
- 视觉验收项可用浏览器自动化辅助核对；若登录失败、页面不可达或截图无法判读，保持「需浏览器人工验收」标注，不得标成「本次已自动验证」。
- 交付报告必须逐条标注验收项，并说明前几轮未提交改动是否计入 diff 摘要。
